# 文档 ↔ 代码一致性（ZXPlat）

> **本 Skill 覆盖并修正** Whale「仅文档先行」口径：ZXPlat **允许代码先行**，但 **同一变更闭环内必须消除漂移**。

## 0. 文档不是垃圾场（硬门禁，优先于后文「回写」冲动）

| # | 规则 |
|---|------|
| D0 | **默认不落盘文档**。用户未说「写文档 / 补 DM·SDD·AS / 更新 docs / 留脚本」且未 @ 文档类 Skill 时，**禁止**新建、扩写 `docs/**` 下任何文件 |
| D1 | **禁止 ops 垃圾桶**：`docs/领域/专题/ops/`（及类似路径）**不是**会话执行留痕处。补数/刷数/纠错 → **直接对目标库执行**；**禁止**主动新建 `补单-*.sql`、`V*__*-pro.sql`、`排查-*.sql`「方便以后」 |
| D2 | **热修 / UI / 文案 / 展示映射**：默认只改代码（及必要库数据）；**不要**顺手改 AS/DM「记一笔」 |
| D3 | **契约回写例外**（仅此可写文档）：本轮已声明模式 A/B，且改动触及 **方法白名单 / BR / 状态机 / IF 契约**，须按 §1–§6 **最小必要**回写对应 DM/SDD/AS——**仍禁止**夹带 ops SQL、排查稿、补单脚本 |
| D4 | 用户明确说「别留文档 / 脚本留着没用」→ 删除本轮已写但未要求保留的 docs 文件，**不得**再补 |

**违反 D0–D4 → 交付失败**（先删垃圾文件，再谈一致性清单）。

## 1. 双模式（任选其一，会话开始声明）

| 模式 | 顺序 | 何时用 |
|------|------|--------|
| **A. 文档先行** | DM/SDD（或 AS）→ 代码 → 再对一遍清单 | 新聚合、改 BR/状态机、对外契约 |
| **B. 代码先行** | 代码（可编译）→ **同会话**回写 DM/SDD → 清单 | 热修、对齐存量实现、探索性实现 |

**禁止**：只改一侧就结束会话；禁止「以后再补」且不留 `DOC-DRIFT`。

## 2. 权威与冲突

| 资产 | 角色 |
|------|------|
| `docs/领域/DomainModel/DM-*.md` §2–§7 | 领域语义、BR、状态机、方法白名单（成稿） |
| `docs/领域/DomainModel-SDD/*-SDD.md` §4–§5 | 字段全集、命令、方法契约摘要（成稿） |
| `*DomainService` / `*QueryService` Java | **可运行真源**；模式 B 时用于回写文档 |

**领域目录只保留四类**：`DomainModel/` · `DomainModel-SDD/` · `缺口/` · `专题/`。  
**禁止**再为单个 `.java` 生成镜像 `.md`，禁止 `docs/领域/包/` 树。  
**`专题/ops`**：仅用户要求保留的运维材料；见 **§0 D1**——Agent 禁止当 SQL 垃圾场。

**冲突裁决（同会话）**：

1. 用户明确裁决 > 一切  
2. 模式 A：改代码对齐文档；记 `DOC-CONFLICT` 仅当文档有误需另开文档任务  
3. 模式 B：改文档对齐代码；在 DM §9 / SDD 变更记录写「代码先行回写 + 日期 + 方法/字段列表」  
4. **禁止**长期双真源；`status: stub|draft` 的 DM **不得**当作唯一成码依据，除非本轮同时升格关键章节

## 3. 一致性门禁（交付前必过）

针对本轮改动的每个聚合对应的 `DM-*.md`（及有则 `*-SDD.md`）：

| # | 检查项 | 模式 A | 模式 B |
|---|--------|--------|--------|
| C1 | `*DomainService` 每个 `public` 写方法在 DM §6.1 或 SDD §5.1 有对应项 | 缺则补代码或删多余方法 | 缺则补文档 |
| C2 | DM §6.1 / SDD §5.1 列出的写方法在 Java 存在（或显式标废弃） | 缺则补代码 | 缺则删文档或标废弃 |
| C3 | 聚合根/子实体字段与 DM §3、SDD §4 可追溯 | 同左 | 同左 |
| C4 | 新发领域事件 ∈ DM §5 / SDD §7 | 同左 | 同左 |
| C5 | 代码/注释中的 `BR-*` ∈ DM §7 | 同左 | 同左 |
| C6 | 无静默 `DOC-DRIFT`；若暂不能关，见 §4 | 必须 | 必须 |

应用层（AS）：IF 编排依赖的领域方法必须能在 DM/SDD 找到；Gap **仅** AS §3 三类（QueryService / DM 写能力 / 代码-文档不一致）。

## 4. DOC-DRIFT（临时欠账）

无法同会话关齐时，**必须**在 `docs/领域/缺口/DOC-DRIFT.md` 追加一条：

```markdown
| 日期 | 聚合 | 模式 | 漂移项 | 计划关闭 |
|------|------|------|--------|----------|
| YYYY-MM-DD | administration/patient | B | DM §6.1 缺 mergePatient | 下一次改患者会话 |
```

无条目却不一致 → **视为交付失败**。

## 5. 模式 B 最小回写包（代码先行）

改完 Java 后至少更新：

1. `docs/领域/DomainModel/DM-*.md`：§6 方法表或对应 `####`、§7 若新 BR、§5 若新事件、§9 变更一句  
2. 若有 SDD：`docs/领域/DomainModel-SDD/*-SDD.md` §5 对应方法块（或标 draft 并 DOC-DRIFT）  

占位聚合：可维持 `status: stub`，但 **本轮新增的 public 方法必须写进 stub 的「已实现方法清单」表**，禁止空 stub。

## 6. 模式 A 最小改码包（文档先行）

1. Read `DomainModel/DM-*.md` §6/§7 → `DomainModel-SDD/*-SDD.md` §5  
2. 按 SDD/DM 改 Java  
3. 跑 §3 门禁  

## 7. 与其它 Skill 关系

| Skill | 关系 |
|-------|------|
| `代码生成通用规范` | Java 工程门禁仍适用 |
| `领域层代码生成提示词模板` | 领域对准；**权威冲突以本 Skill §2 为准** |
| `领域SDD生成提示词模板` | SDD 金骨架；SDD 正文仍禁止 YAML 状态键 |
| `应用服务文档/SDD` | 应用层；Gap 规则不变 |
| `领域模型文档生成提示词模板` | DM 落盘 `DomainModel/` |

## 8. Agent 会话开头（建议粘贴）

```text
模式：A 文档先行 | B 代码先行 | （热修默认不写文档，见 §0）
聚合：{bc}/{agg} · DM-XXX-NNN
本轮改动：…
本轮是否允许落盘 docs：是（用户要求 / 契约回写）| 否
```

结束前输出：`一致性门禁 C1–C6：PASS|FAIL` + `§0 文档落盘：未写 docs | 仅契约最小回写 | …` + 若有 DOC-DRIFT 条目链接。
