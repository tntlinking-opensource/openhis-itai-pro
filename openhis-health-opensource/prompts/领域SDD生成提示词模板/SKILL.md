#领域SDD生成提示词模板

## 1. 适用范围

- 适用于可配置目标工程 `{{TARGET_PROJECT}}` 与目标模块 `{{TARGET_MODULE}}`。
- 仅用于 DomainModel-SDD 生成/修订，不直接生成代码。
- 权威来源顺序：DM > 既有 SDD > 历史实现。

### 1.0 定稿 / 非定稿（流程标签，不出现在 SDD 正文）

**本 Skill 里「定稿」= 可拿进成码会话的 SDD**；**「非定稿」= 仍属草案，不能当写代码唯一依据**。脚本/清单可用 `codeready`、`draft` 作状态值；**禁止**把这类键写入 DomainModel-SDD 正文页眉（见 §1.2）。

| 口语 | 条件摘要 | 流程标签（外部维护） | 会话 B（成码） |
| ---- | -------- | -------------------- | -------------- |
| **定稿** / 可成码 | 已按 §2.1.2 母版写全、缺口已关、**§1.4 可判 PASS** | `codeready` | 允许（且 DM 须锁定） |
| **非定稿** / 草案 | 只有索引/表、缺 §5 逐方法、有「待补」、或 **§1.4 不通过** | `draft` | 禁止 |

### 1.05 正文不重复工程与 DM 成稿条款

DomainModel-SDD **只**写：本 Skill 规定的骨架、`{{TARGET_MODULE}}` 落点、领域契约（实体/命令/事件/BR/查询）。已在**项目级 Java 成码门禁**与 **DM 九章成稿规则**中统一约定的内容（例如注释/JavaDoc 与交付块次序、Flyway 与字段表同轮、Repository 禁手写 JPQL、下拉 DTO 收敛、全局软删语义、文档与实现先后顺序等），**不得在 SDD 正文展开细则**；必要时 **一句**交代「遵循项目级成码门禁」即可。

> **"不重复"的边界（强制）**：本条仅禁止将"工程约定的规格文字"（JavaDoc 规则、Flyway 路径、注解禁令等）抄入 SDD 正文。**以下内容属于 SDD 的落地契约，不在"不重复"范围内，必须完整列出，不得以"DM 已有"为由省略或简化**：
> - `§4.2 / §4.3 / §4.4` 字段表：须与 DM `§3` 对应节**完整对齐**（字段名、类型、必填、说明），**禁止选取子集**；
> - `§7` 事件表：须枚举 DM `§5` 定义的**全部事件**，含最小载荷与触发方法；
> - `§5` 写方法契约：须覆盖 DM `§6.1` 列出的**全部写方法**（含任何重复编号下的所有方法）。

### 1.1 仓库目标（简短）

1. **版式**：凡称定稿者，结构与 **§2.1.2** 一致。  
2. **厚度**：定稿须经 **§1.4**，避免出现 600 行与 70 行混称「都好」。  
3. **分级**：未达标必须 **非定稿（draft）** 或与定稿分区存放，勿让短文拖垮成码口径。

### 1.2 SDD 正文禁止页眉元数据

- **不得出现**：文首 YAML `---` 块、正文中的 `sdd_status:`、`dm_code:` 等键值行（避免与契约正文混淆、避免重复维护）。  
- **定稿状态**：由 §1.4 校验结果 + 评审流程认定；机器可读索引可用侧车清单、目录 manifest 或 CI 注入参数维护，**不写入** SDD 文件。  
- **存量**：若旧稿含上述页眉，修订时应删除以符合本条。

### 1.3 存量治理（简短）

- **可选** `DomainModel-SDD/_draft/` 堆放未定稿短文，避免与「像定稿」混在一起。  
- **PR**：改 SDD 要么升格为 **§1.4 PASS + 认定为可成稿**，要么维持 **非定稿**且 PR 不写「可依此成码」。  
- **引用**：Prompt/Agent **默认可引用的契约**仅限已通过 §1.4、流程认定为定稿的版本；引用 **草案**须写明「草案」。

### 1.4 自动化校验契约（脚本/CI；PASS 定义）

由仓库脚本实现（语言任选）；此处只约定 **PASS/FAIL**，不写脚本路径。

**输入**：单文件，或目录递归 `*-SDD.md`（可排除 `_draft/`）。

**结构硬门禁（任一失败 → FAIL；FAIL 则不得认定为可成稿）**

1. 文件含 `# … · DomainModel-SDD` 标题行。  
2. 含 `## 输入完整性检查结果` 且下一行起为「最小输入项 | 状态 | 说明」三列表头。  
3. 依次含以下 **主章节标题原文**（顺序一致）：  
   `## 1. 设计目标与边界` → `## 2. 工程落点与包结构` → `## 3. 类型 / 字段命名 / 注解规则` → `## 4. 实体 / 值对象 / 枚举 / 仓储 / 查询契约` → `## 5. 写侧与读侧白名单（命令字段全集）` → `## 6. 不变式映射（DM §7）` → `## 7. 事件契约与触发规则（DM §5）` → `## 8. 删除与可见性契约` → `## 9. 框架优先适配规则` → `## 10. 生成与验收清单` → `## 11. 单次会话代码生成门禁（DoD）`。  
4. 含 `### 5.1 写侧` 与 `### 5.2 读侧`（领域服务名可不同，但 **`### 5.1 写侧 —`** 前缀必须存在）。  
5. 含 **至少一个** `#### 5.1.` 子节（逐方法小块）；**`#### 5.1.n` 节数必须严格等于 DM `§6.1` 中所有写方法的数量（含序号重复下的每个不同方法名）**——多或少均 FAIL；脚本可通过同目录 DM 或 CI 传入 `expected_write_methods` 做自动比对（强制，非可选）。  
6. 含 `## 定稿检查清单（可打勾）`、`## 定稿评分（百分制）`、文末 `**本 SDD 正文结束。**`。  
7. 每个 `#### 5.1.` 块内须同时出现：`**命令文件**`、`**字段全集**`、`| 绑定项 | 内容 |`、`` `entityInvariantMethod` ``、`` `unitTestCaseId` ``（防止「只有方法名表」）。  
8. 每个 `#### 5.1.` 块内须出现 `**方法契约摘要**`，并明确前置条件、持久化影响、失败语义与事件触发；缺失任一项 → FAIL。  
9. **正文页眉**：文件首部 **不得** 出现 `sdd_status:`、`dm_code:` 或 YAML front matter（与 §1.2 一致；违反 → FAIL）。
10. **§4.6 QueryModel 字段表**：`### 4.6` 下每个读方法须有独立 `#### 4.6.n` 子节，且子节内须含 `| 字段名（Java）` 三列以上表头行；仅写「至少包含：…」类占位描述 → FAIL。
11. **§4.2/§4.3/§4.4 字段表完整性**：`### 4.2`（聚合根）与每个子实体节（`### 4.3`、`### 4.4` 等）的字段表行数，必须 **≥** DM `§3` 对应节字段表的行数；字段名须与 DM 保持一致，禁止截取子集或省略非必填字段 → 违反 FAIL。
12. **§7 事件表完整性**：`## 7` 事件表中的事件行数必须 **严格等于** DM `§5` 所定义的全部事件数量（含学生类、合并类等所有方法触发的事件）；缺少任一事件行 → FAIL。

**软门禁（默认 WARN；CI 可加 `-Strict`）**

- 命中：`待确认`、`后续补充`、`暂不细化`、孤立 `占位`（例外：条文写「禁止占位」）。  
- **已定稿认定**的目标文件若全文行数 **低于默认 250**（可配置）→ **FAIL**。

**退出码**：`0` PASS；`1` FAIL；`2` 仅 WARN。

**联动**：FAIL → 流程上维持非定稿；已误判为可成稿 → 修正或降级。

**原则**：所有 DomainModel-SDD **排版与章节骨架必须与 §2.1.2「金骨架母版」逐字同构**（标题、层级、表格列名、`---` 位置一致）；差异只允许出现在「业务内容」（聚合名、方法名、字段、BR、事件）。**禁止**依赖仓库里任何既有 `*-SDD.md` 文件作为版式来源（避免缺失、删除或漂移）。

**§2.1.2 金骨架母版（Markdown，复制后替换 `{{占位符}}`）**

- **用法（强制）**：生成或修订 SDD 时，**第一步**输出下方母版全文，再替换占位符；**禁止**删减章节、禁止改 `##`/`###`/`####` 标题文案、禁止改表格列名、禁止去掉方法之间的 `---`。
- **占位符约定**：`{{DM_CODE}}`（如 `DM-ADM-001`）、`{{AGG_EN}}` / `{{AGG_ZH}}`、`{{DM_PATH}}`、`{{BC}}`、`{{ROOT}}`、`{{PKG}}`、`{{DomainService}}`、`{{QueryService}}`、写方法 `{{W1_METHOD}}`…、读方法表行按需增删。

## 6. 质量门禁

- **字段覆盖**：DM `§3` 各实体（聚合根与每个子实体）的字段表 **100% 映射**到 SDD `§4` 对应节；字段名、类型、必填与 DM 保持一致，**不得选取子集或遗漏非必填字段**（§1.05 "不重复"原则不适用于字段表，字段表是落地契约，必须完整）。
- 方法覆盖：DM 第6章白名单方法 100% 映射（写侧+读侧）；DM 中存在序号重复时，须以**方法名**为唯一标识，每个不同方法名各对应一个 `#### 5.1.n` 节。
- 规则覆盖：DM 第7章关键 BR 必须映射到实现策略。
- **事件覆盖**：DM 第5章全部事件逐行出现在 SDD `§7` 表中（含学生类、状态类等所有事件），缺一行视为未覆盖。
- 结构覆盖：章节齐全，无占位小节、无“后续补充”措辞。
- 口径一致：`*_enum`/`*_code`/`_flag`/`isDeleted`、事件机制、分页默认规则保持全篇一致。
- 上线语义覆盖：必须覆盖“占位实现禁用、规则不可降级、分页语义一致、同步幂等、更新不静默新建、关键 BR 可测”六项门禁。
- 简洁性覆盖：必须避免“为分层而分层”的过度封装，保持实现可读、可审计、可维护。

## 6.1 不可跳过验证项（强制）

以下 7 项为“生成前与定稿前”双门禁，任一不满足即判定不合格，禁止进入代码生成会话：

1. **DM 锁定验证**  
   - 必须确认输入 DM 已定稿（Locked DM）。  
   - DM 未锁定时，禁止输出 SDD 定稿结论。

2. **固定章节顺序验证**  
   - SDD 章节顺序必须与本 Skill 固定结构一致。  
   - 禁止重排主章节、禁止新增平行主章节替代既定章节职责。

3. **DM 第6章白名单对齐验证**  
   - 写侧/读侧方法必须 100% 对齐 DM 第6章。  
   - 缺失、重命名、新增未授权方法均判定失败。

4. **软删语义验证**  
   - 必须明确 `isDeleted` 逻辑删除语义，禁止物理 DELETE。  
   - SDD 与实现口径均须写明 `Boolean isDeleted` 与默认过滤。
   - 若框架已统一处理软删过滤，Repository 契约不得强制 `*IsDeletedFalse` 冗余命名。

5. **DM 语义去重验证**  
   - SDD 不得重复抄写 DM 全量业务语义。  
   - 同一事实只能在一处定义，其他章节通过规则 ID/方法名引用。

6. **最小深度验证**  
   - 每个方法契约至少包含：入参、出参、前置条件、失败语义、状态变化、持久化影响、事件输出。  
   - §4.6 每个读方法须有独立 QueryModel 子节（含字段名、类型、来源三列表）；仅占位描述视为深度不达标。  
   - 缺任一项视为深度不达标，禁止定稿。

7. **注释可实施性验证**  
   - 每个复杂方法必须给出“方法内部注释锚点”：校验、状态迁移、持久化、事件发布。  
   - 若契约无法映射到内部注释锚点，禁止定稿。

8. **禁止占位实现验证**  
   - 禁止 `SELECT FALSE/TRUE`、`return false/true` 作为业务占位实现。  
   - 若外部依赖未就绪，必须在 SDD 缺口清单中显式标注并阻断定稿。

9. **规则不可降级验证**  
   - DM 已定义组合规则（如重复建档组合条件）不得简化为单字段判断。  
   - 任一降级实现均判定失败。

10. **分页语义一致性验证**  
   - 禁止“先分页后内存过滤”导致 `totalElements` 与结果集不一致。  
   - 必须在查询层保证分页统计与过滤口径一致。

11. **同步幂等验证（`syncChildRecords` 等子表对齐）**  
   - 默认策略为 **全量对齐 + 软删旧行**：以本次入参集合为权威，对不在集合内的既有子表行执行逻辑删除（`isDeleted=true`），禁止物理 `DELETE`。  
   - 对集合内记录按业务键（如 `typeCode + identifierNo` 或 SDD 约定键）做 **新增或更新**，保证幂等与可追溯。  
   - 不得以「整表物理清空再插入」代替上述语义（除非 SDD 显式批准并说明审计例外）。

12. **更新语义验证**  
   - 指定 ID 的更新路径查无记录时必须报错，禁止静默新建。  
   - 仅显式“upsert 场景”可新建，且需在契约写明。
   - **子实体更新归属**：命令或入参若携带子实体/子记录 `id`，必须在契约与实现中要求 **同时校验聚合根 id 与该子记录 id 归属一致**，禁止仅凭子记录 id 加载后写入。

13. **关键 BR 可测验证**

15. **事务声明验证**
