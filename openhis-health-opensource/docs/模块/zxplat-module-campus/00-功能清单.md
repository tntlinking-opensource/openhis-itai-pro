## 一、模块定位

### 1.1 是什么

**zxplat-module-campus** 是面向 **高校附属/校内医院** 的可选增值 Module，覆盖：

1. **多校区管理** — 支持 **N≥1** 个物理校区（编码、名称、启用态；NENU 示例：`BENBU` / `JINGYUE`）
2. **学院管理** — 教学院系/部（≈ `peis_company_college`；团检单位、学生归属）
3. **部门管理** — 教职工所在单位/人事部门（≈ `his_gf_person.C_RELATIONUNIT`；**非** HIS 临床科室）
4. **学生档案** — 学籍、体检态、转院（`cmp_patient_student`）
5. **教职工档案** — 医疗证、单位、在职态（`PatientStaff`）
6. **公费医疗** — 比例配置、审批、收费拆分、财务台账
7. **多校区协同** — 组织与档案在 **多节点/多院区** 间的增量同步（单校区院点可关闭）
8. **档案变更记录** — 学生/教职工档案 **字段级** 变更历史（改前/改后、操作人、来源）

`nenu-vue-his` 已实现的 **公费比例审批** 子集，演进为本 Module 管理端 UI 之一。

### 1.2 不是什么

| 不在 Campus | 归属 |
|-------------|------|
| 患者主档建档、院内编码、通用证件 | health · `PatientAppService`（ADM-001） |
| **HIS 临床科室/病区/药房**（诊疗科室树） | whale-framework · `Organization` / `sys_dept` |
| 挂号、医嘱、处方、收银主流程 | health 门诊 AS |
| 医保结算（吉林 CHS） | `zxplat-module-chs-jilin` |
| 银联 BPC 被扫 | `zxplat-module-unionpay-bpc` |
| 体检业务流水（个检/团检/总检/号源日程） | `PeisAppService`（**读** Campus 组织与档案 Client） |
| 框架系统用户/角色/菜单 | whale-framework |

> **组织边界**：Campus 维护的是 **校务组织**（校区 → 学院 → 部门/单位），供档案、公费、体检分组、统计使用；**不得**与临床 `sys_dept` 混表。

### 1.3 领域锚点

| 系统 | 聚合 / 表 | 职责 |
|------|-----------|------|
| **campus** | **`CampusSite`**（`cmp_campus_site`） | 多校区：编码、名称、地址、启用态 |

| **campus** | **`PatientStaff`**（`cmp_patient_staff`） | 教职工；**工号**主键；医疗证可空；`department_id` → Department |
| **campus** | **`PublicExpenseProfile`**（`cmp_pe_profile`） | 公费资格：`card_no`（公费卡/二维码）、`gf_status`、医疗证、有效期 |

### 1.4 与 Peis 的分工

| 能力 | Campus（真源） | Peis（消费） |
|------|----------------|--------------|
| 校区 / 学院 / 部门主数据 | ORG-* | GRP-01 / 小程序下拉 **改读 Reader**，废止 `peis_company_college` 双轨 |
| 学生 / 教职工名册 | STU-* / STF-*（`cmp_patient_student` / `cmp_patient_staff`） | GRP/REG **读 Reader** |
| 健康档案主索引 | health `Patient`（绑定） | PEIS 诊台可读 Patient + Campus 档案 |
| 学生档案 `campus_code` | STU-11 绑定校区（真源上移） | 登记/订单可冗余写入；**缴费白名单与号源日程仍属 Peis**（旧 `peis_student_exam_fee_paid`） |

| 微信绑定态 / 客户主档 | — | 归 Peis `peis_customer`；**不**用学籍 `active_status` 表示绑定 |

## 二、阶段与优先级

| 阶段 | 目标 | 能否替代遗留 |
|------|------|-------------|
| **P0** | 校区 + 学院 + 部门 CRUD + 学生/教职工档案 + **变更记录** + **调岗/转院记录查看** + Patient 绑定 + 公费审批已有能力 + 资格校验 Client | 替代 `peis_company_college`、组织下拉、`hisGfPerson.jsp` 主维护 |
| **P1** | 组织树导入、项目比例、门诊公费试算、医保组合、批量导入学籍/教职工 | 替代 `hisGfItem.jsp` + `ClinicChargeGfZf/Yb` |
| **P2** | **多校区**档案/组织同步、交账公费分项、组织维度统计 | 替代 `C_MODIFY` + `his_settlement_record` |
| **P3** | 教务/人事对接、多校版参数化、微信自助查档 | 院点选配 |

### P0 完工定义

- **组织**：支持 **N≥1** 校区（单校区院点仅维护 1 条默认校区即可）；学院、部门可挂任意启用校区
- **档案**：按姓名/身份证/学号/工号检索；与 `Patient` 绑定；**每次增删改写入变更记录**；详情可看历史
- **调动**：学生转院（跨校区/学院）、教职工调岗（跨部门/校区）可登记；详情 Tab **可查看调动时间线**
- **资格**：收费前 `checkPublicExpenseEligibility` 可拦截
- **公费**：全局比例 + 比例调整审批全流程（nenu-vue-his ✅）；**自费公费 / 医保后公费双模式**；审批回写同模式比例（RATIO-05）
- **Client**：Peis 可通过 `listCampusColleges` / `resolveStudentCampus` 读组织与校区，**不再**直连 `peis_company_college`

## 六、组织树结构（目标模型）

```text
CampusSite（校区）
  ├── CampusCollege（学院）          ← 学生 primary 归属
  │     └── CampusDepartment（系/所）  ← 可选
  └── CampusDepartment（直属部门）    ← 教职工 primary 归属
```

- 学生：**学院**必填，**校区**必填（可直接选或由学院默认带出）
- 教职工：**部门**必填，**校区**必填（办公校区）
- Peis 团检「单位」可映射为 `CampusCollege` 或顶层 `CampusDepartment`（院点配置）
