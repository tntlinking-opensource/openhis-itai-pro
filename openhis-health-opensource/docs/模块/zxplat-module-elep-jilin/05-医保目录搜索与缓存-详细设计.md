# 医保目录搜索与缓存 — 详细设计

> **范围**：电子处方 Picker 全局搜索（药品 1301/1312、诊断 1307）；上传组装时批量 code 校验。  
> **数据源**：复用 CHS 镜像表 `yb_national_catalog_item`（**Elep 不另建目录表、不下载目录**）  
> **版本**：v1.0 | **日期**：2026-06-18

---

## 1. 背景

电子处方组装需要：

- **药品**：`rxdrugdetail.medListCodg`（1301 明细 / 1312 摘要）
- **诊断**：`diseinfo.diagCode`（1307）

医生站 Picker 需 **keyword 全局搜索**（名称/拼音/编码）。直接查 PostgreSQL 大表 LIKE 在高峰期偏慢，因此在 **elep-jilin-application** 内增加 **Caffeine 分层缓存**。

CHS 已有：`YbNationalCatalogQueryService`、`YbNationalCatalogItemLookup`（`chs-jilin-domain`）。Elep 通过 **只读 Repository**（轻量 SQL）访问同一张表，**不依赖** `chs-jilin-application`（避免循环依赖）。

---

## 2. 数据源与 infno 映射

| 用途 | source_infno | list_type 示例 |
|------|--------------|----------------|
| 西药中成药 | `1301` / `1312` | `101` |
| 疾病与诊断 | `1307` | 按 1307 规范 |
| 中医疾病（可选） | `1314` | 二期 |

查询条件：`contract_id` + `tenant_id` + `vali_flag=1` + keyword。

1301 明细 vs 1312 去重：复用 CHS 逻辑 `prefers1301Detail(aprvno, spec)`。

## 3. 三层缓存

```text
请求 → L1 精确码缓存 (hilistCode/diagCode → Item)
     → L2 搜索结果缓存 (keyword+type+page → List)
     → L3 热词缓存 (可选)
     → Miss → DB
```

| 层 | Key 示例 | 用途 | TTL |
|----|---------|------|-----|
| **L1** | `{epoch}:{tenant}:{contractId}:1301:{code}` | 上传组装、clone 校验 | 至 catalogEpoch 变 |
| **L2** | `{epoch}:{tenant}:{contractId}:1307:kw:{hash}:p{page}` | Picker 分页 | `catalog_cache_ttl_minutes` |
| **L3** | 高频 keyword Top-N | 可选 | 1h |

**禁止**：启动时全表载入内存（1301/1307 体量过大）。

实现参考：`whale-core` `IndexedCacheService`、Caffeine `LoadingCache`（`InsuranceSignSessionService` 模式）。

## 4. catalogEpoch 失效

```java
long catalogEpoch = max(
    db.maxUpdatedAt(contractId, "1301"),
    db.maxUpdatedAt(contractId, "1307")
);
```

缓存 key **必须** 含 `catalogEpoch` 前缀。

触发失效：

1. CHS 目录 import 完成（理想：Domain Event → `ElepCatalogCacheManager.invalidate(contractId)`）
2. 定时轮询 `yb_national_catalog_item.max(updt_time)`（无事件时的兜底）
3. `ElepContractConfigLoader.getConfigEpoch()` 变更 → 清空该 bus_no 相关缓存

## 5. ElepCatalogSearchAppService

```java
public interface ElepCatalogSearchOperations {
    Page<ElepCatalogItemDto> searchDrug(ElepCatalogSearchRequest req);
    Page<ElepCatalogItemDto> searchDiagnosis(ElepCatalogSearchRequest req);
    Optional<ElepCatalogItemDto> getDrugByCode(ElepCatalogCodeRequest req);
    Optional<ElepCatalogItemDto> getDiagnosisByCode(ElepCatalogCodeRequest req);
    /** clone 时批量校验，返回失效行号 */
    List<ElepCatalogInvalidLineDto> validateLines(ElepCatalogValidateCommand cmd);
}
```

### 5.1 搜索规则

| 规则 | 说明 |
|------|------|
| keyword 长度 | ≥ 2 字符才走模糊（单字符仅精确码） |
| 分页 | 默认 20，最大 50 |
| 排序 | `hilist_code ASC` |

### 5.2 DTO 最小字段

```text
hilistCode, hilistName, spec, dosform, aprvno, pinyin, valiFlag, sourceInfno
```

## 7. 与 CHS 未启用时的行为

若 `-Pwith-chs` 未挂载或 `yb_national_catalog_item` 为空：

- `searchDrug` / `searchDiagnosis` 返回空页 + WARN 日志
- 文档/运维提示：先完成 CHS 目录下载（1301、1307）

---

## 8. 验收要点

- [ ] 同一 keyword 第二次搜索命中 L2（日志或 metrics 可观测）
- [ ] CHS 目录 import 后 epoch 变化，旧缓存不返回脏数据
- [ ] clone 校验 100 行药品 code 在 L1 预热下 < 200ms（院内基准，可调）
