# 与门诊医保结算挂接 — 详细设计

> **范围**：2204 费用明细 `rxno` 与电子处方 `hi_rxno` 的关联。  
> **CHS 参考**：[03-门诊医保结算-详细设计.md](../zxplat-module-chs-jilin/03-门诊医保结算-详细设计.md)  
> **版本**：v1.0 | **日期**：2026-06-18

---

## 1. 平台规则（摘要）

来自 CHS 接口文档与基线规范：

- **电子处方处方号必须从电子处方中台获取**（A0003 返回的 `hi_rxno`）。
- 2204 **`rxno` 有值** → 医保视为电子处方明细，与中台核验。
- **禁止** 伪造 `rxno`；无 elep 方时 `rxno` 必须为空。

---

## 2. 数据流

```text
医生站签发 → ELEP A0003 成功 → yb_elep_prescription.hi_rxno
                                    ↓
收费 2204 组装 ← ElepPrescriptionExtension.findRxNoByPrescription(prescriptionGroupId)
                                    ↓
                            ChargeItem.prescriptionNo / 2204.rxno
```

---

## 3. Extension 方法

```java
Optional<ElepRxNoSnapshot> findRxNoByPrescription(Long prescriptionGroupId);
```

`ElepRxNoSnapshot`：

| 字段 | 说明 |
|------|------|
| `hiRxno` | 2204 rxno |
| `rxTraceCode` | 可选追溯 |
| `hospRxno` | 院内号 |
| `uploadedAt` | A0003 时间 |
| `localStatus` | 须 `UPLOADED` |

实现：`elep-jilin-bridge` 查 `yb_elep_prescription` by `prescription_no` 或业务约定的 group 键。

---

## 4. 挂接点（health-application）

在 **门诊收费预结算/明细上传** 组装 CHS 2204 时（`ChsOutpatientSettlementFacadeImpl` 或 `OutpatientInsuranceContextLoader` 同类位置）：

```java
if (elepPrescriptionExtension.isEnabled()) {
    elepPrescriptionExtension.findRxNoByPrescription(chargeItem.getPrescriptionGroupId())
        .ifPresent(snap -> feeDetail.setRxno(snap.getHiRxno()));
}
```

**规则**：

- 仅当费用项关联的处方组 **已成功 ELEP 上传** 才填 `rxno`
- 混合处方：按 chargeItem 粒度，有则填无则空
- 撤销后（`REVOKED`）：不得再填该 `hi_rxno`

---

## 5. 模块依赖

| 模块 | 依赖 |
|------|------|
| health-application | `ElepPrescriptionExtension`（contracts） |
| chs-jilin-bridge | **不** 依赖 elep-jilin-bridge |
| elep-jilin-bridge | **不** 依赖 chs-jilin-bridge |

同进程 `-Pwith-chs,with-elep` 时，health-application 同时注入两个 Extension。

---

## 6. 验收要点

- [ ] 有 elep 方的药品明细 2204 带正确 `rxno`
- [ ] 无 elep 方时 `rxno` 为空，结算成功
- [ ] 撤销后方再结算不带旧 `rxno`
- [ ] 日志可追踪 `prescriptionGroupId → hiRxno`
