## 一、模块定位

### 1.1 职责

**zxplat-module-einvoice-boss** 将院内 Invoice 与**博思医疗电子票据平台**对接。

| 能力 | 说明 |
| --- | --- |
| 开具 | 挂号 / 门诊 / 住院 / **通用票**电子票 |
| 异步开具 | 支付后立即返回，博思调用后台执行（P0 默认） |
| 冲红 | 退费、退号触发的电子票冲红 |
| 查询补偿 | 超时查票、补开、**入账状态**（P3） |
| 展示 | 收费窗 QR、开票进度查询（P1） |
| 财务运营 | 收费对照、日结核对、批量补开（P2） |

票据状态机（DRAFT / ISSUED / CANCELLED）归 health-domain；本模块不持有票据聚合根。

### 1.2 业务线

| 线 | busType | 博思服务标识 | 触发场景 |
| --- | --- | --- | --- |
| R 挂号 | `06` | `invEBillRegistration` | 挂号缴费成功 |
| O 门诊 | `02` | `invoiceEBillOutpatient` | 门诊收费结算成功 |
| I 住院 | `01` | `invEBillHospitalized` | 住院结算成功（P1） |
| C 通用票 | `09`/`10`/`11` | `invoiceEBillCommon` | 财务手工开具往来/捐赠/非税票（P3） |

**通信基线**：HTTP POST，`{ appid, data(Base64), noise, sign(MD5大写), version=1.0 }`。

**部署**：`einvoice-boss-starter`（embedded）与 `einvoice-boss-host`（HTTP 中转）二选一。

## 二、核心业务规则

### 2.1 异步开票（P0）

收费/结算 HTTP **不得**同步等待博思。

```text
支付事务（同步）
  ├─ 支付入账
  ├─ [实付 > 0] createDraftInvoiceAfterPayment → DRAFT + busNo（**BR-INV-008**）
  └─ [实付 > 0] 发布 InvoiceDraftCreatedEvent
  → 立即返回前端（有票时 invoiceStatus=DRAFT；零元时 invoiceId 为空）

事务提交后（异步，仅实付 > 0）
  ├─ 入队 einv_boss_issue_task
  ├─ Worker 组报文 → 校验（§2.2）→ 调博思
  ├─ 成功 → DRAFT → ISSUED，回写票面
  └─ 失败 → 保持 DRAFT，重试或补开
```

| 前置门禁 | 规则 |
| --- | --- |
| 零元不开票 | 支付单 `displayAmount ≤ 0` 时**不**创建 DRAFT、**不**入队；应用编排 `InvoiceAfterPaymentOrchestration#createDraftAndScheduleIssueIfPayable` |
| 金额口径 | `displayAmount` = 患者应付/实付（Σ 医保 `psn_cash_pay` + 自费原价） |

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `einvoice.boss.issue.mode` | `async` | 生产必须用 async；`sync` 仅联调 |

冲红：原票 ISSUED 调博思；原票 DRAFT（未开出）仅本地作废。

### 2.2 金额校验（P0 · 硬规则）

出站调博思前，**必须**校验明细合计与开票总额一致；不一致则**抛业务异常，禁止调用博思**。

| 校验项 | 规则 |
| --- | --- |
| 开票总额 | 报文 `totalAmt` |
| 明细合计 | `chargeDetail[]` 各行金额之和；有 `listDetail[]` 时各行金额之和 |
| 精度 | `BigDecimal` 比较，scale=2，`ROUND_HALF_UP` |
| 容差 | **0**（不允许分差） |

```text
sum(chargeDetail[].amt) == totalAmt
且（若存在 listDetail）
sum(listDetail[].amt) == totalAmt
```

| 环节 | 行为 |
| --- | --- |
| 校验失败 | 抛 `BusinessException`（明确差额）；任务标记 FAILED，**不调博思** |
| 校验时机 | `BossPayloadBuilder` 组装完成后、HTTP 出站前 |
| 责任模块 | `einvoice-boss-application` · `BossInvoiceAmountValidator` |

与 payment / Invoice.amount 的一致性由 adapter 读模型保证；本规则约束**博思报文内部自洽**。

### 2.3 幂等与补偿

- 同一 `invoice_id` 仅一条活跃开具任务
- 已 ISSUED 跳过重复开具
- HTTP 超时/未知结果：`getEBillByBusNo(busNo)` 查回后再 ISSUED 或重试

### 2.4 院点差异

通过 Profile（平台接口版）+ Setting + 可插拔 `BossPayloadEnricher` / `SettlementAmountStrategy` 扩展，禁止在业务代码硬编码院点逻辑。

| 配置键 | 默认 |
| --- | --- |
| `einvoice.boss.platformProfile` | `boss-medical-cn-v1` |
| `einvoice.boss.protocolVersion` | `1.0` |
| `einvoice.boss.settlementAmountRule` | `STANDARD` |
