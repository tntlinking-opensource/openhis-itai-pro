## 0. 先说清楚：文档里的「map」是什么

对话与设计里说的 **map**，不是 Java `Map`，而是院内落库表：

| 项 | 说明 |
|----|------|
| **表名** | `yb_encounter_platform_map` |
| **实体** | `YbEncounterPlatformMap`（`zxplat-module-chs-jilin` domain） |
| **作用** | 把 **本院就诊** 与 **医保平台就诊号 `mdtrt_id`** 对应起来，避免每次结算都盲目调 2201 |
| **唯一键（概念）** | `(encounter_id, contract_id, med_type, tenant_id)` |
| **读写时机** | **2201 成功** → 写入一行；**2202 撤销** → 使对应行失效/清除；预结算 `resolveMdtrtId` → 先查表 |

### 0.1 一行里通常有什么

| 字段（概念） | 含义 |
|--------------|------|
| `encounter_id` | 本院门诊就诊 ID |
| `contract_id` | 费用性质 / 医保合同 |
| `med_type` | 医疗类别（`11` 普通门诊、`12` 门诊挂号、慢病码等） |
| `mdtrt_id` | 医保平台返回的就诊流水（2201 出参） |
| `ipt_otp_no` 等 | 院内流水等，供 2202 撤销使用 |

### 0.2 `resolveMdtrtId` 在干什么

```text
resolveMdtrtId(encounterId, contractId, medType):
  1. 查 yb_encounter_platform_map（同上三键 + 租户）
  2. 命中 → 直接返回 mdtrt_id（不调 2201）
  3. 未命中 → 调用 2201 → 写 map → 返回新 mdtrt_id
```

因此：

- **map 有值** = 这个「就诊 + 合同 + 医疗类别」已经在平台挂过号。  
- **map 分行** = `med_type=12`（挂号费）与 `med_type=11`（普通门诊）是 **两行、两个 `mdtrt_id`**，不能混用。

## 1. 决策摘要

| # | 约定 |
|---|------|
| 1 | **挂号读卡 / 预挂号：不调用 2201** |
| 2 | **2201 仅在结算预结算链中按需调用**（`resolveMdtrtId` 未命中 map） |
| 3 | **结挂号费**时：`med_type = 12`（门诊挂号）。依据 2206/2206A 重点说明：「仅门诊挂号结算时，医疗类别传入 12」 |
| 4 | **结诊疗费**时：仍按 `11` / 慢病等各自 `med_type` 建/查 map；**不与挂号费共用 `mdtrt_id`** |

挂号窗仍可调 **1101/2001**（待遇确认），与 2201 无关。

**`med_type` 怎么来的（不是 `resolveMdtrtId`「解析」出来的）**：

| 场景 | `med_type` | 是否看诊断 |
|------|------------|------------|
| 结挂号费 | 业务显式 **`12`** | 否 |
| 门诊收费混合结算 | 收费项关联诊断上的医疗类别 | 是 |
| 缺省 | **`11`** 普通门诊 | 否 |

`resolveMdtrtId` 只做「给定 `med_type` 后查/建 map」，**不负责推断**医疗类别。

| 维度 | 现状（旧定稿 / 实现） | 目标 |
|------|----------------------|------|

## 3. 目标时序（按 22xx）

### 3.1 医保挂号 + 挂号费走医保（时序定稿：两段式）

> **评审定稿（2026-07-14）**：保持现网两段，**不把 2201～2206 挪进支付弹窗**。  
> 「延后」= 相对挂号读卡/本地建诊延后，不是相对支付确认延后。

```text
【挂号窗 · 读卡 / 待遇】
  1101（+2001 等）→ 表单核对
  ✗ 不调用 2201，map 无行

【确认挂号 · 预结算】（preRegisterSettlement，ybRegisterFee=true）
  本地：Encounter=PLANNED + 支付草稿
  医保：resolveMdtrtId(..., medType=12)
    → miss → 【2201】→ 写 map(med_type=12)
    → 【2203】(12) → 【2204】→ 【2206】
  → 打开支付核对弹窗（展示统筹/个账/现金）

【支付弹窗 · 确认收费】（payRegisterFee）
  → 【2207】正式结算
  → 本地 PLANNED → REGISTERED

【异常 / 退号】
  预结算中途失败（2201 已成功、2203/2204/2206 失败）：
    → 自动收口：有批次 【2205】→ 有 map(12) 【2202】→ 再返回错误（§3.1.1）
  已 2207 后退费：【2208】→【2202(12)】（必做，见 §3.6）
  2207 结果不确定：【2601】冲正（沿用现有策略）
```

#### 3.1.1 预结算中途失败自动收口（评审定稿）

> **评审定稿（2026-07-14）**：确认挂号预结算链上，**2201 已写 map(12) 后**若 **2203 / 2204 / 2206** 任一步失败，**立即自动收口**，不留给前端事后「作废」清孤儿。

```text
try:
  resolveMdtrtId(12) → 可能 2201 + 写 map
  2203 → 2204 → 2206
catch:
  若本单已有未结算费用批次 → 【2205】
  若本单已有 map(med_type=12) → 【2202】并失效/清除 map 行
  再向上抛出/返回预结算失败
```

| 项 | 约定 |
|----|------|
| 范围 | 仅本单挂号费链路（`med_type=12` / 本批次）；不碰 `11` |
| 与关窗区别 | **预结算未成功、支付窗未打开** → 自动清；**预结算已成功、用户关支付窗** → 不自动清（§3.4） |
| 本地 PLANNED | 随现有失败分支：本次预结算失败则不留下「可收费」脏草稿；若本地已建诊，按现网失败回滚/可重试策略（编码时对齐 `preRegisterSettlement`） |
| 收口再失败 | 记日志 + 明确错误；现场可用 **「作废」** 兜底 |
### 3.2 医保挂号但挂号费自费（`ybRegisterFee=false`）

> **表述约定**：验收与接口一律用请求字段 **`ybRegisterFee`**，不写 UI「勾选挂号费医保」。  
> 现网费用性质为医保时，前端常 **默认 `ybRegisterFee: true`**；界面可见的是「使用个账」等，**没有**独立「挂号费医保」勾选。自费挂号费 / 强制挂号费自费场景传 **`false`**。

```text
【确认挂号】ybRegisterFee=false
  → 本地 PLANNED + 自费草稿；✗ 不走 2201～2206，✗ 不写 map(12)
【收银诊疗费】resolveMdtrtId(..., 11 或慢病码) → 缺则 2201 → 2203→2204→2206→2207
```

### 3.3 统一编排骨架（挂号费与诊疗费相同）

```text
preSettle：resolveMdtrtId → 2203 → 2204 → 2206
confirm   ：2207
差异仅：med_type、明细来源（挂号费锚点 vs ChargeItem）
```

默认仍用 **2206 / 2207**（非 A）；若省端要求 A 变体，仅配置切换，业务语义不变。

### 3.4 支付弹窗关闭：继续收费 vs 手动撤销

预结算成功进入支付核对弹窗后，用户可能直接关闭而不付款。产品约定如下（**关窗不自动冲医保**；与现网实现一致，改造后按「是否已上平台」裁剪撤销步骤）。

#### 3.4.1 关窗时发生什么

```text
确认挂号 → 预结算成功
  → 本地：Encounter = PLANNED（待挂号）+ 支付草稿 paymentDraftId
  → 若挂号费医保：可能已走 2201→2203→2204→2206（尚未 2207）
  → 打开支付弹窗
用户关闭 / 取消
  → 前端仅关弹窗并刷新历史列表
  → ✗ 不调用 cancelPlannedRegistration
  → ✗ 不自动 2205 / 2202
```

落点：`register-confirm-dialog` 关闭 → `emit('cancel')`；`register-left-panel.onRegisterConfirmCancelled` 仅刷新，**无撤医保 API**。

关窗后现场状态：

| 侧 | 状态 |
|----|------|
| 本院就诊 | 仍为 **`PLANNED`（待挂号）** |
| 支付草稿 | 仍在；历史列表带回 `paymentDraftId` |
| 医保（若已走挂号费预结算） | 平台 `mdtrt_id` / 明细 / 2206 **仍在**，未 2207 |
| 防重（BR-REG-011） | 同日同患者同科室的 **PLANNED 占名额**，不撤则挡再次预结算 |

#### 3.4.2 可以继续完成支付（不必先撤销）

| 操作 | 说明 |
|------|------|
| 入口 | 挂号历史列表，状态「待挂号」→ **「收费」**（仅 `PLANNED`） |
| 条件 | 行上仍有有效 `paymentDraftId`；无草稿则提示无法收费 |
| 接口 | `payRegisterFee`（IF-REG-07），复用原草稿，**不重新预对齐本地就诊** |
| 成功 | 本地 `PLANNED` → `REGISTERED`；若此前已医保预结算，补 **2207** |
| 凭证过期 | 电子凭证场景可能失败；须「重新扫码 + 刷新预结算」后再收费 |

前端落点：`history.vue` → `handleCharge` / `executeChargeRegister` → `payRegisterFee`。

#### 3.4.3 放弃本单：作废（评审定稿）

> **评审定稿（2026-07-14）**：本迭代对 `PLANNED` **补手撤入口**，按钮文案统一为 **「作废」**（不用「撤销待挂号」）。  
> 未上平台必须可点，避免防重卡住现场。  
> **2202 范围**：挂号侧作废/退号 **只动 `med_type=12`**，**绝不**因挂号操作撤销 `11`/慢病 map。  
> **作废前置**：本就诊 **尚未产生该 `med_type` 的费用**（挂号「作废」针对 `12`）。

| 操作 | 说明 |
|------|------|
| 入口 | 历史列表 · 状态「待挂号」→ **「作废」** |
| 前置条件 | **未产生 `med_type=12` 的正式费用**（本地未完成挂号费收费确认 / 平台未成功 **2207**）。仅有预结算草稿或已走 2201～2206 未付，仍允许作废。若已产生 **其它 `med_type`（如 `11`）费用**，拒绝挂号「作废」，提示走对应费用退费/撤销链 |
| 接口 | `cancelPlannedRegistration` |
| 平台步骤 | **有**活跃预结算批次 → **【2205]**（本单批次）；**有** map **`med_type=12`** → **【2202]**；**无则跳过**；**禁止**对 `11` 等行 2202 |
| 本地步骤 | 作废支付草稿 + 就诊 → **`CANCELLED`**（释放防重名额） |

后端落点：`OutpatientRegistrationAppService#cancelPlannedRegistration`；前端 `history.vue` 露出 **「作废」**；前置不满足时禁用按钮或接口返回明确错误。

> 注意：AS 中「退号」IF-REG-09/10 **不适用于** `PLANNED`（BR-REG-008）；待挂号放弃走本接口，不是已挂号退号链。  
> 已 `REGISTERED` / 已正式结算的退号/医保退号链不变，文案仍可叫「退号」「医保退号」。
#### 3.4.4 两条出路对照

| 用户意图 | 操作 | 医保 | 本地 |
|----------|------|------|------|
| 稍后付完 | 历史 **收费** | 保留预结算；确认时 **2207** | `PLANNED` → `REGISTERED` |
| 不要了 | 历史 **作废** | **2205**（有批次）→ **2202**（有 map）；无则跳过 | 草稿作废 + `CANCELLED` |

#### 3.4.5 改造后的差异（相对现状）

| 关窗时是否已做挂号费医保预结算 | 继续收费 | 作废 |
|--------------------------------|----------|------|
| **否**（仅本地 PLANNED + 草稿；本方案挂号阶段不 2201） | 同 §3.4.2 | **纯本地作废**，无 2205/2202（本迭代必有入口） |
| **是**（已 2201/2204/2206） | 同 §3.4.2；确认补 2207 | **2205 → 2202** + 本地作废 |

目标：保留「关窗搁置 / 可续费 / 手撤」；手撤文案定 **「作废」**；未上平台撤销更轻。

### 3.5 2203 诊断怎么传（禁止 `-`；挂号兜底；结算传全量）

#### 3.5.1 现状问题

| 项 | 现状 |
|----|------|
| 组装 | `Op2203InputAssembler` 仅拼 **1 条** `diseinfo`，取 `mainDiagCode/Name` |
| 空值 | `blankToDash` 把空诊断变成 **`"-"`** |
| 挂号时 | 就诊通常尚无临床诊断 → 实际上传 `diag_code/diag_name = "-"` |

这与多省接口规范冲突：类型化空值不得用 `"-"` / `"\"` 等特殊符号占位（示例：重庆市定点医药机构接口规范 V1.12「不能传“-”…代表字段为空」；2203 的 `diag_code`/`diag_name` 又为必填）。  
2203 规范本身也写明：`diseinfo` 为**多行**诊断数据——诊疗结算应传齐本诊次全部诊断，而非仅主诊。

#### 3.5.2 公开规范与业界参照（检索结论）

| 来源 | 结论 |
|------|------|
| 国家定点基线 / 省扩版 2203 | `diseinfo` 多行；`diag_code`/`diag_name` 必填；须为国家医保疾病诊断分类代码（经 1307 目录可用） |
| 重庆等地平台说明 | **禁止**用 `-` 等符号假装空值 |
| 流程说明（多省同类） | 挂号后由科室上传就诊信息再按批次传明细；挂号费场景 `med_type=12` 时往往**尚无临床诊断** |
| 老国基 HIS（同院系插件） | 挂号 `clinicReg` 的 2203 诊断来自 **HIS 前台传入的诊断码/名**（管道参数），**不是** `-` |
| 业界常见兜底 | 无临床诊断时使用检查/健康咨询类码；本院定稿见下 |
| **朝阳中医院（吉林）定稿** | **`Z00.001` / 一般医学检查**（院方确认吉林 1307 目录承认） |

> 国家规范未单独颁布「挂号费专用诊断码」。本项目以院方确认的目录码为准，不再使用占位符 `-`。

#### 3.5.3 推荐方案（分层）

**A. 硬约束（先改掉错误行为）**

1. **禁止**对 `diag_code` / `diag_name` 使用 `blankToDash("-")`。  
2. 无有效诊断时：**不得上传**；应失败并提示配置/选择诊断，或走下方挂号兜底（仅允许挂号费路径）。  
3. 诊断码必须能在本地 **医保疾病诊断目录（1307 同步结果）** 中命中（`yb_no` 或院内已对码）。

**B. 结挂号费（`med_type=12`）——尚无就诊诊断时**

```text
优先级：
  1) 若本就诊已有有效诊断列表 → 同 C 规则上传（挂号很少有，但兼容）
  2) 否则使用院点「挂号默认诊断」（吉林已确认）：
         register-fee.default-diag-code=Z00.001
         register-fee.default-diag-name=一般医学检查
  3) 配置被误删或本地目录未同步到该码 → 预结算失败，提示运维，禁止用 "-"
```

| 项 | 定稿 |
|----|------|
| 默认 `diag_code` | **`Z00.001`**（吉林目录已承认） |
| 默认 `diag_name` | **一般医学检查**（与目录名称保持一致；若目录显示名不同以本地 1307 名为准） |
| `diseinfo` 行数 | 挂号费默认可 **1 行**（仅兜底主诊） |
| `diag_type` | `1`（西医诊断） |
| `diag_srt_no` | `1` |
| `vali_flag` | `1`（有效） |
| `diag_dept` / 医师 | 挂号科室、挂号医师医保编码（与 2201 一致） |
| `main_cond_dscr` | 诊断名称或「门诊挂号」短文案（非 `-`） |

默认码 **已确认（吉林目录）**：**`Z00.001`（一般医学检查）**——院方确认本省/本市 1307 疾病诊断目录承认该码，作为挂号费无临床诊断时的默认 `diag_code`。

**C. 门诊诊疗结算（`med_type=11` / 慢病等）——必须传全量诊断**

```text
从 encounter 诊断关联加载全部有效诊断（通常 vali）：
  · 排序：主诊（primaryFlag）优先，其余按 rank 升序
  · 每一条生成一条 diseinfo：
        diag_srt_no = 1..n
        diag_code   = 定义.yb_no（无则禁止上传该行，整单失败或剔除未对码并提示）
        diag_name   = 定义名称
        diag_type   = 按中西医类型映射（缺省西医 1）
        vali_flag   = 1
  · mdtrtinfo.main_cond_dscr ← 主诊名称
  · 主诊同时作为第 1 条 diseinfo（或保持主诊 srt_no 最小）
```

| 无诊断 | 诊疗结算应 **拦截**：提示医生站先下诊断再收费（不能用挂号兜底码糊弄药费/检查结算） |

## 8. 验收口径

表述统一用 **`ybRegisterFee`**（见 §3.2），不写「勾选挂号费医保」。

### Wave A

- [ ] 医保费用性质 + **`ybRegisterFee=false`**（挂号费自费）：挂号确认全程抓包 **无 2201**，**无** map(`12`)。  
- [ ] **`ybRegisterFee=true`** 并缴费：顺序 **2201 → 2203(`12`) → 2204 → 2206 → 2207**，map **`med_type=12`**。  
- [ ] 2201 成功后制造 2203/2206 失败：自动 **2205（若有）+ 2202(12)**，map(12) 清除。  
- [ ] 随后普通门诊收费：若无 `11` 行则另一次 **2201**，`mdtrt_id` **≠** 挂号费行。  
- [ ] 未上平台待挂号：历史有 **「作废」**；执行后 **无 2202**，本地 `CANCELLED`。  
- [ ] 已医保结挂号费后退号：**2208 → 2202(12)** 均出现；map(12) 清除。  
- [ ] 预结算成功后关支付窗：**不**自动 2205/2202；仍有「收费」「作废」。  
- [ ] 历史「收费」完成 IF-REG-07；已预结算单确认时补 **2207**。  
- [ ] 历史「作废」（已上平台）：有批次 **2205**，有 map(`12`) **2202**；**不**动 map(`11`)。  
- [ ] 已产生 `12` 正式费用或已有其它 `med_type` 费用：拒绝「作废」。  
- [ ] 挂号费 2203：`diag_code/name` **不为 `-`**，码为 **`Z00.001`**（或院点配置且目录可命中）。

### Wave B

- [ ] 诊疗费 2203：`diseinfo` 行数 = 本诊次有效诊断数（主诊+其他），含 `vali_flag=1`。
