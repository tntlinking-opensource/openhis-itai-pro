## 第一组：洗成标准落地包（院外 AI）

### 提示词 1A · 单文件清洗（推荐每次只 @ 一个原件）

```text
你是 ZXPlat 医保文件洗数助手。请把我 @ 的局发附件转成「标准落地包」，并做好归档。

【路径】
- 输入：我 @ 的这一个文件（位于 docs/模块/zxplat-module-chs-jilin/目录更新通知/）
- 产出目录：docs/模块/zxplat-module-chs-jilin/目录更新通知/标准化文件/{原文件名去掉扩展名}/
  必须且仅有：
  - notice.meta.json
  - notice.lines.csv（UTF-8，建议带 BOM）
- 成功后：把原文件 move 到
  docs/模块/zxplat-module-chs-jilin/目录更新通知/原始文件/
  （同名已存在则加后缀 _YYYYMMDDHHmmss 再移，禁止覆盖）

【判定 doc_kind】
A) Sheet 名以 新增/停用/变更/省变更 开头（或可识别的目录更新）→ doc_kind=CATALOG_DELTA
B) 表头含「映射对照」「支付类别」或「映射对照 医保支付」，列为项目编码+甲/乙/丙 → doc_kind=PAYMENT_MAP
C) 纯政策说明、无编码明细、打不开的伪 xlsx/.et → 不要硬转；在对话说明原因，原文件移到 原始文件/_无法转换/ 下并写 reason.txt

【notice.meta.json 字段】
doc_kind, category, title, source_filename, notice_date, effective_date, wash_note, wash_tool
- wash_tool 固定 cursor-ai
- wash_note 简述原格式问题与处理要点
- category：DRUG|SERVICE|SERVICE_F|DEVICE|FORMULA|HERBAL|PREP|OTHER
  （F服务→SERVICE_F；药品→DRUG；耗材→DEVICE；配方颗粒→FORMULA；饮片→HERBAL；制剂→PREP；服务/诊疗→SERVICE；支付对照服务类→SERVICE）
- notice_date / effective_date：yyyy-MM-dd；**至少填一个**（文件名解析不到须手填，禁止两个都空）
- wash_tool 固定 cursor-ai

【notice.lines.csv 表头（列名必须完全一致；顺序可任意）】
action,hilist_code,project_code,hilist_name,begin_date,end_date,change_fields,chrgitm_lv,list_type,source_sheet,source_row,ext_json

【行规则】
1) CATALOG_DELTA：
   - action：ADD|STOP|MODIFY|PROVINCE_MODIFY（Sheet 前缀：新增→ADD，停用→STOP，省变更→PROVINCE_MODIFY，变更→MODIFY）
   - 主键按**码的性质**分列，不按动作锁死：物价码（01* 可带 T 等后缀、37*）只进 project_code；医保目录码（001/002/003/地方连写等）只进 hilist_code。ADD/STOP/MODIFY 都可以是其中一种，但至少有一个合法键
   - 禁止把 01*/37* 填进 hilist_code；禁止把「国家未赋码」等汉字当编码（该行不要输出）
   - 不自动补前导 0、不改写历史缺位码
   - 有名称必须写 hilist_name（不要只放在 ext_json.医疗服务项目名称）
   - chrgitm_lv：收费项目等级若已是 1/2/3 则直填；甲→1 乙→2 丙/自费→3
   - 限价/限制：医保目录定价上限金额、超限处理方式、限制使用标志、限制使用范围 用**这些固定中文键**放入 ext_json
2) PAYMENT_MAP：
   - 每行 action=SET_PAY_CLASS
   - project_code=项目编码（trim）；hilist_name=项目名称
   - chrgitm_lv：甲→1，乙→2，丙/自费→3；「未开展丙」「未开展项目丙」→ chrgitm_lv=3 且 ext_json.not_conducted=true
   - 跳过项目编码为空、分组标题行、编码为「未赋码」的行
3) 日期统一 yyyy-MM-dd；多余原列进 ext_json（合法 JSON 对象字符串，CSV 内正确转义）
4) source_sheet / source_row 必须可追溯
5) list_type：能推断则填（药101/服务201/耗材301等），否则空

【验收入口】
写完后自检并在回复里给出：产出路径、行数（按 action 汇总）、doc_kind/category、是否已 move 原文件、无法转换说明。
禁止改动标准化文件以外的业务代码。
```

### 提示词 1B · 批量队列（一次处理根目录下多个，但仍建议串行确认）

```text
按「提示词 1A」的规则，处理目录：
docs/模块/zxplat-module-chs-jilin/目录更新通知/

范围：仅根目录下尚未进入「原始文件/」「标准化文件/」的附件（xlsx/xls/et）。
顺序：先做小文件与服务/支付对照类，再做大药品表。
要求：
1) 每个原件独立一个标准化子目录；成功才 move 到 原始文件/
2) 失败的原件移到 原始文件/_无法转换/ 并写 reason.txt，不要中断整批
3) 最后输出一张汇总表：原文件名 | 结果(OK/FAIL) | 标准目录 | action 行数 | 备注
每处理完 1 个文件就汇报一次，再继续下一个（不要一口气静默处理完才说话）。
```

### 提示词 1C · 全量检查 / 返工

```text
你是 ZXPlat 医保文件全量验收助手。对「标准化文件/」做全量检查（不是抽检），找出错误与遗漏，并就地返工。

【范围】
根：docs/模块/zxplat-module-chs-jilin/目录更新通知/
- 全量：标准化文件/ 下每一个子目录（notice.meta.json + notice.lines.csv）
- 覆盖：对照 原始文件/（不含 _无法转换/）是否「有原件必有标准包」、标准包是否孤儿
- 待洗：根目录是否仍残留 xlsx/xls/et
- 残留失败：原始文件/_无法转换/ 是否仍有未补洗项（若根目录或原始文件已有另存成功件，可在报告里标注「已由 xx 补齐」）

【先跑脚本（必须）】
cd 到 目录更新通知/脚本/
python audit_canonical_packs.py
→ 生成 audit_report.json；以脚本 ERROR/遗漏为准，再人工复核 FAIL/WARN 包。
脚本缺了或不对：先修好脚本再全量跑，禁止只凭目测「抽几个」。

【包内规则（对照方案 §6.0；列名集合必须齐，顺序可任意）】
1) meta：doc_kind/category/source_filename/wash_tool 合法；日期 yyyy-MM-dd 或 null
2) CSV：12 列齐全；建议 UTF-8 BOM；每行 action 合法且与 doc_kind 匹配
   - PAYMENT_MAP 仅 SET_PAY_CLASS；CATALOG_DELTA 仅 ADD|STOP|MODIFY|PROVINCE_MODIFY
3) 服务 ADD（SERVICE/SERVICE_F）：project_code 有值（多为 01*），hilist_code 必须空；禁止 01* 进 hilist_code
4) SET_PAY_CLASS：project_code + chrgitm_lv(1/2/3) 必填
5) 其它目录动作（及非服务 ADD）：hilist_code 必填
6) chrgitm_lv 仅为 1/2/3/空；ext_json 必须是可解析的 JSON 对象（空则 {}）
7) 行日期非法、STOP 无 end_date：记 WARNING（尽量修）

【遗漏规则】
- 原始文件有原件、标准化文件无对应目录 → 遗漏：按 1A 重洗补包
- 标准化有包、原始文件无对应原件 → 孤儿：核对是否目录名 trim/改名；能对齐则改目录名或 meta.source_filename，不能对齐则报告人工确认
- 根目录仍有附件 → 未洗完：继续 1A/1B
- _无法转换 残留且无成功另存对应包 → 仍属缺口

【返工】
- 有 ERROR：就地修好该包 csv/meta（或按 1A 从 原始文件/ 重洗覆盖标准包）
- 不要改动 原始文件/ 里的局发原件内容；可 move 根目录残留件
- 修完再跑一遍 audit_canonical_packs.py，直到 ERROR=0 且 coverage.missing_standard_pack 为空（WARN 须在汇总里点名）

【验收输出】
1) 脚本摘要：OK/WARN/FAIL 包数、遗漏数、孤儿数、根目录待洗、_无法转换 残留
2) FAIL/WARN 明细表：标准目录 | 级别 | code | 说明 | 已修(Y/N)
3) 遗漏/待洗清单与处置
4) 最终是否通过全量门禁（ERROR=0 且无遗漏）
```

## 使用建议

| 场景 | 用哪条 |
|------|--------|
| 每天新来几个局发附件 | **1A** 逐个 @ 文件 |
| 攒了一批要清库存 | **1B** |
| 洗完后查错误与遗漏（全量） | **1C**（先跑 `脚本/audit_canonical_packs.py`） |
| 第一次写后端 | **2A → 2B → 2C** 严格分期，不要一条提示词做完全部 |
| 联调 UI | M1 API 通后开 **2D** |
