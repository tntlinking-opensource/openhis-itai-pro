## 修复一：挂号费正式结算 · 支付草稿金额口径

### 现象

市医保挂号（`ybRegisterFee=true`）预结算成功后，正式缴费报错：

| 错误码 | 文案 |
|--------|------|
| `PAY-BIZ-409` | 支付草稿金额与收费明细不一致，请重新预结算 |

自费挂号不受影响；有基金/个账分担、个人现金应付 ≠ 挂号费原价时必现。

### 根因

```text
IF-REG-06 本地草稿：displayAmount = ChargeItem.totalPrice（原价）
ybRegisterFee → 2206 后 refreshPaymentDraftPreSettleAmounts(psnCashPay)
→ displayAmount = 个人现金应付；ChargeItem 仍为原价
IF-REG-07 旧逻辑强制 displayAmount == totalPrice → PAY-BIZ-409
```

同文件 `resolveRegisterFeeExpectedPayable` 已按 ACTIVE 2206 用草稿金额，头校验未对齐。

### 改动

| 文件 | 说明 |
|------|------|
| `OutpatientRegistrationAppService` | 新增 `hasActiveRegisterFeeInsurancePreSettle`；有 ACTIVE 2206 时跳过 displayAmount↔原价强等；自费仍强等 |

### 验收

- 市医保挂号有分担 → 正式缴费成功  
- 自费脏草稿金额不一致 → 仍报 `PAY-BIZ-409`

## 修复二：医生站签发 · 事前提醒 `chargeItemIds` 空指针

### 现象

门诊医生站（医保费用性质）签发医嘱/申请后：

```text
Cannot invoke "java.util.List.size()" because "chargeItemIds" is null
```

前端包装为：`事前提醒失败；已尝试签退本次签发`（`use-advice-tab` / `use-service-apply-tab` 在 3101 失败后自动签退）。

### 根因

```text
签发成功
→ runOpDetailAuditGate({ encounterId, contractId, trigScen: '2' })
→ 未传 chargeItemIds（医生站设计如此；收费页 trig=7 会传勾选 ID）
→ DetailAuditGateInvokerImpl.analyzeOp → enrichPreSettle(partial)
→ loadChargeItems(null) → chargeItemIds.size() NPE
```

试调契约 `DetailAuditAnalyzeFromEncounterRequest` 已写明「可空时由 ContextLoader 按就诊策略装载」，实现未落地。

### 改动

| 文件 | 说明 |
|------|------|
| `ChsOutpatientInsuranceContextLoader#enrichPreSettle` | `chargeItemIds` 空 → 按就诊装载 `PLANNED` 待收费行并回写 ID |
| 同上 `#loadChargeItems` | 空列表抛业务异常，禁止 NPE |
| `ChsInpatientInsuranceContextLoader#loadChargeItems` | 同步空参防护 |
| `DetailAuditOpGateCommand` | 注释标明 chargeItemIds 可空 |

前端医生站签发挂接**无需改参**（继续可不传 ID）。

### 验收

1. 医保患者：开立诊断 → 草稿医嘱签发 → 事前提醒可出站 3101（无违规则签发完成；有违规可继续/返回修改签退）。  
2. 不再出现 `chargeItemIds is null` NPE。  
3. 若签发后就诊下确无 `PLANNED` 行 → 明确业务错「就诊下无待收费明细，无法事前提醒」（非 NPE）。  
4. 门诊收费预结算（trig=7，显式传 ID）行为不变。

## 修复三：事前提醒缺少 `zxplat.chs.audit.syscode`

### 现象

签发门禁通过装载后，3101 出站前 Gate 失败：

```text
未配置 zxplat.chs.audit.syscode，且命令未传 syscode
```

### 根因

产品约定（Q12=C）：`syscode` **无全局默认**；须院点配置或 Command 显式传入。朝阳院点 `application.yml` 此前未配 `zxplat.chs.audit.*`，医生站/收费主路径也不传 `syscode`。

### 改动

| 文件 | 说明 |
|------|------|
| `projects/project-H22010402403/src/main/resources/application.yml` | 增加 `zxplat.chs.audit.syscode` |

落地配置（`zxplat.chs` 下）：

```yaml
  chs:
    # …
    # 明细审核 3101/3103：syscode 无全局默认，院点必配（AS-CHS-AUD-002 / Q12=C）
    # 值须与医保局登记的「调用方系统简码」一致；联调样例常见 ims，正式以院方备案为准
    audit:
      syscode: ${CHS_AUDIT_SYSCODE:ims}
```

`ims` 为省事前联调样例常用值；**正式环境须与医保局备案的「调用方系统简码」一致**，可用环境变量 `CHS_AUDIT_SYSCODE` 覆盖，无需改 jar。

### 验收

重启院点应用后再次签发：不再报未配置 syscode；若平台拒绝 syscode，核对备案值并改环境变量。

## 修复四：事前提醒 `patn_id` 为空

### 现象

配置 syscode 后，签发事前提醒继续报：

```text
patn_id 不能为空
```

### 根因

```text
医生站 runOpDetailAuditGate 不传 psnNo（收费页会传读卡结果）
→ enrich 后 context.psnNo 为空
→ Op2201Invoker.resolveOrRegister 命中 yb_encounter_platform_map 只返回 mdtrt_id
→ 未把 map.psn_no 回写 context
→ AuditFeeSnapshotProjector 用 ctx.psnNo 填 3101 patn_id → 空 → Gate 失败
```

挂号医保预结算写 map 时已存 `psn_no`，签发门禁可复用。

### 改动

| 文件 | 说明 |
|------|------|
| `Op2201Invoker#resolveOrRegister` | map 命中且 context.psnNo 空时，回填 `mapped.psnNo` |
| `Ip2401Invoker#resolveOrRegister` | 住院同构回填 |

### 验收

1. 市医保挂号（已写 map+psn_no）→ 医生站签发 → 3101 不再报 `patn_id 不能为空`。  
2. 收费页显式传 psnNo 行为不变（不覆盖已有值）。  
3. 若 map 亦无 psn_no（脏数据/未医保挂号建档）→ 仍失败，需重新读卡结算链路补全。

## 修复五：3101 `poolarea` 参保所属统筹区缺失

### 现象

```text
【长春市】FSI-事前控制失败参保人所属统筹区编码长度不在范围内，应该在1到10之间
```

### 根因

**不是 assembler 字段写反**，而是该填的值没带上：

| 平台字段 | 正确含义 | 正确来源 |
|----------|----------|----------|
| `patient_dtos.poolarea` | 参保所属统筹区码（如 `220199`，长 1~10） | `insuplcAdmdvs` |
| `medins_id` | 定点机构编码（如 `H22010402403`，长 12） | 契约 `fixmedins_code` |
| `medins_admdvs` | 就医地医保区划 | 契约 `adm_vs` |

映射 `poolarea ← insuplcAdmdvs` 本身正确。医生站签发不传 `insuplcAdmdvs` → `poolarea` 为空（长度 0）→ 平台报不在 1~10。收费页读卡会传参保地，不易复现。

### 改动

| 文件 | 说明 |
|------|------|
| `DetailAuditGateInvokerImpl` | 投影前回填：入参 → 本就诊预结算 → 1101 人缓存；长度 1～10；**禁止**契约 `adm_vs` 兜底（就医地 ≠ 参保统筹区，会导致结算失败） |

### 验收

签发后 3101 的 `poolarea` 应为 6 位左右区划码（如 `220199`），不得为空，也不得为 `H22010402403`。无真实参保地时本地 Gate 失败（引导读卡/收费预结算），不得静默用就医地冒充。

## 修复六：事前提醒「出生日期不能为空」

### 现象

平台/本地 Gate 报出生日期（`brdy`）为空。

### 根因

签发门禁不传 `brdy`；旧投影仅用 Command.brdy，未从 Encounter 患者上下文写入 Snapshot（与 25 §2.6 不一致）。

### 改动

| 文件 | 说明 |
|------|------|
| `OpPreSettleCommand` | 增补 `brdy` |
| `ChsOutpatientInsuranceContextLoader` | 从 Encounter.`birthDate` 写入 `yyyy-MM-dd` |
| `AuditFeeSnapshotProjector` | `fromOpPreSettle` 投影 `brdy` |
| `DetailAuditGateInvokerImpl` | 入参优先；仍空则本地 Gate 失败 |

### 验收

主档有出生日期 → 3101 带合法 `brdy`；主档无生日 → 本地清晰错误，禁止伪造。

## 修复七：事前提醒「性别长度不在 1～3」

### 现象

```text
FSI-事前控制失败性别长度不在范围内，应该在1到3之间
```

### 根因

`AuditFeeSnapshotProjector` 将 HIS `AdministrativeGender`（`MALE`/`FEMALE`，长度 4～6）原样写入 `patient_dtos.gend`；医保字典 GEND 为 `1`/`2`/`0`。

### 改动

| 文件 | 说明 |
|------|------|
| `ChsDetailAuditConstants` | `GEND_*` / `HIS_GENDER_*` |
| `AuditFeeSnapshotProjector` | `mapHisGenderToPlatformGend`：MALE→1、FEMALE→2、UNKNOWN→0 |
| `DetailAuditGateInvokerImpl` | 本地 Gate 校验 gend 长度 1～3 |

### 验收

签发 3101 `gend` 为 `1`/`2`/`0`，不再报长度非法。

## 修复八：事前提醒「定点医疗机构名称长度不在 1～200」

### 现象

```text
FSI-事前控制失败定点医疗机构名称长度不在范围内，应该在1到200之间
```

### 根因

`fillInstitution` 只写入 `medins_id`/`medins_admdvs`，未写 `medins_name`；`chs-contract.properties` 已有 `fixmedins_name`，但 `ChsContractPropertiesAccess` 原先无 name 端口。

### 改动

| 文件 | 说明 |
|------|------|
| `ChsContractPropertiesAccess` / `Impl` | 新增 `findFixmedinsName` |
| `DetailAuditGateInvokerImpl#fillInstitution` | 写入 `snap.medinsName`；本地 Gate 校验长度 |
| `InsuranceDetailAuditTryAppService` | 试调同源补名称 |

### 验收

3101 `medins_name` 为契约配置院名（如「长春市朝阳区中医院」），非空。
