### 1.2 与 ZXPlat 其它 CHS 能力的关系

```text
3301 对码（yb_no） ──前置──► 350x 上报（med_list_codg）
2207/2304 结算      ──关联──► 3505（setl_id / mdtrt_sn / hi_feesetl_type）
1101 人员信息       ──可选──► 3505/3506（psn_no / certno）
发药/进货/盘点      ──触发──► 3501–3506
运维对账            ──使用──► 3508–3513 + 3507 删除
```

**原则**：进销存上报 **不阻塞** 本地发药/进货/结算成功（P2、`DISPENSE_UPLOAD` non-blocking）；Health 业务 Extension **全部**在事务 `afterCommit` 后 `@Async` 出站；失败可运维补传（编辑 `request_json` 重放，**不从业务表重建**）。

### 2.4 3505 与结算的时序

```text
门诊（医保）
  2204 → 2206 → 2207
       ↓ 本地落账 SUCCESS
  发药 COMPLETED（扣库存 + 写追溯码）
       ↓ 事务提交后（异步）
  3502(107) → 3505（逐发放行；3502 失败仍继续 3505）

门诊（自费）
  本地收费 SUCCESS → 发药 COMPLETED
       ↓ 事务提交后（异步）
  3502(107) → 3505（mdtrt_setl_type=2，mdtrt_sn=院内就诊流水）

住院（医保/自费，与门诊分流）
  在院多次发药 COMPLETED（院内绑码 + HIS OUT；**不调 3505**，尚无 setl_id）
       ↓
  出院全结 2304 / 本地结算 SUCCESS
       ↓
  有活动床 → 护士清床 DISCHARGED
  无活动床（召回未占床轨）→ 结算直接 DISCHARGED
       ↓ 事务提交后（异步）
  3502(107) → 3505（CLEAR_BED_SUMMARY；**与门诊同 Orchestrator**：3502 失败仍继续 3505）
  反结/召回（仅已成功合并 3505）→ 3506 → 3502(106)
              （**与门诊退药同路径**：3506 成功后再 3502；伴生失败不回写 3506；不写 HIS 发放表）
```

**要点**（追溯码 FAQ 与省指引）：

- 医保结算：`mdtrt_sn` = `MDTRT_ID`；尽量带 `setl_id`、`psn_no`
- 自费结算：`mdtrt_sn` = 机构内就诊流水（如 `Encounter.busNo`）
- `mdtrt_setl_type`：1-医保 / 2-自费，**必填**
- **结算性质取支付单**：跟**本批发药收费项所挂支付单**的 `contract_no` 判定医保/自费（**BR-CHS-INV-012**）；**禁止**用同就诊挂号等其它支付单的医保契约冒充药费性质（否则会误写 `mdtrt_setl_type=1` 却无 `setl_id`）
- 无码 / 拆零 / 豁免品种的处理见 **§4.8**
- **住院触发点**：发药/汇总核发当时**不报**；**清床/无床直结**后异步 **3502(107)→3505**（`setl_id` 取 IMP；合并口径见上）；反结/召回仅在已有成功合并 3505 时异步 **3506→3502(106)**（伴生批次=`CLRREV`{原3505上报id}，对标门诊退药单号）；**3502 与 3505/3506 单向隔离与门诊完全相同**（见 §2.6）；未冲销禁再清床（**EX-IP-ATD-404**）；3506 成功后配对 3505 标 `DELETED`；失败经运维台补传

### 2.5 3501 vs 3502：数量字段语义（易混淆）

> 规范原文：[3501-商品盘存上传](./apis/35xx/3501-商品盘存上传.md)（`inv_cnt`）、[3502-商品库存变更](./apis/35xx/3502-商品库存变更.md)（`cnt`）。

**结论：3502 一般不是报「当前库存总量」，而是报「本次变更量」。**

| 接口 | 数量字段 | 语义 |
|------|----------|------|
| **3501** | `inv_cnt` | 盘存/实盘**总量**；ZXPlat：拆零量 → 库存行 `unitCode` 操作单位数量（规范原文「最小计价包装」在院内以操作单位落地） |
| **3502** | `cnt` | 本次库存**有符号变化量**：入库类（101/103/106/108/110）为正，出库类（102/104/105/107/109/111）为负；组装见 `InvChgType#toSignedCnt` |
| **3508** | 平台返回 | 平台侧**当前库存**（查询，非上报） |

**唯一例外——首次初始化**：规范要求「在医药机构首次初始化数据时，需要将盘存信息同时记录一笔商品库存变更」。此时每条 3501 后**必须**再报一笔 3502，`cnt` 与 `inv_cnt` **相同**（均为当前库存操作单位数量），`inv_chg_type=106`（其他入库），用于在平台侧建立初始变更记录。

ZXPlat 各场景数量取值（`Inventory*UploadContextLoader`）：

| HIS 场景 | 3501 `inv_cnt` | 3502 `cnt` | 3502 `inv_chg_type` | 备注 |
|----------|----------------|------------|---------------------|------|
| 运维批初始化 `initializeInventory` | 拆零量 ÷ 操作单位倍数 | 同左且**为正**（106） | 106 | 机构**首次**接入；3501 + 3502 成对；缺 `manu_date`/`expy_end` 跳过该行 |
| 盘点同意 `uploadAfterStocktakeAgree` | — | 盈亏差额操作单位量，**103 为正 / 104 为负** | 103 盘盈 / 104 盘损 | **不报 3501**；无盈亏行不报 3502 |
| 科室领用同意 `uploadAfterDeptIssueAgree` | — | 领用数量（**负**） | **107** 其他出库 | 科室药房真实扣减 |
| 科室退领同意 `uploadAfterDeptIssueReturnAgree` | — | 退领数量（**正**） | **106** 其他入库 | 科室药房真实加回 |
| 损益单同意 `uploadAfterGainLossAgree` | — | 盈亏差额操作单位量，符号随类型 | 行 `reason`（inv_chg_type 101–111）；未填则 103/104 | 105 销毁（负）、110 正 / 111 负 等 |

**快速对照**：

```text
查平台当前库存  → 3508（查询）
报实盘/盘存总量 → 3501 inv_cnt
报某次变动多少  → 3502 cnt（有符号） + inv_chg_type
                 入库/盘盈/退领… cnt>0；出库/盘损/销毁/领用… cnt<0
销售出库        → 3502(107) → 3505
销售退货        → 3506 → 3502(106，批次=退药单号)
采购入库        → 3503 + 3502(108)
采购退货        → 3504 + 3502(109，批次=退供单号)
```

**`cnt` 符号硬规则（与 `InvChgType#toSignedCnt` / `validateQtyDirection` 一致）**：

| `inv_chg_type` | 含义 | `cnt` |
|----------------|------|-------|
| 101 / 103 / 106 / 108 / 110 | 入库类 | **正数** |
| 102 / 104 / 105 / 107 / 109 / 111 | 出库类 | **负数** |

组装顺序：拆零量 → 操作单位**绝对值** → 按类型赋符号 → `assemble3502` 出站前再校验方向。

### 4.4 追溯码 `drugtracinfo`（3502/3505/3506）

| 规则 | 说明 |
|------|------|
| 节点结构 | 与 openhis 相同：`[{ "drug_trac_codg": "..." }]`；码串 **trim 后原样**（不做大小写/前后缀加工） |

### 4.5b′ 3505 ↔ 3506 关联与退货专属（基线规范）

| 职责 | 3505 字段 | 3506 字段 | 口径 |
|------|-----------|-----------|------|
| **对单（吉林省）** | （平台生成 `medinsProdSelNo`，见 3511） | **`medins_prod_sel_no`** | **= 3511 `medinsProdSelNo`（平台数字流水）**；**不是** `rtal_docno`/CI…，也**不是** MDP 同号（联调 CI/MDP 均报「未找到商品销售信息」） |
| **对人** | `mdtrt_sn` | `mdtrt_sn` | 退货须与原销售 **完全一致** |
| **单据号（吉林省）** | `fixmedins_bchno`=发药行 busNo | `fixmedins_bchno`=**原 3505 同号** | 成功口径：原销售 MDP + 平台流水；退药单号仅作本地 `source_line_id`/暂存 |
| **退货时间** | — | `sel_retn_time` | 退药单 `dispense_time` |
| **退货经办人** | — | `sel_retn_opter_name` | **配药人**（无则回落退药确认人）；不得与发药人同人 |

| **非必填** | — | `psn_*` / `finl_trns_pric` / `expy_end` / `memo` 等 | **能写就写，空不拦** |

> **联调实证（长春）**：退药 MDP…011 + CI… → 失败；原销售 MDP…009 + CI / 原销售 MDP…009 + MDP…009 → 仍失败；**原销售 MDP…009 + 3511 平台数字流水** → 成功。3505 `response_json` 无可用流水，组装时**必查 3511**。

**原销售定位（退药对冲行 → 原 3505）**：以退药发放行 `med_req_id` 为起点，**禁止**用退药 `dispense_id` 直接 map 收费项（收费项挂原发药行；门诊退费同条 ChargeItem 改态不新建账单）。

| 就诊 | 定位链 |
|------|--------|
| **门诊 AMB** | 负向药嘱 `refund_medicine_id` → 原药嘱 → 正向 COMPLETED 发药行 → 原 `adm_charge_item`（`bus_no`/id = `feedetl_sn`） |
| **住院 IMP** | 同药嘱锚点下 `refund_id` 非空的**新/冲销账单** → `refund_id` 反查原收费项；无冲销行时回落同 `med_req_id` 正向 COMPLETED 发药 |

对单取值：吉林 3505 成功回包常见 `output={}`（无平台流水），**按原销售 `fixmedins_bchno` 调 3511** 取 `medinsProdSelNo`。实现（`InventorySaleUploadReferenceResolver`）：

- **有原销售批次号即查 3511**，不因本地无成功 3505 审计而跳过（3505 审计仅用于优先取契约）。
- 3511 **只传 `fixmedins_bchno`**（平台必填日期窗含首尾 ≤30 天，回看 29 天）；**不传** `med_list_codg`，避免条件过多查空。
- 契约回落：无 3505 审计时用当前退药契约出站。
- **异步退药组装**：`@Async` 无登录态，3511 须带入调用线程捕获的 `operatorId`（与 3505/3506 出站快照同口径）；禁止在异步线程 `requireOperatorId`。
- **一药多发对单**：同原药嘱多条 COMPLETED 发药时，按退药行拷贝的追溯码/批号/数量一对一匹配，并用本批占用集防串号；**禁止**多行都取 `max(id)`（否则会出现三行 3506 都绑同一 MDP）。

清床冲销：数量/追溯/`mdtrt_sn` 跟审计，**单据号跟原清床 3505，对单跟 3511**。

### 4.8 无码药品与耗材处理

> **原则**：无追溯码时，**进销存销售信息（3505/3506）通常仍须上报**；差异在于 `drugtracinfo` 是否为空、以及 `trdn_flag` 如何赋值。  
> **政策依据**：[医保发〔2025〕7 号](https://www.bypc.gov.cn/zfxxgk/bmdwxzjd/xzjd/wjsz/fdzdgknr/ylwsfb/art/2025/art_7661955aa5f048548335bf38d9922de2.html)、[追溯码采集 FAQ](https://www.lyg.gov.cn/zglygzfmhwz/spyp1/content/c8be558c-92c9-4fb3-989c-6d7a5b323fe3.html)。

#### 4.8.1 四类无码场景

| 类型 | 含义 | 典型品种 | 发药是否强制扫码 |
|------|------|----------|------------------|
| **A 政策豁免** | 国家明确可不采集追溯码 | 中药饮片、中药配方颗粒、院内制剂、零散注射针剂 | 否 |
| **B 拆零销售** | 最小包装有码，但本次按片/支/最小制剂单位发放 | 需拆零的片剂、按支注射剂 | 否（本次可无码） |
| **C 无码库** | 最小销售包装外立面无码，已申报纳入「无码库」 | 部分临床输液、过渡期无码药 | 否 |
| **D 应码未扫** | 本应扫码却遗漏（非豁免、非拆零） | 普通成药整盒 | **是**（合规风险） |

> **类型 D** 不应默认当作「无码」放行。2025-07-01 起销售环节原则上 **扫码后方可医保结算**；ZXPlat 默认 **告警**，是否阻断由配置 `block-settle-without-trace` 控制。

#### 4.8.2 与「未对码（无 yb_no）」的区别

| | 无追溯码 | 无 `yb_no`（未 3301 对码） |
|--|----------|---------------------------|
| 本地发药 | 可以 | 可以 |
| 医保结算 | 视无码库 / 豁免 / 拆零政策 | 通常不允许 |
| **3505 进销存** | **仍应上报**（`drugtracinfo` 可空） | **SKIP**（缺 `med_list_codg`） |

#### 4.8.3 各接口字段填写（无码时）

| 接口 | 无码 / 豁免 / 拆零时怎么填 |
|------|---------------------------|
| **2207 / 2304** | `minpacunt_drug_trac_cnt`、`mcs_trac_cnt`：按 **DD §4.3 两分支 `floor`** 累加应上传最小包装条数（与实扫脱钩）；豁免 / 无码库行可 0 |
| **3505 销售** | 主表字段（数量、批号、`mdtrt_sn`、`mdtrt_setl_type` 等）**照常**；`drugtracinfo` **省略或 `[]`** |
| **3506 退货** | 同 3505；无码退药不带追溯节点 |
| **3502 变更** | 无码入库/调拨时 `drugtracinfo` 可空；拆零相关 `trdn_flag=1` |
| **3503 采购** | 无 `drugtracinfo` 节点（追溯在 3502 / 3512 侧） |

**`trdn_flag` 赋值规则**（对齐 **DD §4.2**）：

| 场景 | `trdn_flag` |
|------|-------------|
| **已扫码** | 任一码实扣非满贴码整出 → **`1`**；全部满码整出 → **`0`** |
| **未扫码** | 默认 **`1`** |
| 无追溯码主档单位可判（无码库等） | **`0`**（整包装兜底） |

#### 4.8.4 耗材

| 情况 | 处理 |
|------|------|
| 高值耗材有 UDI | UDI 写入 `drugtracinfo.drug_trac_codg`（规范：耗材参照药品追溯码字段） |
| 低值耗材无 UDI、未强制采码 | `drugtracinfo` 可空；**3505 销售行仍报**（若产品纳入耗材进销存 Wave） |
| **2207 / 2304** | `mcs_trac_cnt` 仅计 **应扫码且非拆零** 的耗材行 |

> ZXPlat Wave I 门诊发药以 **药品** 为主；耗材 3505 纳入范围见 §3.2，与 AS-OP-PHA-001 边界一致。

#### 4.8.5 发药决策表

| 品种 | 扫码 | `trdn_flag` | `drugtracinfo` | 3505 | 2207/2304 计数 |
|------|------|-------------|----------------|------|----------------|
| 普通成药整盒 | 必须 | 0 | 有码 | 报 | 药品 +1 |
| 拆零发药 | 可不扫 | **1** | 空 | 报 | 不计 |
| 中药饮片等豁免 | 不扫 | 0 或 1 | 空 | 报 | 不计 |
| 无码库品种 | 不扫 | 0 | 空 | 报 | 0 |
| 高值耗材 UDI | 扫 UDI | 0 | UDI | 报（若纳耗材） | 耗材 +1 |
| 低值耗材 | 通常不扫 | 0 | 空 | 视产品 | 0 |
| 应码未扫 | — | — | — | **不应默认上报无码** | 业务拦截/告警 |

#### 4.8.6 ZXPlat `tracePolicy` 判定（Assembler 用）

发药/出库组装 3505 前，按行计算 `tracePolicy`：

```text
tracePolicy（优先级从高到低）:
  NO_YB_NO          → 整行 SKIP（§4.7）
  TRACE_REQUIRED    → 必须有 traceNo；缺码 WARN/BLOCK
  SPLIT_DISPENSE    → trdn_flag=1；drugtracinfo 可空
  NO_CODE_LIBRARY   → trdn_flag=0；drugtracinfo 空；目录标记无码
  POLICY_EXEMPT     → trdn_flag 按 §4.8.3；drugtracinfo 空
```

| `tracePolicy` | 3505 | `upload_status`（无码但已上报） |
|---------------|------|--------------------------------|
| `TRACE_REQUIRED` + 有码 | 调平台 | `SUCCESS` |
| `SPLIT_DISPENSE` / `NO_CODE_LIBRARY` / `POLICY_EXEMPT` | 调平台（无 drugtracinfo） | `SUCCESS` |
| `NO_YB_NO` | 不调平台 | `SKIPPED_NO_YB_NO` |

**拆零判定（ZXPlat）**：门诊发药 3505（`InventoryUploadTraceLineSupport`）优先按发放/领用 `bus_no` 下 HOSPITAL_IO OUT 各码**实扣**判 `trdn_flag`；无 OUT 回落行余数；未扫默认 **`1`**。**住院清床/无床直结合并**须按码汇总多发放 `bus_no` 的 OUT−退药 IN 后再判（`applyClearBedMergedTrdnFlagAndPolicy`），禁止用代表行单 busNo。废止仅凭「操作单位 ≠ trace_unit_code」公式作最终真相。

**目录标记（规划）**：药品/耗材定义增加 `trace_code_required`（或对接国家目录「有无追溯码」）；无码库品种置 `false`。Wave I 可先 **人工维护 + 配置白名单**，自动识别放 Wave IV（见 §3.3）。

### 4.9 追溯码唯一性与码药匹配（业务规则）

> **目标**：防止同一追溯码重复销售（回流/空刷），并保证扫码与发放行 **品种、批号、库房** 一致。  
> **原则**：规则在 **HIS 发药/出库事务内** 强制（硬门禁）；**3505 仅转发已通过门禁的码**，CHS 层不「补码」或改绑。

#### 4.9.1 业务规则清单

| 规则 ID | 名称 | 说明 | 门禁时机 |
|---------|------|------|----------|
| **BR-INV-TRC-001** | 追溯码不可重复出库 | 同一追溯码净在库为 0 或已 OUT 后，**禁止再次 OUT** | 保存配药 / 发药前 |
| **BR-INV-TRC-002** | 码药必须匹配 | 码须绑定在发放行 **item_table + item_id + lot_number + location_id** 下，且 **净在库 > 0** | 保存配药前 |
| **BR-INV-TRC-003** | 同单不可重复扫码 | 同一请求内 traceNo **去重**；重复码整单拒绝 | 保存配药前 |
| **BR-INV-TRC-004** | 非拆零码数与数量一致 | `TRACE_REQUIRED` 时，`drugtracinfo` 条数 = 最小包装 **`sel_retn_cnt`（整数）** | 3505 组装前 |
| **BR-INV-TRC-005** | 3505 只传已出库事实 | `drugtracinfo` **仅**来自发药写入的 `cus_trace_number_record` OUT 行 | CHS Assembler |
| **BR-INV-TRC-006** | 退药复位后可再售 | 退药 IN + **3506** 后净在库恢复，同一码可再次发药 | 退药后再发 |

#### 4.9.2 净在库模型（`cus_trace_number_record`）

```text
对每个 trace_no（租户内）:
  net = COUNT(IN) - COUNT(OUT)

net > 0  → 在该 (item, lot, location) 维度「在库可发」
net = 0  → 已出库或未入库，不可再 OUT
net < 0  → 数据异常，阻断并运维修复
```

**IN**：药库进货、药房领入、退药入库（`MEDICATION_RETURN_IN`）等。  
**OUT**：门诊/住院发药、药库出库等。

> **已落地（门诊）**：`TraceNumberRecordQueryService#assertCodesNotAlreadyOutbound` — 存在 OUT 记录则 **EX-OPP-201**（BR-OPP-003 / BR-MDP-009）。  
> **Wave I 增强**：升级为按发放行四维校验 **net > 0**（§4.9.4）。

#### 4.9.3 码药匹配四维

| 维度 | 发放行 | 追溯记录 | 不匹配后果 |
|------|--------|----------|------------|
| 品种 | `medication_id` + 药品表 | `item_id` + `item_table` | 禁止出库（串换） |
| 批号 | `lot_number` | `lot_number` | 禁止出库 |
| 库房 | `location_id` | `location_id` | 禁止出库 |
| 租户 | `tenant_id` | `tenant_id` | 禁止跨租户 |

3505 Assembler 使用同一四维解析的 `med_list_codg`（`yb_no`），保证平台侧 **码 ↔ 目录编码 ↔ 批号** 与院内一致。

#### 4.9.4 校验链（保存配药）

```text
1. assertSufficientForMedicationDispense（库存）
2. splitTraceCodes(traceNo)
3. BR-INV-TRC-003：同单去重
4. BR-INV-TRC-001：assertCodesNotAlreadyOutbound          ← ✅ 已编码
5. BR-INV-TRC-002：assertCodesInNetStockForDispenseLine  ← 🟡 Wave I
6. prepareMedicationDispense / dispenseMedication
7. appendTraceRecords(OUT)
8. 事务提交后 → 3505（BR-INV-TRC-005）
```

规划接口：

```java
void assertCodesInNetStockForDispenseLine(
    String itemTable, Long itemId, String lotNumber, Long locationId,
    Collection<String> traceCodes);
```

#### 4.9.5 与 3505 / 3506 的衔接

| 环节 | 规则 |
|------|------|
| **3505** | 按 `dispenseId` 读 OUT 记录生成 `drugtracinfo`；禁止未落库的 UI 原始串 |
| **幂等** | `yb_inv_upload` 唯一 `(tenant, infno, fixmedins_bchno, source_line_id)` |
| **3506** | 退药带原销售关联 + 追溯节点；IN 复位后 EX-OPP-201 不再命中 |
| **2207** | `minpacunt_drug_trac_cnt` 按 **DD §4.3** 两分支 `floor` 估算（与实扫脱钩） |

CHS 二次校验：非拆零时 `drugtracinfo` 条数 ≠ `sel_retn_cnt` → 不上送；`yb_inv_upload_trace` 建议对 SUCCESS 的 OUT 码建 `(tenant_id, drug_trac_codg)` 唯一索引。

#### 4.9.6 并发与跨场景

| 场景 | 策略 |
|------|------|
| 同码并发双发 | 先发写入 OUT；后发 EX-OPP-201 或 net 校验失败 |
| 退药后再发 | 须退药 IN + 3506 完成 |
| 跨库房 | 码绑定 location；须调拨 IN 后才能在目标库 OUT |
| 拆零 | 无 drugtracinfo；不触发 BR-INV-TRC-001/002（§4.8） |

#### 4.9.7 错误码

| 错误码 | 场景 |
|--------|------|
| **EX-OPP-201** | 追溯码已出库 |
| **TRACE_NUMBER_RECORD_002**（已实现） | 码不在库 / 与药品·批号·库房不匹配 |
| **TRACE_NUMBER_RECORD_003**（已实现） | 同单重复追溯码 |
| **EX-OPP-207** | 发药成功、3505 失败（不回滚发药） |

#### 4.9.8 测试补充

| 用例 | 期望 |
|------|------|
| T13 重复出库 | 同一码第二次发药 → EX-OPP-201 |
| T14 码药不符 | A 药码用于 B 药 → TRACE_NUMBER_RECORD_002 |
| T15 同单重复码 | 同请求两个相同 traceNo → TRACE_NUMBER_RECORD_003 |
| T16 退药再发 | 退药 IN 后同一码可再次 3505 |

### 6.2 追溯码明细 `yb_inv_upload_trace`

```sql
CREATE TABLE yb_inv_upload_trace (
    id              BIGINT PRIMARY KEY,
    upload_id       BIGINT NOT NULL REFERENCES yb_inv_upload(id),
    drug_trac_codg  VARCHAR(100) NOT NULL,

    ON yb_inv_upload_trace (tenant_id, drug_trac_codg) WHERE is_deleted = FALSE;
```

**写入口径（BR-CHS-INV-013）**：平台 SUCCESS 后写子表；同码再写时 `YbInvUploadDomainService#saveTraceRow` **先软删旧归属再插入**。子表异常**不得**把已 SUCCESS 的 `yb_inv_upload` 打成失败或整笔回滚——否则「有码退药」伴生 **3502(106)** 审计消失，再发 **3502(107)** 平台 191。
