# 医保文件 · 应用场景与操作方法

> **页面**：医保管理 → 医保文件管理（`/chs/catalog-notice`）  
> **关联方案**：[24-医保文件与目录通知管理-方案.md](../../24-医保文件与目录通知管理-方案.md)  
> **现场操作手册**：[README-医保文件操作手册.md](./README-医保文件操作手册.md)（配置、洗数、排障细节）  
> **日期**：2026-07-15

本文只回答两件事：**什么时候要用医保文件**，以及**怎么操作**。

---

## 1. 一句话定位

局端下发的「药品 / 耗材 / 诊疗（服务、F 服务等）数据更新目录」和「支付对照」表，经院外洗成标准包后：

1. **入库**：进入系统文件库（可查、可追溯），**还不改业务口径**；  
2. **应用**：写入目录叠加层（overlay）/ 回写院内甲乙类，**之后**选码、开单、预结算、费用上传才会按局文生效。

> **不是**第二套 13xx 下载；**不替代**国家目录版本链；**不直接改**平台镜像主列。

---

## 2. 两类文件分别管什么

| 种类（界面中文） | 典型局文 | 明细动作 | 应用后主要效果 |
|------------------|----------|----------|----------------|
| **目录增减废** | 药品/耗材/服务「数据更新目录」 | 新增 / 停用 / 变更 / 省变更 | 选码可用、停用终止日、补限价与等级等字段（写 overlay） |
| **支付对照** | 医保支付对照结果表 | 支付对照（SET_PAY_CLASS） | overlay 记甲乙；**回写**院内药/诊/耗 `chrgitm_lv`；同步未收费明细 |

限价金额来自「目录增减废」里的「医保目录定价上限」；纯支付对照文件通常**没有**金额，只管甲乙类。

## 3. 应用场景总表

| # | 场景 | 用医保文件做什么 | 操作入口 | 未做会怎样 |
|---|------|------------------|----------|------------|
| S1 | **维护药 / 耗材 / 诊疗国家码口径**（含可用、停用、补字段、限价写入） | 入库局文 → **应用** → overlay 生效 | 医保文件：扫描入库 → 预览/应用 | 仅靠 13xx，停用日/限价/新增码可能落后或缺失 |
| S2 | **维护支付类别（甲/乙/自费）** | 入库支付对照 → **应用** → 回写院内目录 lv | 同上 | 院内 lv 与局文不一致时，医保开单/上传会被拦 |
| S3 | **选码 / 对码 / 建项** | 应用后的合成「可选码」结果 | 国家目录选码等；本页不选码 | 已停用仍可选、仅 01* 未映射却走医保 |
| S4 | **院内调价超过医保限价** | 限价在 overlay；预结算/开单/上传硬拦 | 调价页（事前宜拦）+ 医保结算链路 | 价表可能改上去，但**医保路径应走不通** |
| S5 | **预结算 / 开单 / 费用上传** | 行级门禁读 overlay（不扫整表明细） | 结算链路自动 | 超限价、已停用、错甲乙、未映射 01* → 拒绝医保 |
| S6 | **国家目录刚下载完（13xx）** | 自动/手动合规校验，对照已应用局文 | 目录下载页校验条；本页「手动重验」 | 仅报告/告警，**不阻断下载成功** |
| S7 | **首页停用 / 甲乙催办** | 待办跟进换码或 3302 等 | 医保文件「催办与合规」；工作台卡片 | 关待办**不能**绕过仍成立的硬阻断 |
| S8 | **审计 / 扯皮回溯** | 查哪份局文、哪行、何时应用 | 已入库文件 → 明细；apply_log | — |

## 4. 核心操作方法（标准路径）

### 4.1 操作总流程

```text
收到局发附件
    → 院外洗成标准包（notice.meta.json + notice.lines.csv）
    → 放到服务器扫描根目录 canonical-root/{子目录}/
    →【医保文件】重新扫描
    → 对「待入库」行「入库」或勾选后「确认入库」
    →【已入库】预览应用 → 应用（二次确认）
    → 处理待办；预结算/开单抽检硬阻断是否符合预期
```

| 步骤 | 是否改库 | 业务是否按局文生效 |
|------|----------|--------------------|
| 扫描 | 否 | 否 |
| **入库** | 是（doc/line/标准包） | **否** |
| **应用** | 是（overlay / 院内 lv / 待办） | **是** |

### 4.2 入库（怎么做）

1. 确认扫描根目录已配置且新包已落到该目录（见操作手册 §3）。  
2. 打开 **医保文件管理** → Tab **扫描入库**。  
3. **重新扫描**（进入页也会自动扫）。  
4. 状态含义：

| 状态 | 含义 | 操作 |
|------|------|------|
| 待入库（NEW） | 内容未见过 | 行内「入库」或勾选后「确认入库」 |
| 已存在（DUPLICATE） | 同内容已入库 | 无需再导 |
| 失败（FAILED） | 缺件/解析失败 | 回洗数目录修复后再扫 |

5. 入库成功后到 **已入库文件** 可见；应用状态一般为「未应用」。  
6. 大包（数千行）入库可能需一两分钟，进度条显示「大包入库中」属正常。

### 4.3 应用（怎么做）

1. 在 **已入库文件** 选中未应用记录。  
2. 先点 **预览应用**，看 overlay / 回写 / 样例影响。  
3. 再点 **应用** → 二次确认。  
4. 成功后状态变为「已应用」；同一文件不要重复应用。

**应用效果对照**

| 明细动作 | 应用后 |
|----------|--------|
| 停用 | overlay 标记不可用 + 终止日；已对码项医保开单/上传将被拦 |
| 新增 | 有国家码：完善可选；仅 01*：PENDING 映射，映射前医保硬拦 |
| 变更 / 省变更 | 合并 overlay 补丁（含限价等非空字段） |
| 支付对照 | 回写院内甲乙类 + 未收费明细；已收费明细不改 |

### 4.4 入库了但没应用？

选码、停用拦、限价拦、甲乙回写都**不会**按这份局文生效。  
处理：回到「已入库文件」做预览 → 应用。

## 5. 场景操作细则

### 5.1 S1 维护药 / 耗材 / 诊疗目录（含限价写入）

**何时**：收到药品/耗材/服务/F 服务等「数据更新目录」。  

**怎么做**

1. 洗包 → 扫描入库（§4.2）。  
2. 核对已入库明细行数与局文量级是否合理。  
3. **应用**（§4.3）。  
4. 到国家目录选码抽检：停用码不可选；有限价的码在结算链路超限应被拦。

**记住**：应用写的是 **医保限价上限（overlay）**，不是改 HIS 零售价表。

### 5.2 S2 支付对照（甲乙类）

**何时**：收到「医保支付对照」类附件。  

**怎么做**：入库 → 预览 → 应用。关注回写条数与未收费受影响单据。  

**冲突**：院内 lv 与局文不一致时，医保开单/上传硬阻断（C-PAY-CLASS），应改数据或重新正确应用，而不是关待办了事。

### 5.3 S4 调价调超了限价

| 环节 | 期望行为 |
|------|----------|
| 调价保存（拟仍走医保） | 宜禁止保存超限价（事前门禁） |
| 若价已改高 | **预结算 / 开单 / 上传**仍应按限价硬拦（C-PRICE-OVER） |
| 出路 | 降回限价内继续医保；或改自费/取消医保关联 |

无限价（局文与镜像都无有效上限）→ 不因金额阻断（C-PRICE-UNKNOWN），可抽查。

### 5.4 S5 预结算门禁

- **要做**：对本单每条医保明细做行级门禁（停用 / 甲乙 / 限价 / 未映射 01*）。  
- **性能**：查的是 overlay 点查，不是每次扫 `notice_line` 全表；门诊单量级可接受。实现上宜批量按编码预取 overlay。  
- **不要**：把「全量合规报告」当成每次预结算的步骤。

### 5.5 S6 目录下载后

- 下载成功照常；系统对照已应用局文出合规报告。  
- 需要时可在本页 **手动重验**。  
- 报告问题需人工跟进；不据此回滚下载。

### 5.6 S7 待办

- 查看停用 / 支付类别 OPEN 待办，处理后填写原因关闭。  
- **关闭待办 ≠ 解除硬阻断**。阻断还在，须换码、改价、补映射或等新局文。

---

## 6. 硬阻断速查（业务侧）

| 码 | 含义 | 常见处理 |
|----|------|----------|
| C-STOP-ACTIVE | 局文停用已生效 | 停开医保；换码或走 3302 待办 |
| C-PAY-CLASS | 甲乙与对照不一致 | 修正院内 lv 或正确应用支付对照 |
| C-PRICE-OVER | 单价 > 医保限价 | 调价或走自费路径 |
| C-PROJECT-UNMAPPED | 仅 01* 未映射国家码 | 完成映射后再走医保 |
| C-PRICE-UNKNOWN | 无限价 | **不阻断** |

---

## 7. 明确不做 / 易混项

| 易混想法 | 正确理解 |
|----------|----------|
| 入库后目录立刻变了 | 必须再点 **应用** |
| 医保文件改 HIS 零售价 | 只管医保限价/等级叠加与回写 lv |
| 关待办就能开停用码 | 不能；硬条件仍在 |
| 用 01* 当国家码进 3301 | 禁止；须映射 |
| 通知替代 13xx 下载 | 不替代；二者互补 |
| 每次预结算跑全库合规报告 | 否；只用行级门禁 |

---

## 8. 推荐落地顺序（院内）

1. 配置扫描根、洗通 1～2 个小样例包。  
2. 入库 → 应用 → 选码/预结算抽检停用与限价。  
3. 再分批导入历史局文；大包（如数千行变更）单独观察入库耗时。  
4. 调价页接事前超限提示（可选增强）；预结算/开单/上传必须保留硬门禁。
