# 医保文件管理 · 操作手册

> **适用**：吉林医保模块运维 / 物价 / 医保负责人  
> **功能**：AS-CHS-CAT-005 医保文件（目录增减废 + 支付对照）  
> **页面**：医保管理 → 医保文件管理（路由 `/chs/catalog-notice`）  
> **原则**：局发原件在院外洗成标准包后放到约定目录；产品内**不提供**手工上传与 AI 转包。  
> **先读场景**：[医保文件-应用场景与操作方法.md](./医保文件-应用场景与操作方法.md)（何时用、入库 vs 应用、调价/预结算）

---
## 1. 角色与权限

| 角色 | 常见操作 |
|------|----------|
| 医保运维 / 物价 | 洗数落盘、重新扫描、确认入库、预览/应用、下载标准包、关待办、手动重验 |
| 医保负责人 | 查看待办与合规问题，确认停用/甲乙类影响后闭环 |
| 系统 | 国家目录下载（CAT-002）成功后自动触发合规校验（无本页按钮） |

## 2. 总流程（先看再动手）

```text
① 收到局发附件（xlsx/xls/…）
        ↓ 院外洗数（Cursor / 人工，见「洗数与成码提示词」）
② 产出标准包 → 落到服务器 canonical-root/{子目录}/
        notice.meta.json + notice.lines.csv
        ↓
③ 页面「重新扫描」→ 勾选 NEW →「确认入库」（二次确认）
        ↓
④ 「预览应用」→「应用」（二次确认）→ 生效叠加 / 回写甲乙类
        ↓
⑤ 处理「待办」；必要时「手动重验」合规报告
        ↓
⑥ 业务侧：开单/医保结算若命中硬阻断码，按报告与待办整改
```

| 阶段 | 是否改业务数据 | 说明 |
|------|----------------|------|
| 扫描 | 否 | 只预览 NEW / DUPLICATE / FAILED |
| 确认入库 | 是（文件库） | 写入 `yb_catalog_notice_*`，**尚未**改目录可用状态 |
| 应用 | 是 | 写 overlay；支付对照回写院内甲乙类；产生待办 |
| 关待办 | 仅待办状态 | **不能**绕过仍成立的硬阻断 |

## 3. 上线前准备（运维一次）

### 3.1 数据库

确认 CHS Flyway 已执行含通知表的脚本（如 starter 下 `V2__yb_catalog_notice.sql`），存在：

- `yb_catalog_notice_doc` / `_line` / `_apply_log` / `_todo` / `_compliance_report`
- `yb_national_catalog_notice_overlay`
- `yb_service_project_map`

### 3.2 配置扫描根目录

在项目 `application.yml`（或环境对应配置）设置：

```yaml
openhis:
  chs:
    notice:
      canonical-root: <绝对路径>/标准化文件
      # pack-store-dir:  # 可选；空则 ~/.openhis/chs-notice-packs
```

（兼容旧键 `chs.notice.canonical-root`；改后须重启后端。）

要求目录结构：

```text
{canonical-root}/
  {子目录名}/                 # 通常与局文 stem 一致
    notice.meta.json
    notice.lines.csv          # UTF-8 BOM
```

示例（开发环境可指向文档仓）：

`D:/0.product/02.ZXPlat/docs/模块/zxplat-module-chs-jilin/目录更新通知/标准化文件`

修改后**重启**后端，使配置生效。

### 3.3 前端入口

- 直达：`/chs/catalog-notice`
- 或从国家目录等相关页入口「医保文件」进入（以实际菜单为准）

## 4. 院外洗数（入库前必做）

产品页**不能**上传原件。收到局文后：

1. 将原件放入洗数工作区（见 [`目录更新通知/洗数与成码提示词.md`](../../目录更新通知/洗数与成码提示词.md)）。
2. 按提示词 1A/1B 转成标准包；失败件进 `_无法转换`，成功归档到「原始文件」。
3. 新包复制/同步到服务器 `chs.notice.canonical-root` 下（保持「一子目录一标准包」）。
4. 大批量上线前建议跑全量审计（提示词 1C / `脚本/audit_canonical_packs.py`），**ERROR=0** 后再扫库。

标准包字段与样例见：`医保文件-标准落地格式/`、方案 §6.0 / **§6.0.3a**。

语义门禁（与产品扫描一致）：

- 通知日、生效日至少一个，否则**禁止应用**
- 物价码 `01*`/`37*` 不得进 `hilist_code`；「未赋码」等脏码跳行
- 有名称必须在 `hilist_name`；限价/限制用固定 ext 键
- `audit_canonical_packs.py`：缺业务日为 ERROR；脏码/名称仅在 ext 为 WARNING

## 5. 页面操作：扫描入库

### 5.1 重新扫描

1. 打开 **医保文件管理**。
2. 页顶提示应显示「当前扫描根目录：…」；若提示去配置 `canonical-root`，先完成 §3.2。
3. 点击 **重新扫描**。
4. 查看「扫描结果」表：

| 状态 | 含义 | 能否勾选入库 |
|------|------|--------------|
| NEW | 内容 hash 未见过，可入库 | 是 |
| DUPLICATE | 与已入库内容重复 | 否（勿强行重复导，除非策略要求强制重导） |
| FAILED | 缺件/解析失败等 | 否；按说明回洗数目录修复后再扫 |

列「动作」含义：`A` 新增 / `S` 停用 / `M` 修改 / `P` 设支付类别（SET_PAY_CLASS）行数概览。

### 5.2 确认入库

1. 勾选需要入库的 **NEW** 行（不勾选且存在 NEW 时，以页面二次确认文案为准：通常视为入库本批全部 NEW）。
2. 点击 **确认入库**，在确认框中再次确认。
3. 成功后提示 imported / skipped / failed 计数；下方 **已入库文件** 出现记录，`应用` 状态一般为 `NOT_APPLIED`。

**注意**

- 入库 ≠ 业务生效；未点「应用」前，停用/甲乙叠加不会生效。
- 同一标准包重复扫描出现 DUPLICATE 属正常，避免重复入库。

### 5.3 查明细与下载

- **单击**已入库文件行 → 右侧/抽屉查看明细行（动作、编码、名称等），可分页。
- 操作列 **下载** → 取回该文件已存标准包 zip（归档/复核用）。

可用筛选：关键字、种类（目录增减废 / 支付对照）、品类、应用状态。

## 6. 页面操作：预览与应用

应用会改 overlay、可能回写院内药品/诊疗/耗材甲乙类，并可能产生待办，**务必先预览**。

### 6.1 预览应用

1. 对 `NOT_APPLIED`（可应用）行点 **预览应用**。
2. 阅读预估影响：overlay 变更量、支付回写量、映射、样例行等。
3. 关闭预览后仍可单独点「应用」，或以预览弹窗内的确认应用（以页面按钮为准）。

### 6.2 确认应用

1. 点 **应用** → 二次确认对话框 → 确认执行。
2. 成功后该文件 `applyStatus` 变为 `APPLIED`。
3. 业务效果概要：

| 文件种类 | 主要效果 |
|----------|----------|
| CATALOG_DELTA | 国家目录 **叠加层**（可用标志、终止日、补字段等）；不改 13xx 镜像主列 |
| PAYMENT_MAP | overlay 记甲乙变更；**回写**院内目录项甲乙类（MD/AD/DD 等） |
| 仅 01* 无国家码 | 建 `yb_service_project_map` 为 PENDING，**禁止**伪造国家码；映射前医保结算硬阻断 |

应用审计写入 `yb_catalog_notice_apply_log`（含影响引用 JSON）。

### 6.3 应用顺序建议

1. 优先小样例包验证环境（导入→应用→开单抽检）。
2. 目录增减废与支付对照按业务通知日/依赖关系分批；大批量前在测试契约演练。
3. 已应用文件勿重复点应用（按钮已禁用 `APPLIED`）。

## 7. 待办与合规

### 7.1 待办 Tab

- 汇总：**停用待办 OPEN**、**支付类别待办 OPEN**。
- 对已处理事项点 **关闭**，必须填写关闭原因。
- **重要**：关闭待办只表示「人工知悉/跟进完毕」，**不会**解除仍成立的硬阻断（例如目录仍停用）。

### 7.2 合规报告 Tab

- 查看最近校验时间、摘要、问题列表。
- **刷新**：读最新已落库报告。
- **手动重验**：二次确认后重跑校验，覆盖最新报告并重算 OPEN 待办。
- 国家目录下载成功后系统也会自动跑合规；校验失败**不会**回滚下载成功结果。

### 7.3 硬阻断码（开单 / 费用上传）

命中以下条件时，医保开单或上传组装会被拒绝（自费路径按产品另定）：

| 码 | 含义 | 通常处理 |
|----|------|----------|
| C-STOP-ACTIVE | 通知叠加后目录已停用且生效 | 停开医保项；选替代码或等业务文件恢复 |
| C-PAY-CLASS | 院内甲乙与对照不一致 | 应用支付对照或修正院内 lv |
| C-PRICE-OVER | 单价大于通知限价（`unit_price > limit`） | 调价或核对限价字段 |
| C-PROJECT-UNMAPPED | 仅 01* 未映射国家码 | 完成映射后再走医保 |
| C-PRICE-UNKNOWN | 无限价 | **不阻断**，可出现在报告中 |

## 8. 日常运维检查清单

| # | 检查项 | 怎样算过 |
|---|--------|----------|
| 1 | canonical-root 可访问且新包已落齐 | 扫描无大量 FAILED；页顶显示正确根路径 |
| 2 | 新局文已入库 | 已入库列表有记录，明细行数与 meta 一致 |
| 3 | 需生效文件已应用 | `APPLIED`；业务侧停用/甲乙已体现 |
| 4 | OPEN 待办有人跟 | 汇总下降或关闭原因齐全；阻断问题另有整改 |
| 5 | 合规报告无未处理硬问题 | 或已知例外已登记 |

抽检 SQL（按环境改库名/条件）：

```sql
SELECT id, title, doc_kind, apply_status, line_count, imported_at
FROM yb_catalog_notice_doc
WHERE is_deleted = false
ORDER BY id DESC
LIMIT 20;

SELECT todo_type, status, count(*)
FROM yb_catalog_notice_todo
WHERE is_deleted = false
GROUP BY todo_type, status;
```

## 9. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 提示配置 canonical-root | 配置未设或未重启 | 按 §3.2 配置并重启 |
| 扫描全空 | 根目录下无合法子目录 | 检查是否多套一层目录；需「根/stem/两个文件」 |
| 大量 FAILED | meta/csv 缺失、编码损坏、非标准包 | 回洗数；对照样例与 1C 审计 |
| 一直 DUPLICATE | 已入库过同内容 | 正常；勿重复导 |
| 已入库但开单无变化 | 未点「应用」 | 预览后应用 |
| 关了待办仍无法医保结算 | 硬条件仍在 | 查阻断码；整改数据或等新通知，而非反复关待办 |
| 下载标准包失败 | 包存储路径权限/磁盘 | 检查 `pack-store-dir` 或默认目录权限 |

**已知能力缺口（现场预期）**

- 「未收费明细甲乙同步」若环境仍为 Charge Port 桩实现，以目录 lv 回写与 `apply_log` 为准；未收费同步能力以发布说明为准。
