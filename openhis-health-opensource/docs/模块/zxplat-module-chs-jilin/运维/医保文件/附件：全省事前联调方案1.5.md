## 一、组织接口改造

由定点医药机构信息系统开发商根据《吉林省医疗保障信息平台定点基线版医药机构接口规范》（最新版，吉林省医疗保障公共服务平台「定点医药机构专版」下载），对当前系统进行接口改造。

### 表1 接口改造清单

| 序号 | 接口名称 | 说明 |
| --- | --- | --- |
| 1 | 【3101】明细审核事前提醒分析服务 | **必须实现** |
| 2 | 【3103】事前提醒服务反馈服务 | **必须实现** |

> **吉林口径（相对国家合订本）**：**不要求实现 3102**（v1.2 起作废并入 3101）。事中场景同样走 **3101**，用 `trig_scen` 区分触发点。

- **3101**：在患者就诊登记、医师开具处方、护士执行医嘱、实际结算或预结算等场景调用，返回违规提醒结果并告知医疗服务提供者。
- **3103**：事前提醒后，采集机构端处理方式（继续执行医嘱/处方、返回修改医嘱/处方）。

## 三、接入流程

### 3.1 事前提醒流程说明

可在以下节点调用 3101：门诊挂号、门诊收费登记、住院登记、住院收费登记、住院执行医嘱、门诊结算、门诊预结算、住院结算、住院预结算。

通用步骤（以住院登记为例，其他场景同构）：

1. 参保人出示身份证 / 医保电子凭证等，机构验证身份；
2. 完成对应业务动作后调用 **3101**；如有提醒，选择「继续执行」或「返回修改」后调用 **3103**；
3. 3103 成功后再继续后续 HIS 流程。

### 3.2 住院结算补充

1. 身份核验 → 入院后上传费用明细；
2. 办理出院后不再上传费用明细，发起住院结算时调 3101；
3. 有提醒则调 3103，再继续结算。

### 3.3 购药划卡补充

1. 身份核验 → 上传费用明细；
2. 药店结算前调 3101（`trig_scen=10`）；
3. 有提醒则调 3103，再继续结算。

> 原文附图（住院登记 / 住院结算 / 购药划卡流程图）未从 docx 抽出，以文字步骤为准。

### 样例要点（成码约束）

| 点 | 结论 |
| --- | --- |
| `syscode` | 样例出现 `ims`、`ASZH`；无统一字面量，须可配置 |
| `trig_scen` | 字符串数字 `"1"`…`"10"` |
| `patient_dtos` / `fsi_encounter_dtos` | **发送一律数组**（国家规范）；样例 2 单对象仅作兼容参考，不作为发送形态 |
| `fsi_his_data_dto` | 可传 `{}` |
| `operation_dtos` vs `fsi_operation_dtos` | 样例 1 出现 `operation_dtos: []`；国家表为 `fsi_operation_dtos` — 联调以平台实测为准 |
| `output.result` | **JSON 数组**（多条违规） |
| 药店 | `adm_dept_codg/name=LD-99`；`med_mdtrt_type=3`；`med_type=41`；机构编码可 `P` 开头 |
