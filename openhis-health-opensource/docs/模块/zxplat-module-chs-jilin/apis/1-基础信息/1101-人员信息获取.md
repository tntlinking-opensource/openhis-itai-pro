## 调用时机

### 业务定位

【1101】是医保侧**人员主数据与参保快照**的入口交易：在院内确认「走医保」后，用就诊凭证换 `psn_no`、险种、参保区划、余额等，供后续挂号、结算、入院登记等交易填写报文头/业务入参。

### 何时必须调用

| 场景 | 时机 | 目的 |
| --- | --- | --- |
| 门诊挂号（医保） | 读电子凭证/身份证/社保卡后、写入挂号事实**之前** | 校验参保有效、展示费别与余额，落库 `psn_no` / `insuplc_admdvs` |
| 门诊收费（医保） | 预结算（2206）**之前**，且本地无当日有效 1101 缓存时 | 补全 `insuplc_admdvs`（报文头必填）、人员编号 |
| 入院登记（医保） | 2401 入院办理**之前** | 入院登记与费用上传依赖人员与参保区划 |
| 处方/收费「转医保」 | 费别由自费切到医保、账户切换**之前** | 确认参保状态与险种，避免无参保结算 |
| 仅查询展示 | 窗口「读卡」「医保资格」按钮 | 对应 FR-INS-001，**不替代**正式结算 |

### 何时可不调用 / 可复用缓存

- 同一自然日、同一就诊凭证、参保状态未变：可复用本院缓存的 1101 结果（含 `psn_no`、`insuplc_admdvs`），避免重复读卡。
- 纯自费流程且不调用任何医保交易：可不调用 1101。
- **不能**用 1101 代替 **2001**（待遇检查）或 **2206/2303**（预结算）的金额试算。

### 前置条件

1. 当日 **9001** 签到成功，报文头 `sign_no` 有效。
2. 已选定 `contractId`（费用性质/医保合同）并完成 `fixmedins_code` 等机构配置。
3. 输入 `data` 与读卡介质一致（`mdtrt_cert_type` / `mdtrt_cert_no` / `card_sn`）。

### 与下游交易的关系

```text
读卡 → 1101 人员信息 → （可选 2001 待遇检查）
                    → 2201 挂号 / 2401 入院
                    → 2204/2301 费用上传 → 2206/2303 预结算 → 2207/2304 结算
```

- 后续任意含「人员编号」的交易，报文头 `insuplc_admdvs`（参保地医保区划）应来自本次 1101 的 `insuinfo.insuplc_admdvs`（多险种时按所选险种行取值）。
- 输出 `insuinfo` 为多行时，应用层需让用户选择险种或按业务规则选定一条再进入结算。

### 失败与降级

| 情况 | 建议处理 |
| --- | --- |
| 超时（>5s） | 提示重试或改手工录入参保信息（SRS FR-INS-001）；勿静默当自费 |
| 无参保 / 暂停参保 | 提示改自费或补办参保，禁止继续医保预结算 |
| 读卡失败 | 校验介质与 `mdtrt_cert_type` 是否匹配 |

## 接口说明

#### 交易说明

通过此交易获取人员信息。

#### 重点说明

交易输入为单行数据，交易输出参保信息为多行数据，输出身份信息为多行数据。

#### 交易对象

交易发送方：医药机构。

交易接收方：地方医保局。

#### 输入

> **JSON 节点**: `data`

| 序号 | 参数代码 | 类型/长度/标识/说明（原文合并） |
| --- | --- | --- |
| 1 | `mdtrt_cert_type` | 就诊凭证类型 字符型 3 Y Y |
| 2 | `mdtrt_cert_no` | 就诊凭证编号 字符型 50 Y 就诊凭证类型为"01"时填写电子凭证令牌，为"02"时填写身份证号，为"03"时填写社会保障卡卡号 |

| 5 | `psn_cert_type` | 人员证件类型 字符型 6 Y |

| 7 | `psn_name` | 人员姓名 字符型 50 |
