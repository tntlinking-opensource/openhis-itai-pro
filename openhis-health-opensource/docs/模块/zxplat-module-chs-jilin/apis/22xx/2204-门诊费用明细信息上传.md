## 接口说明

#### 交易说明

通过此交易上传门诊费用明细信息。

#### 重点说明

1、交易输入费用明细为多行数据，交易输出为多行数据；

2、同一收费批次的费用明细，应一次全部上传，一次可以上传多个收费批次；

3、医院审批标志，配合目录的限制使用标志使用（目前吉林省不启用）：

> a). 当目录限制使用标志为"是"时:
>
> i\) 医院审批标志为"0"或"2"时，明细按照自费处理；
>
> ii\) 医院审批标志为"1"时，明细按纳入报销处理。
>
> b). 当目录限制使用标志为"否"时:
>
> i\) 医院审批标志为"0"或"1"时，明细按照实际情况处理；
>
> ii\) 医院审批标志为"2"时，明细按照自费处理。

4、电子处方相关

电子处方处方号必须从电子处方中台获取，定点医药机构在使用时，需要将电子处方号填入到【rxno处方号】参数中，通过【rxno处方号】上传给医保系统。电子处方中台接入请联系XXX。

【rxno处方号】参数有值时，医保系统将默认为其为电子处方。

【rxno处方号】参数无值时，医保系统将默认此明细为非电子处方。

【rxno处方号】参数需要HIS准确使用，使用不当可能会导致无法结算。

【rx_circ_flag 外购处方标志】需要准确填写。

综上，如药店，医院将非电子处方的处方号信息录入【rxno处方号】参数中，将无法进行正常结算，撤销结算

#### 交易对象

交易发送方：医药机构。

交易接收方：地方医保局。

## ZXPlat 实现注记（院内组装）

> 以下非国家规范原文，描述 `zxplat-module-chs-jilin` 对 2204 的组装口径。

| 场景 | 行为 |
| --- | --- |
| 非套餐 ChargeItem | 一行 → 一条 `feedetail`；`feedetl_sn` = `busNo` 或 id |
| 诊疗套餐（有 `wkf_activity_definition_children`） | 父 Charge **一对多**展开为子项行；**不上传父项**（父项通常无 `yb_no`） |
| 子项 `cnt` | 父数量 × `children_num` |
| 子项 `pric` / 金额 | 子项目录 SALE；各子项金额之和须等于父 `totalPrice` |
| 子项 `feedetl_sn` | `{父feedetlSn}.{序号}`（如 `CI….01`，≤30；禁止拼雪花 childrenId） |
| 代码入口 | `ChsOutpatientInsuranceContextLoader` → `ChsActivityPackageFeeExpandSupport` |
