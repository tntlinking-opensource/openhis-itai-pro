## 1. 背景与问题

局端会不定期下发「药品 / 服务 / F 服务 / 耗材 / 中药配方颗粒 / 饮片 / 制剂」等 **数据更新目录 Excel**。医院目前主要依赖 **13xx 平台目录下载** 维护 `yb_national_catalog_item` 镜像。

已核实缺口（以医疗服务 2026.5.19 通知为例）：

| 通知动作 | 与 1305 镜像关系 | 影响 |
|----------|------------------|------|
| 变更 | 部分文本/属性可随版本包更新 | 可用下载补齐，仍须留审计 |
| 停用 | 编码多已在镜像，但 `vali_flag`/`enddate` **未必**体现通知终止日 | 院内仍可对码、开单 → **合规风险** |
| 新增 | 服务类常见「项目代码 01\*」与国家码「003\*」双码；新增码 **不一定**已进 13xx | 无法选码建院内项 → **业务缺口** |

因此：仅「把目录下新」不够；需要把 **局发通知文件** 结构化入库，并驱动 **校验、补字段、可用状态、首页催办**。

## 2. 目标（本期承诺）

| # | 目标 | 用户价值 |
|---|------|----------|
| **T1** | 医保目录（13xx）导入/下载入库时，对照已导入的「医保文件」做 **合规校验**，并 **补齐镜像不足字段** | 平台包缺字段、缺终止日时可被通知补全；违规码可见 |
| **T2** | 通知「新增」可 **完善医保目录镜像可用状态**（及必要字段），使后续选码/对码可用 | 不必等平台包永远「刚好含本批新增」 |
| **T3** | 通知「停用」首页告知，且已生效停用码对院内已对码项 **硬阻断开单与费用上传** | 停用窗口内无法继续走医保结算 |
| **T4** | 医保管理内提供 **医保文件管理**：院外洗到约定目录后 **重新扫描 + 二次确认入库**（不提供手工上传）；库内文件/明细可查 → 支持 T1～T3、T5 | 一套入口完成「来文—入账—生效」 |
| **T5** | 支持 **支付对照类通知**；与院内/费用 `chrgitm_lv` 不一致时 **硬阻断开单与费用上传** | 错等级不可走医保结算 |
| **T6** | 从目录更新通知解析 **定价上限**；合成限价后 **直接阻断开单与费用上传**（不超限） | 超限不可走医保结算链路 |

**说明（T5）：** 「甲/乙」是支付类别（`chrgitm_lv`），**不是**限价金额。  
**说明（T6）：** 限价权威列在 **`CATALOG_DELTA`** 通知的「医保目录定价上限金额」「医保目录超限处理方式」（对应平台字段 `hilist_pric_uplmt_amt` / `overlmt_dspo_way`）。  
「25 号新医保码 / 纯支付对照」类文件 **通常没有金额列**，只能管甲乙类与计价说明中的计次规则，**不能单独保证限价**。

**非目标（本期不做，评审可打回）：**

- 不替代 13xx/9102 官方版本链（通知不是第二套下载游标）。  
- 不自动静默改写院内 MD/AD/DD/CD 的 `yb_no`（须待办确认）。  
- 不一期自动执行 3302 全量撤销（可做待办+一键，默认人工确认）。  
- **不**在产品内实现 `.et` / 损坏包等畸形解析器；一律经 **院外人工或 AI 洗数 → §6.0 标准落地包** 后再导入（一期 **不做**产品内「转标准包」助手）。

## 3. 概念与边界

### 3.1 「医保文件」

**医保文件** = 局端下发的一则（或一批）可归档目录/支付相关附件，经系统导入后形成：

1. **文件头（Document）**：来源文件、**文件种类 `doc_kind`**、品类、发文/生效日期、导入人、解析状态；  
2. **结构化明细（Lines）**：按动作拆行；  
3. **应用结果（Apply）**：对镜像 overlay、院内等级待办、费用校验的生效记录。

| doc_kind | 典型附件 | 核心动作 |
|----------|----------|----------|
| `CATALOG_DELTA` | 药品/服务/耗材「数据更新目录」 | `ADD` / `STOP` / `MODIFY` / `PROVINCE_MODIFY` |
| `PAYMENT_MAP` | 「医疗服务价格项目规范 **医保支付对照**」结果表 | `SET_PAY_CLASS`（项目编码 → 甲/乙） |

> 界面可统称「医保文件」；列表用种类区分「目录更新 / 支付对照」。

### 3.2 「医保目录」在本方案中的含义

| 层 | 存储 | 职责 |
|----|------|------|
| **国家目录镜像** | `yb_national_catalog_item`（已有） | 选码池、对码主数据、结算校验底座 |
| **医保文件明细** | 新建 `yb_catalog_notice_*` | 局文权威差异与补字段来源 |
| **院内目录** | MD/AD/DD/CD + CID | HIS 可开项；本期以「告警/待办」衔接，创建门禁见后续迭代 |

本方案 **直接改写** 的主要是 **国家目录镜像的可用性与补字段**；不静默改院内 `yb_no`。  
已生效 **STOP** 对已对码项：**硬阻断开单/上传**（T3）；3302 撤销仍走待办确认。

### 3.3 与目录下载（CAT-002）的关系

```text
                ┌─────────────────────┐
  13xx/9102 ───►│ yb_national_catalog │◄─── 医保文件「应用」补字段/可用状态
                │      _item 镜像      │
                └──────────▲──────────┘
                           │ 合校验（下载入库钩子 / 定时 / 手动重验）
                ┌──────────┴──────────┐
  Excel 导入 ──►│ 文件头 + 明细行     │───► 首页停用告警 / 待办
                └─────────────────────┘
```

- **下载链路**：入库前后可触发「对照最新已生效医保文件」的校验与补齐（T1）。  
- **文件管理链路**：导入并确认应用后，更新镜像可用状态与字段（T2），发布停用告警（T3）。

## 6. 导入契约：标准落地包（主路径）+ 局发 xlsx（辅路径）

> **产品原则**：业务引擎只依赖稳定结构（与 `yb_catalog_notice_line` 对齐）。局发原件多变甚至损坏时，**先洗成标准落地包，再导入**——不必在产品里穷举每一种畸形。

### 6.0 标准落地包（Canonical Intake · **系统主契约**）

#### 6.0.1 包结构

一个医保文件对应一个目录（或同名前缀的两个文件）：

```text
{任意名}/
  notice.meta.json     # 文件头
  notice.lines.csv     # 明细（UTF-8，建议带 BOM 以便 Excel 打开）
```

样例见：`医保文件-标准落地格式/`。

#### 6.0.2 `notice.meta.json`

| 字段 | 必填 | 说明 |
|------|------|------|
| doc_kind | 是 | `CATALOG_DELTA`（目录增减废） / `PAYMENT_MAP`（支付对照） |
| category | 是 | `DRUG` / `SERVICE` / `SERVICE_F` / `DEVICE` / `FORMULA` / `HERBAL` / `PREP` / `OTHER` |
| title | 否 | 展示标题；默认用 `source_filename` |
| source_filename | 是 | 局发原文件名（审计用） |
| notice_date | 否 | `yyyy-MM-dd`，从文件名解析或手填 |
| effective_date | 否 | 默认生效日；行级日期优先 |
| wash_note | 否 | 洗数说明：谁转的、原格式（`.et`/损坏 xlsx/对照表等） |
| wash_tool | 否 | 如 `cursor-ai` / `manual` |

#### 6.0.3 `notice.lines.csv` 固定列（列名不可改；顺序可任意）

| 列名 | 必填规则 | 说明 |
|------|----------|------|
| action | 是 | `ADD` / `STOP` / `MODIFY` / `PROVINCE_MODIFY` / **`SET_PAY_CLASS`** |
| hilist_code | STOP/MODIFY/PROVINCE_MODIFY 必填；ADD 按品类 | 国家/医疗目录编码（药/耗材/服务停变等） |
| project_code | SERVICE\* 的 ADD、**全部 SET_PAY_CLASS** 必填 | 物价/项目代码（`01*`）；**禁止**填进 hilist_code |
| hilist_name | 建议填 | 名称 |
| begin_date | 否 | `yyyy-MM-dd` |
| end_date | 否 | `yyyy-MM-dd`；STOP 强烈建议有值 |
| change_fields | MODIFY 建议填 | 原「本期变更/本次变更」 |
| chrgitm_lv | SET_PAY_CLASS 必填；其它可选 | 国标：`1`/`2`/`3`（甲/乙/自费） |
| list_type | 否 | `101`/`201`/`301`…；空则按 category 推断 |
| source_sheet | 否 | 原 Sheet 名（追溯） |
| source_row | 否 | 原行号（追溯） |
| ext_json | 否 | 其余原列 JSON 对象字符串（整行扩展，防丢列） |

**行合法底线：**

- `action` ∈ 枚举，且与 `doc_kind` 匹配（`PAYMENT_MAP` 仅允许 `SET_PAY_CLASS`；`CATALOG_DELTA` 不允许该动作）；  
- 行上至少有一个合法键：`project_code` 或 `hilist_code`（ADD/STOP/MODIFY 两种键都允许，由**码的性质**决定列，不按动作锁死）；  
- `SET_PAY_CLASS` → `project_code` + `chrgitm_lv` 非空；中文/「未赋码」不当编码，**跳过该行**；  
- 日期非法 → 该行警告仍可入 `PARTIAL`。

#### 6.0.3a 语义必填（列名对齐不够）

产品扫描/应用按下列分档，**不自动补前导 0、不改写码形**。

| # | 约定 | 违规分档 |
|---|------|----------|
| S1 | 文件级 `notice_date`、`effective_date` **至少一个**（可排序业务日） | 可入库 `PARTIAL`；**禁止应用** |
| S2 | 物价码（`01*` 可带后缀、`37*`）只进 `project_code`；医保目录码只进 `hilist_code`；禁止对调、禁止汉字当码 | 物价码误入 hilist 且 project 空：解析时**挪列**并警告；脏码：**跳行**；project 已有值则警告不改写 |
| S3 | 有名称必须落到 `hilist_name`（可从 ext `医疗服务项目名称` 提升）；限价/限制标志写入行字段或 ext **固定键**（`医保目录定价上限金额`、`限制使用标志`、`限制使用范围`、`医保目录超限处理方式`） | 空名称行级警告；不因此 FAILED |
| S4 | 后文 ADD **不得复活**已停 overlay；支付对照不插影子国家码 | 引擎硬约束 |
| S5 | 分档 | **挡应用**：缺业务日。**跳行**：脏码/无主键。不要因 1 行废整包 |

`01*` 未映射国家码时仍走 `PENDING_MAP`（BR-08，不伪造 hilist），但 STOP/MODIFY 若仅有物价码且已映射，则改对应 overlay。

**支付对照原文 → 标准列映射（本类附件）：**

| 原列 | 标准列 |
|------|--------|
| 项目编码 | `project_code`（trim；勿写入 hilist） |
| 项目名称 | `hilist_name` |
| 映射对照支付类别 `甲`/`乙`（偶见自费） | `chrgitm_lv` ← `甲→1` / `乙→2` / `自费→3` |
| Sheet 名（放射检查…） | `source_sheet` |
| — | `action=SET_PAY_CLASS`，`doc_kind=PAYMENT_MAP`，`category=SERVICE` |

#### 6.0.4 双通道与职责分工

**已决断（洗数位置）：** 一期洗数仅在 **院外**（Cursor/人工按 §6.0.5）；产品 **不提供**「上传原件一键转标准包」。产品入口只吃标准落地包 + 可解析的常规目录 xlsx。

### 6.1 局发 xlsx 辅路径 · 文件级要求

> 样本依据：`目录更新通知/` 常规 xlsx。兼容「Sheet 名带行数后缀」；**禁止**要求医院改模板。  
> `.et` / 非 zip 伪 xlsx / 无标准动作 Sheet → **不硬解析**，引导产出 §6.0 标准包。

| # | 要求 | 说明 |
|---|------|------|
| F1 | 格式 | 辅路径只吃合法 **`.xlsx`**；其它格式拒收并提示「请洗成标准落地包」 |
| F2 | 工作簿 | 至少一个可读 worksheet；无宏依赖 |
| F3 | 表头 | **每个业务 Sheet 第 1 行（或首个非空行）为中文列表头**；数据从下一行起 |
| F4 | 空行 | 整行主键列为空则跳过；不因此失败 |
| F5 | 编码 | 单元格按 Excel 本地值读取；日期可为 `datetime` 或可解析文本 |
| F6 | 大小 | 建议单文件 ≤ 50MB；超过走异步解析（进度条） |
| F7 | 去重 | 按文件 SHA-256；相同内容拒绝重复导入（可强制重导生成新 doc） |

**不要求**：固定 Sheet 英文名、固定列序（按**表头名**匹配）、医院改名列、去掉 Sheet 名中的数字后缀。

### 6.2 品类识别（category）

导入时可自动推测，**预览页必须允许用户改定**：

| category | 文件名关键词（任一命中，优先级自上而下） | 默认 list_type |
|----------|------------------------------------------|----------------|
| SERVICE_F | `F服务` | 201 |
| SERVICE | `服务目录`、`医疗服务`、`诊疗目录`（且非 F服务） | 201 |
| DEVICE | `耗材` | 301 |
| FORMULA | `配方颗粒` | 见平台约定 |
| HERBAL | `饮片` | 饮片类 |
| PREP | `制剂` | 制剂类 |
| DRUG | `药品`、或文件名含 `X001_` / `Y20` 药品版式 | 101 |
| OTHER | 未识别 | 用户必选后方可入库 |

**已决断（一期品类一次做全）：**  
`DRUG` / `SERVICE` / `SERVICE_F` / `DEVICE` / `FORMULA` / `HERBAL` / `PREP` 均可导入并支持应用（含制剂；院内制剂变更类 Sheet 洗入标准包后同样可应用）。

### 6.3 Sheet 识别（action）

对每个 worksheet，用 **Sheet 名去掉首尾空格后做前缀匹配**（忽略大小写）：

| Sheet 名前缀 | action | 备注 |
|--------------|--------|------|
| `新增` | `ADD` | 如 `新增533`、`新增1087`、`新增对照表4062` → 均识别为新增 |
| `停用` | `STOP` | 如 `停用1295` |
| `变更` / `省变更` | `MODIFY` / `PROVINCE_MODIFY` | 如 `变更`、`变更2`、`变更7178`、`省变更17` |
| 其他（如「放射检查」「院内制剂变更」） | `UNKNOWN` 或专用适配 | 一期：整表进 `payload`，不进标准应用；或人工指定动作 |

同一文件可含多个动作 Sheet，全部解析进同一 `doc_id`。

### 6.5 解析算法（伪代码）

```text
function parseWorkbook(file, categoryHint):
  category = detectCategory(file.name) or categoryHint   // 可被 UI 覆盖
  doc = new NoticeDoc(file, category)
  for sheet in workbook.sheets:
    action = matchActionBySheetName(sheet.name)
    if action is null:
      mark sheet SKIPPED_UNKNOWN; continue
    headerRow = firstNonEmptyRow(sheet)
    colMap = mapHeaders(headerRow, category, action)   // 别名表
    if not colMap.hasRequiredKey(action, category):
      fail sheet with CLEAR_ERROR  // 缺主键列表头
      continue
    for (r, row) in dataRows(sheet):
      line = buildLine(row, colMap, action, category)
      line.payload_json = allColumnsAsJson(row, headerRow)
      if line.primaryKeyBlank: skip
      elif not line.primaryKeyValid: line.apply_hint = FAILED; warn
      else lines.add(line)
  return preview(doc, lines, warnings)
```

**日期规范化：**

- Excel 日期序列 / `yyyy-MM-dd[ HH:mm:ss]` → `LocalDate`；  
- 空终止日 → `end_date=null`（表示未停用）；  
- 非法日期 → 行警告，不阻断整文件。

**编码规范化：**

- `trim`；保留原文（含括号如 `...(z)`），**不做**擅自截断；  
- 服务 ADD 的 `项目代码` 不得写入 `hilist_code`。

### 6.6 解析结果状态

| 状态 | 含义 |
|------|------|
| PARSED | 全部业务 Sheet 解析成功 |
| PARTIAL | 部分 Sheet/行失败，其余可入库 |
| PARSE_FAILED | 无任何有效行或文件损坏 |

预览页必须展示：各动作行数、样例 5 行、失败行原因、品类/生效日（可编辑后确认入库）。

### 6.7 医院侧「合格文件」检查清单（给业务培训）

**优先路径（推荐）：** 洗成 §6.0 标准落地包再导入——任何原格式都适用。

**辅路径（常规 xlsx 直传）：**

1. 使用局方下发的 **合法 xlsx 原件**；`.et`/打不开的包 → 走标准落地包，勿硬传。  
2. 不要删除表头行，不要合并主键列单元格。  
3. 不要把「新增 / 停用 / 变更」数据混在一个未命名 Sheet 且改掉表头关键字。  
4. Sheet 名可带数量（如 `停用1295`），**无需改名**。  
5. 服务类：新增看 **项目代码**，停用/变更看 **国家目录编码**——勿对调。

## 7. 业务流程

### 7.1 导入医保文件（结构化入库）

```text
上传标准落地包（meta.json + lines.csv）     ← 主路径
  或 上传常规 xlsx（§6.1 辅路径）
  → 校验与解析预览
  → 用户确认品类 / 生效日
  → 落 doc + lines（PARSED / PARTIAL）
  → （可选）立即进入「应用」
```

### 7.2 应用医保文件 → 完善医保目录（T2 + 停用态）

用户在「差异应用」确认后（**只写 overlay，不改平台镜像主列**）：

| action | 对 overlay / 院内的动作 |
|--------|-------------------------|
| **STOP** | `notice_avali_flag=0`，`notice_end_date=行终止日`；镜像无码 → `match_status=MISS` 仍可落 overlay 告警 |
| **ADD** | 有 `hilist_code`：overlay 标记可用并写入 patch；仅有 `project_code`：写映射/待映射告警（§8.2），**不**伪造 hilist |
| **MODIFY** | 合并 `notice_patch_json`（通知非空覆盖 patch 内同名字段） |
| **SET_PAY_CLASS** | 见 **§7.5**（支付对照专用） |

应用完成后：`doc.apply_status=APPLIED`，写 `apply_log`（target 指向 overlay 或院内项）。

### 7.3 目录下载时的合规校验与补齐（T1）

**触发点：**

1. CAT-002 某一版本 TXT **入库成功后**自动跑（按 list_type）；  
2. 用户在医保文件管理 / 目录下载页点 **「再次执行校验」**（手动重验，必做能力）；  
3. 定时任务（日切，对齐生效日）可选。

**已决断（下载侧）：** 校验结果 **不阻断下载成功**；数据照常入库、游标照常推进；仅产出校验报告/告警（含 C-STOP-LAG 等高危项）。开单/上传硬阻断仍由 T3/T5/T6 运行时门禁负责，与下载是否成功解耦。

**校验输出：**

| 检查项 | 说明 |
|--------|------|
| C-STOP-LAG | 医保文件已声明停用且已到生效日，但平台行仍显示可用（下载侧告警） |
| C-STOP-ACTIVE | 已生效 STOP 命中医保开单/上传行 → **硬阻断**（已决断） |
| C-ADD-MISS | 文件新增国家码在最新镜像仍不存在 |
| C-FIELD-GAP | 文件有等级/限价/终止日等，镜像对应字段空或占位（如 enddate=`0001-01-01`） |
| C-PAY-CLASS | `PAYMENT_MAP` 已生效且 `chrgitm_lv` 不一致 → **硬阻断开单/上传**（已决断） |
| C-PRICE-OVER | 单价超过合成限价；**硬阻断开单/上传**（已决断） |
| C-PRICE-UNKNOWN | 通知/镜像均无限价；**已决断：允许**开单/上传，仅抽查标记 |
| C-PROJECT-UNMAPPED | 服务项仅有 `01*`、无国家码映射 → **硬阻断医保开单/上传**（已决断；可自费建项展示） |

**补齐策略（仅 overlay）：**

- 用 notice_line 非空字段填充 `notice_patch_json` / `notice_end_date`；  
- **不**用空值覆盖已有 patch/平台非空展示优先级见 §8；  
- 停用类：默认以通知生效日限制 `isSelectable`（可配置）。

### 7.4 停用告知与硬阻断（T3）

**已决断：** 停用已生效（命中院内已对码）→ **硬阻断开单 + 硬阻断费用上传**（与 T6 同口径），不仅首页催办。

**生效判定：** `current_date >= coalesce(line.end_date, doc.effective_date)`；提前 N 天仅预警（可开单），到日开始硬阻断。

**首页 / 待办展示条件：**

1. 存在已应用 `action=STOP` 且临近或已生效；  
2. `hilist_code` 命中院内已对码（MD/AD/DD 的 `yb_no`，或 CD）；  
3. 待办未关闭（已换码 / 已 3302 / 确认例外——例外默认不允许绕过硬阻断，除非显式「合规例外」权限，一期可不做例外）。

**硬阻断口径：**

```text
医保结算行命中已生效 STOP overlay/通知
  → 拒绝开单/计费落库
  → 2204/2301 上传拒绝（C-STOP-ACTIVE）
提示：编码、停用日、来源医保文件、关联院内项目
```

**首页文案示例：**

> 有 **128** 条局发停用目录已生效（或将于 3 日内生效），其中 **36** 条仍关联院内可开项目；已生效项已禁止医保开单/上传，请尽快换码或 3302。

列表字段：编码、名称、生效日、关联院内项目数、来源医保文件、是否已硬阻断、处理状态。

### 7.5 应用支付对照（T5 · `SET_PAY_CLASS`）

**匹配顺序（任一命中即可，记 match_status）：**

1. 院内诊疗/耗材/药品：`yb_no = project_code`（支付对照原文多为 **01\*** 物价码）；  
2. 存在 `yb_service_project_map`：`project_code → hilist_code` 后再对镜像 / 院内 `yb_no`；  
3. 国家目录镜像：`hilist_code` 或 `raw_json` 含该项目码（命中则写 overlay）。

**应用动作（确认后）：**

| 目标 | 动作 |
|------|------|
| overlay | `notice_patch_json.chrgitm_lv = 行值`；键为已解析到的 `hilist_code`（若仅有项目码则先落 map 再补） |
| 院内已对码项 | **确认应用时直接改写** AD/MD/DD（及对应对码）的 `chrgitm_lv`；写 `apply_log` + 修改痕迹（见下） |
| 费用组装/开单 | 改写后应以通知等级为准；若仍不一致（竞态）则 **C-PAY-CLASS 硬阻断** |

**已决断：**

1. 甲乙类不一致 → **硬阻断开单 + 上传**（与 T3/T6 同口径）。  
2. 应用支付对照时 **直接回写院内 `chrgitm_lv`**（非仅待办），**必须保留修改痕迹**。  
3. **开单未收费**（小概率，已决断 **B**）：  
   - 痕迹须 **标注**影响到的收费单（单据号/ID、就诊、明细行）；  
   - 并 **同步改写**这些未收费明细上的 `chrgitm_lv`（与目录回写同一 `after` 值）；  
   - **已收费**单据明细 **不改**（冲正另议，本期不做）。

**修改痕迹最低字段（`apply_log` 或专用 audit）：**

| 字段 | 说明 |
|------|------|
| before_chrgitm_lv / after_chrgitm_lv | 目录项改前改后 |
| target_table / target_id | 院内目录项 |
| notice_doc_id / line_id | 来源对照 |
| operator_id / operated_at | 操作人时间 |
| affected_charge_bills_json | **未收费单据清单**（含同步改写结果）：`[{billId, billNo, encounterId, itemLineId, before, after}]`；无则 `[]` |

**不做：** 不因支付对照把项目标成停用；不改 HIS 零售价；不静默改已收费历史明细的甲乙类。

首页「支付类别不一致」：回写成功后应清空；若仍有未回写冲突项则继续展示硬阻断。一期不做「确认例外绕过」。

### 7.6 限价落地（T6 · 不超过定价上限）

**数据来源（必须有金额，才谈限价）：**

| 来源 | 能否管限价 |
|------|------------|
| `CATALOG_DELTA` 行含「医保目录定价上限金额」 | **能**（主路径；实测服务新增几乎行行有值，药品部分有值） |
| 13xx 镜像 `raw_json` / 若有结构化上限字段 | 能（与通知合成，通知非空优先写入 overlay） |
| `PAYMENT_MAP` / 「25 号新医保码」 | **不能**（无金额；最多解析计价说明里的计次上限，属数量规则） |

**标准包映射：** `医保目录定价上限金额` → `price_limit_amt`；`医保目录超限处理方式` → `overlmt_dspo_way`；应用时写入  
`overlay.notice_patch_json.hilist_pric_uplmt_amt` / `.overlmt_dspo_way`。

**已决断（强硬门禁）：** 存在有效合成限价且 **单价 > 限价** 时 → **直接阻断开单** 与 **阻断 2204/2301 费用上传**（不走「仅告警」）。自费改走（拆自费、取消医保结算标志）须改价或去掉医保关联后才能继续。

**比较口径：** `unit_price > limit` 即超限（按计价单位单价）。数量放大后的行金额不作单独阈值，避免与「限价按单位」混淆。

**三道门禁：**

```text
① 物价/对码维护（事前，辅助）
   院内价表单价 > 合成限价 且 拟医保结算
     → 禁止保存医保可结算/对码通过（与开单同口径阻断）

② 开单/计费（事中，硬阻断）★
   医保结算行 unit_price > limit
     → 拒绝开单/计费落库，提示：编码、限价、当前单价、来源医保文件

③ 费用明细上传 2204/2301（事后硬阻断）★
   组装 pric_uplmt_amt = limit
   det 单价 > limit → C-PRICE-OVER，整批或该明细上传失败（不可静默放过）
```

**合成限价：**

```text
limit = coalesce(overlay.hilist_pric_uplmt_amt, 平台镜像上限, null)
若 limit 为空或 ≤0 → 不做金额硬阻断，允许医保开单/上传
  仍记 C-PRICE-UNKNOWN 供抽查（与「有限价必阻断」不冲突）
```

**已决断（无限价）：** `C-PRICE-UNKNOWN` **允许**照常医保开单与费用上传。

`overlmt_dspo_way` 仍入库供展示/审计；**一期不削弱硬阻断**（不以处理方式改回告警）。

**与计次说明（可选增强）：** 「单日限计费 1 小时」等属数量/频次规则，与金额限价分开（后置，不与 T6 混谈）。

## 8. 关键业务规则

### 8.1 合成「可选 / 可用」

对码搜索、目录新建选码、结算前校验统一走：

```text
isSelectable(code) =
    镜像存在
    AND 平台有效（vali_flag 与 enddate 常规规则）
    AND 通知 overlay 未标记停用或未到停用日
```

`isSelectable=false` 时 UI 不可选，并展示原因（平台停用 / 通知停用 / 未生效）。

### 8.2 服务双码（01\* 项目代码 vs 003\* 国家码）

| 数据 | 用途 |
|------|------|
| `hilist_code`（003\*…） | 3301 / 选码 / 与 1305 对齐 |
| `project_code`（01\*…） | 物价项目、通知新增主键；**禁止**当作 3301 的 med_list_codg |

**建议表** `yb_service_project_map`（可并入 line 关联）：

- `project_code` ↔ `hilist_code`（多对一或一对一，以局文对照表补齐）。

**已决断（仅项目码、无国家码映射时）：**

- **允许**建立院内物价/目录项，并 **临时展示 `project_code`（01\*）**；  
- **禁止**把 `01*` 当作 3301 `med_list_codg` / 假 hilist 写入；  
- 映射完成前：**硬阻断医保开单与费用上传**（可记 `C-PROJECT-UNMAPPED`）；自费开单是否开放由院内物价策略定，默认允许自费；  
- 映射补齐后解除医保阻断，并引导补做 3301（若业务需要）。

### 8.3 与 13xx 再次下载的优先级

| 场景 | 规则 |
|------|------|
| 平台后来写入真实 enddate/vali=0 | 以平台为准；overlay 保留审计 |
| 平台仍无终止日、通知有终止日 | overlay 继续限制可选 |
| 平台空字段、通知有值 | overlay 补齐供展示/校验 |
| 平台非空与通知冲突 | 报告冲突；停用类默认听通知生效日（配置） |

### 8.4 去重与版本

- 同 hash 默认拒绝重复导入。  
- 同编码多文件多行：以 **最新 notice_date / 最新 imported_at** 的 STOP/ADD / SET_PAY_CLASS 为准，旧文件明细标记 `SUPERSEDED`。  
- `PAYMENT_MAP` 同 `project_code` 以最新已应用文件为准（后文覆盖前文甲乙类）。

### 8.5 费用明细上传时的甲乙类（T5）

门诊/住院费用明细上传（如 2204/2301）组装 `chrgitm_lv` 时：

```text
upload.chrgitm_lv =
    coalesce(院内项通知回写值,
             overlay.notice_patch_json.chrgitm_lv,   // 由 SET_PAY_CLASS 写入
             院内项原 chrgitm_lv,
             平台镜像 chrgitm_lv)
```

若存在已生效 `PAYMENT_MAP` 行且算出的等级 ≠ 通知等级 → **C-PAY-CLASS**：**硬阻断开单与 2204/2301 上传**（已决断，与 T3/T6 同口径）。
