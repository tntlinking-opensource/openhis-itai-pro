## 1. 背景与目标

### 1.1 业务背景

52xx 属于国家基线版 **「医保服务查询」** 交易组，供定点医药机构向地方医保局 **实时查询** 人员在本机构的就诊、诊断、结算、费用明细、慢特病用药及累计信息。与 220x/230x **写侧结算**、320x **对账清算** 互补，主要用于：

| 场景 | 典型接口 | 使用者 |
|------|----------|--------|
| 核查患者历史就诊与在院状态 | 5201 | 医保办、住院收费 |
| 查看当次就诊诊断明细 | 5202 | 医保办、病案 |
| 核对平台结算金额与基金分项 | 5203 | 医保办、对账岗 |
| 核对平台费用明细与目录编码 | 5204 | 医保办、对账岗 |
| 慢特病用药记录审核 | 5205 | 医保办、门诊医生 |
| 年度/月度累计额度查询 | 5206 | 医保办、收费窗口 |

OpenHIS 遗留系统仅实现 **5205**（`openhis-application` · `YbController.yb5205SpecialDiseaseDrugRecordSearch`）。ZXPlat **chs-jilin** 需一次性补齐 **5201–5206**，并提供统一运维查询 UI。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **只读、无资金副作用** | 52xx 不调账、不写平台；失败可安全重试 |
| **不落库（Wave 1）** | 实时查平台并返回 DTO；不做本地镜像（与 1312 不同） |
| **1101 前置** | `psn_no` 优先来自读卡；允许手工录入（运维场景） |
| **主从联动 UI** | 5201 为主表；5202/5203/5204 为选中就诊的抽屉/子 Tab |
| **与 3508 查询同构** | `resolveContract` → `assemble` → `invoke` → `parseOutput` |
| **不强依赖 HIS 就诊** | Wave 1 不要求本地 `Encounter` 存在；Wave 2 可做本地对照 |

### 1.3 非目标（Wave 1）

- 5301–5304 人员备案/在院/转院查询（另开 LLD）
- 520x 结果写入本地表、与 3202 明细对账自动勾稽
- 嵌入门诊/住院收费主流程（仅独立运维页 + 可选跳转入口）
- `ChsGateway` 裸透传替代 typed API（运维页需要字典格式化与校验）

## 2. 接口全景

> 字段明细见 `apis/52xx/` 单接口文档；下表为 ZXPlat 落地摘要。

| infno | 名称 | 输入 `data` 必填 | 输出 JSON 节点 | 行/单 |
|-------|------|------------------|----------------|-------|
| **5201** | 就诊信息查询 | `psn_no`, `begntime`, `endtime`, `med_type`；`mdtrt_id` 可选 | `mdtrtinfo`（或 output 首数组） | 多行 |
| **5202** | 诊断信息查询 | `mdtrt_id`, `psn_no` | `diseinfo` | 多行 |
| **5203** | 结算信息查询 | `psn_no`, `setl_id`, `mdtrt_id` | 结算主对象 + `setldetail` | 单行 + 多行 |
| **5204** | 费用明细查询 | `psn_no`, `mdtrt_id`；`setl_id` 可选 | `feeListInfo` / `fee_list_info` | 多行 |
| **5205** | 人员慢特病用药记录查询 | `psn_no`, `begntime`；`endtime` 建议传 | `feedetail` | 多行 |
| **5206** | 人员累计信息查询 | `psn_no`；`cum_ym` 可选（yyyyMM） | `cuminfo` | 多行 |

### 2.1 调用链关系

```text
1101 读卡 → psn_no
    ↓
5201（时间范围 + med_type）→ 就诊列表 [mdtrt_id, setl_id?, ...]
    ├─→ 5202（mdtrt_id）→ 诊断列表
    ├─→ 5203（mdtrt_id + setl_id）→ 结算头 + setldetail
    └─→ 5204（mdtrt_id [+ setl_id]）→ 费用明细

5205（独立：psn_no + 时间范围）→ 慢特病用药
5206（独立：psn_no [+ cum_ym]）→ 累计信息
```

### 2.2 与其它 infno 的边界

| 对比项 | 52xx | 1312 | 3202 |
|--------|------|------|------|
| 数据范围 | 本机构人员就诊/结算 | 国家医保目录 | 本机构结算对账文件 |
| 持久化 | Wave 1 无 | `yb_national_catalog_item` | `yb_recon_detail` |
| 触发 | 人工查询 | 选码/补库 | 3201 不平后 |

### 4.3 Response 策略

**Wave 1 推荐**：强类型 DTO 覆盖 UI 常用列 + `ChsMedicalInfoOutputParser` 统一解析；解析器对 output 键名做 **snake_case / 首数组** 兼容（参照 `ChsInventoryAppService.parsePlatformQueryRows`）。

| Response | 结构 |
|----------|------|
| `Mdtrt5201RowDto` | 5201 单行（`mdtrtId`, `psnName`, `medType`, `begntime`, `endtime`, `inhospStas`, `dscgMaindiagName`, …） |
| `Dise5202RowDto` | 5202 单行（`diagCode`, `diagName`, `maindiagFlag`, `diagTime`, …） |
| `Setl5203Result` | `Setl5203HeaderDto header` + `List<SetlDetail5203RowDto> setlDetails` |
| `Fee5204RowDto` | 5204 单行（`hilistCode`, `hilistName`, `detItemFeeSumamt`, `chrgitmLv`, …） |
| `OpspDrug5205RowDto` | 5205 单行 |
| `Cum5206RowDto` | 5206 单行（`cumTypeCode`, `cum`, `insutype`, `year`, `cumYm`） |

**5203 解析要点**（规范：结算信息单行 + 基金分项多行）：

```java
// output 示例结构（键名以吉林联调为准，Parser 需兼容）

  "setl_id": "...",
  "medfee_sumamt": 123.45,

  "setldetail": [ { "fund_pay_type": "...", "fund_payamt": ... } ]

```

**数组节点解析优先级**（`ChsMedicalInfoOutputParser`）：

| infno | 优先键 | 回退 |

| 5201 | `mdtrtinfo` | output 下首个 JSONArray |

## 5. AppService 实现要点

### 5.1 `ChsMedicalInfoQueryAppService`

每个方法统一模板：

```text
1. validate(request)           // psn_no、日期、med_type 等
2. ContractContext ctx = resolveContract(contractBusNo, contractId)
3. JSONObject input = ChsMedicalInfoPlatformAssembler.assemble520x(request, ctx)
4. ResultBody body = gatewayClient.invoke(ctx.busNo(), ChsInfNo.XXX, input, buildInvokeContext())
5. ChsPlatformResultSupport.requireSuccess(body, infno)
6. return ChsMedicalInfoOutputParser.parse520x(body)
```

### 5.2 `ChsInfNo` 补充

### 5.3 Assembler 示例（5201）

```java
public static JSONObject assemble5201(QueryMdtrt5201Request req) {
    JSONObject data = new JSONObject();
    data.put("psn_no", req.getPsnNo());
    data.put("begntime", ChsTextSupport.formatDateTime(req.getBegntime()));
    data.put("endtime", ChsTextSupport.formatDateTime(req.getEndtime()));
    data.put("med_type", StringUtils.defaultIfBlank(req.getMedType(), "11"));
    if (StringUtils.isNotBlank(req.getMdtrtId())) {
        data.put("mdtrt_id", req.getMdtrtId());
    }
    JSONObject input = new JSONObject();
    input.put("data", data);
    return input;
}
```

### 5.4 校验规则

| 规则 ID | 说明 |
|---------|------|
| BR-MIQ-001 | `psn_no` 非空 |
| BR-MIQ-002 | 5201/5205：`begntime <= endtime` |
| BR-MIQ-003 | 5201/5205：查询跨度 ≤ `zxplat.chs.medical-info-query.max-range-days`（默认 **92** 天） |
| BR-MIQ-004 | 5201：`med_type` 非空 |
| BR-MIQ-005 | 5202/5203/5204：`mdtrt_id` 非空 |
| BR-MIQ-006 | 5203：`setl_id` 非空 |
| BR-MIQ-007 | 5206：`cum_ym` 若传则匹配 `^\d{6}$` |

### 7.3 交互说明

| 交互 | 行为 |
|------|------|
| 读卡 | 调 `POST /api/app/insurancePerson/getPersonInfo`；回填 `psnNo`、姓名、险种 |
| 签到 | 查询前 `ensureInsuranceSignIn(contractBusNo)`（与 national-catalog / reconciliation 一致） |
| 5201 查询 | 默认 `med_type=11`（门诊）；住院场景可切 `21` |
| 行操作「详情」 | 并行或串行请求 5202 + 5203（需 `setl_id`，若 5201 行无则提示仅查 5202/5204） |
| 5203 基金分项 | `setldetail` 用 `ElTable` 展示；头部用 `ElDescriptions` |
| 5204 费用明细 | 支持导出 CSV（前端）；字典列用 `formatMedType` / `formatChrgitmLv` |
| 5205 | 独立 Tab；默认近 90 天 |
| 5206 | 独立 Tab；`cum_ym` 可选月份选择器（`YYYY-MM` → 传 `yyyyMM`） |
| 空结果 | `ElAlert` 提示，区分平台无数据 vs 参数错误 |

## 9. 错误处理

| 场景 | 策略 |
|------|------|
| 平台 `infcode != 0` | `BusinessException(PLATFORM_FAILED, infno + err_msg)` |
| 未签到 | UI 层 `ensureInsuranceSignIn` 拦截 |
| `psn_no` 空 | `CONTRACT_INVALID` / 前端表单校验 |
| 5203 无 `setldetail` | 仍返回 header；分项表空 |
| output 键名与规范不一致 | Parser 多键回退；单元测试覆盖吉林样例报文 |
| remote 模式 | `ChsMedicalInfoQueryOperationsRemoteClientImpl` 与 inventory 同构 |

## 10. 分 Wave 实施

| Wave | 交付 | 验收 |
|------|------|------|
| **I** | 5201 + 5202 + Bridge + UI 就诊 Tab + 诊断 Drawer | 读卡后查门诊就诊 ≥1 条；5202 有诊断 |
| **II** | 5203 + 5204 + UI 结算/费用子 Tab | 选中有 `setl_id` 的就诊，5203 金额与 2207 一致；5204 明细可展开 |
| **III** | 5205 + 5206 + 独立 Tab | 慢特病用药有记录；5206 累计有数据 |
| **IV** | 查询审计表 + 3202 跳转 + 本地 mdtrt 对照 | 可选 |

**建议编码顺序**：domain DTO → Parser 单测（样例 JSON）→ AppService → adapter → UI Tab1 → Tab2/3。
