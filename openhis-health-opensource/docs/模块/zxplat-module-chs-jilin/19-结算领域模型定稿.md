## 1. 设计原则

1. **以平台语义为骨、HIS 语义为皮**  
   国家规范的自然边界是 `mdtrt_id` → `chrg_bchno`（门诊）/ `feedetl_sn`（明细）→ `setl_id`（凭证）。  
   HIS 的 `payment_draft_id` 是收银草稿，**一对多**映射到平台 `chrg_bchno`，不得反向绑架平台模型。

2. **报价与凭证分离**  
   - **报价（Quote）**：2206/2303 的 `setlinfo` + `setldetail`，无 `setl_id`，可作废重算。  
   - **凭证（Voucher）**：2207/2304 产出 `setl_id`，不可变；2208/2305 产生**反向凭证**，不删除原凭证。

3. **报文审计与业务快照分离**  
   - `yb_invoke_log`：全 infno request/response（V12 增 `infname`、`err_msg`；失败记录 `REQUIRES_NEW` 落库），`msgid` 可关联 2601 冲正。  
   - 业务表：结构化字段 + 必要 JSON（`fund_breakdown_json`、`exp_content`）。

4. **不做协同单（Wave 1 定稿）**  
   编排聚合根为 **`InsuranceSettlementSession`（HIS 收银束）**，内含 N 个 **`ChargeBatch`（平台收费批次）**；不引入 `yb_coordination`。

5. **health 管钱、CHS 管证**  
   - CHS：`setl_id`、基金分项、2204 分割结果、撤销回执。  
   - health：`fin_payment_rec_detail`（`INSURANCE_FUND` / `INSURANCE_ACCT` / 现金）。

## 2. 平台身份键（规范 §2204/2206/2207）

| 键 | 规范含义 | 唯一范围 | ZXPlat 值对象 |
|----|----------|----------|--------------|
| `mdtrt_id` | 就诊 ID | 人员一次就诊 | `PlatformMdtrtId` |
| `chrg_bchno` | 收费批次号 | 同一批次 **病种编号必须一致** | `ChrgBchno` |
| `feedetl_sn` | 费用明细流水号 | **单次就诊内唯一** | `FeedetlSn` |
| `setl_id` | 结算 ID | 全局（2207/2304 产出） | `PlatformSetlId` |
| `medins_setl_id` | 医药机构结算 ID | 存放 **发送方 msgid** | 关联 `yb_invoke_log.msgid` |
| `msgid` | 发送方报文 ID | 每次 invoke 唯一 | 2601 冲正 `omsgid` |

**混合结算分组键（修订）**：  
规范强制按 **`chrg_bchno`** 分批上传/预结算/正式结算；HIS 侧 `account_id + med_type` 分组后，**每组生成独立 `chrg_bchno`**，而非仅用 account 分组。

## 3. 门诊交易链与领域对象

### 3.1 规范链路

```text
2203 就诊上传（mdtrt_id + med_type + dise_codg + diseinfo[]）
  ↓
2204 费用上传（feedetail[]，按 chrg_bchno 分批；同批须一次传完）
  ↓ 输出 result[]：分割/等级/自付比例（须落库）
2206 预结算（data，含 chrg_bchno + medfee_sumamt）
  ↓ 输出 setlinfo + setldetail[]
2207 正式结算（data，透传 2206 四个金额字段 + 可选 invono/追溯码数量）
  ↓ 输出 setlinfo（含 setl_id）+ setldetail[]
2208 撤销（setl_id + mdtrt_id + psn_no）→ 输出反向 setlinfo + setldetail[]

2205 费用撤销（mdtrt_id + chrg_bchno + psn_no；0000=删全部未结算明细）
2601 冲正（psn_no + omsgid + oinfno；可冲 2207/2208）
```

### 3.2 聚合结构

```text
InsuranceSettlementSession（HIS 聚合根，health 侧编排）
  paymentDraftId, encounterId, composition: MIXED|INSURANCE_ONLY|SELF_PAY_ONLY
  │
  └── ChargeBatch[]（CHS 子聚合，按 chrg_bchno）
        contractId, accountId, medType, diseCodg, chrgBchno, mdtrtId, psnNo
        │
        ├── VisitUploadSnapshot      ← 2203 业务字段（非全报文）
        ├── FeeDetailLine[]          ← 2204 行 + 平台分割结果（新增 yb_clinic_fee_upload）
        ├── PreSettleQuote           ← yb_clinic_pre_settle（2206 结构化 + setldetail）
        ├── SettlementVoucher        ← yb_settlement_record（2207，setl_id UK）
        │     └── FundPayLine[]      ← yb_settlement_fund_detail
        └── SettlementReversal[]     ← 2208 反向凭证（新增，见 §5.3）
```

### 3.3 金额恒等式（规范 §2206 重点说明）

领域层必须可校验：

```text
medfee_sumamt ≈ fund_pay_sumamt + psn_part_amt + hosp_part_amt
fund_pay_sumamt = Σ setldetail.fund_payamt
psn_part_amt 含 acct_pay（含共济 acct_mulaid_pay）+ psn_cash_pay
```

**2207 入参**必须从 PreSettleQuote 透传：`fulamt_ownpay_amt`、`overlmt_selfpay`、`preselfpay_amt`、`inscp_scp_amt`（已实现，须作为不变量写入领域）。

## 4. 住院交易链与领域对象

### 4.1 规范链路

```text
2401 入院 → mdtrt_id
2301 费用上传（feedetail[]，退单 cnt 为负 + init_feedetl_sn）
  ↓ 输出 result[]（分割结果，已有 yb_inpatient_fee_upload，需补 result 结构化字段）
2302 费用撤销（feedetl_sn，0000=全删）
(2402 出院，全结模式)
2303 预结算 → setlinfo + setldetail[]
2304 正式结算 → setlinfo（setl_id）+ setldetail[]
2305 撤销 → 反向 setlinfo
```

### 4.2 与门诊差异

| 项 | 门诊 | 住院 |
|----|------|------|
| 批次键 | `chrg_bchno`（必填） | 无 chrg_bchno；按 mdtrt_id + 全量/中途 mid_setl_flag |
| 费用撤销 | 2205 按批次 | 2302 按 feedetl_sn |
| 预结算入参 | med_type 在 2206 | mid_setl_flag、dscgTime、insuplc/mdtrtarea |
| 正式结算 chrg_bchno | 平台批次号 | ZXPlat 可用 `IP{preSettleId}` 作内部关联键 |

住院 **`ChargeBatch` 可退化为「一次预结算束」**，仍以 `pre_settle_id` 关联 voucher；`encounter_class=IMP`。

### 5.2 V12 规划：门诊费用上传（对齐 2204）

```sql
CREATE TABLE yb_clinic_fee_upload (
    id                      BIGINT PRIMARY KEY,
    encounter_id            BIGINT NOT NULL,
    charge_item_id          BIGINT NOT NULL,
    feedetl_sn              VARCHAR(30) NOT NULL,

    chrg_bchno              VARCHAR(30) NOT NULL,

    upload_status           VARCHAR(16) NOT NULL,  -- UPLOADED | REVOKED | SETTLED
    det_item_fee_sumamt     NUMERIC(18,2),
    -- 2204 result 分割快照（高价值字段）
    chrgitm_lv              VARCHAR(3),
    med_chrgitm_type        VARCHAR(6),
    selfpay_prop            NUMERIC(5,4),
    fulamt_ownpay_amt       NUMERIC(18,2),
    overlmt_amt             NUMERIC(18,2),
    preselfpay_amt          NUMERIC(18,2),
    inscp_scp_amt           NUMERIC(18,2),
    lmt_used_flag           VARCHAR(3),
    platform_memo           VARCHAR(500),
    platform_result_json    TEXT,                -- 完整 result 行备份
    uploaded_at             TIMESTAMP,
    tenant_id               BIGINT NOT NULL,
    ...审计列
);
CREATE UNIQUE INDEX uk_yb_clinic_fee_upload_item
    ON yb_clinic_fee_upload (charge_item_id, chrg_bchno, tenant_id) WHERE is_deleted = FALSE;
```

**不变量**：`upload_status=SETTLED` 后禁止 2205（规范：已参与结算的明细不能撤销）。

### 5.3 V12 规划：结算撤销凭证（对齐 2208/2305）

```sql
CREATE TABLE yb_settlement_reversal (
    id                      BIGINT PRIMARY KEY,
    settlement_record_id    BIGINT NOT NULL,     -- 原 voucher
    revoke_setl_id          VARCHAR(30),         -- 2208 输出 setl_id（若有）
    mdtrt_id                VARCHAR(30) NOT NULL,
    psn_no                  VARCHAR(30) NOT NULL,
    encounter_class         VARCHAR(8) NOT NULL, -- AMB | IMP
    medfee_sumamt           NUMERIC(18,2),
    fund_pay_sumamt         NUMERIC(18,2),
    acct_pay                NUMERIC(18,2),
    psn_cash_pay             NUMERIC(18,2),
    invoke_log_id           BIGINT,              -- 2208/2305 的 yb_invoke_log.id
    reversed_at             TIMESTAMP NOT NULL,
    tenant_id               BIGINT NOT NULL,
    ...审计列
);
```

原 `yb_settlement_record` **保留不物理删除**；`status` 增 `REVOKED`（V12），软删仅作兼容。

**对账读侧（AS-CHS-REC-001 / BR-CHS-REC-008）**：`YbSettlementReversalQueryService.listReversedBetween` 按 `reversed_at` 左闭右开装载同窗撤销；汇总时金额按原结算险种×清算类别**抵减**（一收一退净 0），笔数与正向各计 1（一收一退计 2）；3202 正向明细**仅** `status=CONFIRMED`（`refd_setl_flag=0`），已 `REVOKED` **不得**再以原 `setl_id` 打正向，只经撤销凭证输出 `refd_setl_flag=1` 反向行（`revoke_setl_id`）。

## 6. 状态机

### 6.1 FeeDetailLine（2204/2301）

```text
UPLOADED ──2205/2302──► REVOKED
UPLOADED ──2207/2304──► SETTLED
SETTLED ──×──► 不可 REVOKED（规范）
```

### 6.2 PreSettleQuote（2206/2303）

```text
ACTIVE ──2207/2304 成功──► SETTLED
ACTIVE ──2205/失败/改费──► CANCELLED
SETTLED ──2208/2305──► REVOKED（关联 Reversal）
```

### 6.3 SettlementVoucher

```text
CONFIRMED ──2208/2305──► REVOKED（写 yb_settlement_reversal，原 row.status=REVOKED）
```

### 6.4 InsuranceSettlementSession（health）

```text
DRAFT ──preSettle 全组成──► PRE_SETTLED
PRE_SETTLED ──confirm 全组 2207 + 本地落账──► COMPLETED
任意组失败 ──► PRE_SETTLED 或 DRAFT（整单 CANCELLED 未结算 pre_settle）
```

## 9. 2204 result 与 HIS charge_item 映射

规范 2204 输出每行与输入 `feedetl_sn` 一一对应，ZXPlat 映射：

| HIS | 平台 |
|-----|------|
| `charge_item.id` | 生成/绑定 `feedetl_sn`（租户内唯一策略：雪花或 CI 前缀） |
| `charge_item` 汇总金额 | `det_item_fee_sumamt` |
| 2204 result | 写入 `yb_clinic_fee_upload`，供预结算展示、对账、审计 |

预结算界面「分割预览」应读 **2204 result**，而非仅 2206 汇总。
