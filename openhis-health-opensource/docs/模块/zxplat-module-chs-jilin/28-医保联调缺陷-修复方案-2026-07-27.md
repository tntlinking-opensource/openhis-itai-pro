### 0.2 对 B 链：以后端「门禁内补齐」为主（符合 LLD）

**结论**：

- trig=7（收费）：继续传 `chargeItemIds` + 读卡字段（现状保留）。
- trig=2（医生站）：**允许**请求只带 `encounterId` + `contractId` + `trigScen`；**Gate/ContextLoader 内补齐**费用与参保人字段。  
- **不**把补齐逻辑堆到前端多处复制；前端可选增强，但不是主修复面。

## 1. 问题 #1 · 挂号正式结算金额口径

### 1.1 目标

### 1.2 改法（对标门诊收费）

- 查 ACTIVE 2206：已有 `OutpatientChargeInsuranceExtension#listActivePreSettlesByPaymentDraft`（SPI），禁止 bridge Repository。
- 成码遵守通用规范：禁多行三元、注释同步。

### 1.4 验收

## 5. 问题 #5 · `poolarea` 统筹区长度非法

### 5.1 目标

`patient_dtos.poolarea` = 合法 `insuplc_admdvs`（1～10 位区划码）。

### 5.2 改法（集中在门禁，投影前）

在 `DetailAuditGateInvokerImpl#analyzeOp`：`resolveOrRegister` 之后、`fromOpPreSettle` 之前，调用 **单一补齐方法**（建议私有方法或抽到 domain access 支持类，**禁止**新建 `*Support`/`*Facade` 包名违规形态；若抽取用现有 `AuditInvokeSupport` 风格或 domain 侧纯函数）：

**优先级**（仅真实参保地；**禁止**契约 `adm_vs` 兜底）：

1. 入参已合法 `insuplcAdmdvs`
2. 本就诊 `YbClinicPreSettleQueryService.listByEncounterIds`（含 SETTLED，优先同 contract）
3. `YbPersonCacheDomainService.findValidByContractIdAndIdCard`（证件号来自 Encounter 上下文）
4. 仍非法 / 仍空 → **本地 Gate 失败**（明确文案，引导重新读卡或走收费预结算），避免打到平台「长度不在范围内」

**硬校验**：`trim` 后长度 ∈ [1,10]；拒绝以 `H` 开头的机构码；**禁止**用契约 `adm_vs`（就医地）冒充 `poolarea`（会与后续结算参保地不一致导致结算失败）。

### 5.3 合规

- 只经 `*QueryService` / `*DomainService` 读 `yb_*`。
- 不把 `fixmedins_code` 写入 `poolarea`。
- **不把**契约 `adm_vs` 写入 `poolarea` / `insuplcAdmdvs`（就医地 ≠ 参保所属统筹区）。
- 报文头 `insuplc_admdvs`（`InsuplcAdmdvsRule`）与 body `poolarea` 语义一致，均须真实参保地；无来源则 Gate 失败，禁止静默填就医地。

### 5.4 验收

平台不再报统筹区长度；日志/试调可见 `poolarea`≈`220199`。

```sql
UPDATE fin_payment_rec_static s
SET amount = ci.total_price,
    updated_at = NOW()
FROM adm_charge_item ci
WHERE s.is_deleted = FALSE
  AND s.amount = 0
  AND s.charge_item_ids ~ '^[0-9]+$'
  AND ci.id = s.charge_item_ids::bigint
  AND ci.total_price IS NOT NULL
  AND ci.total_price <> 0;
```

## 13. 已定：禁止 `adm_vs` 兜底 `poolarea`

`poolarea` / `insuplcAdmdvs` **只允许**来自：入参、本就诊预结算快照、人信息缓存中的真实 `insuplc_admdvs`。

**禁止**用契约 `adm_vs`（就医地）兜底——与参保所属统筹区不一致会导致后续结算失败。无真实参保地时本地 Gate 失败，引导重新读卡或收费预结算后再签发。
