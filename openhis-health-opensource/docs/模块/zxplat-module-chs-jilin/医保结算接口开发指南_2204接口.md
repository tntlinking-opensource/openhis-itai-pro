# 医保结算接口开发指南：2204 门诊费用明细信息上传

> **适用场景**：开发医保结算相关功能时的参考文档，重点说明“单位换算、单价精度控制”及“数据一致性”保障。

---

## 1. 核心业务规则与难点：单价与数量换算

在医保结算（特别是 2204 费用上传）过程中，**药品包装单位与医保计价单位不一致**是常见的开发难点。

### 1.1 业务痛点场景

*   **进货/销售单位**：一盒（例如：1盒 = 10.33 元）
*   **医保目录计价单位**：一片（例如：医保限价 1.47 元/片）
*   **矛盾点**：医院/药店通常按“盒”管理库存和销售，但医保系统要求按“片”进行费用上传。如果直接截断小数（如 `10.33 / 7 = 1.47`），会导致医院实际收入与医保结算金额不一致。

### 1.2 解决方案：利用字段最大精度进行平摊

**核心思路**：医保报文中的 `单价(pric)` 字段支持最多 **6位小数**，`数量(cnt)` 支持最多 **4位小数**。我们可以利用这一点，将总价精确平摊，确保总额一致。

#### 示例计算（一盒药的处理）

*   **进货价**：1盒 = 10.33 元
*   **规格**：1盒 = 7片
*   **单片真实成本**：`10.33 / 7 = 1.475714285...`

**推荐的医保上传参数**：

| 字段 | 建议传值 | 计算逻辑说明 |
| :--- | :--- | :--- |
| `cnt` (数量) | **7** | 按医保计价单位（片）的数量。 |
| `pric` (单价) | **1.475714** | `10.33 / 7`，保留 6 位小数（医保允许的最大精度）。 |
| `det_item_fee_sumamt` (明细费用总额) | **10.33** | `pric * cnt`，四舍五入保留 2 位小数（金额标准精度）。 |

> **校验**：`1.475714 * 7 = 10.329998`，四舍五入后为 `10.33`。这样既满足了医保系统对单价的校验（不超过限价），又保证了医院“多少钱进多少钱出”的要求。

## 2. 2204 接口关键参数规范

### 2.1 接口基本信息

*   **接口编号**：`2204`
*   **接口名称**：门诊费用明细信息上传
*   **调用方式**：实时调用
*   **核心作用**：上传单次就诊的所有费用明细（药品、诊疗项目等）。

### 2.2 输入报文核心字段（feedetail 节点）

> 以下为开发中频繁使用的关键字段，需严格遵守数据类型和长度限制。

| 参数代码 | 参数名称 | 数据类型 | 长度/精度 | 是否必填 | 开发说明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `feedetl_sn` | 费用明细流水号 | 字符型 | 30 | **是** | 单次就诊内唯一，用于定位明细记录。 |
| `mdtrt_id` | 就诊ID | 字符型 | 30 | **是** | 关联2203上传的就诊信息。 |
| `psn_no` | 人员编号 | 字符型 | 30 | **是** | 通过1101接口获取的参保人员唯一编号。 |
| `med_list_codg` | 医疗目录编码 | 字符型 | 50 | **是** | **医保目录编码**（国家标准编码）。 |
| `medins_list_codg` | 机构目录编码 | 字符型 | 150 | **是** | **HIS系统内部编码**，需通过3301接口与医保目录做对照映射。 |
| `det_item_fee_sumamt` | **明细项目费用总额** | 数值型 | **16,2** (2位小数) | **是** | **= pric * cnt**，最终结算金额，通常控制在2位小数。 |
| `pric` | **单价** | 数值型 | **16,6** (6位小数) | **是** | **医保目录下的单价**。核心字段，利用其6位精度进行平摊计算。 |
| `cnt` | **数量** | 数值型 | **16,4** (4位小数) | **是** | **医保目录下的数量**。如按片计费则传片数。 |
| `prcunt` | 计价单位 | 字符型 | 100 | **否** | 建议填写，如“片”、“次”、“盒”，便于理解。 |
| `hosp_appr_flag` | 医院审批标志 | 字符型 | 3 | **是** | 1:审批通过, 2:审批不通过。 |

### 2.3 输出报文核心字段

*   **`infcode`**: `0` 表示成功，`-1` 表示失败。
*   **`err_msg`**: 详细的错误信息，开发调试必看。

## 3. 开发代码示例（JavaScript）

用于演示前端或后端如何组装数据。

```javascript
/**
 * 组装2204接口的费用明细数据
 * @param {object} itemFromHIS - 来自HIS系统的药品/费用对象
 * @returns {object} - 符合医保要求的feedetail对象
 */
function buildMedicalFeeDetail(itemFromHIS) {
  // 假设 itemFromHIS 包含:
  // { hisCode: "内部编码", totalCost: 10.33, specCount: 7, medicalCode: "医保编码" }
  
  const totalCost = itemFromHIS.totalCost || 0; // 医院实际收/付的金额 (10.33)
  const unitCount = itemFromHIS.specCount || 1; // 医保计价单位的数量，如 7片
  const maxPrecision = 6; // 单价允许的最大小数位
  
  // 1. 计算单价 (保留6位小数)
  const unitPrice = totalCost / unitCount;
  const unitPriceFixed = Number(unitPrice.toFixed(maxPrecision)); 
  // 结果: 1.475714
  
  // 2. 计算总额 (保留2位小数, 确保与原价一致)
  const totalAmount = unitPriceFixed * unitCount;
  const totalAmountFixed = Number(totalAmount.toFixed(2)); 
  // 结果: 10.33 (校验通过)
  
  return {
    feedetl_sn: generateUniqueId(), // 生成唯一流水号
    med_list_codg: itemFromHIS.medicalCode, // 必须是医保编码
    medins_list_codg: itemFromHIS.hisCode, // HIS内部编码
    cnt: unitCount, // 数量
    pric: unitPriceFixed, // 单价 (6位小数)
    det_item_fee_sumamt: totalAmountFixed, // 总额 (2位小数)
    prcunt: "片", // 单位描述
    hosp_appr_flag: "1", // 默认审批通过
    // ... 其他必填字段
  };
}

// 使用示例
const hisItem = {
  hisCode: "HIS001",
  medicalCode: "XJ0101",
  totalCost: 10.33,
  specCount: 7
};

const feedetailData = buildMedicalFeeDetail(hisItem);
console.log(feedetailData);
// 输出: { pric: 1.475714, cnt: 7, det_item_fee_sumamt: 10.33, ... }
```

## 4. 开发注意事项 Checklist

*   [ ] **编码映射**：`medins_list_codg` (HIS编码) 必须与 `med_list_codg` (医保编码) 在 3301 接口中存在对照关系，否则会报错。
*   [ ] **限价校验**：上传的 `pric` 单价 **不能超过** 医保目录限价。若超过，系统会拒绝结算。
*   [ ] **数量限制**：`cnt` 必须为正数。对于一次性耗材或药品，通常为 1 或实际数量。
*   [ ] **精度控制**：
    *   单价(`pric`)保留最多 6 位小数。
    *   金额类字段(`det_item_fee_sumamt`)保留最多 2 位小数。
    *   **严禁**直接使用 `Number.toFixed(2)` 截断单价，必须使用 `toFixed(6)` 进行中间计算。
*   [ ] **撤销机制**：如果需要取消明细，调用 `2205`（门诊费用明细撤销）接口，传入对应的 `feedetl_sn`。
*   [ ] **电子处方**：如果是电子处方，必须正确传递 `rxno` (处方号)，否则结算失败。

## 5. 相关接口关联

*   **1101 人员信息获取**：获取 `psn_no` (人员编号)。
*   **1301-1315 目录下载**：获取 `med_list_codg` (医保目录编码) 及限价信息。
*   **3301 目录对照上传**：建立 `medins_list_codg` (HIS编码) 与 `med_list_codg` (医保编码) 的映射关系。
*   **2207 门诊结算**：所有明细上传完毕后，调用此接口进行最终的医保结算。
