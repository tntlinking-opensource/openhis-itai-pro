# 进销存运维 · 应用服务设计（AS）

> **文档职责**：说明「医保进销存运维台」页面的**接口契约（IF）**、业务语义、涉及领域与平台 infno、编排意图；作为上游契约供详细设计与实现对齐。
>
> **本文必须写**：IF 编号；用户动作与读写属性；关键校验；在内/在外；与发药/库存业务域分工。
>
> **本文禁止写**：具体类名/方法名；Request/Response 字段明细；包路径；Mapper；伪代码。
>
> **页面边界**：医保运维人员在同一 **进销存运维台** 完成：**3501–3506 流水查询与补传（主战场）**、**3501/3502 手工上报**、**批初始化**、**失败批量重试**。业务单据页（发药/进货/盘点等）只触发异步上报；**失败后一律回本页补传**，不在业务页补传。**本期 UI 隐藏** 3507、3508–3513、差异比对（API 保留）。
>
> **与业务上报分工**：日常 **3501–3506** 由业务链路经 Extension **afterCommit + @Async** 上报（**在外**）；本页 **「3501–3506 流水补传」Tab** 是失败行的**唯一运维补传入口**（编辑 `request_json` 重放）。**3301 对码**（**AS-CHS-CAT-003**）为上报前置，不在本页维护。
>
> **覆盖声明**：本稿须与 `09-医保进销存-详细设计.md`、UI Tab 及 `insuranceInventory/*` 对照。
>
> **编码**：AS-CHS-INV-001 · **版本**：v0.12 · **日期**：2026-09-15  
> **详细设计编号**：AS-CHS-INV-001

## 1. 场景概述

### 1.1 目标与边界

| 维度 | 说明 |
|------|------|
| **在内** | **3501–3506 流水补传主战场**：筛选 `yb_inv_upload`（契约/infno/来源/状态/busNo **AND**，含 request/response）；**retryUploadWithRequest** 单条补传；**retryPendingUploads** 批重试；**3501/3502** 手工上报；**initializeInventory** 批初始化 |
| **在外** | 发药/退药/进货/盘点/损益/领退领/清床等触发的 **3501–3506 自动上报**（Extension afterCommit+@Async）；HIS 业务单据；**3301**；**3507/3508–3513/compare** API 保留、UI 本期隐藏 |
| **涉及域** | **YbInvUpload**、**YbInvUploadTrace**（追溯比对）；契约 **ChsInsuranceContract**；配置 **ChsInventoryProperties**（开关、批大小） |
| **平台 infno** | 写：3501、3502、3503、3504、3505、3506、3507；读：3508、3509、3510、3511、3512、3513 |
| **编排权威** | 上报/初始化/重试经 **workflow + invoker**；查询经 **Inv35xxQueryInvoker**；AppService **不直连** gateway |
| **前置** | 契约 `contractBusNo` 有效；写操作前 **9001 已签到**（前端 `ensureInsuranceSignIn`）；上报开关 `uploadEnabled` 开启（关闭时写 IF 短路返回） |
| **后置** | 成功上报更新本地流水状态；失败可重试；3507 成功标记平台侧删除 |

### 1.2 角色与关键动作

| 角色 | 关键动作 |
|------|----------|
| **医保运维** | 进「3501–3506 流水补传」→ 默认 FAILED → 按交易号/busNo 定位 → **补传**（编辑 JSON）/ 批重试；必要时 3501/3502 手工或批初始化 |
| **信息科/实施** | 首次接入进销存时批初始化；联调 3501+3502 配对 |

### 1.3 页内 Tab 与 AS 关系

| Tab（UI） | 性质 | AS 内组织 |
|-----------|------|-----------|
| **3501–3506 流水补传**（默认） | 查流水 + 单条/批量补传；覆盖全部 3501–3506 | IF-CHS-INV-R-01 + W-RETRY / W-RETRY-ONE |
| 3501 / 3502 / 批初始化 | 运维手工写平台 | 各 IF；**同一 AS** |
| 3507 / 3508–3513 / 差异比对 | — | **本期 UI 隐藏**；API 保留 |

### 1.4 本期范围与非目标

| 类别 | 内容 |
|------|------|
| **本期** | 上文 **在内** 全部 IF；吉林省 3503/3505 默认口径（见 09-LLD §2.3）；字段映射真源 **09** §4（含 §4.5e `purc_invo_no`←`invoice_no`） |

| **BR-CHS-INV-015** | **3505/3506** 出站契约跟**结算/支付平台**（含工伤）；**销售配对 3502(107/106)** 出站契约跟追溯码**入库平台**（市入市出、省入省出）；无码或无入库归属时回落库房市优先；禁止因结算工伤把 3502 打到工伤平台 | Extension 自动上报（在外） |

## 3. 编排与领域（意图）

| 能力 | 编排意图 |
|------|----------|
| 3501–3506 上报 | Upload workflow → Inv350xInvoker → gateway |
| 3507 删除 | Inv3507Invoker |
| 3508–3513 查询 | Inv35xxQueryInvoker |
| 差异比对 | Compare workflow → 本地 Query + Inv35xxQueryInvoker |
| 失败重试 / 单条补传 | Retry workflow → Inv35xxRetryInvoker（重放持久化报文；禁业务表重建） |
| 批初始化 | Initialize workflow + UploadContextLoader（填充药库/药房盘存对） |

## 4. 异常与非功能

| 类型 | 口径 |
|------|------|
| 平台失败 | `infcode != 0` → 业务异常，消息含平台 `err_msg` |
| 3505/3506 | 平台 `retRslt != 1` 记失败态，可重试 |
| 超时 | 前端长超时配置（`chsLongRequestConfig`）；批初始化/重试宜小批量 |
| 并发 | 重试 worker 按 tenant 批处理，单条失败不阻断批次 |

---

## 5. 业务向测试要点

1. 签到前写 IF 应被前端拦截或平台返回可识别错误。
2. 3501 单条成功后本地流水为 SUCCESS；配对 3502 初始化路径符合 BR-CHS-INV-004。
3. 3508 与本地同批次比对：一致/缺失/多余三类差异行正确。
4. 单条补传：编辑 requestJson 后重放成功并更新状态；**未**从业务表重建。
5. `uploadEnabled=false` 时写 IF 无平台调用、无状态误更新。
