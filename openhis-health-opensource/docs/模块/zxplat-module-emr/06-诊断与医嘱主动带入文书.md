# 诊断与医嘱主动带入文书

> **文档职责**：约定医生站病历（EMR 文书）中，医生**主动**将当前就诊诊断、医嘱内容插入文书正文的产品与交互契约；作为实现与验收真源。  
> **宿主**：门诊/住院医生站「病历」Tab（共用 `MedicalRecordForm` + `SimpleEditor`）。  
> **版本**：v1.0 · **日期**：2026-07-19

---

## 1. 目标与边界

### 1.1 在内

| 项 | 约定 |
| --- | --- |
| **入口** | 文书编辑器工具栏：「从诊断带入」「从医嘱带入」 |
| **文书范围** | **全部**已打开可编辑文书（门诊病历、病程、入院记录、出院小结等，不限 `documentTypeCode`） |
| **写入方式** | 勾选确认后，将格式化纯文本**插入当前光标**；插入后文书标脏，保存走现有 `document.save` |
| **诊断来源** | 当前就诊诊断列表（门/住各自诊断 list 契约，见 AS-OP/IP-DOR-002） |
| **医嘱来源** | 当前就诊医嘱列表，**含草稿、已签发**；**含诊疗申请单**；门诊若有耗材行一并可选（见 AS-OP/IP-DOR-003） |
| **变更提醒** | 本页会话内诊断或医嘱发生保存/签发等变更时，给出「可重新带入」提醒；**不自动写入正文** |

### 1.2 在外（明确不做）

| 项 | 说明 |
| --- | --- |
| **自动同步 / 通道 A** | 不因打开文书、保存诊断、签发医嘱而自动刷新元数据芯片或正文段落 |
| **覆盖段落** | 不自动定位并替换「初步诊断：」「处理意见：」等段落内容 |
| **结构化入院诊断回写** | 住院诊断保存后回写 `admissionDiagnosisStructured`（`EmrDiagnosisSyncOrchestrator`）为 **MRMS/入院结构化既有能力**，与本功能解耦；本功能**不读写**该数据元 |
| **新建 EMR 专用后端带入接口** | 读侧复用诊断/医嘱既有 list；写侧仅前端 `insertContent`；本期 **EMR 后端零改动** |
| **检查检验引用** | 仍归功能清单 11.x；本文件不展开 |

### 1.3 与既有能力关系

```text
诊断 Tab 保存 ──►（既有）入院记录 admissionDiagnosisStructured   【本功能不碰】
                 （既有）打开文书时 diagnosis.* 元数据芯片填充     【本功能不扩展、不依赖】
诊断/医嘱变更 ──►（本期）黄条提醒「可重新带入」                   【仅提醒】
工具栏主动带入 ──►（本期）弹窗勾选 → 插入光标纯文本               【唯一写入路径】
```

## 2. 角色与关键动作

| 角色 | 动作 |
| --- | --- |
| **门诊/住院医生** | 打开病历文书 → 将光标置于目标位置 →「从诊断带入」或「从医嘱带入」→ 勾选 → 确认插入 → 按需编辑 → 保存 |
| **系统** | 无就诊上下文时禁用带入；只读文书禁用；变更后展示提醒条（可关闭）；不替用户改写正文 |

## 3. 接口契约（IF）

> IF 为产品契约编号；HTTP 仍走宿主医生站既有诊断/医嘱 AppService，**不新增** EMR `document.*` 带入方法。

### IF-EMR-IMPORT-01 从诊断带入

| 维度 | 说明 |
| --- | --- |
| **用户动作** | 点击工具栏「从诊断带入」→ 弹窗勾选 → 确认 |
| **前置** | 已选患者且存在 `encounterId`；当前文书可编辑且编辑器有有效光标/选区可插入 |
| **读** | 调用当前站别诊断列表（门诊 IF-DOR-06 / 住院 IF-IP-DOR-02 等价能力） |
| **写** | 仅前端向编辑器插入文本；不调用诊断写接口、不改诊断表 |
| **默认勾选** | 当前列表全部行 |
| **空列表** | 弹窗提示「暂无诊断，请先在诊断页录入」；不插入 |
| **失败** | 只读/无光标/无就诊：按钮禁用或 Toast；列表加载失败 Toast，不插入半成品 |

### IF-EMR-IMPORT-02 从医嘱带入

| 维度 | 说明 |
| --- | --- |
| **用户动作** | 点击工具栏「从医嘱带入」→ 弹窗勾选 → 确认 |
| **前置** | 同 IF-EMR-IMPORT-01 |
| **读** | 调用当前站别医嘱列表（门诊 IF-DOR-10 / 住院 IF-IP-DOR-10 等价能力）；**不过滤掉草稿**；**包含申请单类诊疗行** |
| **写** | 仅前端插入文本 |
| **默认勾选** | 草稿 + 已签发且未停止；已停止行默认不勾选，允许用户手动勾选 |
| **空列表** | 提示「暂无医嘱」；不插入 |

### IF-EMR-IMPORT-03 诊断/医嘱变更提醒（不写入）

| 维度 | 说明 |
| --- | --- |
| **触发** | 本医生站页面会话内：诊断保存成功，或医嘱暂存/签发/签退/停嘱/取消停嘱等成功（与诊断/医嘱 Tab 既有成功回调或页面内事件总线对接） |
| **表现** | 病历区顶栏或编辑器上方提示条：「诊断/医嘱已更新，如需同步到病历请重新带入」；快捷入口「带入诊断」「带入医嘱」打开对应弹窗 |
| **不作为** | **禁止**自动 `insertContent`、禁止改数据元、禁止静默刷新正文 |
| **关闭策略** | 用户关闭后，**同一次变更周期**内不再弹出；诊断或医嘱再次发生变更则重新提示 |
| **持久化** | 提醒仅为前端会话态，不落库 |

## 4. 文案规则（BR）

### BR-IMPORT-DX-01 诊断文本

```text
西医诊断：
1. {名称}（{编码}）（主诊）
2. {名称}（{编码}）
中医诊断：
1. {病名} — {证候}
```

| 规则 | 说明 |
| --- | --- |
| 排序 | 主诊（`mainDiagnosisFlag=1`）优先，其余按 `diagnosisSortNo` 升序 |
| 西医行 | `conditionDefinitionName` + 有编码则括号附 `conditionCode`；主诊附「（主诊）」 |
| 中医行 | 同 `tcmSyndromeGroup` 合并为一行「病名 — 证候」；无法成组则分行 |
| 补充 | 有 `diagnosisDesc` 时行末追加「（{说明}）」 |
| 住院 | 有 `iptDiseaseTypeText` 时可在名称后附「[{类型}]」 |
| 分组标题 | 始终输出「西医诊断：」/「中医诊断：」（某侧无行时仅保留标题，空诊断栏默认带出） |
| 插入形态 | 多行纯文本；换行保留；**不**写入结构化 JSON / 数据元 |

### BR-IMPORT-ADV-01 医嘱文本

```text
1. [草稿] {项目名} {剂量/用法/频次} ×{数量或天数}
2. {项目名}（{申请单/诊疗类型}）
3. 嘱托：{entrustContent}
```

| 规则 | 说明 |
| --- | --- |
| 药品 | 名称 + 剂量/用法/频次/数量等列表已有展示字段拼接（与医嘱表折叠摘要同源口径，避免两套文案） |
| 成组 | 同 `groupId` 可缩进或「同组：A；B」；实现择一并在 UI 固定 |
| 诊疗/申请单 | 名称 + 类型标注；有明细时可一行摘要 |
| 嘱托 | 独立行「嘱托：…」；内容取 `entrustContent` |
| 状态前缀 | 草稿：`[草稿]`；用户勾选的已停行：`[已停]`；已签发无前缀 |
| 插入形态 | 多行纯文本，光标处插入 |

### BR-IMPORT-INS-01 插入与脏标记

- 使用编辑器 `insertContent`（或等价）在**当前光标**插入；有选区时按编辑器默认替换选区语义。
- 插入成功后文书 `dirty=true`；未保存离开仍走现有未保存守卫（功能 1.4）。

## 5. 交互与线框

### 5.1 工具栏

```text
… | 查找 | 【从诊断带入】【从医嘱带入】 | 打印预览 | …
```

- 只读、无 `encounterId`、编辑器未就绪：两按钮禁用。
- 书写模式（`layoutLocked`）下**仍允许**带入（插入的是正文文本，不破坏模板结构节点）。

### 5.2 带入弹窗（诊断）

```text
┌─ 从诊断带入 ─────────────────────────────┐
│ [全选]  共 N 条                           │
│ ☑ 西医  J18.900  肺炎…          主诊      │
│ ☑ 西医  I10.x00  原发性高血压             │
│ ☑ 中医  …  咳嗽病 / 风寒袭肺证            │
│                                          │
│              [取消]  [插入到光标]          │
└──────────────────────────────────────────┘
```

### 5.3 带入弹窗（医嘱）

```text
┌─ 从医嘱带入 ─────────────────────────────┐
│ 默认含草稿与申请单；已停默认不勾选         │
│ ☑ [草稿] 阿莫西林胶囊  0.5g tid …         │
│ ☑ 血常规（检验申请）                      │
│ ☐ [已停] 长期 …                           │
│                                          │
│              [取消]  [插入到光标]          │
└──────────────────────────────────────────┘
```

### 5.4 提醒条

```text
┌─────────────────────────────────────────────────────────────┐
│ 诊断/医嘱已更新，如需同步到病历请重新带入   [带入诊断][带入医嘱][×] │
└─────────────────────────────────────────────────────────────┘
```

## 6. 实现落点（指导成码，非 SDD）

| 层 | 落点 | 说明 |
| --- | --- | --- |
| UI | `SimpleEditor` 工具栏 | 两按钮；只读态联动 |
| 宿主 | `medical-record-form.vue` | 弹窗、提醒条、`encounterId`/站别注入 |
| 弹窗 | 新建组件（建议） | `emr-import-diagnosis-dialog` / `emr-import-advice-dialog` |
| 文案 | 前端纯函数 | `formatDiagnosisImportText` / `formatAdviceImportText` |
| 读 API | 既有 | 门/住 `*Diagnosis` list、`*Advice` list |
| 写 | 编辑器命令 | `editor.chain().focus().insertContent(text).run()` |
| 提醒 | 前端会话 | 订阅诊断/医嘱 Tab 成功事件；不落库 |
| EMR 后端 | **本期无** | 不新增 Contributor、不新增 document 带入 API |

门/住差异仅体现在：**调用哪套 list API** 与弹窗列字段（住院诊断多类型列、住院医嘱多长临轨状态）；文案规则与插入行为一致。

## 7. 验收标准

| # | 标准 |
| --- | --- |
| A1 | 门诊与住院病历 Tab、各类文书类型均可带入；插入位置为光标 |
| A2 | 医嘱弹窗可见草稿行与申请单行；默认可勾选并插入 |
| A3 | 诊断/医嘱变更后仅出现提醒条；关闭后正文未被改写 |
| A4 | 只读文书、无就诊、无编辑器时不可带入 |
| A5 | 带入后未保存离开触发现有脏检查；保存后内容持久化 |
| A6 | 不修改 `admissionDiagnosisStructured`；不新增自动元数据刷新逻辑 |
