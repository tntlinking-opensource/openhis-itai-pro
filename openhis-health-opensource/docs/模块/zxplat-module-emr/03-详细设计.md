# ZXPlat EMR 详细设计

> 依据《[概要设计](01-概要设计.md)》《[功能清单](00-功能清单.md)》《[UI交互说明](02-交互说明.md)》编制，用于指导编码实现。技术栈：**Tiptap + Vue + Java（zxplat-framework）+ OpenPDF**。

---

## 一、文档说明与依据

- **目的**：在概要设计基础上展开接口参数、数据库表结构、前端/服务端关键技术及实现顺序，便于开发直接落地。
- **依据**：概要设计 V6（模块划分、数据模型、接口概要、zxplat-framework 约定）、功能清单 V14（实现顺序、非功能需求）、UI 交互说明（页面与交互）、《打印预览设计》V1（预览与 PrintConfig）。
- **约定**：服务端遵循 zxplat-framework《开发指南》；所有 API 为 `POST /api/app/{serviceName}/{methodName}`，请求体为 JSON 数组 `[arg1, arg2, ...]`；多参合并为单一 Request 对象。

**zxplat-framework 遵守清单（与本详细设计对齐）**：

| 规范项 | 框架要求 | 本设计遵守方式 |
|--------|----------|----------------|
| **API 参数** | 所有 AppService 方法**仅使用 Request 对象**入参，禁止基本类型（如 `Long id`）单独入参 | 所有接口均为单参 Request；单 id 查询/删除使用 `IdRequest` 或 `DeleteXxxRequest` |
| **Request 命名** | 查询 `Query{Entity}Request`（继承 BaseQueryRequest）；创建 `CreateXxxRequest`；更新 `UpdateXxxRequest`（**必须含 id**）；删除 `DeleteXxxRequest` 或 `IdRequest`；单 id 操作可用通用 `IdRequest` | §3 各 Request 命名与上一致；Query 类均继承 BaseQueryRequest |
| **实体与审计** | 实体继承 `BaseAuditedEntity`；**不使用 Entity 后缀**；审计列名：`created_at`、`updated_at`、`created_by`、`updated_by`；软删除：`is_deleted`、`deleted_at`、`deleted_by` | §4 表结构与 BaseAuditedEntity 列名一致；实体类名 Document、Template 等 |
| **对象映射** | **必须使用 MapStruct**；禁止 BeanUtils；`componentModel = "spring"`，`nullValuePropertyMappingStrategy = IGNORE` | §7.3 明确 MapStruct；Request→Command、Entity↔Dto 均经 Mapper |
| **Flyway** | **所有**迁移脚本**统一放在** `zxplat-framework/zxplat-framework/src/main/resources/db/migration/`；**不得**在业务模块内单独放置；版本号 V13+ | §4 明确脚本位置与版本号；不在 zxplat-module-emr 内建 migration |
| **领域层** | 写操作参数用 `command` 包下 Command；查询条件用 `query` 包下 Query（仅条件，不含分页） | §7.1 包结构含 command、query；Application 层 Request 转 Command/Query |

## 二、技术点与解决方案

以下为 EMR 核心**技术点**及推荐**解决方案**，便于在实现阶段做技术选型与攻关。

### 2.1 文档 JSON 与 Tiptap Schema 一致性

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 前后端与 OpenPDF 共用同一 JSON 语义 | 前端 Tiptap、服务端解析、OpenPDF 渲染均依赖同一套节点类型与 attrs，若不一致会导致解析失败或渲染错误。 | **统一 JSON Schema 约定**：在详细设计中固化节点类型名（如 `region`、`section`、`dataElement`、`pageBreak`）、必选 attrs（如 `name`、`type`、`value`）；前端 Tiptap Extension 的 `name`、`addAttributes` 与文档 6.5 一致；服务端解析与 OpenPDF 渲染共用同一份「节点类型→处理逻辑」映射或枚举。可选：抽成 JSON Schema 文件或 TypeScript 类型定义，前后端与渲染侧引用。 |
| 大文档 content 体积 | 单文档 content 过大（如 >2MB）导致传输与解析慢。 | 传输：接口支持 gzip；存储：PostgreSQL JSONB 或 CLOB，超阈值可压缩后存或分块表。非功能需求中约定单文档 content 上限（如 2MB），保存前校验 size。 |

### 2.2 书写模式与结构保护

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 书写模式下禁止删改区域/数据组 | 医生书写时不能删除「主诉」「现病史」等块级结构，仅允许在数据元内输入。 | **Schema 约束**：书写模式使用另一套 Schema，对 region、section 设置 `contentEditable: false` 或 `atom: true`，且禁止 `deleteNode`、`setNode` 等命令删除/替换这些节点；或根节点 `editable: () => false` 且仅数据元 NodeView 内 `contentEditable: true`。 |
| 模板编辑与文书书写切换 | 同一编辑器在不同路由下行为不同（模板可改结构，文书不可）。 | 前端根据路由或「当前打开的是模板 ID 还是文档 ID」决定使用哪套 Schema 或 Extension 配置；不持久化「模式」，仅运行时区分。 |

### 2.3 按数据项名取值/赋值

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 在文档 JSON 中按 name 定位节点并读写 value | 诊断带入、检查引用、批量赋值需通过数据项名（attrs.name）定位数据元并写 value。 | **前端**：遍历 `doc.descendants()`，匹配 `node.attrs.name === name`，对数据元节点 `editor.commands.updateAttributes(nodeType, { value })` 或替换节点。**服务端**：解析 content JSON 递归遍历，按 `attrs.name` 找到节点后修改 `attrs.value`，再序列化回 JSON 落库；批量赋值接口传入 `Map<String, Object>`（数据项名→值）。 |
| 第一层数据项名（区域/数据组列表） | 导航、续打参数、质控段列表需要文档顶层区域/数据组的数据项名列表，不打开全文。 | 服务端「获取文档结构列表」接口：解析 content 的 doc.content 第一层子节点，过滤 type 为 region/section，返回 `List<{name, title, type}>`；前端也可在 onUpdate 时自己算一层列表做导航。 |

### 2.4 不打开文档解析结构（服务端）

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 服务端解析 ProseMirror JSON | Java 侧需要从 content JSON 提取数据项名列表、块→页号、按属性过滤等，不依赖前端。 | 使用 JSON 库（如 Jackson）将 content 反序列化为 `Map`/`JsonNode`，递归遍历 `content` 数组；根据 `type` 识别 region/section/dataElement，读取 `attrs.name`、`attrs.title` 等；块→页号需在 OpenPDF 渲染时记录或二次解析时按 pageBreak 估算。可封装 `DocumentStructureParser` 工具类，供 DocumentStructureAppService、PDF、数据项名索引写入等多处复用。 |
| 数据项名索引表写入 | 若启用 `emr_document_data_item_index`，保存文档时需解析 content 并写入索引。 | 在 Document 保存流程中：保存 content 后调用 `DocumentStructureParser` 提取所有带 name 的节点，删除该 document_id 的旧索引行，批量 insert 新行（document_id, node_type, data_item_name）；可放在领域服务或 Application 层，事务内完成。 |

### 2.5 打印与 PDF（OpenPDF）

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| ProseMirror JSON → PDF 排版 | OpenPDF 需将文档 JSON 转为分页 PDF，支持区域、数据组、数据元、表格、图片、分页符等。 | **渲染管道**：定义「节点类型→OpenPDF 元素」映射；遍历 content 树，遇到 `pageBreak` 则 `document.newPage()`；region/section 渲染为标题+段落；dataElement 按 type 渲染为文本/数值/日期等；表格、图片调用 OpenPDF 对应 API。可先实现纯文本+分页符，再逐步加区域、数据元、表格、图片。 |
| 页眉页脚、水印、页码 | 每页统一页眉页脚、可选水印、「第 X 页/共 Y 页」。 | 使用 OpenPDF 的 `PdfPageEventHelper`（或等价回调），在 `onEndPage` 中根据 pageNumber 绘制页眉页脚、水印；总页数需在渲染完成后或二次遍历得到，可先渲染到内存再写总页数或预留占位。 |
| 按区域/按页范围生成 PDF | 续打、仅打指定区域。 | 解析 content 得到指定 name 的节点子树或从某块到文档末；只将该部分 JSON 或「从第 N 页起」的页交给 OpenPDF 生成；或先生成完整 PDF 再按页号裁剪（如只输出奇数页）。可渲染节点分阶段见《[打印预览设计](04-打印预览设计.md)》§三。 |

### 2.6 版本与留痕

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 版本快照存储 | 每次保存可存一份版本，用于回滚与对比。 | 表 `emr_document_version`：document_id、version_number、content（JSONB 或 CLOB）、created_at、created_by；保存时插入一条版本记录；回滚时取该 version 的 content 写回 document.content 并再存一条新版本。 |
| 留痕展示（增删高亮） | 用户需看到「删除线」「新增高亮」的对比视图。 | **方案 A**：前端 Tiptap 使用 track-changes 类扩展，在节点或 mark 上记录 insertion/deletion，保存时带 mark 的 JSON 存版本；**方案 B**：服务端保存时对上一版本 content 与当前 content 做 diff，生成带 mark 的 JSON 存版本或单独留痕表。渲染 PDF 时保留删除线/高亮样式。 |
| 痕迹提交（落稿） | 提交痕迹后生成新版本、清空未提交痕迹。 | 留痕元数据表记录「未提交」的痕迹；提交动作为：将当前带痕 content 合并为「清洁」content，写回 document 并生成新版本，标记痕迹已提交。 |

### 2.7 保存前校验

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 必填、长度、逻辑、违禁字 | 保存前校验文档内数据元必填、长度、逻辑规则、违禁关键字。 | 服务端「保存前校验」接口：接收 content JSON，使用 `DocumentStructureParser` 遍历所有 dataElement，根据 attrs（必填、maxLength、校验规则、违禁字配置）校验；返回 `List<{dataItemName, message, code}>`。前端保存前可先调该校验接口，若有错误则展示并阻止保存或允许强制保存（按业务）。 |
| 违禁字配置来源 | 违禁字列表可配置。 | 配置表或系统设置存储违禁词列表；校验时遍历数据元 value 与违禁词匹配。 |

### 2.8 复制粘贴与防跨患者

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 书写模式下粘贴仅纯文本 | 避免粘贴进富文本结构破坏模板。 | Tiptap 的 `clipboardTextParser` 或 `transformPasted`：在书写模式下将粘贴内容转为纯文本再插入；或禁用默认的 paste 行为，仅插入 text。 |
| 防跨患者粘贴 | 粘贴内容若来自其他患者，禁止或提示。 | 复制时在剪贴板数据（如 application/json）中写入来源患者 ID；粘贴时读取当前文档的 patientId 与剪贴板中的来源 patientId 比较，不一致则拦截或 toast 提示。若服务端需校验，保存时在 content meta 或请求体中带「粘贴来源」信息，服务端校验。 |

### 2.9 前端状态与未保存提示

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 脏检测（未保存） | 识别文档是否被修改，用于未保存提示与保存按钮状态。 | 初始 setContent 后保存一次 `initialJson = getJSON()`（或 hash）；onUpdate 时对比当前 `getJSON()` 与 initialJson（或 hash），不一致则置 dirty=true；保存成功后重置 initialJson。 |
| 离开前提示 | 关闭页、切换路由、刷新时若 dirty 则二次确认。 | Vue 路由守卫 `beforeRouteLeave`、`window.addEventListener('beforeunload')` 中判断 dirty，弹窗确认；可选「保存后离开」调用保存接口再跳转。 |

### 2.10 打印预览（OpenPDF + emrEditor）

> 完整能力矩阵、PrintConfig 字段、前端触发策略见《[打印预览设计](04-打印预览设计.md)》。

| 技术点 | 问题描述 | 解决方案 |
|--------|----------|----------|
| 预览与正式打印一致性 | 若预览走浏览器 CSS、打印走 OpenPDF，会出现预览≠打印。 | **单一渲染器**：预览与正式打印均调用 `OpenPdfRenderer`；`GeneratePdfRequest.previewMode` 仅控制审计、限页、水印策略，不改变排版逻辑。 |
| 编辑时何时预览 | 每次按键请求 PDF 会导致延迟与服务器压力。 | **双层预览**：L1 emrEditor A4 即时反馈；L2 防抖（建议 1200ms）或手动「刷新预览」；AbortController 取消未完成请求；可选 contentHash 缓存。 |
| 版式配置存储 | 页边距、页眉页脚等与 content 混在一起难以复用。 | **PrintConfig** JSON：系统默认 → 文书类型 → 模板 → 请求体合并；可选列 `emr_template.print_config`、`emr_document_type.print_config`；L1 页边距同步为 mm 写入 printConfig。 |
| 可渲染范围 | 开发需知哪些节点已实现、哪些降级。 | 维护节点能力矩阵（region/section/dataElement/pageBreak/paragraph/表格/图片/marks/留痕等），按 MVP→v3 分阶段；未实现节点跳过或占位，见《打印预览设计》§三。 |
| previewMode 与审计 | 预览不应每次记打印审计。 | previewMode=true：不写打印审计、可 previewMaxPages 限页；previewMode=false：完整渲染、写审计、用于归档与正式打印。 |

## 三、接口详细设计

以下为 zxplat-framework 自动 API 规则下的 **AppService 方法** 与 **Request/DTO** 设计；路径均为 `POST /api/app/{serviceName}/{methodName}`，请求体为 **JSON 数组** `[request]`。

### 3.1 文档服务（document）

| 方法 | 说明 | Request | 返回 |
|------|------|---------|------|
| create | 新建文档 | CreateDocumentRequest | 含 id、content 的 DTO |
| getContent | 打开文档（取 content） | GetDocumentContentRequest | 含 content、readOnly 等 |
| getList | 按患者/就诊查文书列表 | QueryDocumentRequest | 分页列表 DocumentDto |
| save | 保存文档 | SaveDocumentRequest | 成功/失败 |
| saveAs | 另存为 | SaveAsDocumentRequest | 新文档 id、content |
| validate | 保存前校验 | ValidateDocumentRequest | 校验结果（错误列表） |

**CreateDocumentRequest**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| patientId | Long/String | 是 | 患者 ID（与 HIS 对接约定） |
| encounterId | Long/String | 否 | 就诊 ID |
| documentTypeCode | String | 是 | 文书类型编码 |
| templateId | Long | 否 | 模板 ID；不传则用文书类型默认模板或空文档 |

**GetDocumentContentRequest**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| documentId | Long | 否 | 文档 ID（与 patientId+documentTypeCode 二选一） |
| patientId | Long/String | 否 | 患者+文书类型打开时传 |
| encounterId | Long/String | 否 | 就诊 ID |
| documentTypeCode | String | 否 | 文书类型编码（与 patientId 配合） |

**QueryDocumentRequest**（继承 BaseQueryRequest）

| 字段 | 类型 | 说明 |
|------|------|------|
| patientId | Long/String | 患者 ID |
| encounterId | Long/String | 就诊 ID |
| documentTypeCode | String | 文书类型筛选 |
| status | String | 状态：DRAFT/SUBMITTED/LOCKED/ARCHIVED |
| keyword | String | 继承，标题/文书类型搜索 |

**SaveDocumentRequest**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| documentId | Long | 是 | 文档 ID |
| content | Object | 是 | 文档 JSON（Tiptap getJSON()） |
| saveVersion | Boolean | 否 | 是否同时存版本快照，默认 true |

**ValidateDocumentRequest**

| 字段 | 类型 | 说明 |
|------|------|------|
| content | Object | 文档 JSON |
| documentId | Long | 可选，用于上下文校验 |

**返回：** `ValidateResultDto`：`List<{ dataItemName, code, message }>`，无错误时 list 为空。

**SaveAsDocumentRequest**：同 CreateDocumentRequest，另加 `sourceDocumentId`（源文档 ID）；返回新文档 id 及 content（与 source 相同）。

**DocumentDto**（列表项）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 文档 ID |
| patientId, encounterId | - | 患者/就诊 |
| documentTypeCode | String | 文书类型编码 |
| title | String | 文档标题（可选，从 content 解析） |
| status | String | 状态 |
| createdAt, updatedAt | 时间 | 与 BaseAuditedEntity 对应 |
| createdBy, updatedBy | Long | 操作人 |

### 3.2 模板服务（template）

| 方法 | 说明 | Request | 返回 |
|------|------|---------|------|
| getList | 模板列表 | QueryTemplateRequest | 分页 TemplateDto |
| getContent | 模板 content JSON | GetTemplateContentRequest | 含 content |
| create | 创建模板 | CreateTemplateRequest | 含 id、content |
| update | 更新模板 | UpdateTemplateRequest | - |
| delete | 删除模板 | DeleteTemplateRequest | - |

**QueryTemplateRequest**（继承 BaseQueryRequest）：documentTypeCode、enabled、keyword。

**GetTemplateContentRequest**：templateId（Long）。

**CreateTemplateRequest**：name、code、documentTypeCode（可选）、content（可选，空则空文档）、enabled。

**UpdateTemplateRequest**：id（必填）、name、code、content、enabled（均可选更新）。

**TemplateDto**：id、name、code、documentTypeCode、enabled、createdAt 等。

**DeleteTemplateRequest**：id（Long，必填）。与框架 API 参数标准化一致：删除等单 id 操作使用 Request 对象，禁止 `delete(Long id)` 签名。

### 3.3 PDF 服务（pdf）

| 方法 | 说明 | Request | 返回 |
|------|------|---------|------|
| generate | 生成 PDF | GeneratePdfRequest | PDF 流或临时 URL |
| merge | 多文档合并 PDF | MergePdfRequest | PDF 流或 URL |

**GeneratePdfRequest**

| 字段 | 类型 | 说明 |
|------|------|------|
| documentId | Long | 文档 ID（与 content 二选一） |
| content | Object | 文档 JSON（不传则按 documentId 拉取） |
| pageRange | String | 如 "1-3"、"all"；续打时 "fromPage:5" |
| regionNames | List\<String\> | 仅渲染这些数据项名（区域） |
| includeTrackChanges | Boolean | 是否留痕打印 |
| watermark | String | 水印文字（快捷字段，合并入 printConfig.watermark） |
| headerTemplate | String | 页眉模板快捷字段 |
| footerTemplate | String | 页脚模板快捷字段 |
| previewMode | Boolean | true=预览（不写打印审计、可限页）；false=正式打印/导出，默认 false |
| printConfig | Object | PrintConfig JSON，见《[打印预览设计](04-打印预览设计.md)》§4.1 |
| previewMaxPages | Integer | previewMode 时最多渲染页数，默认 20 |
| contentHash | String | 可选，供服务端预览缓存键 |
| patientId / encounterId | Long/String | 页眉页脚占位符上下文 |
| metadata | Map\<String,String\> | 患者/文书元数据 |

**PdfGenerateResultDto**

| 字段 | 类型 | 说明 |
|------|------|------|
| url | String | 临时 PDF URL（与 base64 二选一或并存） |
| pdfBase64 | String | PDF Base64 |
| pageCount | Integer | 总页数 |
| contentHash | String | 内容哈希 |
| renderedAt | DateTime | 生成时间 |
| previewTruncated | Boolean | 预览是否因页数上限截断 |

**返回**：二进制流（application/pdf）或 `PdfGenerateResultDto`（含 url/base64），由网关/前端决定下载或 iframe 展示。

**MergePdfRequest**：documentIds 或 contents 列表；headerTemplate、footerTemplate 可选。

### 3.4 文档结构服务（documentStructure）

| 方法 | 说明 | Request | 返回 |
|------|------|---------|------|

## 五、文档 JSON 结构约定（Tiptap 对齐）

与概要设计 6.5 一致，便于前端 Extension 与服务端解析、OpenPDF 渲染对齐。

- **根节点**：`type: "doc"`，`content: [ block... ]`。
- **区域**：`type: "region"`，block；attrs：id、name（数据项名）、title、required、participatePrint、protected 等。
- **数据组**：`type: "section"`，block，可嵌套；attrs：sectionId、name、title、deletable、editable 等。
- **数据元**：`type: "dataElement"`，inline 或 block（按实现）；attrs：id、name、type（text/number/date/select/multiSelect/checkbox 等）、value、required、maxLength 等。
- **分页符**：`type: "pageBreak"`，block，atom；无 content。
- **表格/图片/链接**：与 Tiptap 内置或扩展一致，需在 OpenPDF 中实现对应渲染。

前端 Tiptap 注册 Node 时 `name` 与上述 type 一致；服务端 `DocumentStructureParser` 根据 `type` 分支处理。

## 六、前端关键技术与组件设计

### 6.1 模块划分（与概要设计 5.1 对应）

| 模块 | 职责 | 技术要点 |
|------|------|----------|
| 文档与列表 | 文书列表（2.1）、新建/打开/保存/关闭、未保存提示；**patientId/encounterId 由宿主注入**（12.1） | 路由或嵌入医生站；调用 document/create、getList、getContent、save；dirty 与 beforeunload |
| 富文本与基础编辑 | 段落、格式、表格、图片、链接、撤销重做 | Tiptap 内置 + History、Image、Table、Link |
| 区域与数据组 | Region/Section 自定义 Block Node | Node 定义、addAttributes、renderHTML 或 NodeView |
| 数据元 | 各类 DataElement + NodeView | Vue 组件包裹 input/select/date-picker，attrs.value 双向同步 |
| 模板与模式 | 模板编辑/书写模式、从模板新建 | Schema 按模式切换；新建时 templateId 传 create |
| 打印与导出 | L1 编辑区 + L2 PDF 预览（防抖/手动）；调 pdf/generate | previewMode、printConfig；iframe/blob 展示；见《打印预览设计》 |
| 结构解析（前端） | 第一层数据项名、按 name 取值赋值 | 遍历 doc.descendants()，get/set value by name |
| 诊断与检查检验 | 侧栏列表、检查引用 | 调检查检验接口；引用写节点或数据元 |
| 诊断/医嘱主动带入 | 工具栏弹窗 → 插入光标 | 见文档 06；复用 health 诊断/医嘱 list；前端 `insertContent`；变更仅提醒 |

### 6.2 Tiptap Extension 设计要点

- **Region**：Block Node，`group: "block"`，`content: "block+"`，attrs：id、name、title、required、participatePrint、protected；书写模式下 `editable: false` 或通过命令禁用删除。
- **Section**：Block Node，可嵌套，`content: "(section|dataElement|paragraph)+"` 等；同上书写模式保护。
- **DataElement**：Node + NodeView（Vue）；根据 attrs.type 渲染不同输入控件；value 变更时 `updateAttributes`。
- **PageBreak**：Block Node，`atom: true`，无 content。
- **按 name 取值**：`getValueByName(name)`：遍历 doc.descendants() 找 attrs.name === name 的 dataElement，返回 attrs.value。
- **按 name 赋值**：`setValueByName(name, value)`：找到节点后 `editor.commands.updateAttributes("dataElement", { value }, pos)` 或替换节点。

### 6.3 状态管理建议

- 当前文档 id、patientId、encounterId、content 初态（用于 dirty）、只读标识：可用 Pinia store 或页面级 state。
- 模板列表、文书类型列表：可缓存，失效时重新拉取。

## 七、服务端分层与关键类

### 7.1 包结构（emr 模块）

```
com.zxplat.plugin.emr
├── domain
│   ├── entity          # Document, Template, DocumentType, DocumentVersion
│   ├── repository      # DocumentRepository, TemplateRepository, ...
│   ├── service         # DocumentManager（领域服务，可选）
│   ├── command         # CreateDocumentCommand, SaveDocumentCommand, ...
│   └── query           # DocumentQuery, TemplateQuery, ...
├── application
│   ├── DocumentAppService, TemplateAppService, PdfAppService, DocumentStructureAppService
│   ├── dto             # DocumentDto, TemplateDto, StructureItemDto, ...
│   ├── request         # CreateDocumentRequest, SaveDocumentRequest, ...
│   └── mapper          # DocumentMapper, TemplateMapper（MapStruct）
└── infrastructure
    ├── persistence     # DocumentRepositoryImpl, TemplateRepositoryImpl
    ├── parser          # DocumentStructureParser（解析 content JSON）
    └── pdf             # OpenPdfRenderer（JSON → PDF）
```

### 7.2 关键类职责

| 类 | 职责 |
|------|------|
| DocumentAppService | create、getContent、getList、save、saveAs、validate；内部调 Repository、可选 DocumentManager、版本写入 |
| DocumentStructureParser | 解析 content JSON，提取数据项名列表、块→页号、按属性过滤；被 DocumentStructureAppService、Pdf、索引写入复用 |
| OpenPdfRenderer | 接收 content JSON 与 PrintConfig，输出 PDF 流；节点类型→渲染逻辑；previewMode 控制限页与审计 |
| PrintConfigResolver | 合并系统/文书类型/模板/请求体 PrintConfig |
| PdfPreviewCache（可选） | contentHash+configHash 短 TTL 缓存预览 PDF |
| DocumentRepository | findById、findByPatientIdAndEncounterId、save；若用数据项名索引则保存后触发索引更新 |

### 7.3 与 zxplat-framework 的对接

- **实体**：继承 `BaseAuditedEntity`（审计列：created_at、updated_at、created_by、updated_by、is_deleted、deleted_at、deleted_by）；实体类名不带 Entity 后缀；多租户实现 `IMultiTenant` 并设 tenant_id。
- **API 参数**：所有 AppService 方法仅接受 **单个 Request 对象**，禁止 `getById(Long id)`、`delete(Long id)` 等；单 id 操作用 `IdRequest` 或 `DeleteXxxRequest`（见《API参数标准化说明》）。
- **Request 命名**：查询 `Query{Entity}Request` 并继承 `BaseQueryRequest`（pageNo、pageSize、sortBy、sortDirection、keyword）；创建 `CreateXxxRequest`；更新 `UpdateXxxRequest`（必须含 id）；删除 `DeleteXxxRequest`。
- **对象映射**：**必须**使用 MapStruct（componentModel = "spring"，nullValuePropertyMappingStrategy = IGNORE）；**禁止** BeanUtils；Entity↔Dto、Request→Command 均经 Mapper。
- **异常**：使用框架 `BusinessException`、`EntityNotFoundException`、`ValidationException`、`UnauthorizedException`。
- **Flyway**：**所有**迁移脚本**仅**放在 `zxplat-framework/zxplat-framework/src/main/resources/db/migration/`；**不得**在 zxplat-module-emr 或其它业务模块内单独放置；EMR 脚本版本号 V13 及以上；命名 `V{版本号}__{描述}.sql`。
