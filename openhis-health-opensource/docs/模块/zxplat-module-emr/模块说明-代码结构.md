## Maven 父工程

`zxplat-plugin/zxplat-module-emr`（artifact：`com.zxplat:zxplat-module-emr`）

## 子模块与 Java 包

| Maven 模块 | Java 根包 | 职责 |
|------------|-----------|------|
| `module-emr-domain` | `com.zxplat.plugin.emr.domain` | 文书实体、仓储、Command/Result、`EmrAdmissionContextLoader` / `EmrPdfRenderer` 端口 |
| `module-emr-bridge` | `com.zxplat.plugin.emr.bridge` + `…bridge.integration` | ContextLoader 实现、ExtensionImpl、Orchestrator |
| `module-emr-application` | `com.zxplat.plugin.emr.application` | EMR UI AppService、Flyway(`emr`)、PDF 渲染适配 |
| `module-emr-starter` | （无业务源码） | 聚合 domain + bridge + application |

**废止**：`emr-contracts`、`emr-adapter`  
**无 gateway**（领域型）

## 依赖（现行）

```text
module-emr-domain        → zxplat-framework
module-emr-bridge        → module-emr-domain + zxplat-domain + zxplat-framework
module-emr-application   → module-emr-domain + zxplat-framework
module-emr-starter       → domain + bridge + application
```

bridge **禁止**依赖 `module-emr-application`；application **禁止**依赖 `module-emr-bridge`（maven-enforcer）。

## 各层边界

### module-emr-domain

| 允许 | 禁止 |
|------|------|
| `emr_*` 表读写；`{cap}/entity\|repository\|service` | `import …gateway.*`；依赖 application / bridge |
| `loader/` HIS enrichment 端口；`document/access` PDF 端口 | 直接改 `zxplat-domain` 实体；写入 application/bridge 实现细节 |

包：`document/` · `template/` · `metadata/` · `loader/` · `enums/`  
端口：`EmrAdmissionContextLoader`（bridge 实现）· `EmrPdfRenderer`（application 适配）

契约文档：[DomainModel/](./DomainModel/说明.md)

### module-emr-bridge

| 允许 | 禁止 |
|------|------|
| `bridge.integration.*ExtensionImpl`；`metadata/context/` loader 实现 | 依赖 `module-emr-application` |
| `diagnosis/workflow/` 编排；注入 domain `EmrPdfRenderer` 端口 | 根级扁平 `context/`；业务膨胀进 ExtensionImpl |

双根包：`…bridge.integration`（ExtensionImpl）· `…bridge`（ContextLoader / Orchestrator / config）  
元数据链：application `EmrMetadataContextBuilder` → domain loader 端口 → bridge `EmrAdmissionContextLoaderImpl`

### module-emr-application

| 允许 | 禁止 |
|------|------|
| `{cap}/service\|request\|response`；`metadata/support/` | 依赖 `module-emr-bridge`；直接改 `zxplat-domain` |
| 注入 domain `loader` 端口；实现 `EmrPdfRenderer` | 依赖 bridge 具体类；在 AppService 散落 PDF 逻辑 |

包：`document/` · `documentType/` · `template/` · `metadataField/` · `encounterMetadata/` · `metadata/support/` · `pdf/` · `config/`  
资源：`META-INF/zxplat/`（Flyway / 模块元数据）；`EmrAutoConfiguration`

契约文档：[AppService/](./AppService/) · [AppService-SDD/](./AppService-SDD/)

### module-emr-starter

装配入口（无业务 Java）。开关 `zxplat.modules.emr.enabled=true`；AutoConfiguration 链 `EmrBridgeAutoConfiguration` → `EmrAutoConfiguration`。  
宿主（Wave4）：`-Pwith-emr` → 本 starter。

## 装配

```bash
mvn -pl zxplat-plugin/zxplat-module-emr/module-emr-starter -am compile
```

开关：`zxplat.modules.emr.enabled=true`
