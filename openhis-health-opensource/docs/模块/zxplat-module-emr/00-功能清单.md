# ZXPlat EMR 功能清单（Tiptap + Java + OpenPDF）

> 基于 **Tiptap（前端编辑器）+ Java（服务端）+ OpenPDF（打印/PDF 渲染）** 技术栈规划，经技术边界裁剪后用于指导概要设计。

---

## 一、技术栈与裁剪说明

### 1.1 技术选型


| 层次          | 技术                        | 职责与边界                                                                                                           |
| ----------- | ------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **前端编辑器**   | Tiptap（ProseMirror）       | 富文本编辑、自定义块/节点（区域、数据组、数据元）、模板与书写模式、选区与 JSON 导出；不负责「真实分页」与「打印机续打」，分页与打印由服务端 PDF 承担。                               |
| **服务端**     | Java（**zxplat-framework**） | 文档 CRUD、模板存储、权限与审计、诊断/检查检验对接、保存前校验；接收前端文档（JSON/HTML）并驱动 OpenPDF 生成 PDF。详见《概要设计》第四节「服务端技术栈与 zxplat-framework 约定」。 |
| **打印与 PDF** | OpenPDF                   | 服务端将文档内容渲染为 PDF（页眉页脚、水印、页码、多页）；支持按页、按范围输出；不依赖浏览器打印对话框。                                                          |


### 1.2 实现方式约定（概要设计依据）

- **文档模型**：以 Tiptap/ProseMirror 的 JSON 为存储与交换格式；区域/数据组用**自定义 Block Node**，数据元（文本框、下拉、日期等）用**自定义 Node + NodeView**（Vue 组件），按 `attrs.id`/`attrs.name` 做按名称取值赋值（名称即《概要设计》所称**数据项名**）。
- **模板与书写模式**：模板即「预置了区域/数据组/数据元结构的文档」；书写模式 = 编辑器 schema 限制（仅允许在数据元内输入、禁止删除块级结构），或只读 + 可编辑节点白名单。
- **打印与导出**：前端将当前文档（或选区）JSON/HTML 提交服务端；Java 用 OpenPDF 将内容排版为 PDF（分页、页眉页脚、水印），返回 PDF 流供「预览」（浏览器打开）或「下载/打印」。**续打** = 服务端生成「从第 N 页起」的 PDF 或「仅指定段落/区域」的 PDF，由前端或业务传入页号/选区范围。
- **留痕与版本**：留痕可在前端用 Tiptap 扩展（如 track changes 类 mark）或业务层「保存时快照 +  diff」实现；版本列表、回滚、痕迹提交由服务端存储与接口提供。

### 1.3 裁剪与降级


| 原功能                           | 裁剪/降级说明                                                                                         |
| ----------------------------- | ----------------------------------------------------------------------------------------------- |
| 1.11 导出 OFD                   | **暂不实现**；OpenPDF 为 PDF，OFD 需另选库，后续可单独模块。                                                        |
| 6.12 静默打印                     | **依赖客户端**：服务端仅提供 PDF 流；静默打印需本地打印程序或浏览器扩展配合。                                                     |
| 6.8 续打细化 / 6.9 满页打 / 6.10 奇偶页 | **以 PDF 能力实现**：服务端生成 PDF 时支持指定页码范围、奇偶页；「续打」即生成从某页起或仅某段内容的 PDF。                                  |
| 4.1.4 按页获取区域名                 | **以「按块/按区域」替代**：Tiptap 无真实页，按块（block）或区域节点列表对应到 OpenPDF 渲染后的页；服务端解析 JSON 可输出「块/区域 → 预估页号」供续打参数。 |
| 4.4.2 / 4.4.3 不打开文档解析结构       | **服务端解析**：Java 解析文档 JSON 提取区域/数据组/数据元名列表，不依赖前端打开编辑器。                                            |
| 13.1 体温单 / 13.2 产程图           | **前端图表 + 服务端出图**：Tiptap 中嵌自定义 Vue 组件（图表库）；打印时前端提交数据或服务端用 OpenPDF 绘图/贴图生成 PDF。                   |
| 13.3 医学表达式（牙位图等）              | **自定义 NodeView**：Tiptap 自定义节点 + Vue 组件渲染；PDF 由服务端用图片或 OpenPDF 绘制。                               |


### 1.4 与外部系统对接边界

与 HIS（患者/就诊）、LIS/PACS（检查检验、影像）的接口形式、协议（如 REST/HL7/FHIR）及数据源由对接方案或项目约定；EMR 侧预留接口抽象与适配层，避免与具体医院实现强绑定。

**12.1（HIS 患者/就诊）范围约定**：EMR **不**提供、也**不要求**在 EMR 内实现患者/就诊**列表**接口。宿主业务（如门诊/住院医生站、zxplat-domain 就诊队列）负责选人与展示；EMR 仅接收并持久化 **`patientId`、`encounterId`**，用于文书 `create` / `getContent` / `getList` / 元数据解析等。患者姓名、科室等展示与列表筛选归属宿主或 **2.1 患者维度文书列表**，不计入 12.1 未完成项。

## 二、阶段与优先级说明


| 阶段     | 说明       | 目标                                                        |
| ------ | -------- | --------------------------------------------------------- |
| **P0** | 必须首期完成   | 按患者打开/保存病历文书，Tiptap 基础编辑与持久化，患者与文档对接、文档存储可用。              |
| **P1** | 核心病历业务   | 模板、结构化（区域/数据组/数据元）、书写模式、诊断与检查检验列表及引用到文书。                  |
| **P2** | 打印、留痕、合规 | 服务端 OpenPDF 生成 PDF、预览与下载、页眉页脚、修订留痕、权限与审计、质控基础、病案首页与编码。    |
| **P3** | 增强与专科    | 批注、签章、公式、智能输入、续打（基于 PDF 范围）、水印、专科文书（体温单/产程图/病程/护理/知情同意等）。 |


**用户与角色**：医生（书写、修改、打印、模板、患者文书列表）；护士（护理文书）；管理员/医务（模板管理、权限、审计）。

## 四、非功能需求


| 类别      | 要点                                                               |
| ------- | ---------------------------------------------------------------- |
| **性能**  | 单文档 content 大小上限（如 2MB）；列表分页大小；保存/打开响应时间目标（如 P95 < 3s）；PDF 生成超时。 |
| **可用性** | 自动保存间隔与重试；离线编辑与恢复策略（若需要）。                                        |
| **安全**  | 敏感字段脱敏（日志/审计）；会话超时。                                              |
| **兼容性** | 支持浏览器范围（如 Chrome/Edge 最新两版）；分辨率或移动端是否支持。                         |
| **合规**  | 电子病历保存期限、审计日志保留策略（可与 zxplat-framework audit 一致）。                            |


详细可在产品说明/需求规格中展开，本清单仅列要点。

## 七、使用说明（概要设计）

- **状态列**：☐ 未开始；☑ 进行中（部分落地、仅后端/仅前端、或替代方案）；✔ 已完成（前后端可验收或该层能力已闭环）。
- **状态口径（V14.8）**：对照 `zxplat/zxplat-module-emr`（`DocumentAppService` create/getContent/getList/save/mergePdf）与 `openhis-pro-ui`（`api/emr/document`、`api/emr/pdf`、`MedicalRecordForm`、门诊/住院医生站）；**1.1～1.4 / 2.1 / 12.2** 以医生站嵌入场景验收为 **✔**（新建仅走模板树、无独立空白新建；历史 Tab = 患者维度全量文书列表）。**13.7** 为 **☑**：住院多份病程 + **本就诊全部病程合并打印**（`progressNoteNavList` → `mergePdf`）已落地；转科页眉、续打遮罩仍归 **☐/6.8**。编辑器仍以 `emrDataElement` / `emrMetadataChip` / `layoutLocked` 为主，`region`/`section` 块级结构未落地。
- **12.1 完成定义**：医生站（或同类宿主）向 EMR 传入 `patientId`、`encounterId` 且文书 open/save 使用该上下文即视为 **✔**；`zxplat-domain` `HealthEmrMetadataContextAdapter` + `EmrDiagnosisMetadataContributor` 提供 `patient.*` / `encounter.*` / `diagnosis.*` 元数据扁平键（读模型 JSON 仅内存解析，不下发 API）。不在 EMR 模块内对接 HIS 患者/就诊列表。
- **1.4 完成定义**：`dirty` + `beforeunload`；离开医生站路由（`onBeforeRouteLeave`）；离开病历 Tab、侧栏换患者/队列、快捷切报告 Tab 前 `confirmEmrDiscardUnsaved`；自动保存失败 toast。
- **实现要点**：第五节「功能清单」的「实现要点」直接对应概要设计中的模块划分：**前端 Tiptap**（自定义 Node/NodeView、命令、事件）、**服务端 Java**（接口、存储、校验、OpenPDF 调用）、**OpenPDF**（分页、页眉页脚、水印、多文档合并）。
- **依赖关系**：先实现阶段 1～2（文档 CRUD + 结构化），再模板与模式（阶段 3），再打印与留痕（阶段 4～6），最后临床数据与专科（阶段 7～8）。
- 可根据迭代裁剪 P3 或部分 13.x，OFD、静默打印见第一节裁剪说明。
- **验收标准 / 完成定义**：功能项视为完成需满足：接口可用、前端可操作、与实现要点一致、无 P0 缺陷；迭代验收时按此判定。
