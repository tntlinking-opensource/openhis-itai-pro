# ZXPlat EMR 元数据字段定义与维护

> 依据《[概要设计](01-概要设计.md)》《[功能清单](00-功能清单.md)》《[UI交互说明](02-交互说明.md)》《[详细设计](03-详细设计.md)》《[打印预览设计](04-打印预览设计.md)》编制，补齐 **患者/就诊上下文元数据**（`fieldKey`）的目录维护、运行时取值与编辑器/打印消费契约。  
> **不包含**：文书结构化 **数据项名**（`attrs.name`，见 UI §2.9）、修订 **留痕元数据**（见详细设计 §2.6）。

---

## 一、文档目的与范围

### 1.1 目的

- 定义 EMR 中「**元数据字段**」的业务含义、与 **数据项名** 的边界，避免与 §2.9 数据项名主数据混用。
- 规定元数据字段的 **维护侧**（目录 CRUD、取值来源、脱敏）与 **消费侧**（模板插入、打开文书刷新、PDF `metadata` 入参）。
- 为功能清单增补条目、详细设计增补表结构与 AppService、前端 `emrEditor` 替换写死 `DEFAULT_METADATA_FIELDS` 提供统一真源。

### 1.2 范围

| 在范围内 | 不在范围内 |
|----------|------------|
| 患者/就诊/文书级占位字段（姓名、性别、病历号、科室、床号等） | 区域/数据组/数据元上的 **数据项名**（主诉、现病史等） |
| `emrMetadataChip` / 行内元数据节点的 `fieldKey`、`label`、`editable` | 留痕记录表、版本 diff 元数据 |
| 元数据字段定义表、管理端维护页、按就诊取值接口 | 全文检索索引 `emr_document_data_item_index`（仍属数据项名域） |
| 打印/预览时 `GeneratePdfRequest.metadata` 的拼装规则 | HIS/LIS 具体协议（仅约定映射扩展点） |

### 1.3 与现有实现的关系

当前 `openhis-pro-ui` 的 `emrEditor` 在 `editor-defaults.ts` 中 **写死** `DEFAULT_METADATA_FIELDS`，`emr-patient-metadata.ts` 用演示数据映射 `fieldKey → value`。本设计落地后：

1. 管理端维护 `emr_metadata_field_def`；
2. 打开文书/应用模板时调用 **按就诊取元数据值** 接口；
3. 模板编辑「插入元数据」从字段定义列表选择 `fieldKey`；
4. 删除前端写死目录（保留极少量兜底仅用于离线演示，需显式开关）。

## 二、名词与边界

### 2.1 术语（并入概要设计术语表）

| 术语 | 技术对应 | 定义 |
|------|----------|------|
| **元数据字段** | metadata field / `fieldKey` | 表示 **患者、就诊或文书上下文** 的只读或可编辑占位项；在模板/文书中以 `emrMetadataChip`（或统一后的 `emrDataElement` + `widgetOverride`）呈现，通过 `attrs.fieldKey` 绑定。示例：`patientName`、`gender`、`bedNo`。 |
| **元数据字段定义** | metadata field definition | 可维护的目录项：fieldKey、显示名、数据类型、是否可编辑、取值来源、脱敏规则、启用状态等；存 `emr_metadata_field_def`。 |
| **元数据值** | metadata values | 某次打开文书时，`fieldKey → string` 的键值对；由就诊上下文解析得到，可覆盖 chip 上的 `attrs.value`。 |
| **数据项名** | `attrs.name` on region/section/dataElement | 文书 **结构内** 业务字段标识，见概要设计术语表；**不得**与 `fieldKey` 共用同一命名空间。 |

### 2.2 与《UI交互说明》§2.9 的区分

| 维度 | 元数据字段（本文档） | 数据项名（§2.9） |
|------|----------------------|------------------|
| 标识 | `fieldKey`（建议 camelCase 或 snake_case，全局唯一） | `attrs.name`（文书内逻辑名，如「主诉」） |
| 存储 | 定义表 + 运行时值接口；节点 attrs 仅存 fieldKey/快照 | 主要在 `content` JSON 内 |
| 典型用途 | 页眉患者条、模板标题区、只读患者信息 | 病历结构化录入、质控、按名赋值 |
| 维护菜单 | **元数据字段维护**（本文 §六） | **数据项名列表/检索**、可选 **数据项名主数据**（§2.9.2） |

### 2.3 编辑器节点约定

与《打印预览设计》§3.4 及现有 `emr-metadata-chip` 扩展对齐：

| 属性 | 类型 | 说明 |
|------|------|------|
| `fieldKey` | string | 绑定元数据字段定义，**必填** |
| `label` | string | 显示标签快照；插入时从定义复制，可随模板保存 |
| `value` | string | 展示值；`editable=false` 时由 `metadataValues[fieldKey]` 刷新覆盖 |
| `editable` | boolean | `false`：仅展示绑定值；`true`：允许在正文内手工改展示文本（不落回患者主档） |

> **演进**：新 Schema 可将元数据统一为 `dataElement` + `elementId === fieldKey`；打印渲染器对 `emrMetadataChip` 与等价 dataElement **注册别名**，见《打印预览设计》§3.4 说明。

## 三、业务规则

### 3.1 字段定义生命周期

1. **新增**：管理员在「元数据字段维护」创建 `fieldKey`（租户内唯一）、显示名、类型、取值来源等；默认启用。
2. **修改**：可改显示名、排序、脱敏、启用状态；**禁止修改已发布模板的 fieldKey**（若需改名：新增 fieldKey + 模板批量替换，另立迁移任务）。
3. **禁用**：禁用后不可在新模板中插入；已存在节点保留 fieldKey，取值接口对该 key 返回空或占位「—」，打印时可配置跳过或显示空。
4. **删除**：仅允许 **从未被任何模板 content 引用** 的定义物理删除；否则只能禁用（可选：提供「引用检查」接口）。

### 3.2 取值与刷新

| 规则 | 说明 |
|------|------|
| 取值时机 | 打开文书、切换就诊、应用模板、患者条信息变更时，重新拉取 **就诊元数据值** |
| 优先级 | 请求体 `metadataOverrides`（`REQUEST`）> 正文已保存的可编辑值 > 各 `value_source` 解析结果 > `default_value` > 空字符串 |
| 可编辑字段 | `editable=true` 时，用户改动的 `attrs.value` 以文档 content 为准保存；刷新就诊时 **不覆盖** 用户已改动的节点（以节点 id 或 dirty 标记判断，详细设计实现） |
| 不可编辑字段 | `editable=false` 时，每次刷新用最新 `metadataValues[fieldKey]` 写回节点展示 |
| 脱敏 | 定义表配置 `mask_rule`（如身份证中间位、手机号）；列表/打印/审计日志按规则脱敏展示 |

### 3.3 取值来源（value_source）

`value_source` 表示 **运行时由谁、从哪类上下文取值的策略**，不是具体字段路径。具体路径写在 `source_path`；字典编码、表达式、外部接口参数等写在 **`source_config`（JSONB）**（见 §3.3.2、§4.1）。

解析器按来源 **分组批量加载上下文**（一次拉患者、一次拉就诊、一次拉机构…），再对同组字段批量映射，避免按 fieldKey 逐条调 HIS。

#### 3.3.1 枚举一览（按类别）

**A. 主数据与就诊（HIS / zxplat-domain 读模型）**

| 枚举 code | 含义 | `source_path` 示例 | 说明 |
|-----------|------|-------------------|------|
| `PATIENT` | 患者主档 | `patient.name`、`patient.gender` | 患者维度，不随单次就诊变化（或取「当前患者」最新主档） |
| `ENCOUNTER` | 当前就诊 | `encounter.deptName`、`encounter.bedNo` | 门诊/住院就诊读模型；无 `encounterId` 时跳过或回退 `default_value` |
| `ADMISSION` | 住院/入院 episode | `admission.wardName`、`admission.admissionTime` | 与门诊就诊区分；住院文书页眉常用 |
| `INSURANCE` | 医保/费别 | `insurance.payorName`、`insurance.insuranceType` | 患者或就诊关联的医保信息 |

**B. 机构、科室、人员（组织与权限域）**

| 枚举 code | 含义 | `source_path` 示例 | 说明 |
|-----------|------|-------------------|------|
| `ORG` | 机构/租户 | `org.name`、`org.code` | 院区名、机构编码；多院区时与当前登录院区一致 |
| `DEPT` | 科室 | `dept.name` | 默认 **就诊科室**；`source_config.deptScope` 可指定 `encounter` / `login` / `document` |
| `WARD` | 病区/护理单元 | `ward.name` | 通常来自就诊/入院，非独立患者属性 |
| `PRACTITIONER` | 医务人员 | `practitioner.attendingName`、`practitioner.primaryNurse` | 主治、管床护士等；路径指向就诊或入院上的角色字段 |
| `USER` | 当前操作用户 | `user.displayName`、`user.title` | 记录人、打印人、当前登录名；**随会话变化** |
| `USER_DEPT` | 当前用户所属科室 | `user.deptName` | 与 `DEPT`（就诊科室）区分，用于「xx 科 医师签名」类页眉 |

**C. 文书与 EMR 自身**

| 枚举 code | 含义 | `source_path` 示例 | 说明 |
|-----------|------|-------------------|------|
| `DOCUMENT` | 当前文书属性 | `document.title`、`document.documentTypeName` | 来自 `emr_document` 及关联文书类型 |
| `TEMPLATE` | 所用模板 | `template.name`、`template.code` | 新建时来源模板；仅展示用 |
| `VERSION` | 版本/留痕（P2+） | `version.number`、`version.lastModifiedAt` | 打印修订稿、版本号页眉 |

**D. 临床摘要（只读「展示用」聚合，非数据项名）**

| 枚举 code | 含义 | `source_path` / `source_config` | 说明 |
|-----------|------|--------------------------------|------|
| `DIAGNOSIS` | 诊断摘要 | `diagnosis.primaryDisplay`；config：`role=primary`、`maxCount=1` | 主诊断一行字；多条时用 `source_config` 控制拼接 |
| `ALLERGY` | 过敏摘要 | `allergy.summary` | 过敏史一行展示 |
| `VITAL_SIGN` | 体征摘要（P2+） | `vitalSign.latest.bp` | 最新体征，非全文结构化录入 |
| `LAB_SUMMARY` | 检验摘要（P2+） | `lab.summary` | 危急值/异常摘要进页眉时需脱敏与权限 |
| `EXAM_SUMMARY` | 检查摘要（P2+） | `exam.summary` | 同上，对接 LIS/PACS 适配层 |

> **边界**：写入文书 **结构化段落** 仍走 **数据项名** + 诊断/检验 **带入**（功能清单 10.x、11.x）；上表仅用于页眉、标题区、只读 chip 等 **元数据展示**，不替代 `dataElement`。

**E. 平台字典、读模型与配置**

| 枚举 code | 含义 | 配置方式 | 说明 |
|-----------|------|----------|------|
| `DICT` | 系统字典 | `source_config`: `{ "dictType": "gender", "codePath": "patient.gender" }` | 先取 code 再译 label；与 whale 字典服务一致 |
| `READ_MODEL` | 指定读模型查询 | `source_config`: `{ "model": "EncounterRm", "query": "byId", "path": "deptName" }` | 与项目读模型/RMQueryService 对齐；避免 EMR 硬编码 SQL |
| `SETTING` | 系统/EMR 配置项 | `source_config`: `{ "key": "emr.print.defaultOrgName" }` | 机构级参数、水印默认文案等 |

**F. 运行时、常量与派生**

| 枚举 code | 含义 | 配置方式 | 说明 |
|-----------|------|----------|------|
| `SYSTEM` | 系统运行时 | `source_path`: `system.now`、`system.today`、`system.printedAt` | 服务器时区；打印时用 `printedAt` |
| `CONST` | 固定常量 | `default_value` | 不依赖上下文 |
| `EXPR` | 表达式派生（P1 可选 / P2 完善） | `source_config`: `{ "expr": "{deptName}-{bedNo}" }` | 引用已解析的其它 `fieldKey`；禁止访问数据项名 |
| `FIELD_REF` | 引用其它元数据字段 | `source_config`: `{ "refFieldKey": "deptName" }` | 同次 resolve 内依赖排序；用于 label 拼接 |

**G. 外部与调用方**

| 枚举 code | 含义 | 配置方式 | 说明 |
|-----------|------|----------|------|
| `HTTP_API` | 配置化外部 HTTP | `source_config`: `{ "provider": "hisPatient", "path": "/..." }` | 走 EMR 适配器注册表，禁止在定义表写死 URL 密钥 |
| `REQUEST` | 调用方覆盖 | 无 path；仅当请求体 `metadataOverrides` 含该 key | 与 §3.2 优先级最高档一致；用于医生站、第三方壳传入 |
| `MANUAL` | 无自动取值 | 仅 `default_value` + 正文 `attrs.value` | 纯手工 chip；刷新时不从 HIS 覆盖 |

#### 3.3.2 `source_path` 与 `source_config`

| 字段 | 适用来源 | 约定 |
|------|----------|------|
| **source_path** | PATIENT、ENCOUNTER、DOCUMENT、SYSTEM 等 | 点分路径，与适配器 DTO 对齐；**禁止** SQL。全院映射表单独维护：《EMR 元数据 source_path 映射表》（对接文档，可后补） |
| **source_config** | DICT、READ_MODEL、 EXPR、HTTP_API、DIAGNOSIS 等 | JSON 对象；管理端按 `value_source` 展示不同表单控件 |
| **default_value** | CONST、MANUAL、解析失败回退 | 任意来源解析为空时的兜底 |

**解析失败**：记录 warn 日志；返回值优先 `default_value`，否则空串；打印/打开文书 **不阻断**（见 §九）。

#### 3.3.3 实现阶段建议

| 阶段 | 建议实现的 value_source |
|------|-------------------------|
| **P1** | PATIENT、ENCOUNTER、DOCUMENT、ORG、DEPT、USER、CONST、SYSTEM、REQUEST、MANUAL |
| **P1.5** | ADMISSION、WARD、PRACTITIONER、USER_DEPT、TEMPLATE、DICT、FIELD_REF |
| **P2** | EXPR、DIAGNOSIS、READ_MODEL、SETTING、INSURANCE、VERSION |
| **P2+** | ALLERGY、VITAL_SIGN、LAB_SUMMARY、EXAM_SUMMARY、HTTP_API |

#### 3.3.4 与功能清单外部对接的关系

| 外部系统 | 主要 value_source | 说明 |
|----------|-------------------|------|
| 就诊上下文（12.1） | PATIENT、ENCOUNTER、ADMISSION、INSURANCE | 宿主传入 **patientId/encounterId**；Resolver 经 `EmrMetadataContextReader` 按 ID 拉主数据；**不含** EMR 患者/就诊列表 |
| 组织/用户/权限 | ORG、DEPT、WARD、USER、PRACTITIONER | zxplat-framework / 科室主数据 |
| 诊断 | DIAGNOSIS（摘要）；带入正文仍用 10.3 + 数据项名 | 不重复建设 |
| LIS/PACS | LAB_SUMMARY、EXAM_SUMMARY（可选） | 11.x 列表与引用为主，元数据仅摘要 |
| 字典 | DICT | 与 4.3.11 下拉字典同源 |

### 3.4 与打印、页眉占位符

- `GeneratePdfRequest.metadata`：调用方 **可传** 完整 Map；未传时服务端按 `documentId` + `encounterId` 调用同一套 **解析器** 生成（与打开文书一致）。
- PrintConfig 页眉页脚模板占位符（如 `{patientName}`）与 `fieldKey` **同名**，由 `MetadataValueResolver` 统一填充，见《打印预览设计》§4.1 header/footer template。

## 四、数据模型

### 4.1 emr_metadata_field_def（元数据字段定义）

| 列名 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键，雪花 |
| field_key | VARCHAR(64) UNIQUE | 机器名，租户内唯一；插入模板后不宜修改 |
| label | VARCHAR(128) | 显示名（如「患者姓名」） |
| data_type | VARCHAR(16) | string / number / date / datetime（影响格式化与校验） |
| editable_default | BOOLEAN | 插入 chip 时默认是否可编辑 |
| value_source | VARCHAR(32) | §3.3 枚举 code |
| source_path | VARCHAR(256) | 点分路径；DICT/EXPR 等可为空 |
| source_config | JSONB | 可选；字典、读模型、表达式、HTTP 提供者等，见 §3.3.2 |
| default_value | VARCHAR(512) | 常量或缺省回退 |
| mask_rule | VARCHAR(32) | 脱敏规则 code：NONE / ID_CARD / PHONE / CUSTOM |
| format_pattern | VARCHAR(64) | 日期等展示格式，可空 |
| sort_order | INT | 列表排序 |
| is_enabled | BOOLEAN | 是否启用 |
| remark | VARCHAR(512) | 备注 |
| created_at, updated_at, created_by, updated_by, is_deleted, deleted_at, deleted_by | - | BaseAuditedEntity |
| tenant_id | BIGINT | 多租户 |

索引：`field_key`（+ `tenant_id`）；`is_enabled`。

### 4.2 与 content 的关系

- **不**在定义表存具体患者值；患者值来自运行时接口或 HIS 适配。
- 模板/文档 content 内节点仅保存 `fieldKey` 及用户改过的 `value`（可编辑时）。

### 4.3 初始种子数据（建议）

与当前前端演示对齐，便于迁移：

| field_key | label | editable_default | value_source | source_path |
|-----------|-------|------------------|--------------|-------------|
| patientName | 患者姓名 | true | PATIENT | patient.name |
| gender | 性别 | false | PATIENT | patient.gender |
| age | 年龄 | false | PATIENT | patient.age |
| idCard | 证件号 | false | PATIENT | patient.idCard |
| medicalRecordNo | 病历号 | false | PATIENT | patient.medicalRecordNo |
| phone | 电话 | true | PATIENT | patient.phone |

阶段 1.5 可扩展示例：

| field_key | label | value_source | source_path |
|-----------|-------|--------------|-------------|
| deptName | 科室 | ENCOUNTER | encounter.deptName |
| bedNo | 床号 | ENCOUNTER | encounter.bedNo |
| orgName | 机构名称 | ORG | org.name |
| recorderName | 记录人 | USER | user.displayName |

| primaryDiagnosis | 主诊断 | DIAGNOSIS | diagnosis.primaryDisplay |

## 五、接口设计

遵循 zxplat-framework：`POST /api/app/{serviceName}/{methodName}`，单参 Request。

### 5.1 元数据字段定义服务（metadataField）

| 方法 | 说明 | Request | 返回 |
|------|------|---------|------|
| getList | 分页列表（管理端） | QueryMetadataFieldRequest | 分页 MetadataFieldDto |
| getEnabledList | 启用中的全量/按关键字（模板插入下拉） | QueryEnabledMetadataFieldRequest | List\<MetadataFieldDto\> |
| getById | 详情 | IdRequest | MetadataFieldDto |
| create | 新增 | CreateMetadataFieldRequest | 含 id |
| update | 更新 | UpdateMetadataFieldRequest | - |
| delete | 删除（带引用检查） | DeleteMetadataFieldRequest | - |
| checkReference | 是否被模板引用 | CheckMetadataFieldReferenceRequest | { referenced: boolean, templateNames: [] } |

**MetadataFieldDto（核心字段）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键 |
| fieldKey | String | field_key |
| label | String | 显示名 |
| dataType | String | string/number/date/datetime |
| editableDefault | Boolean | 默认可编辑 |
| valueSource | String | §3.3 |
| sourcePath | String | 来源路径 |
| sourceConfig | Object | JSON，§3.3.2 |
| defaultValue | String | 常量/缺省 |
| maskRule | String | 脱敏 |
| formatPattern | String | 格式 |
| sortOrder | Integer | 排序 |
| isEnabled | Boolean | 启用 |

### 5.2 就诊元数据值服务（encounterMetadata）

| 方法 | 说明 | Request | 返回 |
|------|------|---------|------|
| resolveValues | 按就诊解析元数据值 | ResolveEncounterMetadataRequest | Map\<String,String\> 或 MetadataValuesDto |
| resolveForDocument | 按文档 ID 解析（内部取 patientId/encounterId） | ResolveDocumentMetadataRequest | 同上 |

**ResolveEncounterMetadataRequest**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| patientId | String/Long | 是 | 患者 ID |
| encounterId | String/Long | 否 | 就诊 ID；无则仅 PATIENT 来源 |
| documentId | Long | 否 | 用于 DOCUMENT 来源 |
| fieldKeys | List\<String\> | 否 | 仅解析指定 key；空则解析全部启用定义 |

**返回**：`values: Record<fieldKey, string>`；可选 `maskedFields: string[]` 供前端展示脱敏提示。

**实现要点**：

- `MetadataValueResolver`：加载启用定义 → 按 `value_source` **分组**（§3.3.1）→ 各 `MetadataSourceProvider` 批量填充上下文 → 逐字段 `source_path` / `source_config` 映射 → `FIELD_REF`/`EXPR` 二次 pass → 格式化、脱敏。
- Provider 示例：`PatientMetadataProvider`、`EncounterMetadataProvider`、`OrgUserMetadataProvider`、`DiagnosisSummaryProvider`、`DictMetadataProvider`（可插拔注册）。
- 与 `DocumentAppService.getContent` 可合并为一次往返（getContent 响应中带 `metadataValues`），减少前端请求。

### 5.3 文档打开响应扩展

**GetDocumentContentResponse** 增加（与详细设计 §3.1 对齐）：

| 字段 | 类型 | 说明 |
|------|------|------|
| metadataValues | Map\<String,String\> | 当前就诊解析结果 |
| metadataFields | List\<MetadataFieldDto\> | 可选；插入器用的启用字段列表，可缓存 |

### 5.4 打印接口（已有字段，行为固化）

`GeneratePdfRequest.metadata`（《详细设计》§3.3）：

- 调用方传入则与服务端解析结果 **合并**（调用方优先）。
- 未传且存在 `documentId`/`encounterId` 时，服务端自动 `resolveValues`。

## 六、UI 与交互

### 6.1 信息架构

- 主导航增加：**元数据字段**（与「模板管理」「数据项名」并列）。
- 路由建议：`/emr/metadata-field`（列表）、`/emr/metadata-field/:id`（编辑，可选抽屉代替）。

### 6.2 元数据字段维护页（管理端）

| 区域 | 内容 |
|------|------|
| 筛选 | 关键字（fieldKey/label）、启用状态、取值来源 |
| 列表列 | fieldKey、显示名、数据类型、取值来源、默认可编辑、脱敏、排序、启用、操作 |
| 操作 | 新增、编辑、启用/禁用、删除（未引用时） |
| 新增/编辑表单 | fieldKey（新建可编辑，保存后只读）、显示名、数据类型、**value_source（分组下拉）**、source_path、**source_config（按来源动态表单）**、default_value、editable_default、mask_rule、format_pattern、sort_order、remark |

**校验**：

- fieldKey：字母开头，字母数字下划线，长度 2～64，租户内唯一。
- PATIENT / ENCOUNTER / DOCUMENT / SYSTEM 等：须填 `source_path`（或文档列出的等价 config）。
- DICT / READ_MODEL / EXPR / HTTP_API：须填合法 `source_config`（服务端 JSON Schema 校验）。
- CONST / MANUAL：`default_value` 或允许空（MANUAL 以正文为准）。
- `HTTP_API`：仅允许引用已注册的 `provider` code，禁止裸 URL。

### 6.3 模板编辑页联动

- 工具栏「插入元数据」：下拉来自 `metadataField.getEnabledList`；选中后插入节点，`fieldKey`、`label`、`editable` 来自定义。
- 禁止手工输入未在目录中的 fieldKey（可配置：严格模式 vs 兼容模式允许手工，默认严格）。

### 6.4 文书编辑页

- 打开文书：`getContent` 返回 `metadataValues` → 编辑器 `applyMetadataValues` 刷新 `editable=false` 的 chip。
- 患者条变更：重新 `resolveValues` 并刷新（不覆盖用户已编辑的可编辑 chip，见 §3.2）。

### 6.5 权限

| 操作 | 建议权限码 |
|------|------------|
| 元数据字段维护 CRUD | `Emr.MetadataField.Manage` |
| 模板插入元数据 | `Emr.Template.Edit`（沿用模板权限） |
| 解析就诊元数据值 | `Emr.Document.Read`（打开文书即可） |

## 八、实现阶段与功能清单增补

建议在《功能清单》**业务 P1** 增补（阶段 3 与模板并行）：

| 序号 | 功能项 | 描述 | 实现要点 | 建议优先级 |
|------|--------|------|----------|------------|
| 5.9 | 元数据字段定义维护 | 元数据字段目录 CRUD、启用/禁用 | emr_metadata_field_def + MetadataFieldAppService | P1 |
| 5.10 | 按就诊解析元数据值 | 打开文书/打印时 fieldKey→value | EncounterMetadataAppService + Resolver + HIS 适配 | P1 |
| 5.11 | 模板插入元数据 | 从目录选择 fieldKey 插入 chip | 模板编辑工具栏 + getEnabledList | P1 |
| 5.12 | 元数据脱敏展示 | 证件号、电话等按规则脱敏 | mask_rule + 前后端一致 | P2 |

**实现顺序建议**：

1. 表 + 定义 CRUD + 种子数据迁移（对齐现有 6 个 fieldKey）。
2. `resolveValues`（先 PATIENT 常量映射，再接就诊读模型）。
3. `getContent` 带 `metadataValues`；前端删 `DEFAULT_METADATA_FIELDS` 写死。
4. 管理端维护页；模板插入下拉。
5. 打印自动合并 metadata；页眉占位符与 fieldKey 对齐。

## 九、非功能与安全

| 类别 | 要求 |
|------|------|
| 性能 | `getEnabledList` 可缓存（租户级，定义变更失效）；`resolveValues` 单次打开 < 200ms（P95），宜批量调 HIS |
| 安全 | 证件号等敏感字段必须脱敏；审计日志不记录完整明文 |
| 多租户 | 定义表 tenant_id 隔离；field_key 租户内唯一 |
| 兼容 | 历史模板中未知 fieldKey：取值空、打印占位「」或配置占位符，不阻断打开 |

## 十、迁移与验收

### 10.1 从前端写死迁移

1. Flyway 插入 §4.3 种子行。
2. 前端 `metadataFields` prop 改为接口数据；`FALLBACK_PATIENT_METADATA` 仅 `VITE_EMR_DEMO_MODE=true` 时使用。
3. 回归：模板插入、打开文书刷新、打印 PDF 页眉患者信息、可编辑 chip 保存后再打开不丢值。

### 10.2 验收标准

- [ ] 管理员可增删改查元数据字段定义，禁用后不可新插入。
- [ ] 打开文书时不可编辑字段随就诊信息更新；可编辑字段用户修改可保存。
- [ ] 模板中 chip 的 fieldKey 均来自目录（严格模式）。
- [ ] 打印未传 metadata 时 PDF 页眉/正文 chip 与屏幕一致。
- [ ] 与《UI交互说明》§2.9 数据项名页面、菜单无混淆。
