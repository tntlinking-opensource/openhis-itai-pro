# ZXPlat EMR UI/交互说明（产品原型）

> 依据《[概要设计](01-概要设计.md)》《[功能清单](00-功能清单.md)》《[打印预览设计](04-打印预览设计.md)》编制，用于指导前端界面与交互实现、供设计/产品评审。技术栈：**Tiptap（前端编辑器）+ Vue + Java（服务端）+ OpenPDF（PDF）**。

---

## 文档说明

- **目的**：明确 EMR 主要页面的信息架构、布局、核心交互与状态，便于前端开发与 UI 设计落地。
- **范围**：患者与文书列表、文书编辑（含书写/模板模式）、模板管理、打印预览、诊断与检查检验、留痕与权限等；与功能清单 P0～P3 对应，专科与 P3 增强可后续补充到本说明。
- **阅读对象**：产品、UI/UX、前端开发；与概要设计中的「五、模块划分」「七、接口设计概要」配合使用。
- **线框图**：第二节各主要页面下均配有 **ASCII 线框图**，表示顶栏、侧栏、主区、列表列、按钮等大致布局与文案，便于开发对照实现；线框为示意，实际像素与组件以前端实现为准。

## 一、信息架构与导航

### 1.1 应用结构概览

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  顶栏：Logo / 系统名 | 患者/就诊快捷信息（在文书内时） | 用户、退出          │
├──────────────┬──────────────────────────────────────────────────────────────┤
│  主导航      │  主内容区                                                      │
│  （侧栏）    │                                                                │
│  · 工作台    │  · 工作台：患者列表 / 在院患者 / 我的患者（可选）              │
│  · 病历文书  │  · 病历文书：患者 → 文书列表 → 文书编辑（或直接文书编辑）      │
│  · 模板管理  │  · 模板管理：模板列表、模板编辑                                │
│  · 数据项名  │  · 数据项名：列表/检索（可选：主数据维护）                      │
│  · 诊断/检查 │  · 诊断/检查：按患者/就诊的诊断列表、检查检验结果（可嵌在文书旁）│
│  · 审计/设置 │  · 审计、系统设置（按权限展示）                                │
└──────────────┴──────────────────────────────────────────────────────────────┘
```

- **主导航**：按角色展示；医生见「工作台、病历文书、模板管理（若有权限）、诊断/检查」等；管理员/配置人员可见「模板管理、数据项名、审计、设置」。数据项名菜单用于列表/检索或主数据维护（见 §2.9）。
- **路由约定（建议）**：`/workspace` 工作台，`/emr/patient/:patientId` 患者文书列表，`/emr/document/:documentId` 文书编辑，`/emr/template` 模板列表，`/emr/template/:templateId` 模板编辑，`/emr/data-item` 数据项名列表/维护；具体与 whale 前端路由集成由项目定。

### 1.2 核心用户路径

| 路径 | 说明 |
|------|------|
| 选患者 → 看文书列表 → 新建/打开文书 → 编辑 → 保存/打印 | 最常用：从工作台或病历文书入口选患者，进入该患者的文书列表，新建或打开一份文书，在编辑器中书写，保存或打印。 |
| 新建文书时选文书类型、可选模板 → 进入书写模式 | 新建时选文书类型（如入院记录、病程记录），可选「从模板新建」并选模板，进入后为书写模式（仅数据元可编辑）。 |
| 模板管理 → 编辑模板 → 插入区域/数据组/数据元 | 管理员或授权用户进入模板管理，编辑某模板：可增删区域、数据组、数据元（设计模式）。 |
| 文书内：从诊断/医嘱主动带入 → 保存 | 编辑器工具栏勾选带入纯文本到光标；诊断/医嘱变更仅提醒不自动写；详见 [06](./06-诊断与医嘱主动带入文书.md)。 |
| 打印预览 → 下载 PDF / 打印 | 编辑页操作「打印预览」→ 服务端生成 PDF 在新标签打开；用户可下载或浏览器打印。 |
| 数据项名 → 列表/检索 或 主数据维护 | 管理员进入数据项名菜单：查看/检索来自模板与文档的数据项名（§2.9.1）；若启用数据项标准库则维护数据项名主数据（§2.9.2）。 |

## 二、主要页面与布局

### 2.1 工作台（患者维度）

- **用途**：按患者维度进入病历、展示**患者维度文书列表**（功能 **2.1**）。**不属于 12.1**：患者/就诊队列由 **zxplat-domain 医生站或 HIS 读模型**提供，EMR 工作台若实现列表页亦归为 2.1，而非 HIS 对接。
- **12.1 在嵌入场景下的交互**：门诊/住院医生站侧栏选患者后，向病历编辑区传入 **`patientId`、`encounterId`** 即可；无需 EMR 再提供患者列表 API。
- **布局**（独立 EMR 工作台可选，对应 2.1）：
  - **顶栏**：系统名、当前用户；可选展示「当前科室」「在院患者」筛选。
  - **主区**：患者列表（表格或卡片）。列建议：患者 ID/姓名、性别、年龄、就诊号、科室、床号、最近文书时间、操作。
  - **操作**：「进入病历」或「文书列表」→ 跳转至该患者的文书列表页。
- **筛选与搜索**：按姓名、就诊号、科室、床号等；支持分页。
- **空态**：无患者时提示「暂无患者」或引导选择科室/时间范围。

### 2.2 患者文书列表

- **用途**：展示某患者下所有文书，新建/打开文书（功能 2.1、1.1、1.2）。
- **布局**：
  - **左侧或顶部**：患者基本信息条（姓名、性别、年龄、就诊号、科室、床号）；可折叠。
  - **主区**：文书列表。列建议：文书类型、文档标题（若有）、创建/修改时间、状态（草稿/已提交/已锁定/已归档）、操作（打开、另存为、打印等按权限）。
  - **操作**：「新建文书」按钮 → 打开新建文书弹窗或跳转新建流程。
- **新建文书**：
  - **弹窗或独立步骤**：选择「文书类型」、可选「使用模板」（下拉选模板，对应功能 2.3）；确认后调用新建接口，获得文档 ID 与初始 content，跳转文书编辑页并 setContent。
- **空态**：该患者暂无文书时，列表为空，突出「新建文书」按钮。

### 2.3 文书编辑页（核心）

- **用途**：打开文档、富文本与结构化编辑、保存、打印、诊断/医嘱主动带入、检查引用等（功能 1.2～1.10、3.x、4.x、5.2、6.x、10.3、10.6、11.4）。
- **布局**：
  - **顶栏（页内）**：文档标题（可编辑或从 meta 解析）、患者/就诊简要信息；**操作区**：保存、另存为、打印预览、导出 PDF、留痕视图切换（若已实现留痕）、关闭（返回文书列表）；未保存时标题旁或顶栏显示「未保存」标识；诊断/医嘱变更后可出现**提醒条**（见 §3.6，不自动改正文）。
  - **可选左侧边栏**：检查检验结果列表等（历史方案）；**诊断/医嘱带入以工具栏弹窗为主**（见 [06](./06-诊断与医嘱主动带入文书.md)），不强制左侧诊断列表。
  - **主区**：Tiptap 编辑器全屏或占满主内容区；工具栏固定在编辑器顶部或浮动（Bubble Menu）。
  - **可选右侧**：留痕列表、版本列表、批注列表（P2/P3）；可收起。
- **编辑器内**：
  - **区域（Region）**：块级，带标题（如「主诉」「现病史」）；可折叠；书写模式下不可删除。
  - **数据组（Section）**：可重复、可嵌套；书写模式下不可删改结构。
  - **数据元（DataElement）**：文本框、数值、日期、下拉、多选、复选框等，由 NodeView 渲染；书写模式下仅数据元可编辑。
- **工具栏**：段落/标题、加粗/斜体/下划线、列表、表格、图片、链接、分页符、日期时间、**从诊断带入**、**从医嘱带入**、插入区域/数据组/数据元（书写模式下结构插入可隐藏或禁用）；撤销/重做；查找替换（可选）。
- **只读时**：整文档只读或仅数据元不可编辑；顶栏可保留「打印预览」「导出 PDF」；带入按钮禁用；根据权限显示「只读」提示文案（功能 8.4）。

│  （未保存时 ● 未保存；诊断/医嘱更新时黄条：可重新带入 [带入诊断][带入医嘱][×]）     │

### 2.5 打印预览

> 可渲染节点、PrintConfig 字段、previewMode 约定见《[打印预览设计](04-打印预览设计.md)》。

- **用途**：服务端 OpenPDF 根据当前文档 JSON + PrintConfig 生成 PDF；与正式打印/导出共用同一渲染器（功能 6.1～6.4、6.11、6.13）。
- **双层预览**：
  - **L1（编辑区）**：emrEditor A4 纸面、页边距、分页符占位；每次编辑即时刷新，不请求服务端。
  - **L2（权威 PDF）**：右侧分栏 iframe 或新标签展示 OpenPDF 结果；**禁止**每次按键请求；MVP 手动刷新，v2 停手 debounce（约 1.2s）。
- **交互**：
  - 「打印预览」/「刷新预览」→ `generatePdf(previewMode=true)`，提交 `getJSON()` + `printConfig` + 可选 `pageRange`/`regionNames`/`includeTrackChanges`。
  - 预览成功后展示 PDF；标记「预览同步于 HH:mm:ss」；content 变更后提示「内容已修改，点击刷新预览」。
  - 「导出 PDF」/「正式打印」→ `previewMode=false`，强制刷新最新 PDF 后下载或 `usePdfPrint`。
  - 可选「打印选项」抽屉：页范围、按区域（数据项名多选）、留痕、水印；页边距与编辑器工具栏预设同步（mm）。
- **布局（阶段）**：MVP 新标签全屏 PDF；v2 左编辑 + 右预览分栏。

### 2.6 诊断与检查检验（列表/侧栏）

- **用途**：按患者/就诊查看诊断与检查检验结果，并带入或引用到文书（功能 10.1～10.4、11.1～11.4）。
- **布局**：
  - **独立页**：可为「诊断管理」「检查检验」菜单下的列表页，支持按患者/就诊筛选，列表 + 详情。
  - **文书编辑页内**：左侧边栏 Tab「诊断」「检查检验」；诊断列表支持「带入文书」「引用」；检查检验列表支持「引用到文书」→ 在光标处或指定数据元插入引用内容。
- **交互**：「带入文书」→ 调用按数据项名赋值接口或前端按名称写回数据元；「引用」→ 插入引用节点或写入指定数据元 value。

### 2.7 版本与留痕（P2）

- **用途**：版本列表、回滚、留痕视图切换、痕迹列表与提交（功能 7.1～7.6）。
- **布局**：
  - **版本列表**：侧栏或弹窗；列表项：版本号、保存时间、操作人；操作「回滚」→ 确认后服务端写回该版本内容，前端 setContent。
  - **留痕视图**：编辑区内「留痕视图」「清洁视图」切换；留痕时展示删除线、高亮新增等。
  - **痕迹列表**：可选侧栏；列出当前未提交痕迹，操作「提交痕迹（落稿）」。

### 2.8 审计与权限（P2）

- **用途**：审计日志查询；按权限控制菜单与按钮（功能 8.1～8.4、8.3）。
- **布局**：
  - **审计**：列表页，筛选条件（时间、用户、操作类型、文档）；列：时间、用户、操作（打开/保存/打印）、文档/患者等。
  - **权限**：菜单与按钮根据角色/权限显示或隐藏；无权限时接口返回 403，前端 toast 提示；只读文档时顶栏或文档内提示「当前为只读」等可配置文案。

### 2.9 数据项名相关页面（依据概要设计二、六、7.4）

依据《概要设计》：**数据项名**为区域、数据组、数据元在文书/模板中的唯一标识名（`attrs.name`），用于按名取值/赋值、结构解析、按区域打印、质控、统计与检索。数据项名**随文档/模板 content 存储**；若启用可选**数据项名索引表**（如 `emr_document_data_item_index`），可在保存文档时解析 content 写入以加速检索。以下页面与上述设计对应。

#### 2.9.1 数据项名列表/检索页（与概要设计一致）

- **用途**：查看、检索系统中出现的数据项名，支持「不打开文档」获取结构列表（概要设计 7.4）、按数据项名查文书（若已实现索引表，概要设计 6.6）。
- **数据来源**：调用「获取文档结构列表」接口（传入文档 id 或 content JSON），返回数据项名列表（区域/数据组/数据元）、可选块→页号；若实现了数据项名索引表，可提供按数据项名检索文档的接口，本页调用展示。
- **布局**：
  - **筛选**：按文书类型、模板、文档（可选）、数据项名关键字；可选「节点类型」：区域 / 数据组 / 数据元。
  - **主区**：列表。列建议：数据项名、节点类型（区域/数据组/数据元）、所属模板或文档（名称/ID）、出现次数（若来自索引表）、操作（如「查看文书」「查看模板」跳转）。
  - **交互**：支持按数据项名关键字搜索；点击某行可钻取到对应模板编辑或文书（只读）并定位到该结构。
- **权限**：管理员或配置/质控角色；与模板管理权限类似，可按角色控制菜单与接口。

#### 2.9.2 数据项名主数据维护页（可选扩展）

- **用途**：若业务需要**数据项标准库**（在模板设计前预定义标准数据项名、显示名、类型、适用文书类型等，供模板选用及质控/统计标准化），可提供本页做增删改查。
- **与概要设计关系**：概要设计当前**未要求**独立「数据项名主数据表」；数据项名随模板/文档 content 存在。若采用本页，需在**详细设计**中增加：数据项名主数据表（如 `emr_data_item_definition`：数据项名、显示名、节点类型、数据类型、适用文书类型、排序等）、对应 AppService 与 CRUD 接口；模板编辑时「插入区域/数据组/数据元」可选用本表数据项名，保证与标准一致。
- **布局**（扩展时）：
  - **主区**：数据项名主数据列表。列：数据项名、显示名、节点类型、数据类型、适用文书类型、启用、排序、操作（编辑、删除、禁用）。
  - **操作**：「新增数据项」→ 弹窗或抽屉：数据项名（唯一）、显示名、节点类型（区域/数据组/数据元）、数据类型（若为数据元：文本/数值/日期/下拉等）、适用文书类型（多选或空表示通用）、必填、参与打印等。
  - **与模板编辑联动**：在模板编辑页「插入区域/数据组/数据元」时，可从数据项名主数据下拉选择，或允许手工输入（兼容现有行为）。

## 三、核心交互流程

### 3.1 新建文书并进入书写

1. 用户在「患者文书列表」点击「新建文书」。
2. 弹窗或页面：选择「文书类型」（必选）、可选「使用模板」并选择模板。
3. 确认 → 调用新建文档接口（患者、就诊、文书类型、可选 templateId）→ 返回 documentId 与 content（空或模板 JSON）。
4. 跳转至文书编辑页，URL 含 documentId；前端请求打开文档或直接使用返回的 content，Tiptap setContent；编辑器进入**书写模式**（仅数据元可编辑）。
5. 用户编辑后点击「保存」→ getJSON() 提交保存接口；成功后可提示「保存成功」、清除未保存状态。

### 3.2 打开文档与未保存提示

1. 文书列表中点击「打开」→ 跳转编辑页，传入 documentId。
2. 编辑页加载时请求 getContent(documentId)，setContent 到 Tiptap。
3. 若用户修改内容（onUpdate 与初态比较或 dirty 标记），在以下时机检测未保存并提示：
   - 点击「关闭」或「返回列表」；
   - 切换患者/文书（若有同一页内切换）；
   - 浏览器 beforeunload、路由守卫。
4. 提示文案如「当前文档未保存，是否离开？」选项：离开并丢弃、取消（继续编辑）、保存后离开。

### 3.3 从模板新建与模板编辑

- **从模板新建**：见 3.1；模板 content 作为文档初值，保存到文档表，不修改模板。
- **模板编辑**：从模板管理进入「编辑」→ 打开模板编辑页，加载模板 content；可插入/删除区域、数据组、数据元；保存时更新 emr_template，不创建文档。

### 3.4 书写模式与复制粘贴

- **书写模式**：打开的是文书（非模板）时，schema 限制或只读 + 数据元可编辑；禁止删除块级节点（区域、数据组）；工具栏中「插入区域/数据组」等可隐藏或禁用。
- **粘贴**：书写模式下粘贴仅纯文本或受控类型（功能 5.4）；若启用防跨患者（功能 5.5），粘贴时校验来源患者 ID 与当前患者一致，否则禁止或提示。

### 3.5 打印预览与导出 PDF

> 详见《[打印预览设计](04-打印预览设计.md)》§二、§四、§六。

1. **L1**：用户编辑时 emrEditor 即时展示 A4 版式；页边距变更同步至后续请求的 `printConfig.margins`（mm）。
2. 用户点击「打印预览」或展开预览分栏 → 可选打开「打印选项」：页范围、regionNames、留痕、水印、页边距。
3. 前端 `generatePdf`：`previewMode=true`，传 `content`（或 documentId）、`printConfig`；AbortController 取消上一次未完成预览。
4. 返回 PDF 后 iframe/blob URL 展示；若 `previewTruncated=true` 提示仅预览前 N 页。
5. **导出 PDF / 正式打印**：`previewMode=false`；若有 dirty 先提示保存；写打印审计；用户下载或通过 `usePdfPrint` 打印 PDF（非 `window.print` 编辑器 DOM）。

### 3.6 诊断/医嘱主动带入与检查检验引用

> **契约真源**：[06-诊断与医嘱主动带入文书.md](./06-诊断与医嘱主动带入文书.md)（IF-EMR-IMPORT-01～03）。以下为交互摘要。

**诊断 / 医嘱主动带入（本期）**

1. 用户将光标置于文书目标位置，点击工具栏「从诊断带入」或「从医嘱带入」。
2. 弹窗加载当前就诊诊断或医嘱列表（医嘱**含草稿与申请单**；已停默认不勾选）。
3. 用户勾选后点「插入到光标」→ 前端按文案规则生成纯文本 → `insertContent`；文书标脏。
4. **不做**打开自动填充、**不做**诊断/医嘱保存后回写正文；与入院 `admissionDiagnosisStructured` 自动同步解耦。
5. 同页会话内诊断或医嘱变更成功 → 顶栏黄条提醒「如需同步请重新带入」，提供快捷打开弹窗；关闭后同周期不再扰；**禁止**自动插入。

**检查检验引用（既有规划，11.x）**

1. 在「检查检验」侧栏或弹窗选择某条结果，点击「引用到文书」。
2. 在当前光标处插入「引用结果」节点，或写入选定数据元摘要/文本。

### 3.7 保存前校验（P2）

1. 用户点击「保存」。
2. 前端可选：先调用「保存前校验」接口（传入 content JSON），服务端返回错误列表（必填、长度、逻辑、违禁字等）。
3. 若有错误：在页面内以批注式或列表形式展示错误项（可定位到数据元）；不提交保存，或允许用户「强制保存」（按业务决定）。
4. 若无错误或用户确认：再提交保存接口。

## 四、组件与状态说明

### 4.1 通用组件建议

| 组件 | 说明 |
|------|------|
| 患者信息条 | 紧凑展示患者 ID、姓名、性别、年龄、就诊号、科室、床号；可折叠，用于文书列表顶/侧、编辑页顶栏。 |
| 文书类型下拉 | 新建文书时选择文书类型；数据来源为文书类型配置接口。 |
| 模板选择下拉 | 新建文书时可选「使用模板」及模板列表；可为空（空白文档）。 |
| 工具栏（编辑器） | 段落/标题、格式、列表、表格、图片、链接、分页符、日期时间、**从诊断带入**、**从医嘱带入**、插入区域/数据组/数据元（按模式显隐）；撤销/重做；查找替换。 |
| 区域块（Region） | 块级，展示标题与内容区；可折叠；右键或工具栏可配置属性（必填、参与打印、保护等）；书写模式下无删除。 |
| 数据组块（Section） | 可重复、可嵌套；标题与子内容；书写模式下不可删改结构。 |
| 数据元控件 | 文本框、数值、日期、下拉、多选、复选框、单选组等，由 Tiptap NodeView 包裹 Vue 组件；按数据项名取值赋值。 |

### 4.2 异常态与提示

| 场景 | 建议表现 |
|------|----------|
| 文档加载中 | 编辑器区骨架屏或 Loading；禁止操作。 |
| 打开失败（如 404、403） | Toast 或页面内提示「文档不存在」或「无权限」；可提供返回列表按钮。 |
| 保存失败（网络/校验） | Toast 展示服务端返回 message；校验错误在页面内列表或定位到数据元。 |
| 未保存离开 | 二次确认弹窗：「当前文档未保存，是否离开？」。 |
| 只读文档 | 顶栏或文档内常驻提示「当前为只读」；编辑与带入操作禁用。 |
| 无就诊上下文 | 「从诊断/医嘱带入」禁用，Toast 或 title 提示先选患者/接诊。 |
| 诊断/医嘱已变更 | 黄条提醒可重新带入；不自动改正文（见 [06](./06-诊断与医嘱主动带入文书.md) IF-EMR-IMPORT-03）。 |
| 列表无数据 | 工作台无患者、文书列表为空、模板列表为空：空状态插画或文案 + 主要操作按钮（如「新建文书」「新建模板」）。 |
| 打印/PDF 生成失败 | Toast「生成失败」+ 原因；可选重试。 |

### 4.3 权限与显隐

- 菜单：根据当前用户角色/权限只展示有权限的菜单项。
- 按钮：无「保存」权限时隐藏或禁用保存；无「打印」权限时隐藏打印预览/导出 PDF；无模板管理权限时隐藏「模板管理」菜单或编辑/删除按钮。
- 只读文档：由接口返回或文档状态（已锁定、已归档）决定；前端统一设为只读并展示只读提示。
