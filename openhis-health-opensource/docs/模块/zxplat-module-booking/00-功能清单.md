## 一、模块定位

### 1.1 Booking 是什么

**zxplat-module-booking** 是 HIS 的**统一预约扩展包**（独立可售 Module），负责号源编排、预约登记、候诊叫号及多渠道预约能力，覆盖五条业务线：


| 线     | 内容                     | 负责模块          |
| ----- | ---------------------- | ------------- |
| **O** | 门诊预约挂号（医师/诊室号源）        | zxplat-module-booking |
| **D** | 医技预约（检验/检查/治疗等设备或诊室号源） | zxplat-module-booking |
| **H** | 体检预约（个检/团检/校园体检；套餐与时段） | zxplat-module-booking |
| **B** | 床位预约（病区床位预留与日历）        | zxplat-module-booking |
| **Q** | 候诊叫号（报到入队、叫号、过号、大屏）    | zxplat-module-booking |


**核心领域事实**（**Schedule / Slot / Appointment**）归 **可售 `booking-domain`**，**不再**留在开源 `health-domain`；床位 Location 预留写侧仍委托 health **DM-ADM-003**。本模块提供 **领域聚合、应用编排、扩展配置、Reader/Writer/Client 桥接、可售 UI 能力**。

> **架构定稿（v1.3）**：自 health-domain 迁出 `workflow/schedule`、`workflow/slot`、`workflow/appointment` 至 `booking-domain`；表名保持 `wkf_`*；Flyway 脚本迁入 `db/migration/booking`。未购 booking 的纯 HIS 部署**不含**号源/预约能力。

### 1.2 五条业务线速查表


| 线        | 资源模型                                           | 占用机制                                         | 典型用户               | 下游衔接                                  |
| -------- | ---------------------------------------------- | -------------------------------------------- | ------------------ | ------------------------------------- |
| **O 门诊** | Schedule(actor=医师/诊室) + Slot                   | `Slot.allocateBooking`                       | 预约员、**排班员**、患者（渠道） | **门诊排班放号** → 预约 → 窗口挂号 → 候诊叫号 → 医生站接诊 |
| **D 医技** | Schedule(actor=设备/诊室/医疗服务) + Slot              | 同上                                           | 医技预约员、护士           | ServiceRequest（医嘱）→ 到检叫号 → 执行         |
| **H 体检** | Schedule(actor=体检中心 Location/医疗服务) + Slot；套餐快照 | 同上；团检按「批次+时段」计容量                             | 体检前台、团检管理员、学校保健老师  | 到检签到 → 导检队列 → 健康体检工作台（FR-PE）          |
| **B 床位** | Location(form=BED)                             | 床位 `operational_enum=RESERVED` + Appointment | 住院预约员、护士           | 床位预留 → 住院登记 → 入科占床                    |
| **Q 候诊** | Appointment(CHECK_IN_ONLY)                     | 队列 `displayOrder`                            | 分诊台、叫号大屏           | 医生站/医技站/体检导检待办（只读 Encounter 或体检流水）    |


**O 线排班与预约分层**：

```text
PractitionerRole 出诊模板（health-domain · DM-ADM-006，开源主数据）
  adm_pr_assign_schedule（周几、时段 JSON）
        ↓ 可选同步 / 手工维护
Schedule 号源日程（booking-domain · DM-WKF-009）
  actor：PRACTITIONER + LOCATION [+ HEALTHCARE_SERVICE]
        ↓ 发布 + 放号策略
Slot 号源时段（booking-domain · DM-WKF-010）
        ↓ 预约占用
Appointment（booking-domain · DM-WKF-002）
```

- **岗位排班**（`PractitionerRole.updateSchedule`）仍归 **health 开源主数据**；booking 经 `HealthPractitionerRoleReader` 读取并生成 Schedule 草稿。
- **号源日程 / 时段 / 预约**（Schedule / Slot / Appointment）归 **booking-domain**；health **不持有**对应实体与写侧服务。

**booking-domain 聚合清单（迁出后）**：


| 聚合          | 包路径（目标）                                        | 表                                       |
| ----------- | ---------------------------------------------- | --------------------------------------- |
| Schedule    | `com.zxplat.plugin.booking.domain.schedule`    | `wkf_schedule`、`*_actor`、`*_identifier` |
| Slot        | `com.zxplat.plugin.booking.domain.slot`        | `wkf_slot`、`*_identifier`               |
| Appointment | `com.zxplat.plugin.booking.domain.appointment` | `wkf_appointment_queue`                 |
| 扩展配置        | `com.zxplat.plugin.booking.domain.policy` 等    | `bkg_*`                                 |


**H 线与 O/D 线差异**：体检预约以**套餐（含必选/可选项目）为业务主键之一，支持团检批次与名单**；到检后的导检路径、项目执行、总检报告归 **健康体检管理（FR-PE / M-23）**，booking 只做到**预约占用、签到入队、与体检流水衔接**。

> **命名注意**：workflow 域 **号源时段** 英文为 `Slot`；本模块 JSON/API **禁止** 使用键名 `slot`/`slots` 表达排版或无关语义（与 report layoutJson 约定一致，避免与号源混淆）。

| 序号  | 功能项                | 描述                                                                                                     | 优先级  | 状态  |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------ | ---- | --- |

| 0.2 | 领域服务迁移             | `*DomainService`、`*QueryService`、Command 迁至 `booking-domain`                                           | P0   | ✅   |
| 0.3 | Flyway 迁移          | `wkf_schedule`/`wkf_slot`/`wkf_appointment_queue` 等脚本迁至 `db/migration/booking`；health 侧不再新增 `wkf_*` 版本 | P0   | ✅   |
| 0.4 | health 代码删除        | 移除 `health-domain` 下 `workflow/schedule`、`workflow/slot`、`workflow/appointment` 包                      | P0   | ✅   |

| 0.6 | appointmentKind 扩展 | `DIAGNOSTIC_BOOKING`、`BED_BOOKING`、`HEALTH_CHECKUP_BOOKING` 在 **booking-domain** 落地                    | P1 前 | ✅   |
| 0.7 | OutpatientBookingReader   | health 挂号/医生站经 Reader 查有效预约、可约号源（**只读**）                                                                 | P0   | ✅   |
| 0.8 | 床位预留写侧             | Location `reserveBed` / `releaseBedReservation` 仍留 **health-domain**（DM-ADM-003）                       | P1 前 | ✅   |

### 4.6 门诊预约 ↔ 挂号衔接

> **设计真源**：[01-概要设计.md](./01-概要设计.md) §4～§8（岗位资格层 + booking 库存层、三种院点模式、IF-REG-12～14、Reader/Writer/Client 契约）。  
> **挂号 AS**：[AS-OP-FIN-001](../cmmi3ddd/02-通用语言与领域建模/AppService/AS-OP-FIN-001-门诊挂号.md) IF-REG-01～11 **不变**；booking 仅 **增量** IF-REG-12～14。

**兼容原则（摘要）**：


| 层次           | 真源                                      | 挂号消费方式                                               |
| ------------ | --------------------------------------- | ---------------------------------------------------- |
| 科室 / 医生资格    | health `PractitionerRole`               | IF-REG-04/05 **不变**                                  |
| 号源类型主数据      | health `HealthcareService` + 用户管理医师可接诊号源（`PractitionerRoleServiceItem`） | IF-REG-01：无医生=全量 ACTIVE；有医生=医师可接诊；**禁止 ∩ 当日排班**（与用排班挂号解绑） |
| 时段 / 名额 / 预约 | booking `Schedule`/`Slot`/`Appointment` | 点选号源（`slotId`）或 IF-REG-12～14；写回填经 `OutpatientBookingWriter` |


**院点模式**（`bkg_registration_policy.walk_in_slot_mode`；影响策略展示/预约优先等，**不再**驱动 IF-REG-01 号源求交或无 `slotId` 自动占号）：


| 模式                  | 说明                          |
| ------------------- | --------------------------- |
| `WALK_IN_NO_SLOT`   | 纯现场语义标识（历史兼容） |
| `APPOINTMENT_FIRST` | 先约后挂（P1+ 预约菜单开放后）                 |
| `WALK_IN_WITH_SLOT` | 允许点选当日 Slot 占号（须传 `slotId`）        |



| 序号  | 功能项          | 描述                                                                        | 优先级 | 状态  |

| 6.2 | 预约转挂号        | **IF-REG-13**：衔接 `preRegisterSettlement`；`validateForRegistration` + 岗位复核 | P1  | ✅   |

## 六、验收原则

1. **号源占用与释放成对**：预约创建必须 `allocateBooking`；取消/改约必须释放，禁止孤儿占用。
2. **门诊排班先于预约**：P0 须先完成 Schedule 发布 + 放号，再开放预约；未发布日程不得产生可约 Slot。
3. **领域归属 booking**：`wkf_schedule` / `wkf_slot` / `wkf_appointment_queue` 写侧仅在 `**booking-domain`**；health 不得保留平行实现。
4. **岗位与号源日程分离**：`PractitionerRole` 出诊模板归 health 主数据；Schedule 归 booking-domain，二者可同步不可混表。
5. **候诊写侧唯一**：队列写操作仅在 booking；医生站经 Encounter + `**OutpatientBookingReader`** 消费。
6. **床位不用 Slot**：床位预约走 health Location + `BED_BOOKING`（Appointment 在 booking-domain）。
7. **health 不依赖 booking 实现包**：`health-application` 不 import `booking-domain` / `booking-application`；仅依赖 `**booking-contracts`** 接口（可选装配）。
8. **adapter 不依赖 application**：Enforcer 红线与 report 一致；adapter **可**依赖 `booking-domain` 以实现 `OutpatientBookingReader`。
9. **单 Module 可装可售**：未装 `booking-starter` 时纯 HIS **无** Schedule/Slot/Appointment 能力。
10. **P0 完工**：**领域迁出完成** + 门诊排班放号 + 预约闭环 + 候诊叫号 + Flyway `booking`。
11. **P1 完工**：医技预约 + 床位预留 + 挂号衔接（经 `OutpatientBookingReader`）+ 团检批次预约。
12. **P2 完工**：渠道预约 + 个检套餐 + 导引单/预约凭证打印。
