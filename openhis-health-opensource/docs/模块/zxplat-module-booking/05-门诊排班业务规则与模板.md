## 2. Schedule 模式与 Actor 规则（v2）

> **v1（初版）**：`PRACTITIONER + LOCATION` 倾向必填。  
> **v2（本文）**：科室为主键维度；诊室可选；支持科室号。

### 2.1 三种 Schedule 模式

| 模式码 | 名称 | `organizationId` | 必选 Actor | 可选 Actor | 典型场景 |
| --- | --- | --- | --- | --- | --- |
| `MODE-A` | 医师门诊 | 门诊科室 | `HEALTHCARE_SERVICE` | `PRACTITIONER`、`LOCATION` | 专家号、指名预约 |
| `MODE-B` | 科室号/分诊号 | 门诊科室 | `HEALTHCARE_SERVICE` | `LOCATION`（诊区） | 排人到科室，到院分诊绑医师 |
| `MODE-C` | 诊区号 | 门诊科室 | `HEALTHCARE_SERVICE` + `LOCATION` | `PRACTITIONER` | 有物理点、暂不绑医师 |

**院点默认模式**：`bkg_schedule_policy.default_schedule_mode`（默认 `MODE-A`）。

### 2.2 Actor 校验规则

| 规则 ID | 描述 | 门禁 |
| --- | --- | --- |
| BR-SCH-001 | `organizationId` 须为 **门诊科室**（`OrganizationClassification.CLINIC`） | 创建/发布 |
| BR-SCH-002 | Actor 列表非空，且 `(actorType, actorId)` 不重复 | 创建/替换 Actor |
| BR-SCH-003 | `HEALTHCARE_SERVICE` 引用须为 ACTIVE 挂号类型 | 创建/发布 |
| BR-SCH-004 | `PRACTITIONER` 须在 `organizationId` 下有激活医师岗（`ROLE_DOCTOR`） | MODE-A 含 PRACTITIONER 时 |
| BR-SCH-005 | `LOCATION` 须属于 `organizationId` 或院点允许的上级机构 | 含 LOCATION 时 |
| BR-SCH-006 | MODE-B **禁止** 仅含 PRACTITIONER 而无 SERVICE | 发布 |
| BR-SCH-007 | 发布时 `planningHorizonEnd > planningHorizonStart` | 发布 |
| BR-SCH-008 | **LOCATION 可为空**（MODE-A/B）；为空时 `destinationLocationId` 在预约/报到时再定 | 创建/发布 |

### 2.3 与挂号三要素对齐（03 §4.2）

| 挂号字段 | booking 来源 | MODE-B 说明 |
| --- | --- | --- |
| `organizationId` | `Schedule.organizationId` | 一致 |
| `practitionerId` | Actor(PRACTITIONER) | **可空**；窗口分诊后写入 Encounter |
| `serviceTypeId` | Schedule.`healthcare_service_id` / Actor(SERVICE) | 一致 |
| `slotId` | `Appointment.slotId` | 占号凭证 |

## 3. 排班变更分类

| 代码 | 名称 | 操作入口 | 影响 Slot | 影响预约 |
| --- | --- | --- | --- | --- |
| CHG-SCH-01 | 整日停诊 | `deactivateSchedule` | 下属全部不可约 | 是 |
| CHG-SCH-02 | 部分时段停诊 | `blockSlots` | 指定 Slot busy-unavailable | 是（该 Slot） |
| CHG-SCH-03 | 换医师 | 改 Actor / 停 A 开 B | A 释放，B 新 Schedule | 是 |
| CHG-SCH-04 | 换诊室 | 改 LOCATION Actor | 通常否 | 视策略通知 |
| CHG-SCH-05 | 改容量/时段 | 重新 `provisionSlotBatch` | 仅未约 Slot | 否 |
| CHG-SCH-06 | 改规划窗口 | `updateScheduleDraft` / 发布 | 可能跨日 | 视范围 |

| CHG-SCH-09 | 加号/加班 | 追加 Slot / T3 `EXTRA` | 新增 | 否 |

## 4. 停诊与预约处置

### 4.1 有效预约定义

满足以下全部条件的 `Appointment`（`appointmentKind = OUTPATIENT_BOOKING`）：

- 非终态（未取消、未 noShow 完成态）
- `encounterId IS NULL`（未转挂号）
- 所属 Slot 落在本次停诊/封锁的时间范围内
- 所属 Schedule 的 Actor 匹配停诊对象（如 PRACTITIONER=A）

**扩展扫描（P1）**

- 模式 C **现场占号**（`WALK_IN_WITH_SLOT`）未挂号占用
- **渠道预约**（`originChannel` 非空）同等对待

### 4.2 院点策略 `bkg_schedule_change_policy`

建议独立表（或扩展 `bkg_registration_policy`），按 `organization_id` 配置：

| 策略键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `on_practitioner_stop_mode` | enum | `MANUAL` | `TRANSFER` / `RESCHEDULE` / `CANCEL` / `MANUAL` |
| `transfer_match_rule` | enum | `SAME_SERVICE_SAME_SLOT` | 见 §4.3 |
| `transfer_require_same_service` | bool | true | 禁止专家↔普通自动转交 |
| `transfer_allow_cross_practitioner` | bool | true | 允许 A→B |
| `transfer_patient_confirm_mode` | enum | `NONE` | `NONE` / `SMS_CONFIRM` / `WINDOW_CONFIRM` |
| `block_deactivate_if_unhandled` | bool | true | 未处置预约禁止完成停诊 |
| `notify_on_transfer` | bool | true | ~~调用 BookingChannelNotifyClient~~ **保留字段，产品不实现停诊短信** |
| `notify_on_cancel_stop` | bool | true | ~~停诊取消预约时通知~~ **同上** |
| `freeze_source_slot_on_preview` | bool | true | 预览后冻结源 Slot 新预约（防并发） |
| `freeze_ttl_minutes` | int | 15 | 冻结超时自动释放 |

### 4.3 转交 B 医师 — 匹配规则 BR-STOP-001

**触发**：CHG-SCH-01/02/03，且 `on_practitioner_stop_mode=TRANSFER`。

**单条预约匹配顺序**

1. **SAME_SERVICE_SAME_SLOT**：同科室、同 `healthcare_service_id`、同时段，目标 Schedule 含 PRACTITIONER=B，Slot 有余量  
2. **SAME_SERVICE_NEAREST**：同日、同 service，最近可用 Slot  
3. **SAME_DEPT_ANY**：同日、同科室，任意 service（仅当 `transfer_require_same_service=false`）  
4. 仍无 → 标记 `MANUAL_REQUIRED`，不计入自动成功

**执行步骤（单条，须同事务或带补偿）**

```text
1. slotDomainService.releaseBooking(sourceSlotId)
2. slotDomainService.allocateBooking(targetSlotId)
3. appointmentDomainService.rescheduleOutpatientBooking(...)
4. 更新 Actor 快照/展示字段（B 医师）
5. bookingAuditSupport.record(...)
6. ~~可选 BookingChannelNotifyClient~~（**产品范围外**）
```

**批量规则 BR-STOP-002**

- 默认 **部分成功**：返回 `{ success[], failed[] }`  
- 院点可选 **atomicBatch=true**：任一条失败则整批回滚  

**硬规则**

| 规则 ID | 描述 |
| --- | --- |
| BR-INV-001 | 转交须释放源 Slot + 占用目标 Slot，禁止孤儿占用 |
| BR-INV-002 | 停诊完成后源 Slot 为 busy-unavailable 或 Schedule inactive |
| BR-INV-003 | 批量结果须可追溯 |
| BR-INV-004 | **`busNo` 不变**，便于 IF-REG-12 与患者凭单 |
| BR-INV-005 | 已 `checkIn` 或已叫号：**禁止**自动改约/转交 |
| BR-INV-006 | 已挂号（`encounterId NOT NULL`）：走 health 退号/换号，booking 不自动转交 |
| BR-INV-007 | 目标 Slot 已满且不允许超售 → 该条失败 |

### 4.4 替诊 vs 转交

| 维度 | 转交预约 | 替诊（SUBSTITUTE） |
| --- | --- | --- |
| 患者预约信息 | 改为 B 的 Slot/时段 | **不变**（仍显示 A） |
| 号源占用 | 迁移到 B 的 Slot | **不迁移** |
| 适用 | A 永久停诊、B 接替号源 | A 临时不能出诊，B 顶班 |
| 叫号/大屏 | 显示 B | 显示「B 替 A」 |
| 数据 | `rescheduleOutpatientBooking` | Schedule 扩展 `substitute_practitioner_id` + 当日生效 |

**规则 BR-SUB-001**：替诊 **不触发** §4.3 转交流程；须单独接口 `substitutePractitioner`。

### 4.5 场景矩阵（处置真源）

| 触发 ↓ \ 患者状态 → | 未报到 | 已报到未叫号 | 已叫号/就诊中 | 已挂号 |
| --- | --- | --- | --- | --- |
| 整日停诊 | 转交/改约/取消 | 转交或分诊人工 | 仅人工 | health 退号 |
| 半天/部分 Slot 停诊 | 同左（缩范围） | 同左 | 人工 | 退号 |
| 换医师（无替诊） | 转交 | 转交或人工 | 人工 | 退号/换挂 |
| 替诊 | 不改约 | 队列改显示 | 医生站提示 | 可选不改 |
| 仅换诊室 | 可选通知 | 更新 destination | 人工 | 一般不改 |
| 节假日 CLOSED | 批量取消或转交 | 同左 | 人工 | 退号 |

### 4.6 停诊向导 UI 流程（04 引用）

```text
[发起停诊] → previewStopClinicImpact
  → 若 freeze_source_slot_on_preview=true：写入 bkg_stop_clinic_slot_freeze（TTL 默认 15min）
  → 展示：Schedule 数、Slot 数、预约数、已挂号数、渠道数、冻结到期时间
  → 选择处置方式 + 目标 B（若 TRANSFER）
  → 预览映射表（appointmentId → targetSlotId）
  → [执行并停诊] transferAppointmentsOnStopClinic + deactivate/block → 释放冻结
  → [取消] releaseStopClinicPreviewFreeze
  → 结果明细 + 审计
```

### 5.2 T1 — 放号时段模板

### 5.6 模板 Fallback 链 BR-TPL-001

自动生成 Schedule 时，按序取第一个命中：

```text
1. 当日 T3 例外（OVERRIDE/EXTRA/REDUCED/CLOSED）
2. 科室 enabled T2（priority 降序，effective 内）
3. health 岗位 scheduleItems（2.10 已有）
4. 科室 default T2（院点配置）
5. 失败 → 告警，不静默跳过
```

**BR-TPL-002**：已发布 Schedule **不受** T2 后续修改追溯影响。

### 5.7 默认周排班模板 fallback（2.25 · BR-TPL-003）

> **非**定时任务 / AUTO 物化；**非**无审核自动放号。

**业务语义**

- 科室（或院点）配置 **默认周排班模板**（按 **周一～周日** 描述「惯例应怎样出诊」）。
- 查询 **周历 / 月历** 时：若某自然周 **尚无已落地 Schedule**，则用默认周模板 **合成展示格**（`fromTemplate=true`，可无 `scheduleId`）。
- **是否可预约由模板配置决定**（见下表），非写死「一律不可约」。
- 需要排班员提前 **物化** 时，仍走「从模板生成」→ `generateFromTemplate`（可选发布/放号）。

**周模板配置**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 见 §5.3b | | `bkg_week_schedule_template` + `_item` |

**`fallback_bookable` 行为（BR-TPL-004）**

| 值 | 周历/月历 | 预约 / `listBookableSlots` |
| --- | --- | --- |
| **`false`（默认）** | 展示模板格（虚线/「未发布」） | **不可约**；不返回模板态号源 |
| **`true`** | 同上，标识 `fromTemplate=true` | **可约**：按 T1 时段返回**虚拟可约列表**；**首次占号时**同事务内 **lazy 物化** 当日 Schedule + Slot 再 `allocateBooking`（仍 respect T3 CLOSED） |

**硬规则**

- 模板态可约 **不等于** 已发布 Schedule；物化前 `scheduleId`/`slotId` 可为空或临时标识，占号成功后必须有真实 Slot。
- T3 `CLOSED` 日：即使 `fallback_bookable=true` 亦 **不可约**。
- 已有真实 Schedule 的格子：**以真实数据为准**，不叠加模板。
- 停诊预览冻结（TC-FRZ-01）仅作用于 **已物化 Slot**；纯虚拟可约列表在物化前不受冻结表约束，物化后按常规则。

**与现有能力关系**

| 能力 | 作用 |
| --- | --- |
| T2 日程模板 | 单日 Actor + T1；物化生成 / 周模板明细可引用 |
| T3 日历例外 | 国庆 CLOSED、调休 EXTRA；展示与可约均应 respect |
| `generateFromTemplate` | 排班员 **主动** 批量物化 Schedule |
| **2.25 fallback** | 读路径补齐空白周；**可约性由 `fallback_bookable` 控制** |
