### 2.2 环境与前置

**后端**

```bash
cd zxplat
mvn -Pwith-booking -pl zxplat-app -am package -DskipTests
```

**前端**

- `openhis-pro-ui` web-ele；菜单 **后端动态下发**，非静态路由（除叫号大屏）

**主数据（测试前）**

- 机构/科室、医师岗位、挂号类型（HealthcareService）、患者
- **诊室 Location** 挂到目标门诊科室（种子 `V15__adm_location` 无门诊诊室，需手工补或加种子）
- 可选：就诊 + ServiceRequest（医技）、病区床位（床位线）

## 3. 联调问题排查纪要

### 3.1 「找不到统一预约菜单」

**结论**：不是前端没做页面，而是 **DB 菜单种子 + 模块开关 + Maven Profile** 未同时满足。

| 条件 | 说明 |
| --- | --- |
| Maven `-Pwith-booking` | `health-app` 依赖 `booking-starter`，否则无 Flyway 脚本 jar |
| `zxplat.modules.booking.enabled=true` | `application.yml` 默认 **未** 开启 booking（emr/mrms/chs/report 有，booking 无） |
| Flyway V1～V6 | 写入 `whale_menus`「统一预约」及子菜单、`whale_permission_grants`（菜单在 **V6**） |
| 重新登录 | 菜单在登录时拉取 `POST /menu/getTreeByLoginUser` |
| 非 admin | 需角色勾选 `Booking.Schedule.View` 等权限 |

**自查 SQL**

```sql
-- booking 迁移是否执行
SELECT version, description, success FROM flyway_schema_history_booking ORDER BY installed_rank;

-- 菜单是否入库
SELECT code, display_name, path, is_enabled FROM whale_menus WHERE code LIKE 'Booking%' ORDER BY sort_order;
```

### 3.2 「排班页全是空的」

**周历每天显示「—」**：**正常** — 尚未创建/发布 Schedule；需「新建日程 → 发布 → 放号」。

**顶部下拉为空**（医师/诊室/号源类型）：

| 下拉 | 接口字段 | 常见原因 |
| --- | --- | --- |
| 医师 | `practitioners` | 当前科室无激活「医生」岗位 |
| 诊室 | `clinicLocations` | **种子无挂到该科室的诊室**；按 `organization_id` 查 Location |
| 号源类型 | `healthcareServices` | `adm_healthcare_service` 无 ACTIVE 记录 |

页面科室来源：**登录科室**（`useBookingOrganization` → `authStore.getSelectedOrganization()`），非页面内科室下拉。

**当前实现口径**：`schedule-form-drawer.vue` 诊室 **可选**；号源类型（`HEALTHCARE_SERVICE`）必选，与 [07 §2](./05-门诊排班业务规则与模板.md) MODE-A/B/C 一致。

## 4. 门诊排班产品完善（会话共识）

### 4.1 排班资源模型：科室为主、诊室可选

建议三种 **Schedule 模式**（院点策略可选默认）：

| 模式 | organizationId | Actors | 场景 |
| --- | --- | --- | --- |
| **A · 医师门诊** | 科室 | PRACTITIONER + [LOCATION 可选] + HEALTHCARE_SERVICE | 最常见 |
| **B · 科室号/分诊号** | 科室 | HEALTHCARE_SERVICE（+ 可选 LOCATION 诊区） | 排人到科室，挂号/分诊再绑医师 |
| **C · 诊区号** | 科室 | LOCATION + HEALTHCARE_SERVICE | 有物理点、暂不绑医师 |

**规则要点**

- **科室** 由 `Schedule.organizationId` 表达；页面应支持显式展示/切换排班科室（不只靠右上角登录科室）
- **诊室** 全局 **可选**；为空时预约/叫号按科室维度，到院后再分诊室
- **发布校验**：领域层改为「至少 1 个有效 Actor + 规划窗口合法」，不再硬编码「PRACTITIONER + LOCATION 必填」
- **文档已有**「科室号」actor 组合（01 §4.2）；**代码/UI 需对齐**

### 4.2 视图与交互提效

| 视图 | 用途 |
| --- | --- |
| **月视图（建议默认）** | 看整月覆盖、批量建班、复制、停诊；格内摘要 + 点击开「日抽屉」 |
| **周视图（现有）** | 精细编辑单条 Schedule、放号时段 |

**P0 提效**

- 月视图框选多日 → 套用模板批量生成草稿  
- 复制增强：下一月 / 选中日期 / 复制并自动放号  
- 「发布并放号」一步完成  
- 左侧资源树：科室 → 医师，点选过滤日历  

**P1 提效**

- 同人同时段 / 同诊室冲突警告  
- 月历顶栏：已发布/草稿/未排/已约摘要（`pageSchedulesByMonth.summary`）
- 从月格跳转号源日历 — P1 提效项

周/月切换见 04 §2.1（`UI-SCH-09`）。

## 5. 停诊与改排班 — 业务规则

> **规则真源**：[07 §4](./05-门诊排班业务规则与模板.md)。排班台/号源日历接停诊向导；`transferAndStop` 在传 `slotIds` 时仅封锁选中号源。

### 5.1 变更类型

| 代码 | 场景 | 影响预约 |
| --- | --- | --- |
| CHG-SCH-01 | 整日停诊 | 是 |
| CHG-SCH-02 | 部分 Slot 停诊 | 是（该 Slot） |
| CHG-SCH-03 | 换医师 A→B | 是 |
| CHG-SCH-04 | 换诊室 | 视院点策略 |
| CHG-SCH-07 | 节假日批量停诊 | 是 |

### 5.2 核心规则：A 停诊 → 预约转交 B

**流程（停诊向导）**

1. 发起停诊 → 扫描有效预约（未终态、未转挂号 `encounterId IS NULL`）  
2. 若存在预约且 `block_deactivate_if_unhandled=true` → **禁止直接停诊**，打开向导  
3. 处置方式：转交 B / 改约 / 取消+通知 / 稍后人工  
4. 转交：释放 A Slot → 占用 B Slot → `rescheduleOutpatientBooking`（**busNo 不变**）  
5. 完成后停诊/封锁 A  

**匹配 B 的 Slot**：优先同时段同号源类型 → 同日最近时段 → 标记需人工  

**院点策略（建议扩展 `bkg_registration_policy` 或新建 `bkg_schedule_change_policy`）**

| 策略键 | 说明 |
| --- | --- |
| `on_practitioner_stop_mode` | TRANSFER / RESCHEDULE / CANCEL / MANUAL |
| `transfer_match_rule` | SAME_SERVICE_SAME_SLOT / SAME_SERVICE_NEAREST / SAME_DEPT_ANY |
| `block_deactivate_if_unhandled` | 未处置预约时禁止完成停诊 |
| `notify_on_transfer` | ~~短信/微信（BookingChannelNotifyClient）~~ **产品不做**；字段保留 |

**API（07 §4 · 2.18～2.19）**

```text
POST /api/app/outpatientSchedule/previewStopClinicImpact
POST /api/app/outpatientSchedule/releaseStopClinicPreviewFreeze
POST /api/app/outpatientSchedule/transferAppointmentsOnStopClinic
```

**TC-FRZ-01 验收要点**

1. 打开停诊向导 → `previewStopClinicImpact` 返回 `sourceSlotsFrozen=true`  
2. 冻结期间对源 Slot 新约 → 拒绝（`号源停诊预览冻结中，暂不可预约`）  
3. 取消向导 → `releaseStopClinicPreviewFreeze` → 可约恢复  
4. 执行停诊 → `transferAppointmentsOnStopClinic` 内释放冻结  
5. TTL 过期后 lazy 清理，可约恢复（默认 15 分钟）

**自动化（建议）**：`StopClinicSlotFreezeDomainServiceTest`（5 用例，覆盖冻结/拒绝/释放/过期 lazy 清理）
`mvn -Pwith-booking clean test -pl zxplat-module-booking/booking-domain "-Dtest=StopClinicSlotFreezeDomainServiceTest"`

| 步骤 | 操作 | 预期 |

## 6. 排班模板体系

与 health **岗位模板** 分离：岗位 = 资格层；booking 模板 = 号源生产层。

| 类型 | 建议表 | 用途 | 状态 |
| --- | --- | --- | --- |
| **T1 · 放号时段模板** | `bkg_slot_provision_template` | 时段粒度 + 容量 JSON | ✅ |
| **T2 · 排班日程模板** | `bkg_schedule_template` | Actor + 服务类型 + 关联 T1 | ✅ |
| **T3 · 日历例外** | `bkg_calendar_exception` | CLOSED / REDUCED / OVERRIDE / EXTRA | ✅ |
| ~~**T4 · 节假日套系**~~ | — | **取消**（直接维护 T3） | ⛔ |

**T3 类型语义**

| 类型 | 行为 |
| --- | --- |
| CLOSED | 不生成 Schedule；已有则走停诊向导 |
| REDUCED | 减半放号 |
| OVERRIDE | 替换为指定 T2（节日特需门诊） |
| EXTRA | 调休上班等加班 |

**建议功能序号（写入 01 扩展）**：2.13～2.20（模板 CRUD、从模板生成、停诊向导、批量转交等）。

**建议 AppService**：`scheduleTemplate`、`calendarException`；扩展 `outpatientSchedule.generateFromTemplate`。

**UI**：统一预约 → **排班模板**（与放号策略并列）；排班台内嵌 **停诊向导**。
