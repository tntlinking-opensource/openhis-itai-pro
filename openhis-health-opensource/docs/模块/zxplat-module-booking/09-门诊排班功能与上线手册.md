### 1.3 核心术语（院端口径）

| 术语 | 含义 |
| --- | --- |
| **占位预览** | 当天尚无正式排班时，周历上以虚线格展示的「惯例出诊」；来自周排班模板 |
| **正式排班** | 已落地到系统的 `Schedule`（草稿或已发布）；实线格，可发布、放号、停诊 |
| **放号时段（T1）** | 精确到起止时间与容量的时段定义，如「08:00–12:00，容量 20」 |
| **日排班（T2）** | 单日出诊内容：医师/诊室/号源类型 + 放号时段 + 可选放号策略 |
| **周排班（TW）** | 周一～周日各引用一个日排班；控制占位预览与批量生成 |
| **放号** | 在已发布日程下生成可预约的号源时段（Slot） |
| **预约策略** | 挂号衔接 + 停诊处置（不含放号策略；放号策略在排班设置内维护） |

### 2.3 门诊排班业务链路（P1）

```text
health 主数据（科室、医师岗位、诊室、号源类型）
        ↓
排班设置：放号策略 → 放号时段 → 日排班 → 周排班 → 日历例外
        ↓

        ↓
挂号台：选科室/医师/号源 → 点选当日号源 → 预结算占号（booked_count +1）→ 收费
        ↓
（P1+）门诊预约 / 候诊叫号 …
候诊叫号：报到 → 叫号 → 过号
```

## 3. 排班设置（`/booking/schedule-template`）

> 页面级操作详解见 [11-排班设置操作说明.md](./11-排班设置操作说明.md)。

**定位**：科室级「排班蓝图」维护页，不直接产生可预约号源；配置完成后到「门诊排班」落地为正式排班。

页顶说明区概括了五类配置的关系：**周排班**管占位预览，**日排班**描述单日出诊，**放号时段**定义精确时间片，**放号策略**在无放号时段时按粒度切分，**日历例外**处理节假日与调休。

### 3.1 放号策略

**作用**：控制「提前几天可约、默认时段多长、每段几个号、各渠道占比」。在以下场景生效：

1. 日排班关联了放号策略，且**未**配置放号时段（T1）时，批量放号按策略切分；
2. 手工批量放号对话框中，若未选手工时段方案，可回落到策略默认值。

**主要字段**：

| 字段 | 说明 | 上线建议 |
| --- | --- | --- |
| 策略编码/名称 | 科室内唯一标识 | 如 `RP-INTERNAL-DEFAULT` |
| 提前天数 | 患者最早可约未来第几天 | 常见 7～14 天 |
| 时段粒度（分钟） | 自动切分每段长度；0 表示整段 1 个 Slot | 专家号 15～30；普通号 30～60 |
| 单段容量 | 每个时间片默认可约人数 | 专家 1；普通 5～10 |
| 渠道配额 JSON | 窗口/小程序等占比 | 初期可留空，均匀分配 |

**提示**：若日排班已绑定**放号时段（T1）**，放号时 **T1 优先于放号策略**（T1 一行 = 一个 Slot，不会按分钟再切）。

### 3.2 放号时段（T1）

**作用**：定义一天内各出诊段的**起止时间与额定容量**。一行 JSON 对应生成 **1 个 Slot**（不是自动按 15 分钟切 20 格）。

**示例**（内科专家上午 + 下午）：

| 段 | 开始 | 结束 | 容量 | 含义 |
| --- | --- | --- | --- | --- |
| 上午 | 08:00 | 12:00 | 20 | 1 个 Slot，最多 20 人 |
| 下午 | 14:00 | 17:00 | 15 | 1 个 Slot，最多 15 人 |

午间 12:00–14:00 无行即表示休息，不会放号。

**操作**：新建 → 填编码/名称 → 添加时段行 → 保存。被日排班引用时不可删除（系统会提示引用关系）。

### 3.3 日排班（T2）

**作用**：物化正式排班的**最小单元** — 描述「谁、什么号、在哪、用哪套时段放号」。

**主要字段**：

| 字段 | 说明 |
| --- | --- |
| 排班模式 | MODE-A 医师门诊 / MODE-B 科室号 / MODE-C 诊区号（见 §6.1） |
| 号源类型 | 必填；对应 health `HealthcareService`（专家号、普通号等） |
| 医师 | MODE-A 建议填；MODE-B 不填 |
| 诊室 | 可选；MODE-C 必填 |
| 放号时段 | 推荐绑定 T1；不绑则放号时走放号策略 |
| 放号策略 | 未绑 T1 时使用 |
| 占位有效期 | 控制该日排班是否参与**占位预览**及有效日期范围 |
| 占位优先级 | 多模板同日冲突时，数值大者优先 |
| 启用 | 关闭后不参与生成与占位 |

**排班模式速查**：

| 模式 | 典型场景 | 必选 |
| --- | --- | --- |
| MODE-A | 专家门诊、指名预约 | 号源类型；医师建议填 |
| MODE-B | 只排到科室，到院分诊 | 号源类型 |
| MODE-C | 诊区号，暂不绑医师 | 号源类型 + 诊室 |

### 3.4 周排班（TW）

**作用**：把「周一～周日」映射到各日的日排班，用于：

1. **占位预览**：门诊排班周历上，无正式排班的日期显示虚线格；
2. **批量生成**：在门诊排班页「生成正式排班」选周排班 + 日期区间。

**关键开关**：

| 字段 | 建议上线值 | 说明 |
| --- | --- | --- |
| 科室默认 | 每科室 1 套设为默认 | 占位预览优先用默认周排班 |
| 无排班时可约 | **false**（推荐） | true 时患者可在未落地排班前预约（lazy 物化）；多数医院先关闭 |
| 占位有效期 | 覆盖当前季度 | 与占位预览显示范围一致 |
| 周明细 | 周一至周日各选 T2 | 周六日可留空 |

### 3.5 日历例外（T3）

**作用**：覆盖常规周排班，处理节假日、调休、临时停诊。

| 类型 | 生成行为 | 典型用途 |
| --- | --- | --- |
| CLOSED | 该日跳过生成；已发布则走停诊流程 | 国庆、春节 |
| EXTRA | 在常规之外额外生成一条排班 | 周末加班门诊 |
| OVERRIDE | 用指定日排班替代 | 调休工作日按周六班表 |
| REDUCED | 用减半模板 | 半日门诊 |

**操作**：列表维护 + 月历视图点选日期快速新建。勾选「参与生成」的例外会在「生成正式排班」时自动生效。

## 4. 门诊排班（`/booking/outpatient-schedule`）

**定位**：排班员日常主战场 — 查看周历/月历、维护正式排班、发布放号、停诊替诊。

### 4.1 页面结构

| 区域 | 功能 |
| --- | --- |
| 顶栏 | 排班科室、医师筛选、周视图/月视图切换 |
| 周历/月历 | 按日展示正式排班与占位预览 |
| 工具栏 | 新建日程、复制到下一周、**生成正式排班** |
| 详情抽屉 | 点格子进入：编辑、发布、放号、停诊、替诊等 |

**图例**：

- **虚线格** = 占位预览（来自周排班，尚无正式 Schedule）
- **实线格** = 正式排班（draft 灰 / active 绿 / inactive 停诊）

### 4.2 生成正式排班

路径：工具栏 →「生成正式排班」

| 步骤 | 说明 |
| --- | --- |
| 选类型 | 日排班（单日模板重复）或周排班（按 weekday 取 T2） |
| 选模板 | 下拉选择已启用的 T2 或 TW |
| 生成区间 | **本次**要落地的起止日期（与排班设置里「占位有效期」无关） |
| 自动发布 | 建议首批关闭，生成后人工核对再发布 |
| 自动放号 | 依赖自动发布；首批建议关闭，放号前核对 T1 |

系统行为：区间内逐日生成；**已存在正式排班的日期跳过**；T3 `CLOSED` 日跳过。

### 4.3 单条排班生命周期

```text
新建（draft）→ 编辑 Actor / 出诊时间 → 发布（active）→ 批量放号 → 患者可约
                    ↓                              ↓
              整日停诊（inactive）          部分 Slot 停诊
                    ↓
              恢复开诊（须重新放号）
```

**新建/编辑**（详情抽屉）：

- 选择号源类型（必填）、医师、诊室、规划日期与出诊起止时间
- 草稿可多次修改；发布后改 Actor 需谨慎（涉及已约患者）

**发布**：

- 须填规划起止时间（通常等于当日出诊窗口）
- 同人同时段可能冲突警告，确认后可继续

**批量放号**（详情抽屉 → 放号）：

- 若日排班绑定了 T1：按 T1 行生成 Slot
- 否则：填写开始/结束、每段时长（0=整段 1 个）、容量，或使用放号策略默认
- 放号成功后可在号源日历核对

**复制到下一周**：

- 复制当前筛选条件下已发布排班到下一周（含 Actor；**重新放号**）

**从岗位模板生成**（P1，可选）：

- 选医师 → 读取 health 岗位 `scheduleItems` → 生成草稿 Schedule
- 适合岗位已在基础资料维护、尚未配 T2 的科室

### 4.4 停诊

| 方式 | 入口 | 影响 |
| --- | --- | --- |
| 整日停诊 | 详情抽屉 | Schedule → inactive，下属 Slot 不可约 |
| 部分停诊 | 详情抽屉勾选 Slot / 号源日历多选 | 仅选中 Slot → 停诊态 |

若存在**有效预约**（未取消、未挂号）：

1. 系统弹出**停诊向导**，预览影响人数；
2. 按「预约策略 → 停诊策略」执行转交/改约/取消或人工处置；
3. 处置完成后再完成停诊（默认策略：未处置则禁止停诊）。

### 4.5 替诊

**适用**：医师 A 临时不能出诊，B 顶班；**患者预约与号源占用不变**。

操作：active 日程 → 替诊 → 选 B 医师 + 原因。周历、候诊叫号显示「B 替 A」。

与「转交预约」区别：转交会迁移 Slot 占用；替诊不迁移。详见 [10 §8.1](./08-门诊排班概念梳理.md)。

### 4.6 月视图

切换月视图可查看整月摘要；点击某日 drill-down 到周视图或打开当日详情。

## 5. 号源日历（`/booking/slot-calendar`）

**定位**：按日查看 Slot 明细，核对容量与占用，执行封锁/解封。

### 5.1 列表字段

| 列 | 说明 |
| --- | --- |
| 时段 | Slot 起止时间 |
| 科室 | 所属机构 |
| 医师 | 出诊医师（MODE-B 可能为空） |
| 号源类型 | 专家号/普通号等 |
| 容量 / 已约 / 剩余 | 来自 `capacity`、`bookedCount` |
| 状态 | 可约 / 已满 / 停诊 |

### 5.2 常用操作

| 操作 | 说明 |
| --- | --- |
| 查询 | 按日期、科室、医师、状态筛选；支持分页 |
| 详情 | 双击行或点详情，查看关联 Schedule、预约占用 |
| 封锁 | 多选 → 封锁；有预约时走停诊向导 |
| 解封 | 停诊 Slot 恢复可约 |
| 超售标记 | P1；允许已满 Slot 继续预约（院点策略） |

**建议**：每次批量放号后，排班员在号源日历抽查 1～2 条，确认时段与容量与 T1 一致。

## 6. 预约策略（`/booking/policy`）

**定位**：院点级策略，分两个 Tab。**放号策略已并入排班设置**，本页不再维护放号。

### 6.1 挂号策略

控制预约与窗口挂如何衔接（对应 `bkg_registration_policy`）。

| 字段 | 选项 | 上线建议 |
| --- | --- | --- |
| 现场取号模式 | 纯现场不占号 / **先约后挂** / 现场占当日号源 | 多数医院选「先约后挂」 |
| 挂号时自动签到 | 开/关 | 视分诊流程；默认关 |
| 取消预约处置 | 释放号源并取消预约（默认）/ 取消预约 / 保留预约（KEEP_SLOT） | 默认 `RELEASE_SLOT_ONLY`：**释号 + 软删预约行**（与「取消预约」在退号回调等价）；勿理解为「仅释号保留预约行」，否则撞 `uk_wkf_appt_patient_service_day` 导致退号后再挂失败 |
| 允许从预约改医师 | 开/关 | 分诊号可开；专家号通常关 |

### 6.2 停诊策略

控制停诊向导默认行为（对应 `bkg_schedule_change_policy`）。

| 字段 | 说明 | 上线建议 |
| --- | --- | --- |
| 停诊默认处置 | 人工 / 自动转交 / 自动改约 / 自动取消 | 初期选「人工」 |
| 转交匹配规则 | 同时段同号别 / 同日最近 / 同科任意 | 转交模式下配置 |
| 未处置禁止停诊 | 开/关 | 建议**开启** |
| 预览后冻结源号源 | 防并发新约 | 建议开启，TTL 15 分钟 |

## 7. 医院上线标准数据初始化

以下 SOP 适用于**单科室试点 → 全院推广**；顺序不可颠倒：主数据 → 策略 → 模板 → 正式排班 → 验证预约。

### 7.0 阶段总览

```text
阶段 A  环境与权限
阶段 B  health 主数据（科室、医师、岗位、诊室、号源类型）
阶段 C  预约策略（挂号 + 停诊）
阶段 D  排班设置（放号策略 → T1 → T2 → TW → T3）
阶段 E  正式排班落地（生成 → 发布 → 放号）
阶段 F  预约与叫号验证
阶段 G  角色授权与培训
```

### 7.1 阶段 A：环境与权限

| 步骤 | 操作 | 验收 |
| --- | --- | --- |
| A-1 | 确认 `-Pwith-booking` 编译部署，`zxplat.modules.booking.enabled=true` | 重启后菜单出现「统一预约」 |
| A-2 | 确认 Flyway `booking` V1～V10 已执行 | 库中存在 `wkf_schedule`、`bkg_*` 等表 |
| A-3 | 管理员重新登录 | 可见排班设置、门诊排班等子菜单 |
| A-4 | 创建角色：排班员、预约员、分诊员 | 各角色勾选 §2.3 对应权限 |

### 7.2 阶段 B：health 主数据

在 **基础资料** 中完成（booking 只读消费，不可在本模块维护）：

| 步骤 | 数据 | 要求 |
| --- | --- | --- |
| B-1 | 门诊科室 | `Organization` 分类为门诊科室；排班员登录时能选为「排班科室」 |
| B-2 | 医师 | 人员档案完整 |
| B-3 | 医师岗位 | `PractitionerRole`：医师 ↔ 科室，角色含 `ROLE_DOCTOR`；绑定可挂号号源类型 |
| B-4 | 诊室 Location | 归属科室或院点允许的上级；form 为诊区/诊室 |
| B-5 | 号源类型 | `HealthcareService`：专家号、普通号等，状态 ACTIVE，可用于挂号 |

**验收**：进入「门诊排班」，顶栏下拉能加载医师、诊室、号源类型；无数据时页面会提示「请在基础资料维护岗位」。

**可选 B-6**：在岗位管理中维护 `scheduleItems`（周几、时段 JSON），便于门诊排班「从岗位模板生成」— 非必须，若已配齐 T2/TW 可跳过。

### 7.3 阶段 C：预约策略（P1 可选 / 菜单隐藏）

> **P1 默认**：**不必**维护挂号策略；无 `bkg_registration_policy` 行时系统默认 `WALK_IN_WITH_SLOT`（窗口挂号占当日号源）。下列步骤仅在需要切换为「先约后挂」等高级模式时执行（需开放「预约策略」菜单或 DBA 直写）。

路径：**统一预约 → 预约策略**（P1 菜单隐藏）

| 步骤 | 操作 | 试点建议值 |
| --- | --- | --- |
| C-1 | 选试点科室 | 如「内科门诊」 |
| C-2 | 挂号策略 → 现场取号模式 | 默认 **`WALK_IN_WITH_SLOT`**；先约后挂选 `APPOINTMENT_FIRST` |
| C-3 | 停诊策略 → 停诊默认处置 | `MANUAL`（人工） |
| C-4 | 停诊策略 → 未处置禁止停诊 | 开启 |
| C-5 | 保存 | 切换科室重复 C-2～C-4，或确认租户默认 |

### 7.4 阶段 D：排班设置（以「内科专家门诊」为例）

路径：**统一预约 → 排班设置**（页内切换 Tab）

#### D-1 放号策略

| 字段 | 示例值 |
| --- | --- |
| 编码 | `RP-INTERNAL-EXPERT` |
| 名称 | 内科专家默认放号 |
| 提前天数 | 7 |
| 时段粒度 | 30 分钟 |
| 单段容量 | 1 |

#### D-2 放号时段 T1

| 编码 | 名称 | 时段 |
| --- | --- | --- |
| `T1-AM-20` | 上午 20 号 | 08:00–12:00，容量 20 |
| `T1-PM-15` | 下午 15 号 | 14:00–17:00，容量 15 |

#### D-3 日排班 T2

为每位出诊医师各建一条（或按号别建）：

| 字段 | 示例 |
| --- | --- |
| 编码 | `T2-ZHANG-EXPERT` |
| 模式 | MODE-A |
| 号源类型 | 专家号 |
| 医师 | 张医生 |
| 放号时段 | `T1-AM-20` + `T1-PM-15`（或只绑上午） |
| 占位有效期 | 如 2026-01-01 ～ 2026-12-31 |
| 启用 | 是 |

科室号（MODE-B）示例：不填医师，只选号源类型「普通号」+ T1。

#### D-4 周排班 TW

| 字段 | 示例 |
| --- | --- |
| 编码 | `TW-INTERNAL-DEFAULT` |
| 科室默认 | **是** |
| 无排班时可约 | **否**（试点推荐） |
| 占位有效期 | 与 T2 一致 |
| 周一 | `T2-ZHANG-EXPERT` |
| 周二 | `T2-LI-EXPERT` |
| … | 周三～周五同理 |
| 周六日 | 留空或绑周末加班 T2 |

#### D-5 日历例外 T3

| 日期 | 类型 | 说明 |
| --- | --- | --- |
| 2026-10-01～10-07 | CLOSED | 国庆 |
| 2026-09-28 | OVERRIDE | 调休按周日班表（选对应 T2） |

### 7.5 阶段 E：正式排班落地

路径：**统一预约 → 门诊排班**

| 步骤 | 操作 | 说明 |
| --- | --- | --- |
| E-1 | 选择排班科室 | 与试点科室一致 |
| E-2 | 生成正式排班 | 选 TW、`2026-07-01`～`2026-07-31`；**自动发布/放号先关闭** |
| E-3 | 周历核对 | 实线 draft 格出现；T3 CLOSED 日无格 |
| E-4 | 逐日或批量发布 | 详情抽屉 → 发布 |
| E-5 | 批量放号 | 详情抽屉 → 放号；确认 T1 段数与容量 |
| E-6 | 号源日历抽查 | 选一日，核对 Slot 条数与容量 |

**首批上线技巧**：

- 先落地 **2 周** 排班验证，再批量生成整月；
- 自动发布/放号适合模板稳定后的例行任务，首批建议人工把关。

### 7.6 阶段 F：预约与叫号验证

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| F-1 | 门诊预约 → 选日期/科室/医师 | 可见可约 Slot |
| F-2 | 选测试患者 → 确认预约 | 成功，余号减 1 |
| F-3 | 号源日历 | 已约数增加 |
| F-4 | 候诊叫号 → 报到 | 队列出现该患者 |
| F-5 | 叫号 / 过号 | 状态正常 |
| F-6 | （P1）挂号台加载预约 → 挂号 | IF-REG-12 衔接正常 |

完整用例见 [06-门诊排班手工测试清单.md](./06-门诊排班手工测试清单.md)。

## 8. 日常运营 SOP

### 8.1 每周例行（排班员）

| 时机 | 动作 |
| --- | --- |
| 每周一 | 检查未来 2～4 周占位预览是否正常；缺失则补生成正式排班 |
| 发布前 | 核对医师、号源类型、T1 时段 |
| 发布后 | 放号 → 号源日历抽查 |
| 周五 | 「复制到下一周」或按 TW 生成下月 |

### 8.2 临时停诊

1. 门诊排班或号源日历发起停诊  
2. 停诊向导处置预约  
3. 通知分诊台（系统短信接口产品侧未默认接入，需院点自行通知）  
4. 恢复开诊：恢复日程 → **须重新放号**

### 8.3 临时加号

- 方式一：详情抽屉 → 放号 → 追加时段（手工填写）  
- 方式二：T3 `EXTRA` + 重新生成该日（适合整段加班）

### 8.4 新医师加入

1. 基础资料：岗位 + 号源类型  
2. 排班设置：新建 T2 → 更新 TW 对应 weekday  
3. 门诊排班：生成/新建正式排班 → 发布放号

## 9. 典型院点配置方案

### 9.1 专家指名预约（MODE-A + T1 大段容量）

- 一个上午 1 个 Slot、容量 20（或按 30 分钟 T1 多行）  
- TW 每 weekday 绑不同医师 T2  
- 挂号策略：先约后挂  
- `fallback_bookable = false`

### 9.2 科室分诊号（MODE-B）

- T2 不填医师，只选普通号 + 诊室（可选）  
- 预约时患者只选科室+时段；挂号时分诊绑医师  
- 放号策略粒度可更细（30 分钟一段）

### 9.3 周末加班门诊

- 常规 TW 周六日留空  
- T3 `EXTRA` 指定周六日期 + 绑加班 T2  
- 生成正式排班时自动包含 EXTRA 日

## 10. 放号优先级与常见问题

### 10.1 放号优先级

```text
1. 日排班绑定的放号时段（T1）— 按 JSON 行原样生成
2. 日排班绑定的放号策略 — 按粒度/容量切分
3. 门诊排班手工批量放号 — 操作员填写起止、粒度、容量
```

### 10.2 FAQ

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 周历只有虚线没有实线 | 仅有占位预览，未生成正式排班 | 「生成正式排班」 |
| 发布了但预约查不到号 | 未放号 | 详情抽屉 → 放号 |
| 占位预览不显示 | TW 未设科室默认 / 占位有效期不含该日 | 检查 TW 配置 |
| 生成跳过某些天 | 该日已有正式排班或 T3 CLOSED | 预期行为 |
| 删除日排班失败 | 被 TW 或 T3 引用 | 先解除引用 |
| 停诊按钮灰 / 提交失败 | 有未处置预约且策略禁止 | 完成停诊向导 |
| 医师下拉为空 | 该科无激活医师岗 | 基础资料维护 PractitionerRole |
| 菜单看不见 | 模块未启用或未授权 | §7.1 |
