# 体检号源日历与预约 · 需求定稿

> **文档性质**：H 线改造需求真源（产品已确认）  
> **状态**：定稿 · 待成码  
> **日期**：2026-08-30  
> **模块**：`zxplat-module-booking`（号源/预约）+ `zxplat-domain` peis（合同类型）+ `zxplat-module-miniapp` / `openhis-pro-mini`（C 端）  
> **对照遗留**：`sdpeis` 号源排期 / 小程序体检预约（业务意图对齐，不照搬表结构）  
> **上游讨论**：会话确认结论（见文末决策表）

## 1. 背景与目标

### 1.1 现状问题

- 现有 `/booking/health-checkup` 是 **团检单位/批次/名单 + 个检下单** 操作台，不是号源规划页。
- 号源依赖门诊排班间接放号，缺少「每天每时段可约人数」「哪天开哪些体检对象类型」的运营能力。
- 学生/教工等对象与校区（校园场景）无法在号源层分池。

### 1.2 目标

将「体检预约」改造为 **体检号源日历中心**，并打通 **窗口预约页 + 小程序预约** 真实占号；号源按 **合同类型 ×（可选）校区 × 时段** 分池。

### 1.3 非目标（本需求不做）

- 本日历页内不做窗口下单 UI（下单另开页 / 小程序）。
- 不做 peis 登记后流程（收费、分科、总检、报告）。
- 不把 peis「团检筹备」合同/名册迁回 booking（筹备仍在 peis）。
- 不硬编码校区日程（如某年某校区周末表）；校区仅在校医院模块启用时作为分池维度。

## 2. 范围与分期

### 2.1 P0（一次交付，四条一起上）

| # | 交付物 | 负责 |
|---|--------|------|
| 1 | 体检号源日历页（替换现 `/booking/health-checkup` 主内容） | booking + web-ele |
| 2 | peis 团检合同增加 **合同类型**；类型字典预置 | peis |
| 3 | 窗口体检预约页（新菜单/路由） | booking + web-ele |
| 4 | 小程序体检预约（选日/时段/校区占号） | miniapp + 小程序 |

### 2.2 P0 日历页功能清单（全部纳入）

1. 月历总览（余量 / 休息 / 约满）
2. 当日时段表明细（容量 / 已约 / 剩余；有校区时按列展示）
3. 改某档容量（新容量 ≥ 已约）
4. 开放 / 关闭某日或某档
5. 设置某日可开展的合同类型（含散客）
6. 时段模板配置 + 一键生成未来 N 天
7. 某天手改：加档 / 删档
8. 复制某日计划到后续多天
9. **已约 / 剩余来自真实预约统计**（非占位 0）

### 2.3 从本页移除

现有「团检（单位/批次/名单/批量约）」「个检下单」Tab **去掉**。团检筹备继续用 peis `/peis/group-check`。

## 3. 业务规则（已确认）

### 3.1 分池维度

| 维度 | 规则 |
|------|------|
| 合同类型 | **分池**（各类型容量互不影响） |
| 校区 | **仅当校医院/校区模块启用时**有意义；与类型组合再分池；日历 **按列** 区分校区（不是顶栏只切一个校区） |
| 时段 | 同一天同一开始时刻下，按「类型 × 校区」各占一行配额 |

**池键（概念）**：`(organizationId, date, slotStart, slotEnd, contractTypeCode, campusCode?)`  
无校区模块时 `campusCode` 为空，不参与分池。

### 3.2 合同类型（预置）

| code（建议） | 显示名 | 说明 |
|--------------|--------|------|
| `STUDENT` | 学生 | 团检合同类型 |
| `STAFF` | 教职工 | 团检合同类型 |
| `ENTERPRISE` | 企业 | 团检合同类型 |
| `WALK_IN` | 散客 | **无合同**时进此池；也作为日计划可勾选类型 |

- 类型以 **合同类型为主**；散客为单独一类。
- 字典 **存放于 peis 种子**，booking / 窗口 / 小程序 **只读引用**；P0 以上四类必须预置。
- 允许后续扩展显示名/启用停用（在 peis 维护）。

### 3.3 进池判定（下单时）

1. **有效合同**：`valid_from ≤ 当天 ≤ valid_to`（若边界为空则按实现约定放宽）且未删除；**不校验支付态**。  
2. 仅一份有效合同 → 使用该合同的 `contract_type_code` 进对应池。  
3. **多份有效合同 → 窗口/用户手选合同**，再按其类型进池。  
4. 无有效合同 → **散客**（`WALK_IN`）。  
5. **不**允许手选类型覆盖合同类型（只能选手选「哪份合同」）。  
6. **下单必须选择体检套餐**（写入预约扩展；不可仅占号不选套餐）。

### 3.4 校区判定（下单时）

- 无校区模块：不选自区，号源无校区列。  
- 有校区模块：用户在下单流程中 **自选校区**；仅展示该日、该合同类型（或散客）仍有余量的校区。

### 3.5 日开放类型

运营可配置「某日允许哪些合同类型（含散客）」：

- 未勾选的类型：该日不可约（即使模板曾生成过该类型档，也应关闭或不可选）。  
- 与「休息日」关系：整日休息时所有类型不可约。

### 3.6 时段生成

- **模板**：由运营配置间隔分钟、上午/下午开放窗、各类型默认容量等；**系统不预填时段窗与容量默认值**。  
- **记住上次**：模板配置保存后，下次打开模板设置带回 **上一次** 配置（按机构）。  
- **默认容量**：模板中各类型容量初始为 **0**；生成后的档位须运营在日历中设容量后才可约（容量为 0 视为不可约）。  
- **生成**：按当前模板生成未来 N 天的日计划与时段行（有校区模块时按校区列展开配额行）。  
- **单日手改**：允许加档、删档、改容量、开闭；覆盖模板结果。  
- **复制**：将某日计划复制到后续多天；若任一目标日 **已约 > 0**，则 **整次复制禁止**，提示先处理有约日期后再复制。

### 3.7 占号与释号

- 窗口页与小程序共用同一套号源与占号 API。  
- 下单必填：患者、套餐、日期时段、（多合同时）合同、（有校区模块时）校区。  
- 下单成功：对应池 `booked_count + 1`（或等价实时统计），不可超容量。  
- 取消/改约：释号；改约先释后占（同事务）。  
- 并发：占号需防超卖（乐观锁 / 条件更新 `booked < capacity`）。

### 3.8 与 peis / campus 边界

| 能力 | 归属 |
|------|------|
| 号源日历、占号、窗口/小程序预约 | booking H 线 |
| 合同类型 **字典种子**、合同类型字段、团检筹备 | peis（booking 只读字典） |
| 校区主数据 | campus（有模块才启用） |
| 到检后登记/诊台/报告 | peis |

## 4. 信息架构与交互

### 4.1 菜单与路由

| 名称 | 路径（建议） | 说明 |
|------|----------------|------|
| 体检预约 | `/booking/health-checkup` | **号源日历**（改造现页） |
| 窗口体检预约 | `/booking/health-checkup-register`（建议） | 新页；权限可挂 `Booking.HealthCheckup.View` 或细权限 |
| 小程序 | 既有体检预约流程改造 | 选日 →（校区）→ 时段 → 提交 |

### 4.2 号源日历线框

```text
┌─ 体检预约（号源日历）─────────────────────────────────────────┐
│ 机构▼  月份  [模板设置] [生成未来N天] [复制日计划]              │
├──────────────┬────────────────────────────────────────────────┤
│ 月历         │ 当日：2026-09-01   可开展类型 ☑学生 ☑教工 …     │
│ 余量/约满/休息│ 状态：开放 / 休息                               │
│              │ 时段表（行=时段起止；列=类型×校区 或 类型）        │
│              │ 08:00-08:30 | 学生·本部 100/12 | 教工·本部 …    │
│              │ [改容量] [关闭档] [加档] [删档]                   │
└──────────────┴────────────────────────────────────────────────┘
```

无校区模块时：列仅为各合同类型（含散客）。

### 4.3 窗口预约页线框（P0）

```text
选患者 → 列出有效合同（0 份=散客；1 份自动；多份手选）
→ 选套餐（必选）→ [有校区则选自区]
→ 选日期（仅可约日）→ 选时段（显示剩余）→ 确认占号
```

### 4.4 小程序（P0）

与窗口同一业务规则（含必选套餐、多合同手选）；展示文案可后续接配置，P0 以可约日/时段/占号正确为准。

## 5. 数据设计建议（成码前可微调表名）

> 以下为逻辑模型；正式 DDL 以 booking / peis Flyway 为准。

### 5.1 peis

- `peis_group_contract.contract_type_code`（有合同必填；散客无合同行）  
- **合同类型字典**：peis 种子表（或等价配置）；booking / miniapp **只读**拉取  
- 存量合同迁移：成码时定默认类型或要求补录  

### 5.2 booking（号源）

| 逻辑实体 | 用途 |
|----------|------|
| 时段模板 | 间隔、上下午窗、各类型容量（可全 0）；**按机构记住上次配置** |
| 日计划 | 日期、是否休息、备注 |
| 日开放类型 | 日 × 合同类型 |
| 日时段配额 | 日 × 起止时间 × 合同类型 × 校区(可空) × capacity × booked × status |

预约扩展需落：`contract_id`（可空）、`contract_type_code`、`campus_code`（可空）、`package_id`（**必填**）、`day_slot_id`。

### 5.3 与旧 H 线表关系

- `bkg_group_checkup_*` / 页内团检操作：**本需求不再作为主路径**；表可保留，UI 移除。  
- `bkg_health_check_package*`：**P0 下单必选套餐**，沿用或对接 peis/booking 套餐主数据（成码时统一数据源）。  
- 门诊 `wkf_slot`：P0 **推荐体检专用配额表**，避免与医师排班号源混用；若复用 Slot 须单独 Schedule 种类并打类型/校区标签（不推荐首版）。

- 包装可约日/时段/下单，传入患者上下文；校区列表在模块启用时返回

## 7. 验收标准（P0）

1. 日历可生成两周号源；可改某档容量；可设休息；可勾选日类型。  
2. 同日同时段，学生池约满不影响教职工池（及企业/散客）。  
3. 启用校区模块时，表头分列校区；下单可选校区；未选或选满不可约。  
4. 有学生合同的人只能进学生池；无合同进散客池；多有效合同须手选合同。  
5. 窗口与小程序约同一档时，已约数同时增加，不可超卖；下单无套餐应失败。  
6. 取消预约后剩余回升。  
7. 原 health-checkup 页不再出现团检单位/批次/名单操作。  
8. peis 合同可维护类型（字典在 peis），且影响进池。  
9. 模板容量默认 0；未设容量（0）的档不可约。  
10. 复制日计划时，目标日有已约则整次失败并提示。
