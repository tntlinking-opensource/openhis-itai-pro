## 2. 架构决策：不共用省医保 FSI HTTP 入口

### 2.1 结论

**工伤不走 `ChsHttpAccessor` / FSI `call_service_url`。**

省医保与工伤对比：

| 维度 | 省医保（`CHS_NATIONAL_JILIN`） | 工伤（`WORK_INJURY`） |
|------|-------------------------------|------------------------|
| 传输 | HTTP POST + OAuth Token + 可选国密 | 本地 **DLL** `Si_Busi(input, output)` |
| 配置键 | `contract.{bus_no}.call_service_url` 等 | **DLL 路径、专线环境**（由 `Si_INIT` 自检） |
| 公共头 | `mdtrtarea_admvs`、`insuplc_admdvs`、`cainfo`… | `infno`、`msgid`、`recer_sys_code=LNYTH`、`sign_no`… |
| 签到 | 9001（HTTP） | **9001（DLL）**，`sign_no` 写入后续交易 |
| 目录/进销存 | 130x、350x（FSI） | 工伤 DLL **无 350x**；院点进销存仍走 **省医保契约**（见 [04-院点生产日志与MVP范围.md](./04-院点生产日志与MVP范围.md) §5） |

### 2.2 复用边界

以下 **可复用**（方案无关）：

- `InsuranceGatewayClient` 接口（`invoke(contractBusNo, infno, input, context)`）
- `yb_invoke_log` / `yb_settlement_record` 审计与结算凭证（`scheme_code=WORK_INJURY`）
- `fin_contract` / `fin_account` 费用性质与账户模型
- HIS 收费分组、退费冲正 **编排模式**（非 infno 实现）

以下 **必须新建**（工伤专用）：

- `OpenHIS.Win.WorkInjury` — 本机 `Si_INIT` / `Si_Busi` + 9001 会话（见 [07-OpenHIS.Win工伤本地桥接.md](./07-OpenHIS.Win工伤本地桥接.md)）
- `WorkInjuryClientInvokeAppService` — `prepareInvoke` / `submitInvokeResult`（**编排真源在 Whale**）
- `dto/scheme/workinjury/*` — 工伤入参/出参（1101 出参含 `qualification_id` 等）
- 编排：`WorkInjuryOutpatientSettlement旧命名（已废止） 等（2204→2206→2207 链，字段映射不同）

```text
┌─────────────────────────────────────────────────────────────┐
│ web-ele（浏览器 @ 业务窗口 PC）                                 │
└───────────────┬─────────────────────────────┬───────────────┘
                │ REST                         │ localhost:5000
                ▼                              ▼
┌───────────────────────────┐    ┌────────────────────────────┐
│ Whale JVM (8081)          │    │ OpenHIS.Win.WorkInjury     │
│ prepareInvoke / submit    │    │ 9001 sign_no + Si_Busi     │
│ yb_wi_invoke_session / BR-WI  │    │ JLSiInterface.dll          │
└───────────────────────────┘    └────────────────────────────┘
                │
                ▼（仅省医保）
        ChsHttpAccessor → FSI HTTP
```

> **WORK_INJURY 不经 Whale 侧 `InsuranceGatewayClient` 直调 DLL**；服务端 Accessor 仅作 scheme 路由占位，防止误配 `bridge_url`。

## 3. 纯 DLL 落地形态（已定稿）

院点为 **Windows + 纯 DLL**；Whale（Java，**可为 Linux**）不能 `LoadLibrary`。  
**二期 MVP：DLL 出站放在 `openhis-pro-win`**，与银联通道 C 同模式 — **web-ele 调本机 OpenHIS.Win**，Whale 只做编排与落库。

### 3.1 OpenHIS.Win.WorkInjury（P0 真源）

```text
web-ele @ 挂号/收费/医生站 PC
    │ prepare-invoke ← Whale 8081
    │ POST /api/work-injury/invoke → OpenHIS.Win :5000
    │ submit-invoke-result → Whale 8081
    ▼
OpenHIS.Win.WorkInjury
    │ ensureSign (9001，本进程 sign_no)
    │ Si_Busi(inputdata)
    ▼
JLSiInterface.dll + 工伤专线环境
```

- **不**再单独部署 `work-injury-bridge.exe`
- Win **不理解** 2201→2207 编排；只注入 `sign_no` / `msgid` / 公共头并透传
- **`sign_no` 真源在 Win 进程**（每台业务 PC 独立 9001），Whale 不缓存全院 sign_no
- 详细 HTTP API：[07-OpenHIS.Win工伤本地桥接.md](./07-OpenHIS.Win工伤本地桥接.md)

### 3.2 配置要点

```properties
# chs-contract.properties — 工伤段（见 03-fin_contract映射示例.md）
contract.H22010402403-GS.scheme=WORK_INJURY
contract.H22010402403-GS.fixmedins_code=JL2201992002    # DLL 出站（院内 fin_contract 列仍 H22010402403）
contract.H22010402403-GS.recer_sys_code=LNYTH
contract.H22010402403-GS.infver=V1.0
# 无 bridge_url / dll_path — DLL 路径仅在 OpenHIS.Win native/workinjury/
```

```json
// OpenHIS.Win — WorkInjurySettings（示例）
{
  "Enabled": true,
  "DefaultFixmedinsCode": "JL2201992002",
  "RecerSysCode": "LNYTH",
  "DllFileName": "JLSiInterface.dll"
}
```

> **院内** `fin_contract.fixmedins_code` 可与省医保同为 `H22010402403`；**Win invoke 出站** 用 `JL2201992002`。`bus_no` 必须 **`H22010402403-GS`**，以便 Whale 按 scheme 路由。

### 3.3 不建议

- 在 `ChsHttpAccessor` 内 if-else 混入工伤逻辑
- 假设工伤可复用省医保 1101/2207 DTO（字段语义不同）
- 用省医保 `default-contract-bus-no` 回落到工伤契约（多契约院点会串线）

## 4. 签到与会话（9001 / 9002）

| 交易 | 用途 | 运行侧 |
|------|------|--------|
| 9001 | 签到，获取 `sign_no` | **OpenHIS.Win** `WorkInjurySignSession.ensureSigned` |
| 9002 | 签退 | Win 日终 / 托盘退出；Whale **不**代调 |

规则（摘自 V1.3 手册）：

- 除 9001 外，所有交易 `sign_no` **不可为空**
- `msgid` = 协议机构编号(6) + `yyyyMMddHHmmss` + 顺序号(4)，不可重复
- 工伤 **无** 省医保式 OAuth Token 缓存；会话仅维护 `sign_no` + 操作员信息

## 5. 与省医保共存部署

同一院点可同时启用：

| 费用性质 | scheme | 网关 |
|----------|--------|------|
| 吉林省医保 | `CHS_NATIONAL_JILIN` | FSI HTTP |
| 工伤 | `WORK_INJURY` | DLL Bridge |

收费时按患者选择的 **账户 → fin_contract.bus_no** 决定路由；读卡 1101 亦走对应 scheme（工伤 1101 出参结构不同）。

## 6. 扩展组件（可选模块）

工伤 **不是** 省医保 `zxplat-module-chs-jilin` 的默认组成部分；须 **独立开关** `zxplat.modules.work-injury.enabled`（默认 false）。

| 要求 | 实现要点 |
|------|---------|
| 未装模块行为不变 | `health-infrastructure` 提供 **NoOp** Extension；`health-application` 不 import 工伤包 |
| UI 不泄露 | 无 `fin_contract` 工伤行 / 开关关闭 → 不展示费用性质、9102/2301、工伤对账菜单 |
| 路由隔离 | Whale 仅 `scheme=WORK_INJURY` 且 enabled 时走 **客户端 invoke 编排**；JVM 不调 DLL |
| 进销存不变 | 350x 仍走省医保契约（见 [04](./04-院点生产日志与MVP范围.md) §5） |

详见 [08-概要设计.md](./08-概要设计.md) §7。
