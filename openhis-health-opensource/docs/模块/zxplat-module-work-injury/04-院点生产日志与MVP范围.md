## 4. 院点实际交易链（固化）

### 4.1 门诊收费（主链）

```text
9002 → 9001                    # 几乎每次业务前刷新签到
1101                           # 读卡（人员 + diagnosis 认定结论）
2301                           # 审批上传（approveType=12 + injureAffirmID）
2201                           # 登记（ipt_otp_no / qualification_id / adm_diag_dscr / med_type）
2203                           # 就诊信息
2205 → 2204                    # 先撤明细再上传（院端固定习惯）
2206 → 2207                    # 预结算 → 结算
```

**观察：**

- 有 2203 的当天 **100% 同日有 2201**（登记是硬前置）。
- 2206 与 2207 同天 55/56；仅 1 天有预结算未正式结算。
- 日志中 **`med_type` 多为 `12`**（工伤门诊）。
- **`9102` 从未调用**；审批走 **2301 上传**，与手册「1101→9102→2201」推荐链不一致，**以院点为准**。

### 4.2 撤销

| 场景 | infno | 2026 上半年 |
|------|-------|------------|
| 登记后、结算前取消 | 2202 | 9 次 |
| 已结算退费 | 2208 | 1 次（全库 3 次） |

### 4.3 对账（医保办）

```text
9002 → 9001 → 1320（stmt_begindate/enddate + social_pool_code=220100）
           → 1322（month=YYYYMM）
```

- 1320 与 1322 **始终同天成对**（2026 上半年 8 次，无单独 1320 或 1322）。
- **1321、1323 未使用**。
- **不用** 省医保 3201 / 3203A。
