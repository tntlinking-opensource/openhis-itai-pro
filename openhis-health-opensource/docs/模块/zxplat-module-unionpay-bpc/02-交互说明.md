## 二、银联被扫流程（P0 · 仅 `scanPayAmount`）

### 2.1 用户路径

```text
收费员打开 chargeDialog
  → 填写 scanPayAmount（或医保自付段自动带出到 scanPayAmount）
  → **不**预选微信/支付宝/银联（聚合扫码，渠道由 BPC payType 决定）
  → 弹出付款码输入框（扫码枪）
  → 确认 → submitScanPayment()
       a. unionPayBpc#prepareConsumerScan（Whale → merTradeNo）
       b. POST OpenHIS.Win /api/unionpay/consumer-scan
       c. 成功 → confirmSettlement / payRegisterFee
            · paymentDetails 一行：{ payChannelCode: SCAN_PAY, amount: scanPayAmount }
            · 顶层 clientScanResult：Win 回传 + merTradeNo
            · health AppService 内 applyClientScanResult → 替换为 WECHAT/ALIPAY/BANK_CARD 后 settle
  → Loading「等待支付结果…」
  → 失败 → respMsg → 重试或改其它支付方式（health）
```

### 2.2 chargeDialog 银联区（ASCII 线框）

```text
┌─ 收费确认 ─────────────────────────────────────┐
│ 应付：¥ 128.00    医保：¥ 80.00   自付：¥ 48.00 │
├────────────────────────────────────────────────┤
│ … health 其它自付栏（现金等）略 …                 │
│ 扫码支付：[________]  scanPayAmount ← enabled 时 │
├────────────────────────────────────────────────┤
│ 付款码：  [________________________] [扫码]      │
│ （scanCode；扫码枪回车即提交）                    │
├────────────────────────────────────────────────┤
│ 状态：⏳ 等待支付结果…  （轮询时显示）           │
│        或 ✓ 支付成功  tradeNo: 4200…             │
├────────────────────────────────────────────────┤
│           [取消]  [确认支付]                      │
└────────────────────────────────────────────────┘
```

### 2.3 状态机

| 状态 | UI | 后端 |
| --- | --- | --- |
| `IDLE` | 可输入付款码 | payment 草稿已建 |
| `SCANNING` | 按钮禁用、Loading | 已调 Win consumer-scan |
| `POLLING` | 「查询支付结果…」 | Win query-order 轮询 |
| `SUCCESS` | 绿色成功提示 | upc_bpc_order=SUCCESS；允许 settle |
| `FAILED` | 红色 respMsg + 重试 | 不 settle |
| `TIMEOUT` | 提示超时 + 查单/改现金 | order=FAILED 或仍 PENDING |

### 2.4 轮询规则

| 项 | 默认值 | 配置 |
| --- | --- | --- |
| 首次查单延迟 | 2s | `contract.*.poll_interval_ms` |
| 轮询间隔 | 2s | 同上 |
| 最大时长 | 300s | `contract.*.query_timeout_sec` |
| 停止条件 | SUCCESS / FAILED / 超时 | — |

前端实现建议：`useUnionPayPoll` composable（参考 `usePrintJob` 轮询模式）。

## 五、与其它自付明细组合（P0）

同一 payment 可含 health 其它自付明细（如现金 **CASH**）+ 本 Module **银联被扫**一行：

```text
health 明细（不经 BPC）+ scanPayAmount>0
  → prepareConsumerScan → Win consumer-scan
  → settle 一次提交：
       paymentDetails += { payChannelCode: SCAN_PAY, amount: scanPayAmount }
       clientScanResult = Win 回传
  → health AppService：applyClientScanResult → 行替换为 WECHAT|ALIPAY|BANK_CARD
  → upc_bpc_order.pay_type = WEIX|ZFBA|UPAY
  → 正式落库
```

**双存原则**（仅银联行）：BPC 原值与 HIS `pay_enum` 分开存。字段契约见 [03 §3.10](./03-详细设计与编码指导.md#310-settle-挂接-dto定稿-2026-06-23)。

merTradeNo 规则见 [05 §3](./05-BPC接口对照表.md)（`PAYMENT_INDEX_TS`）。

## 六、住院与退费（P0）

与门诊同构：预交金、出院结算 **「扫码支付」** + Extension。

**退费（与 settle 对称）**：

```text
submitScanRefund
  → 金额 = BPC paidAmtFen（无则 txnAmtFen；渠道患者实付；混合支付不含医保个账）
  → HIS 冲账仍按院内下单，与 Win R 金额分账
  → Win /api/unionpay/refund（或已退幂等）→ 缓存 clientRefundResult
  → health 退费 IF + 顶层 clientRefundResult
  → AppService 内 applyClientRefundResult（渠道实付等额 Gate）→ 本地退费
  → 院内成功清缓存；半成功（银联已退）本页重试收口
```

生产试交易 **每笔 C 必须 R 退清**。DTO 见 [03 §3.11](./03-详细设计与编码指导.md)。

## 六点五、半成功补偿（P0）

| 场景 | UI | 后端 |
| --- | --- | --- |
| BPC 已成功、settle 失败 | 收银窗/补偿页提示「支付已成功，结算未完成」 | `retrySettleFromBpcOrder` |
| 操作 | 收费员点「补结算」 | **重传完整 clientScanResult** + 同结构 paymentDetails；禁止重复 C |
| 列表 | 财务/收费主管可选菜单「待补结算扫码单」 | `pagePendingSettleOrders` |
