## 一、模块定位（一句话）

**zxplat-module-unionpay-bpc** + **OpenHIS.Win.UnionPay**：在挂号/门诊/住院收银场景完成**扫码被扫、查单、退货**，将第三方结果映射为 HIS 支付明细（**DM-FIN-002**）；支付单领域与 settle 编排仍在 **zxplat-domain**。

**P0 出站**：通道 **C** — 收银 PC 上 OpenHIS.Win 调 `posinf.dll`（[08](./08-OpenHIS.Win银联本地桥接.md)）。Whale Java 负责**订单落库与 settle 门控**。

### 2.1 模块边界（与 health 收银）

本 Module **仅负责** `scanPayAmount` 银联被扫（C/G/R、`upc_bpc_order`、`ThirdPartyPaymentExtension`）。

**不在本 Module 内**：现金 `CASH`、固定码手工微信/支付宝 `wechatAmount`/`alipayAmount` → `WECHAT`/`ALIPAY` — 属 **zxplat-domain 收银窗 + settle** 既有能力，真源见 **ADR-PAY-001**、**DM-FIN-002 §9.3**、**AS-OP-FIN-001/002**。

> 集成注意：同一 `pay_enum`（如 `WECHAT`）可能来自 health 手工行或银联被扫；**是否经银联**以是否存在 `upc_bpc_order` 为准，非本 Module 实现范围。

### 2.2 银联被扫：BPC payType ↔ HIS pay_enum（D-01）

| BPC `pay_type`（`upc_bpc_order`） | 含义 | HIS `pay_enum` |
| --- | --- | --- |
| `WEIX` | 微信 | **`WECHAT`** |
| `ZFBA` | 支付宝 | **`ALIPAY`** |
| `UPAY` | 云闪付/银联扫码 | **`BANK_CARD`** |

> **双存**（仅银联被扫）：BPC 原值 → `upc_bpc_order.pay_type`；HIS 渠道 → `fin_payment_rec_detail.pay_enum`（由 `BpcPayTypeMapper` 映射，实现位于 `health-domain-shared`）。映射真源 [05 §6](./05-BPC接口对照表.md)、[ADR-PAY-001 §4.3](./01-概要设计.md)。  
> UI 用户选 **`SCAN_PAY`（扫码支付）**；**禁止**落库 `SCAN_PAY`；实际渠道 **以 BPC 返回 `payType` 为准** 映射为 `WECHAT`/`ALIPAY`/`BANK_CARD`。

## 三、范围

### 3.1 在范围内

| 类别 | 内容 |
| --- | --- |
| **场景** | 挂号、门诊收费、**住院预交金/出院结算**、原路退费/退号 |
| **混合** | 医保/工伤 **CHS confirm 后**个人自付段 **银联被扫**；可与 health 其它自付明细（现金等）同一 payment |
| **横切** | 半成功补偿、多租户 mid 隔离、模块可关闭 |
| **客户端** | OpenHIS.Win 替代 UnionPayPlugin；web-ele「扫码支付」（`scanPayAmount`） |

### 3.2 范围外

| 项 | 说明 |
| --- | --- |
| 现金、固定码微信/支付宝手工记账 | **health** 收银窗（DM-FIN-002）；本 Module 不实现 |
| 微信/支付宝官方 SDK、固定码支付对接 | 另立 Module |
| 支付单领域迁出 health | 仍开源 |
| 分账/营销/优惠券 | 单独立项 |
| 实体 POS 硬件驱动 | P0 无硬件 B 扫 C |
| 全院收单行差异硬编码 | 用 Profile + properties + project-H* |
| 旧 `ThreePartPayServiceImpl` 全量 | P2 评估 |

### 编排决策（D-01～D-07）

| # | 决策 | 规则 |
| --- | --- | --- |
| D-01 | payType 双存 | 见 §2.2（**仅银联被扫**） |
| D-02 | 银联被扫 UI | 聚合「扫码支付」；**不**预选微信/支付宝/银联；渠道由 BPC `payType` 决定 |
| D-03 | 医保混合 | **CHS confirm → 自付段扫码 → settle**；CHS 失败不扫码 |
| D-04 | 退费 | **先 Win R 成功 → 再 Whale 本地退费**；**双账**：Win R 金额=`paidAmtFen`（无则 `txnAmtFen`，渠道患者实付）；HIS 冲账仍按院内下单；R 失败不进本地退费；银联已退则带凭证幂等收口 |
| D-05 | 半成功 | 银联已成功、settle 失败 → WARN + **补 settle** API/UI；**禁止**重复 C；**禁止** health 裸作废半成功 DRAFT（BR-OPC-025） |
| D-06 | 配置 | `contract.{fixmedins_code}.*`；P0 **`transport=openhis-win`** |
| D-07 | posNo | 缺省 **= tid**；可选 Practitioner 覆盖 |

## 七、验收标准（P0）

> 用例步骤见 [06-P0手工测试清单.md](./06-P0手工测试清单.md)。

| # | 验收项 | 通过条件 |
| --- | --- | --- |
| AC-01 | 模块装配 | `-Pwith-unionpay-bpc` + enabled 启动无报错 |
| AC-02 | 纯 HIS | 未装 starter 可编译；无银联不影响现金收银 |
| AC-03 | 被扫成功 | 银联 SUCCESS → `upc_bpc_order` → 允许 settle |
| AC-04 | 被扫失败 | 失败不 settle；可重试 |
| AC-05 | 查单 | G / Win query 可补单 |
| AC-06 | 多租户 | 两租户 mid 不串单 |
| AC-07 | Profile | 换 profile 不改 health 代码 |
| AC-08 | 依赖红线 | adapter 不依赖 health-application |
| AC-09 | posNo | 无 pos_no/tid 报错；pos_no=tid 通过 |
| AC-10 | payType 双存 | 银联被扫：WEIX→WECHAT、ZFBA→ALIPAY、UPAY→BANK_CARD |
| AC-11 | 退费门控 | Win R 失败则本地不退费 |
| AC-12 | 半成功 | 可补 settle，不重复 C |
| AC-13 | 医保顺序 | CHS confirm 失败不发起扫码 |
