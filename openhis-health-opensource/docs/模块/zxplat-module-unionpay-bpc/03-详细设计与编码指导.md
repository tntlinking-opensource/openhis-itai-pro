### 3.9 编排与一致性（P0）

| 场景 | 规则 |
| --- | --- |
| 医保混合 | **CHS confirm 成功 → Win consumer-scan（自付段）→ settle**；CHS 失败不扫码 |
| settle 挂接 | **定稿 2026-06-23**：settle 携带 `clientScanResult`；health AppService **内调** `Extension.applyClientScanResult`；扫码行 `SCAN_PAY` **替换**为语义码后落库（见 §3.10） |
| 退费 | **定稿 2026-06-23**：与 settle 对称——退费 IF 顶层 `clientRefundResult`；AppService 内 `applyClientRefundResult` 后再本地退费（见 §3.11） |
| 半成功 | BPC SUCCESS + payment DRAFT → `retrySettleFromBpcOrder`；**重传完整 clientScanResult**（见 §3.12）；禁止重复 C；**health 侧禁止裸作废该 DRAFT**（**BR-OPC-025** / `PaymentDraftHalfSuccessAbortGate`；`PreSettlementAborted` 仅关 PENDING） |
| settle 并发 | 条件更新 DRAFT（对齐 GAP-FIN-001） |

### 3.10 settle 挂接 DTO（定稿 2026-06-23）

> 与 [ADR-PAY-001 §9](./01-概要设计.md)、[02 §五](./02-交互说明.md) 一致。

**前端 → health settle**（如 `confirmOutpatientChargeSettlement` / `payRegisterFee`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `paymentDetails[]` | 数组 | Y | 与其它自付明细（CASH 等）同一结构 |
| `paymentDetails[].payChannelCode` | string | Y | 扫码行固定 **`SCAN_PAY`**（UI 入口；落库前服务端替换） |
| `paymentDetails[].amount` | decimal | Y | = `scanPayAmount` |
| `clientScanResult` | object | 扫码时 Y | **settle 请求顶层字段**，与 `paymentDetails` 并列；**不**嵌在明细行内 |

**`clientScanResult` 字段**（映射 `ThirdPartyScanConfirmCommand`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `merTradeNo` | string | Y | `prepareConsumerScan` 下发 |
| `tradeNo` | string | Y | 银联/BPC 交易号 |
| `payType` | string | Y | BPC 原值：`WEIX` / `ZFBA` / `UPAY` |
| `respCode` | string | Y | 成功 `00` |
| `respMsg` | string | N | 可读描述 |
| `txnAmtFen` | long | N | 实际金额（分）；校验与明细 amount 一致 |

**health AppService 内处理顺序**（扫码行存在时）：

```text
1. 校验 paymentDetails 含 SCAN_PAY 行且 amount>0
2. 校验 clientScanResult.respCode=00
3. Extension.applyClientScanResult(cmd) → upc_bpc_order=SUCCESS
4. 将该行 payChannelCode 替换为 BpcPayTypeMapper.toPayEnum(payType)
5. PaymentChannelGate.requirePersistablePayChannelCode（此时已为语义码）
6. 继续既有 settle 落库
```

**禁止**：前端在 settle 前自行映射 `payType` 为语义码（双存与幂等以服务端为准）。

### 3.11 退费挂接 DTO（定稿 2026-06-23 · 修订 2026-08-01）

> 与 settle（§3.10）**对称**：先 Win `/api/unionpay/refund`，再 health 退费 IF。

**前端 → health 退费 IF**（门诊/挂号/住院原路退）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `clientRefundResult` | object | 原扫码段退费时 Y | **退费 IF 顶层字段**（与明细并列） |
| 其它 | — | — | 沿用既有退费 IF 字段 |

**`clientRefundResult` 字段**（映射 `ThirdPartyRefundConfirmCommand`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `merTradeNo` | string | Y | 原 C 交易 merTradeNo |
| `tradeNo` | string | Y | 原 `trade_no` |
| `refundMerTradeNo` | string | N | 逆向 merTradeNo；缺省 Whale 生成 |
| `respCode` | string | Y | Win refund 成功 `00` |
| `respMsg` | string | N | 可读描述 |
| `refundAmountYuan` | decimal | Y | **须等于**原消费单渠道实付：`paidAmtFen`/100（无则 `txnAmtFen`/100）；与 HIS 下单冲账分账 |

**前端 `submitScanRefund`（web-ele）**：

```text
1. resolveScanRefundPath（BPC）：SUCCESS C → 须 Win R；C 已 REFUNDED → 跳过 Win
2. Win 退货金额 = paidAmtFen（无则 txnAmtFen）；禁止用账单应退总额；HIS 冲账仍按下单
3. session 缓存凭证；命中须 merTradeNo+渠道退货金额与当前 BPC 一致
4. Win「已全额退款/订单已退货」→ 视为成功；头寸类错误仅当查单明确已退才幂等
5. 返回 clientRefundResult → 调 health 退费 IF；院内成功清缓存
```

**`applyClientRefundResult`（BpcSettleDomainService）**：

```text
1. respCode=00
2. Gate：toFen(refundAmount) == resolveChannelRefundAmtFen（paid_amt_fen，无则 txn_amt_fen）
   （否则 BPC_REFUND_AMOUNT_MISMATCH；医院账不参与本 Gate）
3. 原单已 REFUNDED：有 R 行 → 幂等成功；无 R 行 → 补记 R 后成功
4. 否则插 R + 原 C → REFUNDED
```

**health AppService 内处理顺序**（原路退扫码段时）：

```text
1. 校验 clientRefundResult.respCode=00
2. Extension.applyClientRefundResult(cmd) → upc_bpc_order 逆向状态（含等额/幂等）
3. 继续既有本地退费落库（单事务门控：R 失败则不本地退）
```

### 3.12 半成功补偿 DTO（定稿 2026-06-23）

**`retrySettleFromBpcOrder`**（或 health settle 补偿入口）请求：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `paymentId` | long | Y | 半成功 payment |
