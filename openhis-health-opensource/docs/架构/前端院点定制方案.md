# 前端院点定制方案（zxplat-ui）

> **文档性质**：`zxplat-ui` 多院点差异的**唯一架构真源**  
> **版本**：v1.0 | **日期**：2026-07-13  
> **关联**：[模块化开发规范 §11](./模块化开发规范.md#11-院点定制projects) · [HIS 发布与热更新方案 §1](../运维手册/04-HIS发布与热更新方案.md) · [project-H22010402403](../project/project-H22010402403/)

---

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| **主线干净** | `apps/web-ele/src` 只放产品通用能力，不写 `if (hospital === 'xxx')` |
| **与后端对称** | 院点 ID 与 `projects/project-H*` 一一对应 |
| **单仓维护** | 同一 Git 仓库、同一主线分支；**不用**长期院点分支或独立 fork |
| **编译期选型** | 构建参数 `ZXPLAT_PROJECT` 决定 env 与文件重载；产物为静态 dist |
| **最小覆盖** | 只改差异文件，不全量复制前端工程 |

### 1.1 明确不做（Non-Goals）

- **一院一分支**：长期分支 merge 成本指数上升，禁止作为院点交付方式
- **一院一 Git 库**：除非院方/外包自持代码且合规要求物理隔离
- **运行时换肤/换页**：SPA 无 Spring 式 classpath 热替换；差异在 **Vite 构建阶段** 注入
- **污染 `@zxplat/*` 与 packages/**：院点代码不进 workspace 公共包

## 2. 与后端对照

```text
zxplat/                                  zxplat-ui/
├── projects/project-H22010402403/       ├── apps/web-ele/src/
│   ├── pom.xml + src/                   ├── packages/
│   └── （部署信息等）                    └── projects/project-H22010402403/
└── docs/projects/project-H22010402403/      ├── .env.*
                                             └── overrides/
```

| 维度 | 后端（主仓 zxplat） | 前端（独立仓 zxplat-ui） |
|------|------|------|
| 选型键 | Maven Profile（`with-chs` 等）+ 院点模块 | 环境变量 `ZXPLAT_PROJECT=H22010402403` |
| 配置差异 | `application.yml`、Flyway 院点脚本 | `.env.production` / `.env.development` |
| 代码重载 | 院点 jar 内 `@Primary` / 同名 bean | `overrides/` 下同名 `#/` 模块 |
| 构建入口 | `mvn -pl projects/project-H*` | `run-web-ele.mjs` + `ZXPLAT_PROJECT` |
| 院点定制 | `zxplat/projects/project-H*`（代码）· `docs/projects/project-H*`（文档） | `zxplat-ui/projects/project-H*` |

## 3. 目录结构

```text
zxplat-ui/
├── VERSION                            # ZXPlat 前端业务版本（研发手工，单行 x.y.z[.n]）
├── VERSION.md                         # 简短说明（勿与 package.json 的 Vben 5.x 混淆）
├── apps/web-ele/
│   ├── src/                           # 产品源码
│   ├── .env / .env.production         # 产品默认 env（不含院点差异）
│   ├── vite.config.mts
│   └── vite.project-override-plugin.ts
├── projects/
│   ├── README.md
│   └── project-H22010402403/          # 长春市朝阳区中医院（示例）
│       ├── README.md
│       ├── .env.production
│       ├── .env.development
│       └── overrides/
│           └── layouts/auth.vue       # 登录页授权文案
└── scripts/zxplat-project/
    └── run-web-ele.mjs                # 加载院点 env 后启动 Vite
```

**命名约定**：目录名固定为 `project-{定点医疗机构编码}`，与主仓 `projects/project-H*` **同名**（如 `H22010402403`）；UI 落在 **zxplat-ui**，文档落在 **`docs/projects/project-H*`**。

## 4. 定制分级

与 [模块化开发规范 §11](./模块化开发规范.md#11-院点定制projects) 对齐：

| 级别 | 场景 | 前端做法 | 放置位置 |
|------|------|----------|----------|
| **L0** | API 地址、医保电子凭证 URL、机构编码 | 环境变量 | `projects/project-H*/.env.*` |
| **L1** | 菜单、开关、字典、Feature Flag | 后端配置 + 主线读接口 | 不改院点目录 |
| **L2** | 单页文案、流程微调、打印映射 | 编译期文件重载 | `projects/project-H*/overrides/` |
| **L3** | 整模块差异、大量新页面 | 评估独立 workspace 或产品化进 Module | 需架构评审 |

**优先级**：能 L0 就不 L2；能 L1 就不改前端；L2 只覆盖必要文件，禁止复制整个 `src/`。

## 5. 工作机制

### 5.1 环境变量（L0）

设置 `ZXPLAT_PROJECT=H22010402403` 后，`run-web-ele.mjs` 在启动 Vite **之前** 按序加载：

```text
projects/project-H22010402403/.env
projects/project-H22010402403/.env.production   # 或 .env.development
projects/project-H22010402403/.env.local
projects/project-H22010402403/.env.production.local
```

后加载文件覆盖先加载项；再与 `apps/web-ele/.env*` 合并（Vite 标准行为）。  
同时写入 `VITE_ZXPLAT_PROJECT`，供运行时读取（若需要）。

**示例**（朝阳中医院 `.env.production`）：

```env
VITE_GLOB_YB_EC_VOUCHER_URL=http://10.47.0.67:8089/localcfc/api/hsecfc/localQrCodeQuery
VITE_GLOB_YB_EC_ORG_ID=H22010402403
```

### 5.2 文件重载（L2）

Vite 插件 `zxplat-project-override`（`apps/web-ele/vite.project-override-plugin.ts`）在 `resolveId` 阶段拦截以 `#/` 开头的导入：

```text
import '#/layouts/auth.vue'
  → 若存在 projects/project-H22010402403/overrides/layouts/auth.vue → 用院点文件
  → 否则 → apps/web-ele/src/layouts/auth.vue（主线默认）
```

**规则**：

- 仅对 `#/` 别名生效（与 `package.json` 的 `imports` 及业务 import 习惯一致）
- `overrides/` 内路径与 `src/` **相对路径一致**（不含 `src/` 前缀）
- 支持 `.ts` / `.vue` / `.tsx` 及目录 `index.*`
- 相对路径 `./foo` 的 import **不会**被重载；院点扩展请通过 `#/` 引用可被覆盖的模块

### 5.3 构建产物

院点构建仍输出到 `apps/web-ele/dist/`，与主线相同路径；差异已打入静态包。  
换院点 = 换 `ZXPLAT_PROJECT` 重新构建，**不能**同一份 dist 切换院点。

## 6. 日常命令

在 `zxplat-ui` 根目录：

```powershell
# 本地开发（朝阳院点）
$env:ZXPLAT_PROJECT = 'H22010402403'
pnpm run dev:ele:project

# 本地联调（vite.config.local.mts，端口 5778）
pnpm run dev:local:project   # 需先设 ZXPLAT_PROJECT

# 生产构建
pnpm run build:ele:project
```

在 `publish/` 目录：

```powershell
# 默认本院 H22010402403
.\publish-frontend.ps1

# 指定院点
.\publish-frontend.ps1 -Project H22010402403

# 产品主线（无院点 env、无 overrides）
.\publish-frontend.ps1 -NoProject

# 前后端一起（后端 -Customer，前端 -Project 默认同步）
.\publish.ps1 -Customer H22010402403 -Project H22010402403
```

构建日志出现 `[zxplat-project] project-H22010402403 (overrides enabled)` 表示院点插件已生效。

## 7. 新建院点

1. 复制 `projects/project-H22010402403` → `projects/project-Hxxxxxxxxxx`
2. 修改 `.env.production` / `.env.development`（L0）
3. 将差异文件放入 `overrides/`，目录对齐 `apps/web-ele/src`（L2）
4. 本地验证：`ZXPLAT_PROJECT=Hxxxxxxxxxx pnpm run dev:ele:project`
5. 在 `docs/project/` 补充院点说明（可选，与后端 project 文档并列）
6. 更新 `publish` 脚本调用处的默认 `-Project`（若该院为新的默认交付院点）

**禁止**：在 `apps/web-ele/src` 增加院点硬编码。
