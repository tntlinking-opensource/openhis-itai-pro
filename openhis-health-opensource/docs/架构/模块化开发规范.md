## 1. 设计目标

| 目标 | 说明 |
|------|------|
| **全仓开源** | `zxplat-framework`、`zxplat-core`、`zxplat-module-*` 均以源码形式公开（LGPL-3.0-or-later） |
| **扩展 Module 可选装配** | EMR / CHS / Booking 等独立 `{mod}-starter`，Maven Profile 按需启用 |
| **构建期装配** | fat jar 在 Maven 构建时组装；**不做**运行时动态加载 JAR |
| **同构六层** | 领域型与网关型共用骨架；差异在 gateway 是否有出站实现、AppService 是否调外平台 |

### 1.1 明确不做（Non-Goals）

- 运行时 OSGi / PF4J / Spring Boot Loader 插件化
- 组合 SKU（临床包、全院包）
- 在 `zxplat-core` 内直接依赖扩展 Module 的 bridge/application（扩展在 `zxplat-module-*`）
- 院点定制污染 `zxplat-core`（定制在 `projects/project-H*`）

## 3. 六层 Module 骨架

每个 `zxplat-module-{name}`（或迁移中的 `whale-{mod}`）采用 **contracts → domain → gateway → application → bridge → starter**（+ 可选 **host**）。

| 层 | Maven 模块 | 职责 | 依赖要点 |
|----|------------|------|----------|
| **contracts** | `{mod}-contracts` | **chs 样板**：仅根包平铺 `*Facade`；其他 Module 过渡态可仍含 `*Reader/*Writer/*Client` | 不依赖 health、不依赖其他 Module |
| **domain** | `{mod}-domain` | 本 Module 实体、仓储、DomainService | 可依赖 `{mod}-contracts` |
| **gateway** | `{mod}-gateway` | 外平台传输：HTTP/SDK、签名、编解码、调用审计；领域型可为 **NoOp 占位** | 依赖 contracts + domain；**禁止** `*AppService` |
| **application** | `{mod}-application` | `*AppService`、`*ClientImpl`、hisproxy、Flyway | 依赖 contracts + domain + gateway |
| **bridge** | `{mod}-bridge` | `*ExtensionImpl`、Mapper、`**internal/*ContextLoader**`（**自写**读 HIS） | 依赖 contracts + **zxplat-domain** + zxplat-domain；**禁止** health-module-support、application/gateway |
| **starter** | `{mod}-starter` | 安装入口；聚合 bridge + application（gateway 经 application 传递，chs 另显式依赖 gateway） | Host / 院点声明 |
| **host** | `{mod}-host` | remote：health 侧 `*Facade` HTTP 客户端（原 http-starter） | contracts + gateway + domain；**禁止** application |

**remote 可选**：`{mod}-host` 在 health 进程实现 contracts 的 **`*Facade`** 远程客户端；**禁止**依赖 `{mod}-application`。

### 3.0.1 bridge 读 HIS（硬约束）

- **自包含**：每个 `{mod}-bridge` 在 `internal/*ContextLoader` 内完成「Extension 调 Facade 前」所需的 HIS 读组装；**不得**依赖 `health-module-support`（含 `EncounterContextReader`、`ProductDefinitionBatchLoader` 等）。
- **唯一数据 API**：只调用 `zxplat-domain` 的 `*QueryService` 与 `queries/model`；**禁止** `*Repository`、JPA Criteria、自写 SQL。
- **允许重复**：与其它 Module 逻辑相同可 **复制粘贴**，不抽回 health 共享 querysupport。
- 细则：[模块代码规范 · module-bridge-his-read.md](../.cursor/skills/模块代码规范/references/module-bridge-his-read.md)

### 3.1 领域型 vs 网关型（同一骨架）

| 类型 | 示例 | AppService 终点 | gateway 层 |
|------|------|-----------------|------------|
| **网关型** | chs-jilin、einvoice-boss、elep-jilin、unionpay-bpc | 调 gateway 接口 + 写 domain | 有 HTTP/SDK 实现（chs 已拆 `{mod}-gateway`） |
| **领域型** | booking | 主要写 domain | NoOp 或渠道通知占位；**可无**独立 gateway 子模块 |

主链路 **Health → Module**（网关型结算/进销存）：

```text
zxplat-application
  → *Extension（zxplat-infrastructure / com.zxplat.domain.infrastructure.integration）
  → bridge ExtensionImpl + Mapper + *ContextLoader（bridge 内，**自写**读 HIS）
  → contracts *Facade
  → application *FacadeImpl
  → *AppService
  → {mod}-gateway.*GatewayClient（接口在 gateway 模块）
  → {mod}-gateway 实现（或 remote host）
  → 外平台
  → 并行/之后写 domain
```

**Booking 等领域型**仍走 Extension → Client，但 ClientImpl/AppService 终点以 **domain** 为主；Mod→Health 读写可由 bridge 直接调 `booking-domain`（见 §12.1）。

Mod → Health：`bridge` 的 `*ContextLoader` / `*WriterImpl` 读/写 `zxplat-domain` 或本 Module domain（**只经** `*QueryService` / `*DomainService`，**不**依赖 `health-module-support`）。

### 3.2 样板：zxplat-module-chs-jilin（六层目标态）

代码见 [`zxplat-module-chs-jilin/代码仓库-README.md`](../模块/zxplat-module-chs-jilin/代码仓库-README.md)；增量决策见 `docs/模块/zxplat-module-chs-jilin/17-zxplat-module-chs-jilin-架构-v3.md`；**结构优化推广**见 [`zxplat-module-chs-jilin/OPTIMIZATION-PLAYBOOK.md`](../模块/zxplat-module-chs-jilin/OPTIMIZATION-PLAYBOOK.md)（模板 `docs/_templates/OPTIMIZATION-PLAYBOOK-template.md`）。

```text
chs-jilin-domain         yb_* 实体、Command/Result、*DomainService/*QueryService
chs-jilin-gateway        InsuranceGatewayClient、scheme/、observability/ 审计
chs-jilin-bridge         ExtensionImpl、{Op|Ip}<InfNo>Invoker、port/*Port、Mapper
chs-jilin-application    Insurance*AppService（UI 页）、Flyway(chs)
chs-jilin-starter        embedded 安装入口
chs-jilin-host           gateway-proxy + GatewayClient RemoteImpl（Gateway-Only Remote）
```

**v3 要点**：**无** `{mod}-contracts` / `*Facade`；Extension 链经 bridge **Invoker** 直调 domain 服务；remote **仅** gateway 出站 HTTP。

## 4. 两套契约与 Extension

| 契约 | 模块 | 消费者 | 接口后缀 |
|------|------|--------|----------|
| **HIS Extension** | `zxplat-domain` … `integration` | `zxplat-application`、bridge `@Primary` 实现 | `*Extension` |
| **Module 契约（chs 样板）** | `{mod}-contracts` | `{mod}-bridge` / `{mod}-application` / `{mod}-host` | **根包 `*Facade` 仅此（无子包）** |
| **Module 契约（其他 Module 过渡）** | `{mod}-contracts` | bridge / application | `*Reader` / `*Writer` / `*Client` / `*DatasetLoader` |

**硬约束**：`zxplat-application` **禁止** POM 依赖任意 `{mod}-contracts`（Enforcer）。Health→Module 只经 Extension；Mod→Health 经 bridge 内 Loader/Writer，**不**经 contracts Reader 接口（chs 目标态）。

### 4.1 zxplat-application 与 CHS 解耦

```text
zxplat-application
  ✅ zxplat-domain（integration SPI）
  ✅ zxplat-application（读/写组装在 application.shared + feature support；**health-module-support 已删除**）
  ✗ import com.zxplat.framework.chs.*
  ✗ chs-jilin-contracts / chs-jilin-*（Enforcer）
```

未购/未启 CHS：`NoOp*Extension`，`isEnabled() == false`，业务静默跳过。

### 4.2 Extension 装配约定

- 未装配：`zxplat-domain` … `noop` 注册 NoOp + `@ConditionalOnMissingBean`
- 已装配：bridge `*ExtensionImpl` + `@Primary` + `@ConditionalOnProperty(zxplat.modules.{mod}.enabled=true)`
- **禁止** health 侧 `required=false` 注入 Extension
- Extension DTO 保持**中性语义**（不含省平台字段名）；Mapper 在 bridge 完成防腐

### 4.3 常用 Extension（health 侧）

| Extension | 职责 |
|-----------|------|
| `OutpatientChargeInsuranceExtension` 等 | 门诊/住院医保结算、进销存、追溯 |
| `BossElectronicInvoiceExtension` | 电子发票 |
| `ElepPrescriptionExtension` | 电子处方 |
| `OutpatientBooking*Extension` | 预约衔接 |
| `ThirdPartyPaymentExtension` | 银联等第三方支付 |

清单以 `zxplat-domain/.../integration` 源码为准；新增能力先加 Extension + NoOp，再在 `{mod}-bridge` 实现。

## 5. Contracts 命名与包结构

### 5.0 chs-jilin 目标态：contracts **仅 Facade**

`{mod}-contracts` **Maven 模块保留**（防火墙 + remote 依赖面），**源码**只放 bridge ↔ application 对内解耦用的 **`*Facade` 接口**（平铺于 `com.zxplat.framework.{mod}.contracts`，**无** `orchestration` 子包）。其余一律迁出：

| 原 contracts 包 | 迁往 |
|-----------------|------|
| `reader/*` | `bridge/internal/*ContextLoader`（具体类，**自写**读逻辑） |
| `gateway/*` | `{mod}-gateway` … `gateway.*` |
| `scheme/*` | `{mod}-gateway` … `scheme.*` |
| `command/`、`result/` | **删除** → domain |
| `dto/*` | domain 或 application |
| `client/*`（仅 application/hisproxy） | application 内部，删 contracts 接口 |

DTO/命名：AppService 入参 Request、出参 Dto；扩展模块无 contracts 层。

| 后缀 | 含义 | 落点 |
|------|------|------|
| **`*Facade`** | Module **对内编排门面**（chs 样板） | **`com.zxplat.framework.{mod}.contracts`**（根包平铺，仅此） |
| **`*Reader`** | **zxplat-application** 读聚合 | `zxplat-application` … `application.shared` / feature `support/`；**禁止** bridge 依赖 |
| **`*ContextLoader`** | bridge 内读 HIS 组装 Command | `bridge.internal`（具体类，**自写**，无 contracts 接口） |
| **`*GatewayClient`** | 调**外平台**传输 | **`{mod}-gateway`**（**不在 contracts**） |
| **`*Client`** | 存量 Module 过渡 | 迁移目标 → `*Facade` 或 application 内部 |

**命名红线**：跨边界接口仅用上表后缀；禁止历史 `*Port` 等自造后缀。  
**health 读侧（仅 zxplat-application）**：读聚合入口用 **`*Reader`**（如 `EncounterContextReader`，`application.shared.encounter`），**禁止** `*Facade`（Facade 专指 Module 对内编排）。**bridge 不得 import zxplat-application Loader/Assembler/Orchestrator。**

```text
com.zxplat.framework.{mod}.contracts.*                 # chs 样板：*Facade（contracts 根包平铺，仅此）
com.zxplat.framework.{mod}.gateway.*                   # *GatewayClient、scheme（不在 contracts）
com.zxplat.chs.application.facadeimpl.*         # chs 样板：*FacadeImpl（实现类，非 contracts）
com.zxplat.domain.integration.{mod}.*              # Extension 实现（bridge）
com.zxplat.domain.integration.{mod}.internal.*     # *ContextLoader（bridge 自写读 HIS）
com.zxplat.domain.application.shared.*            # 仅 zxplat-application 读侧 *Reader / *Loader
```

### 5.1 FacadeImpl 落点

| 模式 | 实现类 | 说明 |
|------|--------|------|
| **网关型（chs 样板）** | `{mod}-application` … `*FacadeImpl` | adapter ExtensionImpl 调 Facade；remote 在 `{mod}-http-starter` … `*FacadeRemoteImpl` |
| **网关型（einvoice/elep/unionpay 过渡）** | `{mod}-application.client` … `*ClientImpl` | 迁移目标：contracts 根包 `*Facade` + application `*FacadeImpl` |
| **领域型（booking/crb，过渡）** | 部分仍在 `adapter.client` | **迁移目标**：迁至 application |

`*GatewayClient` **接口**在 **`{mod}-gateway`**；**实现**同模块（chs 已落地）。application 依赖 gateway 模块获取接口。

**gateway 模块内部**：HTTP 工具放 `gateway.http.*`（如 `ChsHttpAccessor`），**禁止**与 `contracts.*Facade` 同包名 `client`。

**application 内部编排**（catalog、session、对账等 hisproxy 专用）：**不**经 contracts；hisproxy 直调 `*AppService`；remote 走 `ChsRemoteAppServiceClient`。

#### 5.1.2 remote 模式：操作人 / 租户如何传递

remote **不转发** HIS 登录 JWT；health ↔ chs-server 之间仅 **`X-Chs-Api-Key`**（可选，机机鉴权）。

| 信息 | health 侧（remote 客户端进程） | 跨进程传输 | chs-server 侧 |
|------|-------------------------------|------------|---------------|
| **登录用户** | JWT → `ICurrentUser` / `CurrentOperatorResolver` | **写入 domain Command**（如 `operatorId`、`tenantId`）随 JSON body 传递 | 优先用 Command 字段；AppService 内若再调 `ChsCurrentOperatorResolver`，**standalone** 时固定 `1` |
| **租户** | 会话租户 → `TenantUtils`；ContextLoader 写入 Command | Command 内 `tenantId` | 同库部署时 chs-server 也配租户上下文；**不**信任客户端 `X-Tenant-Id` |
| **省平台 opter** | adapter ContextLoader / Extension 填 Command | Command → Facade → AppService → `InvokeContext` | **standalone**：`ChsSignCredentialResolver` 固定 `admin`/`1`；**嵌入同进程**：读 `ICurrentUser` |

**原则**：remote 下「当前用户」在 **health adapter 调 Facade 前** 解析并**显式写入 Command**；chs-server **不依赖** health 会话 cookie。独立 chs-server（`zxplat.chs.deployment.standalone=true`）平台签到/经办人走契约固定账号，业务审计以 Command 携带的 `operatorId` 为准。


**chs-jilin application 包分工**（2026-07-09 起）：

| 包 | 后缀 | 说明 |
|----|------|------|
| `application.appservice.*` | `*AppService` | **仅 UI 页面**（hisproxy 暴露 `/api/app/insurance*`） |

**命名红线（v2.7）**：

| 场景 | 后缀 | 包 |
|------|------|-----|
| Mod → **Health 主表**回写 | `*Writer`（adapter） | `{mod}-adapter`（booking/einvoice 样板） |
| Module 自有 **`yb_*` 表** | `*DomainService` | `{mod}-domain`（**禁止** application 层 `*Writer`） |

**禁止**：非 UI 路径使用 `*AppService` 命名（结算编排已并入 `*FacadeImpl`）；domain **不得**依赖 `ResultBody`/gateway。

### 5.4 DTO 分层后缀（chs 样板，与 Extension 减层）

| 层 | 模块 | 后缀 | 示例 |
|----|------|------|------|
| Extension | health-integration-contracts | `*ExtensionIn` / `*ExtensionOut` | `OutpatientChargePreSettleExtensionIn` |
| 编排 Facade | contracts（根包） | `*Facade`（**仅此**） | `ChsOutpatientSettlementFacade` |
| domain 入参 | chs-jilin-domain | `*Command` | `OpPreSettleCommand` |
| domain 出参 | chs-jilin-domain | `*Result` | `OpPreSettleResult` |
| hisproxy | chs-jilin-application | `*Request` / `*Response` | `UploadSale3505Request` |
| 省平台报文 | chs-jilin-application … scheme | `*Input` / `*Output` | `Wi2206Input` |

**减层**：删除 `contracts/command|result|reader|gateway|scheme|dto`；Facade 方法签名直接使用 **domain** 类型。`{mod}-contracts` Maven 模块**不可删除**，但源码**仅**根包平铺 `*Facade`（2026-07-09 起取消 `contracts.orchestration` 子包）。

**实施顺序**（详见决策清单）：**阶段 0** health `EncounterContextReader` rename → **阶段 1** 门诊结算全家桶 + contracts 仅 Facade → **阶段 2** 推广 + remote 主链路 Facade + 规范 v2.4 定稿（**chs-jilin 已落地**，见决策清单「实施完成状态」）。

## 6. 各层开发红线

### 6.1 bridge（原 adapter）

- **禁止** `*AppService`、**禁止**依赖 `{mod}-application` / `{mod}-gateway`、**禁止**依赖 `health-module-support`
- 读 HIS：**仅** `zxplat-domain` 的 `*QueryService`；在 `bridge/internal/*ContextLoader` **自写**组装；**禁止** `application.shared.*` / feature `support/`、health `*Repository` / JPA（ArchUnit）

### 6.2 application

- **唯一**允许 `*AppService` 的 Module 层（另含 `zxplat-application`）
- hisproxy：模块前端 API 在 `{mod}-application.hisproxy`
- **禁止** raw HTTP（注入 `{mod}-gateway` 的 `*GatewayClient` 或 gateway Bean）
- Flyway：`{mod}-application/.../db/migration/{mod}/`

### 6.3 gateway

- HTTP、签到、加解密、invoke 审计装饰、平台连接配置（如 chs `ContractConfig*`）
- **禁止**结算状态机、**禁止** hisproxy Controller
- 可依赖 domain（如 `yb_invoke_log` 审计落库）

### 6.4 domain

- 实体、仓储、DomainService；**禁止**调外平台、**禁止**依赖 application/gateway
- Module 自有 `yb_*` 持久化：**`*DomainService`**（如 `YbClinicPreSettleDomainService`）；状态跃迁由 `ChargeBatchLifecycle` 在 DomainService `save` 前调用
- bridge 层 `*Writer` **仅**用于 Mod → Health 主表回写，不得用于 `yb_*` 表

### 12.1 v3 样板与迁移目标

**统一样板**：`zxplat-module-chs-jilin`（已落地）。新 Module 与存量迁移均对齐 v3 六层：**domain → gateway → bridge → application → starter**（+ 可选 **host**），**不引入** `{mod}-contracts` / `*Facade`。

| 原则 | 说明 |
|------|------|
| Maven 父工程 | `zxplat-module-{name}`；子模块 `{mod}-domain/gateway/bridge/application/starter[/host]` |
| bridge | `*-bridge` 替代 `*-adapter`；`*ExtensionImpl` + `*IntegrationMapper`；读 HIS 只经 `zxplat-domain.*QueryService` |
| 出站编排 | 网关型：bridge/application 内 `{Context}<Op>Invoker`（CHS 例 `Op2601Invoker`）；**禁止** `internal/*Support`、`*FacadeImpl` 厚层 |
| remote | **Gateway-Only Remote**：仅 `{mod}-gateway` 的 `*GatewayClient` 可 HTTP 出站；**禁止** application/bridge/domain 整包 remote |
| 领域型 | booking/emr 等可无独立 gateway 或 gateway 为 NoOp；Extension 链仍经 bridge，终点以本 Module **domain** 为主 |

存量 `whale-{mod}`（如 `zxplat-module-booking`、`zxplat-module-emr`）迁移时：父工程改名为 `zxplat-module-{name}`，artifact `*-adapter` → `*-bridge`，删除 contracts 层，出站逻辑迁入 gateway + Invoker。细则见各 Module 文档及 [模块代码规范 · 非 CHS 模块 v3](../.cursor/skills/模块代码规范/SKILL.md#9-非-chs-模块-v3)。

## 13. 自检清单（新 Module / PR）

```text
□ 六层 artifact（gateway 至少 NoOp 或独立模块）；父工程 `zxplat-module-{name}`
□ **无** {mod}-contracts / *Facade（v3）；Health→Module 只经 Extension SPI
□ bridge 无 AppService、无依赖 application/health-module-support（gateway 出站时 ✓ gateway）
□ bridge 读 HIS 只调 zxplat-domain *QueryService / 写 *DomainService（自写组装，允许 Module 间重复）
□ zxplat-application 未新增任意 {mod}-* POM 依赖
□ health querysupport 读聚合用 *Reader（**health 专用**）
□ Extension + NoOp；@ConditionalOnProperty 与 Profile 一致
□ Flyway 独立目录 + history 表
□ 网关型：AppService 不经 raw HTTP，只经 {mod}-gateway *GatewayClient
□ 主链路（v3 网关型）：Extension → Mapper → Invoker/Port → domain Service → GatewayClient
□ remote 仅 gateway 出站（Gateway-Only Remote）；host 不含 application/bridge
```
