## 1. 六层 / 四层选型

| 类型 | 示例 Module | Maven 子模块 | 出站 |
|------|-------------|--------------|------|
| **网关型六层** | chs-jilin、elep-jilin、einvoice-boss、unionpay-bpc、crb | domain · gateway · bridge · application · starter ·（可选 host） | HTTP/SDK + scheme |
| **Win 网关型五层** | work-injury | domain · gateway · bridge · application · starter | ZXPlat.Win + scheme（gateway 无 HTTP 客户端） |
| **领域型四层** | booking、emr | domain · bridge · application · starter | 无外部 HTTP；domain `access` 占位 |

**选型规则**：需对接外平台 HTTP → 六层 + gateway；仅读写 HIS + 本 Module 表 → 四层，**不**引入 gateway/host。详见 [新扩展包开发指南 §1](./新扩展包开发指南.md)。

## 2. Maven 命名：`module-{short}-*`

| 约定 | 示例 |
|------|------|
| 父工程 | `zxplat-module-{name}` |
| 子模块前缀 | `module-{short}-domain` · `module-{short}-bridge` · … |
| 已统一 | 8 个扩展 Module 均已 `module-{short}-*`（含 CRB P17 ✅） |

Java 根包保持业务语义（如 `com.zxplat.framework.emr.domain`），与 Maven artifact 解耦。

## 3. 依赖铁律 + Enforcer 模板

```text
domain ← gateway ← bridge
domain ← application
bridge ✓ gateway、zxplat-domain、zxplat-domain
bridge ✗ application、~~health-module-support~~（**已删除**）
application ✗ bridge（编译期；运行时由 starter 装配）
host   → gateway only（无 bridge/application）
```

**application `pom.xml` Enforcer**（有 application 层的 Module）：

```xml
<bannedDependencies>
  <excludes>
    <exclude>com.zxplat:module-{mod}-bridge</exclude>
    <exclude>com.zxplat:zxplat-application</exclude>
  </excludes>
</bannedDependencies>
```

**bridge `pom.xml` Enforcer**：

```xml
<bannedDependencies>
  <excludes>
    <exclude>com.zxplat:module-{mod}-application</exclude>
    <exclude>com.zxplat:zxplat-application</exclude>
    <exclude>com.zxplat:health-module-support</exclude>
  </excludes>
</bannedDependencies>
```

## 4. ArchitectureTest 矩阵（v1.1）

与 Enforcer 互补，扫描 **main** 源码 `import` 违规。

| Module | application 测试 | bridge 测试 | application 额外禁止 |
|--------|------------------|-------------|---------------------|
| einvoice-boss | ✅ | ✅ | `gateway.client/local/remote/scheme.*` + `bridge.*` |
| elep-jilin | ✅ | ✅ | 同上（严格六层） |
| unionpay-bpc | ✅ | ✅ | 同上 |
| booking | ✅ | ✅ | `bridge.*` |
| emr | ✅ | ✅ | `bridge.*` |
| chs-jilin | ✅ | ✅ | **`bridge.*` only**；application main 全 cap 禁 `gateway.*`（P15 foundation ✅ 完成 Invoker 迁移） |
| work-injury | ✅ | ✅ | `bridge.*` |

**CHS 母版说明**：application Invoker 已按 cap 全量迁至 bridge（**P11 medicalinfo ✅** … **P15 foundation ✅**）；application main 禁止任何 `com.zxplat.chs.gateway.*` import。新 Module **不应**复制旧模式，应以 **einvoice-boss** 为严格样板。

## 5. domain access / loader 端口命名

| 包 | 后缀 | 职责 | 实现位置 |
|----|------|------|----------|
| `{cap}/access/` | `*Access`、`*Invoker` | 出站 / 跨层能力 | bridge `{cap}/invoker/` 或 application adapter |
| `{cap}/loader/` | `*ContextLoader` | HIS → Command enrichment | bridge `{cap}/context/` |
| `{cap}/command` `{cap}/result` | Command/Result | 编排入参 / 出站结果 | — |

**示例**：

- CHS：`Med5206QueryInvoker`（domain access）← bridge 实现
- EMR：`EmrPdfRenderer` ← application `EmrPdfRendererAdapter`
- Booking：`BookingChannelNotifyAccess` ← bridge `NoOpBookingChannelNotifyAccess`

```text
  model/ | assembler/ | parser/
```

| ELEP | OpCode A0001–A0006 |
