# Health 系统完善（待办与方案）

> **用途**：记录代码审查、联调、生产问题复盘后确认的**已知缺口**及**推荐改法**，与 AS/SDD 需求文档分离；成码后以 PR 关闭对应条目。
>
> **原则**：每条须可独立排期；含严重度、影响面、改法、验收用例；禁止只写「加强校验」而无落点。
>
> **编号规则**：`SYS-IMP-XXX` 为**稳定编号**（不因目录调整而变）；`GAP-{前缀}-{序号}` 为条目标识。
>
> **问题单**：每条 GAP 已拆为独立文档 → **[问题清单/](./问题清单/README.md)**（共 119 条，按问题类型分子目录）。

| 类型 | 典型问法 | 技术特征 | 代表 GAP |

## 严重度口径

| 级别 | 含义 |
| --- | --- |
| **高危** | 高概率正常使用下可导致实物多发、账面扣负或已结算仍多收费，且难自动发现 |
| **中危** | 需并发/重复操作/非常规路径；物理库存通常仍被核发层拦住；多为多单、多费、待办堆积 |
| **低危** | 产品设计允许的能力，或仅影响报表/执行记录；有明确运维补救 |
| **已知限制** | 规格已声明「以后写者校验为准」等，属文档化约束而非未披露缺陷 |
