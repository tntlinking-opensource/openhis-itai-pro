# GAP-STALE-007 仅前端防重、后端不重读

> **问题类型**：Stale页面与跨角色
> **严重度**：中危（已知模式）
> **影响范围**：门+住 + booking + 入出转
> **优先级**：P2
> **状态**：已实施（Wave 2 审计闭环）
> **父文档**：[SYS-IMP-007](../02-Stale页面与跨角色/SYS-IMP-007-跨角色Stale页面与状态不同步.md)
> **Gate 矩阵**：[SYS-IMP-007-跨角色写接口Gate矩阵](../02-Stale页面与跨角色/SYS-IMP-007-跨角色写接口Gate矩阵.md)

---

## 1. 问题描述

仅前端 disable、写路径不重读锚点态

## 2. 发生场景

各模块 AS §7 写「双开以后写者为准」，但仅靠按钮 disable；接口直调、Stale Tab 仍可提交。

## 3. 根因分析

见父文档；核心为读 Gate + 无源态条件更新或 Gate 缺失。

## 4. 业务影响

账实/账价不一致，或合规与安全风险。

## 5. 修改方案（已确认并落地）

### 5.1 统一标准

所有 **跨角色写接口** 在 Cmd 前增加 **最小重读 Gate**（ Charge 态 / Dispense 态 / 医嘱态 **三选其二** 按场景）；能叠加则 **条件 UPDATE**；前端 `disable` 仅体验层。

### 5.2 Wave 2 交付

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| A | STALE-005 签退 Gate（方案 A：`EX-IP-ORD-103`）+ 单元测试 | ✅ |
| B | 全量 Gate 矩阵（Health + IMP-004 + IMP-003） | ✅ |
| C | 审计：无 P0 后端缺口 | ✅ |
| D | 体验层（E1～E4，见矩阵 §5） | ✅ |

### 5.3 审计结论摘要

- **Health**：STALE-001～006 均已后端 Gate 或条件 UPDATE；护士执行写路径重读 `VERIFIED` + occurrence 净态。
- **IMP-004**：ATD-001～008 行锁/条件占床已覆盖 Stale 直调 API。
- **IMP-003**：取消/改约经 `requireAppointment` + `assertActive`（终态 `isDeleted`）；Query 加载拒终态。
