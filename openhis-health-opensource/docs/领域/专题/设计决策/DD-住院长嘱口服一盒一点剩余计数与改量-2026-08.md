# DD · 住院长嘱「单位领用」剩余计数与改量（口服一盒一点 + 拆零下限）

> **状态**：产品裁决已确认（对话 2026-08-19；**拆零下限同源** 2026-09-14）  
> **覆盖**：  
> ① 院点 `inpatientStandingOrderSplittable=0` 下口服长嘱一盒一点的**理论剩余展示**、**待执行按天抑制**、医生站**改量**（停旧+开新 + `based_on` 链）；  
> ② 产品默认拆零下限（单次临床拆零 &lt; 1，如胰岛素）**同一套算法**，仅领入每次 = **1** 拆零（见 **DD-住院执行-拆零单位下限取整-2026-08 §3**）  
> **承接 AS**：**AS-IP-NUR-004**（**BR-IP-EXE-038**，扩展 **BR-IP-EXE-035/036**）、**AS-IP-DOR-003**（**BR-IP-ORD-032** / **IF-IP-DOR-28**）；待执计数 **AS-IP-NUR-001 BR-IP-NUR-005**；出院 **AS-IP-NUR-002 BR-IP-ATD-011①′** 与执行列表同源  
> **明确区分**：本 DD **不**改变写路径整盒/整拆零记账（仍 **BR-IP-EXE-035④** / **036**）；剩余**不落库**，读路径实时计算  
> **文档冲突**：与「每条长嘱独立切批、改量后立刻出新单位待执行」冲突时，**以本 DD 为准**

---

## 1. 问题与目标

院点不可拆时，口服长嘱执行形态对齐临嘱：**一次执行领一整盒**（一盒一点）。  
产品默认下，单次不足 1 拆零（胰岛素等）一次执行领 **1 拆零单位**。  
患者实际按医嘱频次/剂量消耗；护士线下心算「还剩多少、哪天该再领」。改量时医生常停旧开新，若按单条医嘱重开切批，会在仍有剩余时立刻再出待执行并再领。

| 目标 | 口径 |
| --- | --- |
| **展示** | 在对应医嘱上显示已吃 / 剩余 / 预计下次领用日（医生站开嘱列表、护士站执行列表） |
| **待执行** | 剩余仍够覆盖某自然日当天**全部**理论服药量时，该日**不出**领用待执行；不够的那天在**当日第一个频次点**出单位锚点 |
| **改量** | 开嘱页「改量」：停旧（或已停）+ 同药重开；`based_on` 链式关联；观察期（已停未开新）**冻结不扣** |
| **计费库存** | 仅影响列表 pending 与展示；真执行仍整包装或 1 拆零（035④ / 036） |
| **出院** | 门禁 pending 与列表同源抑制；剩余仍够导致无 pending → **不拦** |

## 2. 资格与非目标

### 2.1 资格（两种模式，035 优先）

| 模式 | 条件 | 每次领入拆零 |
| --- | --- | --- |
| **PACKAGE（一盒一点）** | 全局 `inpatientStandingOrderSplittable=0` + 长期药 + 目录 **`injectFlag≠true`** + `packageUnitCode ≠ splitUnitCode` + 用法展示名以「口服」开头 | `packageUnitRatio` |
| **MIN_SPLIT（拆零下限）** | 长期药 + 常规单次临床拆零 `0 < split < 1` + **非「输液开瓶即弃」**（`injectFlag=true` 且用法非「皮下注射」则排除；皮下注射放行）；**不**要求不可拆/口服 | `1` |

同条命中 PACKAGE 时**不再**叠 MIN_SPLIT。未命中任一模式 → 不展示剩余字段、不抑制 pending。  
**035**：药典输液一律不按箱（即使用法误开口服）。**036/038 MIN_SPLIT**：输液默认开瓶即弃；用法「皮下注射」放行（胰岛素）。

### 2.2 非目标

- 不落剩余/已吃持久化表  
- 不按床旁实吃确认扣减（只按医嘱理论频次×剂量）  
- 不靠「同就诊 + 同 medicationId」猜链；**无 `based_on` 的手停重开不续算**  
- 不改门诊半退等其它 `based_on` 语义；住院改量锚 **药嘱→药嘱** 且同就诊、同 `medication_id`  
- 不另开前端字段名（继续 `oralPackage*`，语义=单位领用）

## 3. 改量（医生站 · BR-IP-ORD-032 / IF-IP-DOR-28）

### 3.1 入口

开嘱列表/编辑区「改量」：带出**旧嘱全部可编辑信息**，**药品（`medication_id`）不可换**，其余均可改（剂量、频次、首日量、用法、药房、备注等）。

### 3.2 两种触发（本质相同）

| 源嘱状态 | 行为 |
| --- | --- |
| **在用**（已校对 `VERIFIED`） | 同一事务：停嘱（`stopTime` **允许**医生指定，默认当前时刻）+ 新建长期药品草稿（或 UI 约定后续签发） |
| **已停**（`STOPPED`） | 不再重复停嘱；直接开新长期药嘱 |

### 3.3 关联

- 新嘱：`based_on_table = med_medication_request`，`based_on_id = 源嘱 id`  
- 多次改量：A←B←C **整链**可追溯；剩余与领用事实在链上汇总  
- 同就诊为底线；新嘱 `medication_id` **必须**等于源嘱  
- **禁止**级联停/改 `based_on` 子嘱以外的无关行

### 3.4 观察期冻结

已停且**尚无**以其为 `based_on` 父的新嘱：

- **不扣**剩余（观察几天不算吃）  
- 剩余展示**挂在该已停嘱**上  

改量开出新嘱后：从**新嘱开立日**起按**新用量**继续扣冻结剩余；剩余挂到**链尾最新嘱**；已停旧嘱**不再**展示剩余。

### 3.5 未领第一单位就改量

链上尚无有效单位领用已执行 → 等价于直接新开一条：新嘱按常规出第一单位待执行，无结转剩余。

### 3.6 无 basedOn 手停再开

不续算；新嘱独立切批。

## 4. 剩余计数（读路径 · BR-IP-EXE-038）

> **单位**：一律换算为目录**拆零单位**后再加减（兼容半片、首日量、隔日频次、胰岛素小数次）。

### 4.1 改量链

自当前展示行向上沿 `based_on_table/id` 收集同就诊、同 `medication_id` 的药嘱序列（根→尾）；向下若存在子嘱则展示行不是链尾时**不**挂剩余（观察期挂已停无子的那条；有子则只挂最新）。

### 4.2 领入（患者手里药）

链上所有命中本模式的 **净 COMPLETED** 单位首槽执行（取消执行/不执行的不计；取消后再执行则**仅**当前净完成计入，并从该次执行日**整单位重计**消耗起点）：

```
领入拆零 = 有效领用次数 × claimPerExecution
claimPerExecution = packageUnitRatio（PACKAGE）| 1（MIN_SPLIT）
```

### 4.3 已吃（理论消耗）

按链上各段「用药责任期」展开频次点并累加临床拆零量：

| 段 | 起 | 止 | 用量口径 |
| --- | --- | --- | --- |
| 某次有效领用之后 | **执行当日 00:00**（执行当天也吃） | 见下 | 该责任医嘱当时的剂量/频次/首日量规则 |
| 责任医嘱停嘱后、后继改量开立前 | — | — | **不扣**（观察期） |
| 后继改量开立后 | **新嘱 `req_opened_time` 所在自然日 00:00** | `asOf`（列表截止或当前业务日）与新嘱停嘱取 min | **新**用量；见 §4.4 当天切换 |

`asOf`：护士站列表取 **min(列表截止日, 当前业务日)**——截止日只负责展开待执行窗口，**禁止**把尚未到达的自然日算进「已吃」（否则会出现「剩余 0 但领用时间点还没出、无法执行」）；医生站列表用当前业务日（或请求日）；**禁止**把观察期天数算进已吃。

**取消执行 / 不执行**：该单位视为未领、未吃；若曾按该单位累计过消耗，取消后整段重算。  
**取消后再执行**：从新的执行日起按满单位重新往下扣。

首日量、隔日、半片：与执行侧同一套频次展开 + 槽量换算（**BR-IP-EXE-004/032**），只是用于累加「理论吃掉的拆零」，**不**因此多出日频次 pending。

### 4.4 改量当天（多↔少）

同一自然日发生停旧+开新（或观察后开新落在某日）：

| 情形 | 当天理论日消耗 |
| --- | --- |
| **多→少** | 按**旧（多）**的当日总量 |
| **少→多** | 按**新（多）**的当日总量 |

次日及以后均按新嘱用量。

### 4.5 剩余与下次领用日

```
剩余 = 领入 − 已吃（≥0；算负则按 0 并应已出现领用点）
```

**预计下次领用日**（与 `asOf` 展示截止解耦）：自**首领用自然日**起，按改量链各日理论需求拆零扣减**领入总量**；某日 `当日理论需求拆零 > 行走剩余` → 该日为下次领用日。  
语义：**上一单位够吃到的最后一日的次日**才领下一单位（例：8.26 起、日服 2 片、盒 14 片 → 够吃到 9.1，**下次领用 9.2**）。  
禁止用「asOf 后剩余」再从 asOf 当日重扣——已吃已含 asOf，重扣会把领用日提前一天。

待执行锚点 = 该日**第一个**频次计划点（仍一次领一单位）。

**按天判定、不按次**（方案 A）：一次执行领一单位，按槽位「吃光再领」无业务意义。

示例（盒=10 片，原 QD 1 片，已执行后理论吃 3 天剩 7；改量 BID 每次 1 片）：

- 新量下第 1～3 个服药日各需 2 片，剩 1  
- 第 4 日需 2、剩 1 → 出领用待执行；执行领 10 后当日再扣 2 → 剩余 `1+10-2=9`

### 4.6 待执行抑制（相对 BR-IP-EXE-035/036）

在切批回传单位首槽之后：

- 若「预计下次领用日」晚于某候选首槽所在日 → **抑制**该 pending（不回传）；**剩余恰为 0**（截止日刚好吃完）时仍抑制「够吃到的末日」上的过早首槽  
- 前瞻窗内算不出下次领用日（仍够用）→ 抑制可见的过早首槽  
- **已领用且截止覆盖预计领用日**：抑制后若该日无锚点（改量后切批仍把首槽落在新嘱开立日的典型空窗）→ **在预计领用日第一个频次点补回** pending（列表、待执计数、**出院门禁**同源）；补点前须认该 `planTime` 的 occurrence **终态**——**不执行（Procedure STOPPED）与净已执行（COMPLETED）同为终态，禁止只认已执行**；已终态则**不得**再补回假 pending（否则「不执行后仍 LONG_PENDING_SLOTS」误拦出院）  
- 领入为 0（从未有效领用）→ **不抑制**，按开立出第一单位  
- 真执行写路径不变  

待执行条数（**BR-IP-NUR-005**）与列表 pending **同源**抑制。

### 4.7 展示宿主

| 场景 | 挂在哪一行 |
| --- | --- |
| 链尾在用 / 最新开立 | **最新那一条** |
| 已停、尚无改量子嘱（观察期） | **该已停嘱** |
| 已被改量指走的旧嘱 | **不展示**剩余 |
| 命中规则但**从未有效领用** | **不展示**已吃/剩余/下次领用（避免「0/0」）；第一单位 pending 仍按开立出 |

建议字段（名称以实现 DTO 为准，语义固定）：

- `oralPackageRemainSplitQuantity` / 展示文案（已吃、剩余、**拆零单位字典名**）  
- `oralPackageNextClaimDate`（预计下次领用日；无可空）  
- `oralPackageBatchInventoryApplied`（是否命中本规则**且已有净领用**才为 true）

医生站 **IF-IP-DOR-10/22** 与护士站 **IF-IP-EXE-01** **同源计算**（共享 Support），禁止两套口径。

## 6. 与 based_on 其它用法的区分

| 用法 | 表/指向 | 识别 |
| --- | --- | --- |
| **长嘱改量链** | 药嘱 → 药嘱；同就诊同药；父多为已停长期 | **IF-IP-DOR-28** 写入；剩余计数只认此链 |
| 皮试 companion | 诊嘱 → 皮试药 | `ServiceRequest.based_on` → 药 |
| 护士划价父嘱 | 派生诊/耗 → 父 | 诊疗/耗材，非本剩余规则 |
| 门诊半退克隆 | 药嘱 → 源药嘱 | 门诊场景；住院改量编排不走半退命令 |

## 7. 验收要点（摘）

1. 一盒 14、日服 2 片、8.26 领盒：够吃到 9.1（已吃含截止日）；**预计下次领用 9.2**（不是 9.1）。截止 8.31 时已吃 12、剩余 2、下次领用仍为 9.2。  
2. 改量 BID 后剩 7：前 3 个新量服药日无 pending；第 4 日首点 pending；执行后剩余 9。  
3. 停嘱观察 3 天不扣；改量开新后从开立日起扣。  
4. 取消盒/单位执行后剩余清零逻辑恢复为未领；再执行整单位重计。  
5. 无 basedOn 手开新嘱：立刻可出第一单位 pending，不继承剩余。  
6. 半片 / 首日量 / 隔日 / **胰岛素 0.03 支**：剩余与「预计领用日」与频次展开一致；MIN_SPLIT 领入每次 1。  
7. 从未有效领用：列表不展示已吃/剩余；第一单位 pending 仍可出。  
8. 在用改量：前端可改停嘱时间并写入 `stopTime`；已停源嘱不传。  
9. 出院：改量停旧或剩余仍够导致无 pending → ATD-03/05 **不拦**；真 pending 仍拦并可批量不执行。  
10. **不执行后不补假 pending**：剩余 0、预计领用日=停嘱日、对该日首频次点已登记不执行（STOPPED）→ 列表/待执/出院门禁 **不得**再补回该点 pending；办理出院 **不拦**（禁止只认 COMPLETED 才跳过补点）。
