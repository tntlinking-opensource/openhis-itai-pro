# 追溯码：可选扫、拆零剩余先出、医保字段分工

> **文档性质**：改造基线（按本文落地 = 对话定稿效果）  
> **定稿日期**：2026-07-25  
> **对话来源**：追溯码全链路梳理 → 退供应商剩余码 / 门诊半扫 → 拆零剩余与医保 `trdn_flag` / `minpacunt_drug_trac_cnt` → 覆盖范围与退药余量红线  
> **适用范围**：药库/药房/科室库存单据；门诊/住院发药与退药；清床汇总发药；吉林医保进销存（3502/3505 等）与结算（2207/2304）；相关 AS/SDD（`AS-CUS-TRC-001`、`AS-OP-PHA-001`、`AS-INV-WHS-005`、`09-医保进销存` 等）  
> **禁止误读**：`minpacunt_drug_trac_cnt` **不是**「操作单位≠追溯单位就一律填 0」；拆零数量按 **`floor(拆零量 ÷ trace_unit_ratio)`** 计完整最小包装个数（见 §4.3）。  
> **余量红线**：主档 `remaining_split_quantity` / 在院态一旦写错，后续选码、盖住校验、再发再退会系统性漂移——**发药 OUT、退药 IN、领用、流转写侧必须同一套纪律**（见 §5）。

## 1. 要解决什么

| 原状 / 误区 | 定稿目标 |
|-------------|----------|
| 扫码与主流程耦合，半扫/码数硬 Gate 挡发药 | **扫码可选**（消耗/流转侧）；码校验与主流程脱钩，一律**友好弹窗** |
| 退供应商回放进货单历史 `trace_no` | 预填**当前院内剩余码**（本库净量优先 → 全院在院剩余） |
| 拆零用「应扫个数 = ceil(量÷比)」+ 扫码顺序前填 | **剩余合计盖住即合法**；扣减在已扫集合内 **剩余少的先扣**；已盖住则提示勿再扫 |
| `trdn_flag` 仅靠单位不等/余数公式 | **有扫认实扣**；**未扫默认 `1`** |
| 2207 `minpacunt_drug_trac_cnt` 用收费 `ceil(cnt)` 且与实扫挂钩的误解 | 字段 = **应上传最小包装码条数**；与实扫枚数脱钩；公式见 §4.3 |
| 结算时尚未扫码却想用实扫结果填 2207 | 2207 **只按收费行 + 比例估算**；实扫与 `trdn_flag`/`drugtracinfo` 在发药后 **3505** |
| 退药按「当前剩余」再分摊或新建主档 | **禁止新建**；按发药 **OUT 每码扣减镜像** 加回同一主档（见 §5） |

## 2. 总原则（全局）

1. **消耗/流转侧扫码始终可选。** 不扫不挡主流程；只影响是否写追溯主表/流水。  
2. **入库后中途流转不扫为常态。**  
3. **`locationId` 仅优先匹配**：先本库净剩余 > 0；本库空则回落**全院**同品同批、在院且剩余 > 0。本库没有 ≠ 业务错误。  
4. **无码批**（该品+批主表从未建码）：不校验、不强扫、不写主子表硬路径。  
5. **码与系统校验不一致 → 只弹窗提示，不阻断主流程**（消耗/流转侧）。例：码已耗尽请继续扫、扫多了、盖不住、半扫确认后按未扫继续等。  
6. **领用/退领**（机构库存真变）→ 进销存 **3502**；**院内请领退库/调拨** → 院内流转，**不上**进销存进销类（勿与领用混谈）。  
7. **清床 / 无床直结**触发住院净销售合并 **3505**（药品+批号+包装锚价分桶；同码去重；`trdn_flag` 按码累计 OUT−IN；IMP `setl_id`）：缺码软提示。住院发药当时**不**调 3505；住院退药当时**不**调 3506（退量进同一净合并）。  
8. **退药**：不扫；从原发放单带出码；**还原同一主档剩余**（§5）；门诊退药可报 3506，住院退药仅院内 IN、医保进销存进清床/直结合并。  
9. **拆零 vs 整包装（业务理解）**：看 **追溯码单位与操作单位是否一致**；本期**不做**「必须拆零品种暂可不采码」单独目录。  
   - **注意**：本条**不替代** §4.3。结算 `minpacunt_drug_trac_cnt` **一律按 `floor(拆零量÷ratio)` / 已是包装单位则用数量本身**，禁止理解成「单位不一致就整行填 0」。  

### 2.1 场景优先级与软硬边界（覆盖范围）

| 优先级 | 场景 | 口径 |
|--------|------|------|
| **不软化** | **药库进货** | 有码则个数/量继续**硬 Gate**；**不考虑**「零进货 / 拆零软过」；与 §3 消耗侧软提示**脱钩** |
| **与消耗同软** | **库存期初建账** | 扫码可选；半扫/无码**不挡**提交·同意；有码仅禁单内重复；写侧前填消化 |
| **P0（主战场）** | **门诊发药、住院发药、领用**等**真正消耗** | §3 盖住就发 + 剩余先出 + 软提示；§4 `trdn_flag` / 结算 `floor`；§5 退药镜像 |
| **P1** | **流转**（调拨、请领入库/退库等） | **尽量按同一套分摊计算**；算不清 → 软提示，不挡主流程 |
| **配套** | **退药 / 退领** | 必须与正向 OUT **成对**（§5）；余量写错优先于功能缺失 |

**公共内核（改一处多处受益）**：`TraceNumberQueryService` 覆盖/软校验、`TraceNumberRecordOrchestrator` 剩余先出分摊、前端 `utils/trace/trace-line-scan-count`（消耗/流转扫码页）；进货 Gate **不在此软化范围**。

## 3. 院内拆零：盖住就发 + 剩余先出

> 适用于 **P0/P1**（发药、领用、流转、**期初**尽量算）。**不适用于**进货硬 Gate。

### 3.1 放行（有扫时）

- **合法**：已扫各码的 **`remaining_split_quantity` 合计 ≥ 本次操作拆零量**。  
- **不再要求**：扫码个数必须等于 `ceil(操作拆零 ÷ 每码拆零)`。  
- **前端动态**：每扫一枚重算是否已盖住；**已盖住 → 弹窗提示勿再扫**（扫多了）。  
- **盖不住 / 码耗尽等**：弹窗友好提示；**不硬拦主流程**。用户确认继续时须 **清掉本行已绑码再提交**（等同未扫，与 §7 半扫一致），**禁止**带着「盖不住的码串」仍去写 OUT（否则主档余量必坏）。
- **盖住需求量单位（前端硬约束 · 2026-08-19）**：主档剩余永远是**拆零**。`resolveDispenseOperationSplitQty` 必须输出真拆零再与剩余比：
  - 操作单位已是拆零（含中包装贴拆零同名，如支）→ 需求=操作量，**禁止**再 × 码倍；
  - 操作单位是包装（盒）→ 需求=操作量 × **目录包装比**（五类优先）；无包装比时才回落主档码倍；
  - **禁止**「操作单位=贴码单位」就直接把操作量当拆零（发 4 盒、码倍 30、扫 1 满盒剩 30 片 → 误判盖住、待扫变 0）。
  - 后端盖住仍走 `MedicationProductQuantityToSplitUnitConverter`；前后端须同阶。

### 3.4 发药扫码软硬边界与跨行同码（定稿 · 对话 2026-08-05）

> 与「零有整 / 拼码」同场：比例≠1 时开几支≠必须扫几码；**待扫**展示用建议个数，**硬拦**只认上限与行内重复。

| 项 | 口径 | 软/硬 |
|----|------|--------|
| **弹窗「待扫」列 / 绑码硬上限** | **就是操作量**：`ceil(操作量) − 已扫`（开 2 支→2、开 1 盒→1）。**仅当**已扫剩余合计盖住**真拆零需求**时待扫才为 0。**禁止**用码倍/拆零推个数（勿 1 盒×48→待扫 48，勿 2÷50→待扫 1）；**禁止**用盒数直接比主档片剩余冒充盖住 | **硬拦**扫多 |
| **码倍 / 拆零** | 只用于剩余盖住、分摊扣减；盖住左侧需求量须已是拆零（见 §3.1） | 与「待扫个数」脱钩 |
| **建议应扫（半扫回落）** | 拆零同名中包装：`ceil(操作量÷码倍)`；包装同阶（盒）：`ceil(操作量)`（勿÷片码倍）；异构：`ceil(操作拆零÷每码拆零)` | **软提示**；半扫不够弹窗确认（§7） |
| **拼码** | 发 2：旧盒剩 1 的码 + 新盒码 → **2 个不同码合法**；也可只扫新盒 1 码盖住 2 支 | 少扫 / 只扫满盒 → **软提示**；盖住后勿再扫 |
| **行内同码** | 同一明细行逗号串内不得出现两个相同码 | **硬拦** |
| **跨行同码** | 同品多行（如两行氯化钠）**允许**共扫同一箱/盒码 | **不**因「整单/请求内重复」硬拒；多行拆零合计 vs 主档剩余 → **软提示** |
| **主档无数据** | 无法算剩余盖住 | **软提示**；仍受绑码硬上限约束 |
| **进货** | 仍按应扫个数硬 Gate | **不在本条软化范围** |

**实现锚点**：前端 `resolveDispenseMaxTraceCount`=`ceil(操作量)`；后端 `TraceScanCountSupport#resolveOutboundMaxCodeCount(operationQuantity)`；保存配药 **按行**去重；**禁止**整单跨行码去重硬拒。规则编号：**BR-TRC-023** / **BR-OPP-016**。

### 3.2 扣减分摊（流水准度）

- 在**已扫码集合**内按 **剩余拆零量升序**扣减（**剩余少的先扣光**），与扫码先后无关。  
- 扫码顺序**只**用于交互：够了不准再扫。  
- 同分再比：建档时间升序 → 码字符串升序（保证可复现）。  
- **每一枚码的实扣拆零必须落入子表流水**（供退药镜像，见 §5）。  

**示例（比例/每码满量 = 6）**

| 操作 | 扫码剩余 | 扣减结果 |
|------|----------|----------|
| 发 7 | 满 6 + 满 6 | 先扣光一枚 6，另一枚扣 1（剩 5） |
| 发 6 | 仅一枚满 6 | 整枚扣光（允许只开新盒，不强制先清半盒） |
| 发 2 | 剩 1 + 满 6 | 先扣光 1，再从满盒扣 1 |
| 发 7 | 只扫一枚满 6 | 盖不住 → **提示**（不按旧硬 Gate 卡死流程） |

### 3.3 写追溯时机

- 门诊：**码数/剩余硬 Gate 不在保存配药**；核发写追溯走 `TraceNumberDispenseTraceOrchestrator`（**BR-OPP-014 → IF-OPP-05**）。现行若保存配药仍调用 `assertRemainingSplitSufficientForDispenseOut`，须去掉或降为与软提示一致。  
- 空码 / 无码批：跳过写主子表。  
- 有码批且提交了码：按 §3.2 写流水并更新主档剩余；扣光可标不在院。

## 4. 医保字段分工（互不绑死）

### 4.1 时序

常见：**收费结算（2207/2304）→ 再发药扫码（3505）**。  
结算当下**没有**实扫结果；**禁止**用实扫枚数填 `minpacunt_drug_trac_cnt`。

### 4.2 `trdn_flag`（进销存 3502/3505 等，非结算字段）

| 条件 | 取值 |
|------|------|
| **已扫码** | 只认发药/出库后**各码实扣**：任一码非「满贴码单位整出扣光」→ **`1`**；全部为满码整出 → **`0`** |
| **未扫码** | 默认 **`1`** |
| 废止 | 以「单位不等 / 余数」公式作为进销存**最终真相**（可作辅助，最终以实扣/未扫默认为准） |

拆零时仍应在 **`drugtracinfo`** 上传实扫码（与数量字段填 0 不矛盾）；同一盒码可分次销售多次出现。

### 4.3 `minpacunt_drug_trac_cnt`（2207/2304）

**含义**：本次结算**应上传最小包装药品追溯码条数**（整包装个数统计工具），**不是**扫码次数。

**比例来源（强制顺序）**

1. 结算行有批号 → 查该 **品+批** 追溯码主表上的 **`trace_unit_ratio`**（药典可改，主表快照优先）；  
2. 主表无 → 回落药典 `trace_unit_ratio`。

**计算公式（定稿，禁止再写成「单位不一致一律 0」）——两分支，实现必须写对**

| 分支 | 条件 | 该药品行贡献 |
|------|------|----------------|
| A | 收费/`cnt` 的单位 **已是** 贴码单位（或最小包装单位，与主表 `trace_unit_code` 同阶） | **`ceil` 不用**；贡献 = **`floor(数量)`**（实质即包装个数；2 盒 → 2） |
| B | 收费单位是拆零单位（片/支等），与贴码单位异阶 | 先得拆零量（通常即 `cnt`）→ **`floor(拆零量 ÷ trace_unit_ratio)`** |

- `trace_unit_ratio` 来源仍按上文主表优先。  
- 多行累加；非需追溯品种 / 豁免按目录可不计；耗材走 **`mcs_trac_cnt`**，勿混。  
- **禁止**：分支 B 算完又用「单位不一致」改成 0；**禁止**：对分支 B 用 `ceil(cnt)` 当码数（现行债）。

**比例 = 6、收费按支（分支 B）验收例（必须写对）**

| 拆零数量（支） | 字段值 |
|----------------|--------|
| 1 | **0** |
| 6 | **1** |
| 7 | **1** |
| 12 | **2** |

**分支 A 例**：收费 2 盒且单位=盒（贴码单位）→ **2**（不要做成 `floor(2÷6)=0`）。

**与拆零扫码的关系**

- 拆零销售即使扫了码，**不把实扫枚数写入本字段**；完整最小包装用 `floor` 计，余数对应的拆零部分不计。  
- 实扫码在 **3505 `drugtracinfo`**；拆零标识在 **`trdn_flag`**。

> **错误口径（已否决，文档与实现禁止再写）**：  
> 「操作单位 = 追溯单位 → 填收费数量；不一致 → 一律 0（即使按片卖满一盒含量也不 floor）」。

### 4.4 现行代码债

- `SettlementTraceCountSupport`：对药品行 `ceil(cnt)` 累加 → **必须改为 §4.3**。  
- `InventoryTracePolicySupport.resolveTrdnFlag`：最终以 §4.2 实扣/未扫默认为准 → **必须改**。

## 5. 退药余量红线（极易写错，必须按本节落地）

> 对齐 `AS-CUS-TRC-001` **BR-TRC-008/012**、**IF-TRC-17～19**：退药复用原码，`HOSPITAL_IO` IN。  
> **核心风险**：主档剩余一旦与真实「盒内还剩多少」偏离，后续发药选码、盖住校验、再退会**越修越乱**——本节优先于「功能能跑通」。

### 5.1 结论（先钉死）

| 问题 | 定稿 |
|------|------|
| 新建主档行还是还原？ | **还原同一 `trace_no` 主档**（翻回在院 + 加回剩余）。**禁止**退药新建第二行主档。 |
| 退药扫不扫？ | **不扫**；从原已发发放行 / 发单带出 `trace_no`（护士带出 → 药房确认同构）。 |
| 「以前剩几个」怎么知道？ | **不靠记忆发药前剩余，也不靠退药时主档当前剩余再算一遍**。真源 = 该次发药 **OUT 子表（或发时落库的每码扣减）** 上「每枚码扣了多少拆零」的**镜像加回**。 |
| 原发未扫码？ | 退药**不写**追溯主子表（与可选扫对称）。 |

### 5.2 为什么不能「按当前剩余再分摊」或「新建」

发 7（比例 6）剩余先出示例：

1. OUT：码 A 扣 6 → 剩余 0、可不在院；码 B 扣 1 → 剩余 5。  
2. 子表已记：A/−6，B/−1。  
3. 若退药时对 A/B **按当前剩余**或 **前填/剩余先出重算** 再拆 7：A 当前剩 0，无法正确加回；或顺序一变每码加减与 OUT 不对齐 → **主档余量永久错**。  
4. 若**新建**主档：同一国码两行身份，且新行「初始剩余」无真源 → 禁止。

**正确**：退 7（整单退）→ 对**同一**主档 A **+6**、B **+1**（严格镜像 OUT 每码量），并恢复在院。

### 5.3 落地规则

1. **正向 OUT（发药/领用等消耗）**  
   - 必须按 §3.2 把**每码实扣拆零**写入子表（可关联发放 `bus_no` / dispenseId）。  
   - 主档剩余 = 扣减后值；扣光可标不在院。  

2. **反向 IN（退药确认 `recordReturnInLines` / IF-TRC-17）**  
   - 入参：原发放行上的码串 + 本次退药拆零量。  
   - **定位 OUT 明细**：  
     1. 先用退药发放行 `bus_no` 查该次发药各码 OUT 子表的 **`split_quantity`**；  
     2. 若为空（**对冲 REFUND 行自带新 `bus_no`**，与原发 MDP/汇总单号不一致，见 BR-PHA-038 / BR-IPR-007）→ 按行上**已拷贝**的 `trace_no`，在追溯子表轧差 OUT−`MEDICATION_RETURN_IN`，取仍未回冲的原发 OUT 所属 `bus_no`，再拉整单 OUT（`listUnreturnedDispenseHospitalIoOutRecordsByTraceNos`）。**只读子表**，禁止为镜像去改写原正向发放单。  
   - **整单退**（退量 = 原发总量）：每码加回量 = 该码 OUT 拆零量（**全额镜像**）。  
   - **部分退**：在「该次 OUT 每码已扣量」上做**逆向耗尽**——按 OUT 记录的**相反顺序**（后扣的先退回），从各码「仍可退回的 OUT 量」中扣减，直到凑满本次退药拆零量；**仍落原码**，不得按当前主档剩余重算。  
   - **禁止**调用与发药相同的「对当前剩余做剩余先出/前填」来拆退药数量。  
   - 写 IN 子表（IN 行 `bus_no` = **退药行**单号，供码上放心 116）；主档 `remaining_split_quantity` 增加；若加回后剩余 > 0 则恢复 `IN_HOSPITAL`。  

3. **部分退补充**  
   - 未退部分对应的 OUT 量保持已消耗；不得把整单 OUT 量全部加回。

## 9. 验收要点（抽检）

1. 不扫码可完成发药/领用/清床（软提示可确认继续）；**进货有码个数错误仍应硬拒**。  
2. 比例 6：发 7 → 6+1 落子表；发 6 可只扫一满码；发 2 → 1+1。  
3. 已盖住再扫 → 提示过多。  
3a. **发 N 盒、码倍=包装拆零比、扫 1 满盒码** → 待扫应为 N−1（非 0）；仅当已扫剩余合计 ≥ N×包装比 时待扫才为 0。  
4. **整单退药**：主档余量与在院态回到发前；再发无幽灵账（§5.4）。  
5. 3505：未扫 `trdn_flag=1`；有扫按实扣。  
6. 2207：数量 1/6/7/12 且 ratio=6 → 字段 0/1/1/2；与是否已扫无关。  
7. 退供应商预填为当前剩余码，非进货快照。
