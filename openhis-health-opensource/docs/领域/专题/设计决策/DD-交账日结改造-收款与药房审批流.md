> **范围**：门诊/住院**收款**日结、门诊/住院**药房**日结、**交账审批**；共用 `fin_cashier_settlement`

## 0. 一句话

交账头只记录「谁在何时、对哪个**科室或药房**、把哪些完成态事实打成一批并交财务审」；**账在源表挂载**；退费/退药靠**新对冲事实再交下一批**；**不存打印/金额流水快照**；本轮**不做耗材与科室药房日结**。

## 2. 业务模型（要实现成什么样）

### 2.1 主路径（四页同构）

```
选业务时间窗（时分秒）
  + 收款：选科室 org_id（不绑款台）+ 收款人可选（岗池 ROLE_CASHIER；空=不按人；查询后合并窗内收费人）
  + 药房：选单个 location_id（药房）+ 发药人可选（岗池 ROLE_PHARMACIST；空=不按人；查询后合并窗内发药人）
  → 查询（主区含已交；待交笔数仅未挂载）
  → 点「确认交账」打开明细弹窗（默认全选、可分批勾选）→ 确认提交
       · 写交账头 status=SUBMITTED（submitter / submitted_at / date_from～date_to / payment_count / total_income / practitioner_ids 等）
       · 批量挂载源行 cashier_settlement_id
  → 财务审批通过 → status=APPROVED（结束）
```

> **交互主路径硬约束**：须保持「查询 → 确认交账 → 弹窗勾选 → 确认」；漏交硬栏**不**灰确认入口、**不**挡弹窗；人选**非必选**。### 2.2 待交账准入（硬性）

只有**完成态事实**可进待交账列表：

| 域 | 纳入状态（语义） | 说明 |
| --- | --- | --- |
| 收款 | 已结算成功、已退费（逆向单）、反结（逆向单）等现网日结已纳入集合 | 仍按现 BR-CS / 门住 DCL 的 kind+status；**正负成分录** |
| 发药 | 已发药（正向 COMPLETED）、已退药（REFUND+REFUNDED） | 门/住场景用 encounter / dispense_enum 收窄；**一发一退两行** |

未完成、草稿、处理中等**一律不进**。

### 2.3 对账与退费退药（与交账的关系）

| 结论 | 说明 |
| --- | --- |
| 费用 / 药品逆向 | **新增单据**（payment `UN_PAY`、dispense `REFUND`），**不改原单金额** |
| 已交账原单 | 可继续挂在旧批次；**不必拆单** |
| 新逆向 | `cashier_settlement_id IS NULL` → **下一批再交** |
| 跨批次抵净 | 财务接受「收在批次 A、退在批次 B」 |
| **退费 / 退药门禁** | **与交账无关**：**待审（SUBMITTED）或已审（APPROVED）均不拦截**退费、退药、反结等；业务照常开对冲新单，再按时间窗二次交账 |

因此：**不存交账流水快照**；**不为退费/退药做审批后驳回**；**交账审批态不是退费退药门禁**。

### 2.4 撤回 / 驳回（仅交账流程纠错，与退费退药无关）

| 动作 | 谁 | 何时 | 效果 |
| --- | --- | --- | --- |
| **撤回** | 提交人 | 仅 `SUBMITTED` | 清挂载；头 → `WITHDRAWN`（或等价）；可再提新单 |
| **驳回** | 财务 | 仅 `SUBMITTED` | 清挂载；头 → `REJECTED`；可再提新单 |
| **审批后驳回** | — | **本轮不做** | 批完即锁流程；业务靠新对冲再交 |

旧头表行保留作审计，不清物理删除。

### 2.5 查询维度与头表业务窗

| 场景 | 时间条件 | 说明 |
| --- | --- | --- |
| 待交账预览 / 提交锁候选 | 源表业务时间闭区间，**精确到时分秒** | **查询入参**；默认当天 |
| **提交落库** | 将本次所选窗写入头表 **`date_from` / `date_to`** | 表示「**交的是从何时到何时的账**」；审批列表必显 |
| 交账历史 / 审批列表 | `submitted_at`（交账时间）、`approved_at`、以及 **`date_from`～`date_to`（业务窗）** | 时间最重要；见 §2.8.4 |

### 2.6 时间窗、漏交提示与去重（硬规则）

#### 2.6.1 默认与可选

- 筛选项支持 **日期 + 时分秒**；默认 **当天**（建议：当天 00:00:00 ～ **当前时刻**）。
- 用户可改窗覆盖跨天（例如昨天 17:00:00 ～ 今天 16:30:00）。

#### 2.6.2 筛选主轴：时间（+ 药房）；人选可选软筛

| 项 | 口径 |
| --- | --- |
| **主条件** | **业务时间窗**（到时分秒） |
| **药房日结** | **`location_id` 必填**；一次只交 **一个** 药房；候选与漏交扫描均限该药房 |
| **收款日结** | 以时间为主；候选/漏交再限当前 **`org_id`（科室）**；**不绑款台** |
| **人（下拉岗池）** | **不是**漏交硬栏维度；**非必选**（空=不按人过滤）。收款人岗池 = **`ROLE_CASHIER`**；发药人岗池 = **`ROLE_PHARMACIST`**。**不含**因 `ROLE_ADMIN` 身份单独入池；日结岗池显式 `excludePlatformAdmin=false`（保留挂业务岗的平台 admin） |
| **人（窗内带出）** | 按时间查询后，将窗内实际收费人/发药人**合并进下拉**供改选；admin 仅当本窗确有收费/发药事实时才会因此出现 |
| **人（软筛）** | 勾选后仅软过滤预览/主区；漏交扫描仍不按人 |
| **提交挂载** | 去重与漏交以 **时间 + 范围键（收款 org / 药房 location）+ `cashier_settlement_id IS NULL`** 为准 |

#### 2.6.3 典型场景（产品口径）

1. 昨天 **16:30** 已提交交账。  
2. 昨天 **17:00** 退费/退药 → 未挂载新事实。  
3. 今天默认「当天」看不到该笔。  
4. 若本次 **截止时间 `dateTo`** 已选到较晚时刻，但 **`dateTo` 之前（含）** 仍有未交且落在当前 `dateFrom` 左侧 → **硬栏禁止提交**，须把起点改到不晚于最早漏交时刻。  
5. 若 **`dateTo` 之后** 还有未交 → **仅提醒，不拦**（可二次再交）。  
6. 上批 **`SUBMITTED`**：可撤回清 id 后扩窗一次再提；已 **`APPROVED`**：再提新单覆盖漏交时段。

#### 2.6.4 去重（与时间窗正交）

- 候选 = 业务时间 ∈ `[dateFrom, dateTo]` **且** `cashier_settlement_id IS NULL`  
  **且** 收款按 `type_enum`（门/住 kind）收窄（头表另落 `org_id`；**读侧不**按 payment.location / 科室下地点白名单过滤）；药房限 `location_id`。  
- 已挂载行自动排除，不会二次提交。  
- **撤回 / 待审驳回** 必须清空 `cashier_settlement_id`。

#### 2.6.5 硬栏与提醒（按时间）

在当前交账类型 + 范围键（收款：`type_enum`+时间窗，头表落 `org_id`；药房：`location_id`）下，对未交账完成态事实：

| 条件 | 行为 |
| --- | --- |
| 未交账且业务时间 **≤ `dateTo`**，但又 **&lt; `dateFrom`**（截止前左侧漏在窗外） | **硬栏：禁止最终提交**（提交 IF Gate）；提示最早漏交时刻与建议起点 |
| 未交账且业务时间 **&gt; `dateTo`** | **仅提醒，不拦**；允许二次交账 |

> 漏交扫描：收款按 **type + 时间**（**不**按人；**不**用「科室下 location 白名单」过滤 payment——payment 无科室列、收款不绑款台）；药房按 **时间 + 单药房 location_id**。  
> **窗内勾选分批**：允许只交窗内一部分；硬栏只保证「截止前不存在窗外更早的未交」，不强制一次交净窗内全部。  
> **交互硬约束**：漏交硬栏**不得**灰掉「确认交账」入口，**不得**阻止打开明细弹窗与勾选；用户须能走「查询 → 点确认交账 → 弹窗勾选 → 确认」；若仍有左侧漏交，确认时由提交接口拒绝并提示调起点。

### 2.7 人与库房 / 科室

| 字段语义 | 口径 |
| --- | --- |
| **提交人** `submitter_id` | 点「确认交账」的人（一个） |
| **practitioner_ids** | 本批人员快照（收款=所选/窗内收费人；药房=所选/窗内发药人）；**不是**漏交硬栏维度 |
| **收款人下拉** | 页初始化 `cashierOptions`：仅 **`ROLE_CASHIER`** 且已落 `adm_pr_assign` 的在职医务人员；多选、非必选；**选日期查询后**合并窗内收费人（enterer 归一；含非款员岗）并自动带出；**不**因 `ROLE_ADMIN` 单独入池；日结岗池显式 `excludePlatformAdmin=false`（保留挂款员岗的平台 admin，与业务选型下拉默认剔除相对）；软筛不按代交账权限拦截 |
| **发药人下拉** | 页初始化 `practitionerOptions`：仅 **`ROLE_PHARMACIST`**；多选、非必选；查询后合并窗内发药人；**不**因 `ROLE_ADMIN` 单独入池；日结岗池同样显式 `excludePlatformAdmin=false` |

| **org_id** | **收款日结：绑定科室即可，不绑款台**（`location_id` 收款侧可空/不用） |

#### 2.8.0 主区金额 vs 待交账笔数（对齐门诊日结 BR-OP-DCL-014 语义）

| 区块 | 口径 |
| --- | --- |
| **主区金额 / 大类 / 品规（或收款 rows/summary）** | 按时间窗（+ 范围键）汇总**窗内全部完成态事实**（**含已挂载已交**）；**交不交账不改变这些钱** |
| **待交账笔数 / 弹窗明细候选** | 仅 `cashier_settlement_id IS NULL`；交账成功后笔数减少或归零 |
| **弹窗「本次交账合计」** | 对应当前勾选（默认同全量未交）；可分批；**不必**等于主区金额 |

> 药房主区大类/品规净额 = 窗内已发已退轧差（含已交批次挂载行）；**品规有发药事实即展示**（一发一退净 0 仍出一行）。

#### 2.8.1 药房日结主区（查询结果）

**上：大类汇总（净）— 固定行**

术语 `medication_category_code` ↔ 目录 `med_medication_definition.category_code`（与 `DailySettlementSharedConstants` / 发药报表一致）：

| code | 展示名 | 主区 |
| --- | --- | --- |
| `2` | 西药 | **固定展示**（无发生则数量/金额为 0） |
| `1` | 中成药 | 固定展示 |
| `4` | 中草药 | 固定展示 |
| `3` | 外购药品 | 固定展示 |

| 列（语义） | 口径 |
| --- | --- |
| 药品大类 | 上表固定四行 |
| 进价总额 / 售价总额 | **净**（已发 − 已退）；**售价** = 发放锚点账单 `ChargeItem` 行额（有账单不回放）；**账单缺失**时回落批号 `LOT_NUMBER_PRICE`（同批号调价回放与进价同构；禁目录 `SALE`）；**进价** = 批号 `LOT_NUMBER_COST` × 数量（按 `unitCode` 分支；仅同批号回放调前进价；**禁止串批**；**禁止**回落维护态 `PURCHASE`/`SALE`）；**品规进价一律 `sumThenPurchaseSettle`（3 位；无中药第三位为 0），售价 2 位；大类 = 下属品规已结算额之和**；**禁止**进价套用售价两位；**含已交** |

> **大类主区不展示净数量**（仅进/售总额）。

**下：品规合计（净）**

按 **`medication_id` + 进价单价 + 售价单价** 分桶汇总；**单价一致才合并成一行**，同药不同单价分开统计。展示须带目录/业务识别信息（不仅 id）：

| 列（语义） | 口径 |
| --- | --- |
| 药品名称 | 目录名 |
| **bus_no** | 药品目录业务编码 |
| **规格 / 厂家** | 目录规格、生产厂家等（与发药记录/目录展示同源） |
| 净数量 | 已发 − 已退；**一发一退净数量为 0 仍展示该行** |
| **进价单价 / 售价单价** | 本桶单价（分桶键；同桶内一致；同价合并、不同价分行）；进价=批号进价，售价=账单单价 | 
| 进价总额 / 售价总额 | **净额**（进价：批号进价×数量，品规结算 **3 位**；售价：账单行额，品规结算 **2 位**）；一发一退轧差可为 0 |

- 事实状态：仅 **已发（COMPLETED 正向）+ 已退（REFUND+REFUNDED）**。  
- 主区金额范围：时间窗 + 单药房内**全部**上述事实（**含已挂载**）。  
- **一律净额**；**有发药事实的品规行一律展示**（含净数量与净进/售均为 0）。  
- **大类固定四行仍始终展示**（无发生为 0；**不展示净数量列**）。  
- 另展示 **待交账笔数**（仅未挂载）。  
- 弹窗明细进/售与主区同口径（账单售价 + 批号进价）；头表 `total_income` 为**售价合计**（各大类售价总额之和，与主区同口径；不为售价−进价）。

#### 2.8.2 药房日结确认弹窗

- 与收款一样：提交前弹窗展示**未挂载明细**（逐笔发/退），默认全选、可勾选分批；确认后提交挂载。  
- 弹窗「本次交账合计」对齐勾选集（**进价合计 / 售价合计**）；**主区金额不因勾选/交账而改口径**（仅待交笔数变）。  
- 明细列至少：单号、发药时间、状态、类型（发/退）、药品名、规格、厂家、数量、单位、进价、售价/小计；进/售与主区同口径（**账单售价 + 批号进价**）。  
- 主路径：**查询 → 点确认交账 → 弹窗勾选 → 确认**；漏交硬栏不挡打开弹窗。
#### 2.8.3 历史重打 / 审批详情凭证

- **按挂载现算**：按该交账单 `cashier_settlement_id` 反查 payment 或 dispense，用**当前汇总算法**重算；响应字段 **`mountedVoucher`**；**不落库**、不依赖 `print_snapshot_json`。  
- 查历史/详情本来就要查源表，与去快照一致。
- **交账历史列表**（四页作业弹窗）：弹窗宜宽（约全屏 90%+）；列须含单号、业务窗、交账人、交账时间、审批人、审批时间、笔数、金额、状态；收款展**科室**、药房展**药房**；展示名批量 enrich，勿只回主键。

#### 2.8.4 交账审批页（新建 · 财务管理）

| 项 | 口径 |
| --- | --- |
| **菜单** | **财务管理** 下新增独立页（建议名：**交账审批**） |
| **筛选** | 可选业务大类：**费用日结**（`OP_PAYMENT` / `IP_PAYMENT`）或 **药房日结**（`OP_PHARMACY` / `IP_PHARMACY`）；可再加时间、状态（待审/已审/驳回等）；**大类=药房日结时**可再筛 **`location_id`（药房）**；init 返回 `pharmacyOptions` |
| **列表** | 头表能展示的都展示；**时间优先**（`submitted_at`、`date_from`～`date_to`）；并展示 **`payment_count`、`total_income`**（§3.2.1）；**必展展示名**：交账人（`submitter_id`→姓名）、审批人/审批时间（待审可空）、**药房/科室**（药房优先 `location` 名，否则 `org` 名） |
| **详情** | 点开看 **日结单内容**（与对应日结页主区同口径；按挂载源表现算）；头区回显交账人/审批人/审批时间/药房或科室；收款体用 rows+summary；药房体用大类/品规（§2.8.1） |
| **操作** | 待审可 **通过 / 驳回**；驳回清挂载（§2.4）；作业员撤回仍可在日结页做 |

> 日结作业页（收费日结 / 药房日结）负责查询、提交、撤回；**财务审批以本页为主入口**，不必再把「审批」做成唯一散落在各日结 Tab 的能力（日结页可保留只读历史）。

### 3.2 `fin_cashier_settlement` — 保留 / 重释义

| 字段 | 本轮口径 |
| --- | --- |
| `id` / `bus_no` | 不变 |
| `type_enum` | **扩枚举**：`OP_PAYMENT` / `IP_PAYMENT` / `OP_PHARMACY` / `IP_PHARMACY`（勿存裸表名） |
| `status_enum` | **审批流**，见 §3.4（废止「提交即 HANDED_OVER」） |
| `org_id` | **收款：交账科室必填**；**药房：可空（不必填）**，范围键以 `location_id` 为准 |

| `date_from` / `date_to` | **保留**：提交时写入本次业务窗（时分秒）；审批列表展示「交的是何时～何时的账」 |
| `payment_count` | **保留**：费用=挂载 payment 笔数；**药房=挂载发药单数（dispense 行数）** |

| `tenant` / 审计列 | 不变 |

#### 3.2.1 `payment_count` / `total_income` 口径（列表快照，免扫源表）

与 `date_from`/`date_to` 同理：审批**列表**只读头表，不按行聚合 payment/dispense。

| `type_enum` | `payment_count` | `total_income` |
| --- | --- | --- |
| `OP_PAYMENT` / `IP_PAYMENT`（费用日结） | 本次挂载的 **payment 笔数** | 日结单下半区 **「总收入」**：提交时对**勾选 payment 子集**调用门/住 `*DailySettlementMapper#resolveSelectedSettlementTotalIncome`，**复用**预览 `buildDisplayBundle`（与无费用性质筛时的 `handoverSummary.totalIncome` **同一管线**）：有 fin_type 快照则分类代数和，否则回落 payment `netAmount` 代数和（**BR-OP-DCL-011** / **BR-IP-DCL-007**）；**禁止**另写平行算法，**禁止**用 `tendered−returned` 实收净额冒充 |
| `OP_PHARMACY` / `IP_PHARMACY`（药房日结） | **发药单数**：本次挂载的 `med_medication_dispense` 行数（含已发、已退对冲行，一发一退计 2 笔） | **售价合计**：勾选挂载发药各大类售价总额之和（`PharmacyDailySettlementPricingSupport#sumSaleAmount*`；含退药无自身账单时原正向补价取负；与主区同口径；**不**读 payment；**不为**售价−进价利润） |

> 详情页日结单内容仍可按挂载**现算**复核；头表金额仅服务列表与摘要。  
> 药房作业页主区「进价/售价大类·品规」中的**售价合计**与头表 `total_income` **同口径**；进价列仅主区对照，不写入头表金额。  
> **费用日结 `total_income` ≠ 药房日结 `total_income`**：费用=科室窗内收费「总收入」；药房=该单挂载发药**售价合计**（时间轴可能是 `bill_date` vs `dispense_time`，集合本就可能不一致）。

### 3.3 `fin_cashier_settlement` — 新增 / 替换

| 字段 | 类型（建议） | 说明 |
| --- | --- | --- |
| `practitioner_ids` | TEXT（逗号分隔 Long，与现 scope 存法同构） | 多选收费人/发药人；替代 `cashier_id`+scope |
| `submitter_id` | Long NOT NULL | 提交人 |
| `submitted_at` | timestamptz NOT NULL | **交账提交时间**（展示「交账时间」） |
| `approver_id` | Long NULL | 审批人；通过时写 |
| `approved_at` | timestamptz NULL | **审批时间**；与提交时间分列展示 |

废止列 `cashier_id` / `settled_at` / `cashier_scope_ids` / `print_snapshot_json` **不在终态 DDL 中出现**（见 `V4__fin_ddl.sql` / `V5__med_ddl.sql`）；运行期仅读写新列。

### 3.4 状态机（`status_enum`）

| code | 含义 | 允许动作 |
| --- | --- | --- |
| `SUBMITTED` | 已提交待审；源行已挂载 | 撤回、驳回、审批通过 |
| `APPROVED` | 财务已通过（终态） | 无写（本轮） |
| `REJECTED` | 待审驳回；已清挂载 | 只读审计 |
| `WITHDRAWN` | 提交人撤回；已清挂载 | 只读审计 |

废止本轮对业务使用：`HANDED_OVER`（存量数据迁移为 `APPROVED`）。

参考 supply 审批语义，**交账专用枚举**，不直接复用 `SupplyStatus` code（避免单据域混淆）。

### 3.5 源表挂载

| 表 | 变更 |
| --- | --- |
| `fin_payment_reconciliation.cashier_settlement_id` | **已有**；语义扩展：非空=已纳入某交账批次（含待审） |
| `med_medication_dispense.cashier_settlement_id` | **新增** Long NULL + 索引（未交账扫描） |

挂载规则：

- **提交时写入**；同一源行不能挂两个有效批次（`IS NULL` 才可挂；去重）。
- **撤回/驳回清空** `cashier_settlement_id`。
- **审批通过不改挂载**（已挂着即可）。

不建 junction、不建金额明细快照表。

## 4. 接口 / 应用层意图（开工清单）

### 4.1 收款日结（改造）

- 预览 / 提交：不携带打印体与 `cashierScopeLabel`；**保留并落库 `dateFrom`/`dateTo`**。
- 历史重打 / 审批详情凭证加载：响应字段 **`mountedVoucher`**（按挂载 payment 现算，不落库）。
- 提交：写 `SUBMITTED` + 挂载；返回后进待审，**不再视为终态归档**。
- 新增：待审列表、审批通过、撤回、驳回。
- 历史：按 `submitted_at` / `approved_at`；重打 / 再看凭证 → **按挂载 payment 现算**（§2.8.3）。

### 4.2 药房日结（新建）

- 同构：初始化、按**时间窗 + 单药房**预览未交账发退药（人自动带出）、大类/品规汇总、勾选提交、**撤回**、只读历史。  
- **审批通过/驳回**走财务管理「交账审批」页（§2.8.4），不在药房作业页做主入口。  
- 汇总口径见 §2.8；挂载权威仍是 dispense 行。

### 4.3 领域

- `CashierSettlementDomainService`：submit / withdraw / reject / approve；挂载委托各源聚合或应用编排批量 update（跨聚合边界按成码规范）。
- `PaymentReconciliation` / `MedicationDispense`：提供「按交账候选预览 / 提交锁挂载 / 清挂载」Query+写能力。
