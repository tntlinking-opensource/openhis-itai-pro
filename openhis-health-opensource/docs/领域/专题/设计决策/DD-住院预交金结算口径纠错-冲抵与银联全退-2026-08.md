## 0. 一句话

出院结算时：**结算 payment 主单金额始终 = 个人现金应付 P**；收银实付为 **C**，冲抵为 **O**（`P=O+C`）；不够/刚好用明细冲抵占用押金；有余时冲抵 P 并**退现金 D−P**（**不判**原收款渠道）。自费与医保同一套；反结有冲抵必须回冲 O。

## 1. 背景与错误点

### 1.1 真实医院口径（产品裁定）

| 场景 | 例子 | 正确资金动作 |
| --- | --- | --- |
| 预交金不够 | 赵桂英：D=1000，医保后个人应付 P≈1187 | 预交金**占用不退**；结算再收 **P−D≈187**；账户余额 → 0 |
| 刚好够用 | D=P=1000 | **不收不退**（禁止 0 元收/退单）；冲抵占用；余额 → 0 |
| 预交金有余（可部分退） | 现金预交 D=700，P≈20 | 结算冲抵 P；**退现金多余 D−P** |
| 预交金有余（原含银联收款） | 银联扫码预交 D=700，P≈20 | **同左**：冲抵 P；**退现金 D−P**（不再全退重收） |

### 1.2 现网错误（须废除）

| 旧逻辑 | 问题 |
| --- | --- |
| 自费：`balance −= 本批已结`，少补自动 `collectAdvanceDeposit`，多退只退盈余且常现金占位 | 少补进预交金账户；与「结算另付」不符；退费非原路 |
| 医保：不冲抵，渠道收全额 P，事后一律原路退清 D | 赵桂英类 D&lt;P 会逼患者先付满 1187 再退 1000，错误；摘要「预交押金— / 应付 1187」误导 |
| 自费 / 医保两套公式 | 产品裁定：**与是否医保无关** |

## 2. 符号与输入

| 符号 | 含义 | 真源 |
| --- | --- | --- |
| **P** | 本次出院全结**个人现金应付** | 医保：平台预结后个人现金；自费：本批应收合计 |
| **D** | 结算前个人现金户**库内预交金余额** | `adm_account.balance` |
| **渠道实付 C** | 确认结算时收银员须实收的金额 | R1=`P−D`；R2/R3=`0`；R5=`P` |
| **冲抵额 O** | 结算明细「预交金冲抵」行金额 | R1=`D`；R2/R3=`P`；R5=`0` |
| **多退** | 有余应退金额 | R3=`D−P`；R6=`D`；落账渠道恒 **CASH**（不判原收款） |

> **不变式**：出院全结成功且预交金退（若有）收口后，个人现金户余额必须为 **0**。  
> **勾稽（患者自付段）**：`P = O + C`。  
> **已废除**：含银联粗判、方案 1 全退重收（原 R4）。

## 3. 定稿业务规则

### 3.1 分支表（自费 = 医保）

| # | 条件 | 结算 payment（**仅 1 张**，`kind=INPATIENT_CLINIC`） | 预交金 `HOSPITAL_DEPOSIT` | 账户余额 |
| --- | --- | --- | --- | --- |
| R1 | **D &lt; P** | 主单金额 **= P**；明细：**冲抵 D** + **渠道实付 P−D** | **不退** | 冲抵后 **→ 0** |
| R2 | **D = P** | 主单金额 **= P**；明细：**仅冲抵** | **不退** | 冲抵后 **→ 0** |
| R3 | **D &gt; P** | 主单金额 **= P**；明细：**冲抵 P** | **退现金 D−P** | 冲抵 + 退款后 **→ 0** |
| ~~R4~~ | （已废除） | 原「含银联全退+重收」→ 并入 R3 现金退 | — | — |
| R5 | **D = 0** 且 **P &gt; 0** | 主单 **= P**；仅渠道实付 | 无 | 保持 0 |
| R6 | **P = 0** 且 **D &gt; 0** | 零元结算；无冲抵 | **退现金 D** | 退清后 **→ 0** |
| R7 | **P = 0** 且 **D = 0** | 零元结算 | 无 | 保持 0 |

> **分支判定顺序**：P=0 → R6/R7；D=0 → R5；D&lt;P → R1；D=P → R2；D&gt;P → R3（**不判**渠道）。

### 3.2 收银顺序（硬）

1. **先**结算落账（冲抵/渠道、ChargeItem；**仅 O&gt;0** 时 `balance −= O`）。  
2. **再**多退现金（仅 R3/R6；一笔 `HOSPITAL_DEPOSIT`+`UN_PAY`，明细 `CASH`）。  
3. **废除**出院多退原路 / Win 第二阶段挂起。

### 3.3 数据落账（验收关键）

#### 3.3.1 结算只有一张 payment

- **禁止**再为「冲抵 1000」单独新建一张 payment 主单。  
- 主表 `tendered_amount` / `display_amount` **= P**（个人应付全额）。  
- `charge_item_ids` = 本次勾选结算的**全部**收费项快照（**不**按金额拆成「值 1000 的那几行」）。

#### 3.3.2 冲抵落在明细行

- 新增（或启用）支付明细渠道语义码：**预交金冲抵**（建议 `pay_enum=DEPOSIT_OFFSET`，名称以成码 ADR/枚举为准；**非用户可选**）。  
- 明细 `account_id` = 个人现金户；金额 = 冲抵额（R1 为 D，R2/R3 为 P）。  
- **不**回头把历史预交金收款 payment 改成已退；历史收款 SUCCESS 保留为「当初进账」真源。  
- 账户占用：应用层对个人现金户做余额扣减（`adjustAdvanceDepositBalance` 负向），**不**为此落 `HOSPITAL_DEPOSIT` UN_PAY。

#### 3.3.3 有余退款落预交金 payment

- R3/R6 另落 `HOSPITAL_DEPOSIT` + `UN_PAY`，明细渠道 **恒为现金 `CASH`**；**不**挂原收款、**不**拆 LIFO 原路。  
- R3：退款合计 = D−P；结算冲抵 O = P。  
- R6：退款合计 = D。

#### 3.3.4 废除的写动作

| 废除 | 说明 |
| --- | --- |
| `collectSettleSupplementAdvanceDeposit`（少补收预交金） | 少补改为结算渠道实付，**禁止**再记 `HOSPITAL_DEPOSIT` PAY |
| 自费「本批已结直接 `balance −= 本批`」与医保「永不冲抵、一律全退」双轨 | 统一为 §3.1 |
| 自费多退现金占位（非原路） | **已改为正式口径**：出院多退**就是**退现金（`CASH`）；废除原路/银联全退重收 |
| 预结/确认把 `displayAmount` 当成「少补」或「医保全额且与冲抵无关」的双语义 | 见 §3.3.6 字段契约 |

#### 3.3.5 医保基金 / 个账明细

- 结算 payment 上若仍落 `INSURANCE_FUND` / `INSURANCE_ACCT` 等（沿用现网医保编排），**不属于**患者自付段。  
- **患者自付勾稽**仅：`P = O + C`（冲抵 + 现金/微信/支付宝/银行卡等用户渠道）。  
- 禁止用「Σ全部明细 = P」验收医保单。

#### 3.3.6 预结 / 确认字段契约（防前端接错）

| 字段（语义名） | 含义 | 备注 |
| --- | --- | --- |
| `personalCashPayable` / 主单拟落 `tendered`·`display` | **P** | 结算 payment 主单金额 |
| `channelPayable`（**勿再滥用**旧字段名表示少补） | **C** | 收银员 `paymentDetails` 合计必须 = C；C=0 时明细可空数组 |
| `depositOffsetAmount` | **O** | 服务端写入冲抵明细；前端只读展示 |
| `prepayRefundAmount` | 应退预交金 | R3=`D−P`；R6=`D`；R1/R2=0 |
| `prepayFullRefund` | 是否退清全部 D | 仅 R6 为 true |
| `prepayRefundPlan` | 多退计划 | 单笔现金展示；确认落账不再要 Win |

> 现网 `PreSettleInpatientChargesResponse.displayAmount` 注释为「自费少补 / 医保全额」——成码时**打破该双语义**：要么改名为 `channelPayable` 并新增 `personalCashPayable`，要么保留字段但**赋值为 C**，另增 P/O 字段；**禁止**继续用同一字段在自费/医保表示不同轧差。

#### 3.3.7 发票票面（硬约束）

- 发票草稿金额 = **本次结算收费项合计（费用票面）**，例：赵桂英住院总费用 **≈2600**。  
- **禁止**用个人现金应付 P（≈1187）或渠道实收 C（≈187）当票面。  
- 预交金冲抵 / 原路退只影响付款方式与账户，**不改发票费用口径**。  
- 成码时继续走现网 `invoiceFaceAmount = receivableTotal`，本轮只回归不改公式。

### 3.4 金额勾稽（账怎么平）

| 分支 | O 冲抵 | C 渠道 | 另退预交金 | 说明 |
| --- | --- | --- | --- | --- |
| R1 | D | P−D | 0 | 历史预交金收款仍在；结算主单 = P |
| R2 | P | 0 | 0 | 无 0 元收/退主单 |
| R3 | P | 0 | D−P（现金） | 多退不判渠道 |
| R5 | 0 | P | 0 | 无预交金 |
| R6 | 0 | 0 | D（现金） | 个人应付为 0，只退押金 |

日结视角：

- **预交金列**（`HOSPITAL_DEPOSIT`）：仍只汇总预交金收/退主单；冲抵行**不是**预交金主单。  
- **退预交金列**（`depositRefundAmount`）：窗内预交金逆向流水绝对值合计（R3/R6 多退现金 + 预交金页手工退）。  
- **结算补收列**（`settleSupplementAmount`）：住院结算单上自付渠道实付代数和（DD 的 **C**；现金/微信/银联等，**不是**补预交金）；排除统筹/个账/冲抵。R1/R5 有 C 则计入；R2/R3 的 C=0。  
- **总收入 / fin_type**：跟结算 payment（及收费项快照）走；冲抵行**不得**计入微信/现金等自付渠道小计。  
- R1 例：历史 +1000 预交金 + 结算渠道 +187 + 结算主单 P=1187（明细含冲抵）→ 平；日结「结算补收」=187、「退预交金」=0。  
- R3 例：冲抵 P + 退现金 D−P → 日结「退预交金」含该笔；「结算补收」=0。

### 3.5 反结对称（覆盖 AS-IP-FIN-004）

现网「出院全结反结**不回冲** balance」在**冲抵占用**模型下会导致：押金仍被医院持有（无 UN_PAY），再结时 D=0 又收满 P → **重复计收**。本 DD 强制：

| 原结算 | 反结必须 |
| --- | --- |
| 存在冲抵明细 O&gt;0（R1/R2/R3） | **`adjustAdvanceDepositBalance(+O)`** 回冲个人现金户 |
| 存在本分出院触发的预交金 UN_PAY（R3/R4/R6） | **本轮默认**：不自动追回已退现金（与现网医保全退反结类似）；库内余额以回冲后为准；再结按新口径。若院方要求「反结后账户恢复到结前 D」，须另开追收/撤销退款编排（**非本轮必做**，但 R1/R2 回冲 O **必做**） |
| 结算渠道实收 C | 随结算逆向单原路退回（现网反结能力） |

> **DOC-CONFLICT**：`AS-IP-FIN-004` §1.3「出院结算反结不回冲 balance」→ 改为「无冲抵则可不回冲；有冲抵必须按 O 回冲」。
