# DM-CUS-007 Supplier 供应商

> **限界上下文**：本地扩展 · 供应商管理  
> **聚合类型**：实体聚合  
> **版本**：v1.0.2 · **日期**：2026-10-07

---

## 1. 概述

### 1.1 业务定义

供应商（Supplier）是**药品与物资采购业务链的起点主数据**，管理与本院存在供货关系的企业**主档信息**（名称、类型、统一社会信用代码、联系方式、生命周期状态等）。它回答的核心问题是：「**谁可以作为供货方出现在本院采购链路中？**」——在创建 SupplyRequest（供应请求）或 SupplyDelivery（供应发放）时，系统据此解析可选供应方范围。

### 1.2 核心职责

| 职责           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| 主数据维护     | 维护供应商名称、类型、信用代码、联系方式、检索码等基本信息             |
| 主数据质量控制 | 供货方准入与可引用门控；资质子表等**实现级**扩展由应用层或独立聚合维护，本 DM 以主表为语义锚点 |
| 采购引用支撑   | 为 SupplyRequest / SupplyDelivery 提供合法、有效的 `supplierId` 引用 |
| 生命周期管控   | 通过状态机与持久化状态列控制可引用范围                         |

### 1.3 适用范围

| 类型     | 说明                                                       |
| -------- | ---------------------------------------------------------- |
| 供应商准入  | 新供应商注册，录入基本信息，审核通过后启用                                    |
| 到期类预警  | 与主档并行的时效类扫描/预警（若有）由应用编排或定时任务定义，不在本主档聚合内建模                           |
| 采购下单选商 | 创建 SupplyRequest 时从**已启用（ACTIVE）**且满足引用门控的供应商中筛选                 |
| 供应商停用  | 合作暂停或不再满足引用条件时停用，阻断新采购引用                                 |
| 供应商评价  | 到货及时率、质量合格率等由外部上下文维护，本聚合只提供主键引用                          |

### 1.4 与关键上下游及交换边界的关系

供应商主档归属机构上下文（Organization）；供应请求（SupplyRequest）与供应发放（SupplyDelivery）在创建与执行链路中引用 `supplierId`。能否被选商、资质与在途单据门控等**实现细则**由应用层与采购域编排约定，须与不变式及本 DM 状态语义一致。对外交换可映射为 FHIR `Organization`（supplier）；本 DM 约束主档语义与标识引用边界。

| 维度 | 上游 | 本聚合 | 下游 |
| --- | --- | --- | --- |
| 锚点 | Organization（管理域） | 供应商主档 | SupplyRequest、SupplyDelivery、财务追溯 |
| 交换 | — | 院内编码 + 主数据属性 | Organization（supplier）投射 |

## 2. 聚合根与持久化形态

### 2.1 持久化形态

**持久化形态**：以 **`cus_supplier` 主表**为聚合根锚点；资质等子实体若启用，**不改变**主表作为供应商标识与状态权威来源（子表结构由实现维护，本 DM 不展开列级定义）。

聚合根对应表 `cus_supplier`，主键 `id`；一行表示一家供应商主档。

**高频查询模式（建议索引口径）**：按 `bus_no`、`name` / `py_str`、类型、`org_id`、状态（`status_enum` 或等价启用标记）、未逻辑删除；分页管理端按动态条件 + 租户。

### 2.2 聚合根标识

| 属性       | 类型           | 说明              |
| ---------- | -------------- | ----------------- |
| 供应商标识 | `SupplierId` | 系统内部唯一标识（雪花 ID） |

### 2.3 状态机

```text
  [DRAFT] ──启用──> [ACTIVE] ──停用──> [SUSPENDED] ──恢复──> [ACTIVE]
    │                  │                   │
    └──废弃──>         └──废弃──>          └──废弃──> [DELETED]
```

| 状态   | 英文（文档主标识） | 说明             | 允许的操作           |
| ------ | ------------------ | ---------------- | -------------------- |
| 草稿   | `DRAFT`            | 新建待完善或待审核   | 维护信息、启用、废弃 |
| 已启用 | `ACTIVE`           | 允许进入采购选商与引用 | 维护信息、停用、废弃 |
| 已停用 | `SUSPENDED`        | 暂停合作，不接受新采购引用 | 恢复（启用）、废弃   |
| 已废弃 | `DELETED`          | 逻辑删除，终态       | —                    |

> **落地口径**：推荐以 **String** `status_enum` 存储上述四态（存枚举 code）。若过渡期采用二态启停表达，则须在应用层维护与上表的一一映射，并在配置或数据迁移脚本中固化，避免静默语义漂移。仅二态实现时，可将 `DRAFT` 与 `ACTIVE` 在落库阶段合并为「可引用启用」。

## 4. 值对象（含枚举）

### 4.1 供应商生命周期状态（SupplierStatus）

与 §2.3 一致；**对应主表字段 `status_enum`，使用字符串编码存储（存枚举 code）**。

| 文档状态 | 英文主标识 | 与库字段示意 |
| -------- | ---------- | ------------ |
| 草稿 / 已启用 / 已停用 | `DRAFT` / `ACTIVE` / `SUSPENDED` | `status_enum`；若仅有 `active_flag`，以实现映射为准 |
| 已废弃 | `DELETED` | `is_deleted` 置位，且 `status_enum` 同步为终态（若采用双写） |

### 4.2 供应商类型（SupplierType）

**对应主表字段 `type_enum`，使用字符串编码存储（存枚举 code）。**

> **实现真源**：`com.zxplat.domain.share.enums.SupplierType`（非下表历史四分类草案）。

| value | code | info | 语义 |
| ----- | ---- | ---- | ---- |
| 1 | `1`（枚举常量 `MANUFACTURER`） | 生产厂家 | 药品/耗材生产厂家主数据；目录 `manufacturer_id` 指向本类型 |
| 2 | `2`（枚举常量 `SUPPLIER`） | 供应商 | 进货/退供等业务供货方；与生产厂家分离，禁止混用下拉 |

**目录厂家口径（2026-08）**：历史 `manufacturer_text` 原样迁入本表 type=生产厂家后，药品/耗材定义仅保留 `manufacturer_id`；API 出参 `manufacturer`/`manufacturerText` 为展示名（由 id 解析），非持久化列。

### 4.3 地址（Address）

> **当前持久化**：主表仅 `address` 单行文本（§3.1）。下表为**概念值对象**，用于表单拆分、QueryService组装或未来结构化落库；**不要求**与当前单行列表列一一对应。

| 属性   | 类型       | 说明        |
| ------ | ---------- | ----------- |
| 省份   | `String`   | 省/自治区/直辖市 |
| 城市   | `String`   | 地级市       |
| 区县   | `String`   | 区/县       |
| 详细地址 | `String` | 街道门牌      |

## 5. 领域事件

### 5.1 事件定义

| 编号    | 事件名称                       | 触发时机                                                                                 | 消费方            | 版本  |
| ----- | -------------------------- | ------------------------------------------------------------------------------------ | -------------- | --- |
| 5.1.1 | `SupplierRegisteredEvent`  | 新供应商记录创建                                                                             | 采购编排、主数据投影（可选） | v1  |
| 5.1.2 | `SupplierActivatedEvent`   | **启用**：`DRAFT` 或 `SUSPENDED` → `ACTIVE`（由 `activateSupplier` 触发；不设独立 `reactivateSupplier`） | 采购、下拉缓存        | v1  |
| 5.1.3 | `SupplierSuspendedEvent`   | `ACTIVE` → `SUSPENDED`（`suspendSupplier`；支持单条或多标识）                                                | 采购预警           | v1  |
| 5.1.4 | `SupplierReactivatedEvent` | **可选**：自 `SUSPENDED` → `ACTIVE` 若与 5.1.2 **分开发布**时使用；否则仅发 `SupplierActivatedEvent`（实现二选一，须在团队内固定一种并贯穿订阅方） | 采购             | v1  |
| 5.1.5 | `SupplierRetiredEvent`     | 废弃（逻辑删除）                                                                             | 引用校验、缓存        | v1  |
| 5.1.6 | `SupplierInfoUpdatedEvent` | 基本信息维护                                                                               | QueryService（可选）        | v1  |

> 事件**载荷最小集**、包路径与可选资质类事件由实现与共享事件契约约定；本表为领域语义与触发边界的权威说明。

### 5.2 事件触发规则

| 当前状态   | 操作     | 目标状态   | 发布事件 |
| ---------- | -------- | ---------- | -------- |
| —          | 注册     | `DRAFT`    | `SupplierRegisteredEvent` |
| `DRAFT`    | 启用     | `ACTIVE`   | `SupplierActivatedEvent` |
| `ACTIVE`   | 停用     | `SUSPENDED`| `SupplierSuspendedEvent` |
| `SUSPENDED`| 启用     | `ACTIVE`   | `SupplierActivatedEvent` 与/或 `SupplierReactivatedEvent`（§5.1.4，实现二选一） |
| 非 `DELETED` | 废弃   | `DELETED`  | `SupplierRetiredEvent` |
| `ACTIVE`   | 维护信息 | `ACTIVE`   | `SupplierInfoUpdatedEvent` |

> 未列出的迁移与发布以落库与交互契约为准；稳定后须与本节矩阵一致，避免在 §9 重复维护第二套触发矩阵。

## 6. 领域服务

### 6.1 写侧领域服务（SupplierDomainService）

> 写侧方法不使用 `@Transactional` 替代应用层事务边界；事务边界、传播行为与幂等策略由应用层统一声明。  
> 历史应用层命名与领域方法对照见 **附录 A**。批量启停不设独立 `batchToggleStatus`：入参为供应商标识**列表**（长度为 1 即单条），分别调用 `activateSupplier` / `suspendSupplier` / `retireSupplier`。

#### 6.1.1 注册供应商（`registerSupplier`）

- **业务意义**：创建供应商主数据，为采购链提供唯一业务身份。
- **边界说明**：BR-SUP-001/002；不写采购订单。
- **入参**：名称、类型、统一社会信用代码、机构标识等（可改字段集以落库与交互契约为准）。
- **出参**：供应商标识。
- **前置条件**：名称非空（BR-SUP-004）；类型合法；采番后查重；信用代码唯一。
- **状态变化**：新建为 `DRAFT` 或产品约定的初始态。
- **聚合内影响**：插入主档行。
- **事件输出**：`SupplierRegisteredEvent`。
- **失败语义**：唯一冲突、必填缺失时拒绝。

#### 6.1.2 启用供应商（`activateSupplier`）

- **业务意义**：使供应商进入 `ACTIVE`，参与下拉与采购引用；**同时覆盖**「`DRAFT` → `ACTIVE`」与「`SUSPENDED` → `ACTIVE`」——**不设**独立 `reactivateSupplier`（若代码层已拆分方法名，语义须与本条一致）。
- **边界说明**：入参可为单个标识或标识**列表**；多标识须满足 **BR-SUP-007**。
- **入参**：供应商标识或标识列表；批量时操作人、原因等以落库与交互契约为准。
- **出参**：无；或多条时的成功/失败明细（以落库与交互契约为准）。
- **前置条件**：每条当前为 `DRAFT`、`SUSPENDED` 或其他允许启用的前置态。
- **状态变化**：每条 → `ACTIVE`。
- **聚合内影响**：批量更新状态列。
- **事件输出**：每条成功发 `SupplierActivatedEvent`；若实现另发 `SupplierReactivatedEvent`，与 §5.1.4 二选一并在实现与接口契约中固定。
- **失败语义**：非法状态迁移；批量默认建议**整批回滚**，若产品要求部分成功须在应用层与接口契约中约定逐条结果结构并文档化。

#### 6.1.3 停用供应商（`suspendSupplier`）

- **业务意义**：暂停合作，阻断新开引用；单条与多条同契约（列表长度为 1 即单条）。
- **边界说明**：停用原因用于审计；BR-SUP-007。
- **入参**：供应商标识或列表；停用原因（结构以落库与交互契约为准）。
- **出参**：无；或多条明细（以落库与交互契约为准）。
- **前置条件**：每条当前为 `ACTIVE`。
- **状态变化**：每条 `ACTIVE` → `SUSPENDED`。
- **聚合内影响**：批量更新状态与原因字段。
- **事件输出**：每条成功 `SupplierSuspendedEvent`（或合并批量事件，以落库与交互契约为准）。
- **失败语义**：重复停用、状态非法；批量策略同 6.1.2。

#### 6.1.4 废弃供应商（`retireSupplier`）

- **业务意义**：逻辑删除主档（BR-SUP-003）；单条与多条同契约。
- **边界说明**：BR-SUP-005/008；不物理删行；在途采购处理由他域策略决定；BR-SUP-007。
- **入参**：供应商标识或列表；废弃原因可共用或逐条。
- **出参**：无；或多条明细（以落库与交互契约为准）。
- **前置条件**：每条非 `DELETED`；满足 BR-SUP-008 等引用约束。
- **状态变化**：每条 → `DELETED`（逻辑删除）。
- **聚合内影响**：批量逻辑删除标记与状态。
- **事件输出**：每条成功 `SupplierRetiredEvent`（或合并批量事件）。
- **失败语义**：禁止废弃的强引用时拒绝该行或整批回滚（以落库与交互契约为准）。

#### 6.1.5 维护基本信息（`maintainSupplierInfo`）

- **业务意义**：更新名称、地址、联系方式等非状态机字段。
- **边界说明**：BR-SUP-006；`credit_code` 注册后不可改；若涉及唯一性字段须重校验。
- **入参**：供应商标识、变更字段集。
- **出参**：无。
- **前置条件**：主档存在且非 `DELETED`。
- **状态变化**：`N/A`（属性更新）。
- **聚合内影响**：部分列更新；名称变更时同步 `py_str` / `wb_str`。
- **事件输出**：`SupplierInfoUpdatedEvent`。
- **失败语义**：唯一冲突、越权字段修改时拒绝。

> 资质维护等**主档外**写能力归入资质子实体或应用服务编排，不在本 §6.1 展开；本 §6.1 仅列主档生命周期与信息维护。

### 6.2 读侧查询服务（SupplierQueryService）

#### 6.2.1 按主键查询（`findSupplierById`）

- **业务意义**：详情与引用回显。
- **边界说明**：只读；逻辑删除主档默认不可见（以落库与交互契约为准）。
- **查询范围（读库，无写入）**：主档；主键定位。
- **过滤口径**：租户；`is_deleted` 等。
- **组装规则**：主档详情 DTO；扩展视图字段由应用层或QueryService挂载。
- **返回约束**：不含采购订单明细。

#### 6.2.2 全量列表（`listSuppliers`）

- **业务意义**：小规模部署或导出前拉取全量主数据列表。
- **边界说明**：慎用大数据量；建议管理端改用分页（见 6.2.4）。
- **查询范围（读库，无写入）**：主档全表或租户子集。
- **过滤口径**：基础过滤条件。
- **组装规则**：简单列表 DTO。
- **返回约束**：排序稳定。

#### 6.2.3 按类型与状态过滤（`listSuppliersByTypeAndActive`）

- **业务意义**：下拉与选择器展示某类型且处于 `ACTIVE` 的供应商。
- **边界说明**：只读；过滤条件与 `status_enum`（或等价启用标记）对齐。
- **查询范围（读库，无写入）**：主档。
- **过滤口径**：类型 + 已启用 + 未废弃。
- **组装规则**：轻量 id/名称/类型。
- **返回约束**：列表体量受控；可缓存。

#### 6.2.4 动态分页（`pageSuppliers`）

- **业务意义**：管理端条件分页检索。
- **边界说明**：只读；动态 WHERE 与租户隔离（实现可用 `Specification` 或等价方案）。
- **查询范围（读库，无写入）**：主档。
- **过滤口径**：多字段组合；排序字段以产品为准。
- **组装规则**：分页 DTO（总行数 + 当前页）。
- **返回约束**：不内嵌导出流；导出由应用层编排。

### 6.3 领域边界说明

- 供应商**主档**属于本聚合；**采购订单行、入库验收、发票与付款**由他域编排。
- 展示用 Organization 树、字典下拉等为应用层或他域能力。
- 历史 CRUD 命名与领域方法对照见 **附录 A**。
- **不设** `reactivateSupplier`、`batchToggleStatus`：恢复与批量启停通过 `activateSupplier` / `suspendSupplier` / `retireSupplier` 的标识列表入参表达（列表长度为 1 即单条）。

### 9.1 QueryService与查询规则

### 9.2 与 SupplyRequest / SupplyDelivery 的协作流程

1. 创建 SupplyRequest → 查询 `ACTIVE` 且满足门控的供应商列表。
2. 选择供应商，单据记录 `supplierId`。
3. 到货后创建 SupplyDelivery，沿用同一 `supplierId`。
4. 财务付款与成本追溯引用链路，不在本聚合维护。

### 9.3 与 MedicationDefinition 的间接关系

供应商不直接外键关联药品定义；同一药品多供应商供货在 SupplyRequest 选商时决定。
