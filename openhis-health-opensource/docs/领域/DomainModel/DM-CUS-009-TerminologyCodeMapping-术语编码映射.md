# DM-CUS-009 TerminologyCodeMapping 术语编码映射

> **限界上下文**：系统基础 · 术语编码管理  
> **聚合类型**：实体聚合  
> **版本**：v1.0.1 · **日期**：2026-05-28

---

## 1. 概述

### 1.1 业务定义

术语编码映射（TerminologyCodeMapping）是维护**源编码体系到目标编码体系**之间对照关系的基础数据聚合。它为 HIS 中跨编码体系的数据互通提供统一的查询与维护能力，覆盖诊断（ICD-10/ICD-11）、药品（ATC）、诊疗项目（国家医疗服务价格项目编码）、器材、医保目录等多对象类型的编码转换场景。

### 1.2 核心职责

| 职责 | 说明 |
|---|---|
| 编码对照维护 | 维护"源编码 → 目标编码"的映射关系，支持新增、修改、停用、逻辑删除 |
| 多对象类型支持 | 通过源对象类型（sourceItemTable）区分诊断、药品、项目、耗材等不同业务对象的编码映射 |
| 编码转换查询 | 为其他领域（诊断、药品、收费等）提供按源编码查目标编码的统一查询能力 |
| 批量导入 | 支持 Excel/CSV 批量导入对照关系，按身份键判重实现新增与更新混合处理 |
| 数据一致性保障 | 通过身份键（源对象类型+源编码+目标编码）保障对照关系的唯一性和可追溯性 |

### 1.3 适用范围

| 类型 | 说明 |
|---|---|
| 诊断编码转换 | ICD-10 院内码 → 国标码，或 ICD-10 → ICD-11 对照 |
| 药品编码转换 | 院内药品编码 → ATC 编码，院内药品编码 → 医保药品目录编码 |
| 诊疗项目编码转换 | 院内项目编码 → 国家医疗服务价格项目编码 |
| 器材编码转换 | 院内耗材编码 → UDI 编码，院内编码 → 医保耗材编码 |
| 医保结算 | 院内诊断/项目/药品编码 → 医保中心统一编码，支撑医保申报与结算 |
| 统计报表 | 统一统计口径，将院内多样化编码归并到标准分类编码 |

### 1.4 与关键上下游及交换边界的关系

诊断定义、药品定义、诊疗项目定义、器材定义及医保结算（Claim）等消费方在**申报、对账、上报**场景调用本聚合的编码转换查询；本聚合不持有业务事实表，仅维护对照行。批量导入的调度与进度属应用层。

| 维度 | 上游 | 本聚合 | 下游 |
|---|---|---|---|
| 输入 | 各业务主档的「院内码」 | 源类型 + 实现 → 目标码 | Claim、报表、外部交换 |
| 输出 | — | 即时查询结果 | 不反写业务主档 |

**FHIR**：R5 `ConceptMap` 以 group/element/target 描述映射；本模型为单表扁平化，交换时可投射为 `ConceptMap`（字段级映射见 §9.4）。

## 2. 聚合根与持久化形态

### 2.1 持久化形态

**持久化形态**：单表。

聚合根对应表 `cus_terminology_code_mapping`，主键 `id`；一行表示一条「源对象类型 + 实现 + 目标码」对照（启用/停用/逻辑删除语义见 §2.3）。

**高频查询模式（建议索引口径）**：按 `source_item_table` + `source_item_no`、`target_item_no`、租户；唯一约束覆盖自然键；分页维护按组合条件。

### 2.2 聚合根标识

| 属性 | 类型 | 说明 |
|---|---|---|
| 映射标识 | `TerminologyCodeMappingId` | 全局唯一标识，系统生成（雪花 ID） |

### 2.3 状态机

```
  [启用] ──停用──> [已停用] ──恢复──> [启用]
    │                 │
    └──删除──> [已删除]  └──删除──> [已删除]
```

#### 状态定义

| value | code | info | 语义 |
| ----- | ---- | ---- | ---- |
| 1 | ACTIVE | 启用 | 对照关系生效中，可用于编码转换查询，允许修改、停用、删除 |
| 2 | INACTIVE | 已停用 | 对照关系暂停使用，不参与编码转换但保留历史，允许恢复、删除 |
| 3 | DELETED | 已删除 | 逻辑删除，不可恢复 | — |

> **状态枚举说明**：`active` 与全局文档"生效/进行中"语义一致。停用与删除语义分离：停用（`inactive`）仍保留历史可追溯，删除（`deleted`）通过逻辑删除实现不可逆终止。

## 3. 实体

本聚合为**扁平化单实体聚合**，不包含独立子实体。所有对照关系直接由聚合根管理。

### 3.1 术语编码映射（TerminologyCodeMapping）

术语编码映射聚合根的属性定义，对应 `cus_terminology_code_mapping` 表；唯一索引约束 `源对象类型 + 源编码 + 目标编码`。

| 属性 | 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 映射标识 | `id` | `Long` | 是 | 主键，雪花 ID |
| 源对象类型 | `source_item_table` | `String`（`SourceItemType`） | 是 | 标识编码所属的业务对象类型，见 §4.1 |
| 源编码 | `source_item_no` | `String` | 是 | 源编码体系中的编码值 |
| 目标编码 | `target_item_no` | `String` | 是 | 目标编码体系中的编码值 |
| 目标名称 | `target_name` | `String` | 否 | 目标编码对应的名称（冗余存储，便于展示） |
| 是否启用 | `active_flag` | `Boolean` | 是 | 启用标志（`true`=启用 / `false`=停用） |

> 审计字段（`created_at`/`updated_at`/`created_by`/`updated_by`）、租户字段（`tenant_id`）、逻辑删除（`is_deleted`）继承自 `BaseAuditedEntity`，遵循统一约定。

## 4. 值对象（含枚举）

### 4.1 源对象类型（SourceItemType）

标识编码映射所属的业务对象类型，确保不同业务对象的编码不会混用。

| 枚举值 | 英文 | 说明 | 对应业务表 |
|---|---|---|---|
| 诊断 | `condition` | 诊断编码对照（ICD-10/ICD-11） | `ConditionDefinition` |
| 药品 | `medication` | 药品编码对照（ATC/医保药品） | `MedicationDefinition` |
| 诊疗项目 | `activity` | 诊疗项目编码对照（国家价格项目编码） | `ActivityDefinition` |
| 器材 | `device` | 器材/耗材编码对照（UDI/医保耗材） | `DeviceDefinition` |
| 检验指标 | `observation` | 检验指标编码对照（LOINC） | `Observation` |
| 其他 | `other` | 其他编码对照 | — |

### 4.2 映射状态（MappingStatus）

见 §2.3 状态定义中的枚举表。

### 4.3 映射身份键（MappingIdentity）

联合封装 `源对象类型 + 源编码 + 目标编码` 的业务身份，用于导入判重和唯一性约束。

| 属性 | 类型 | 说明 |
|---|---|---|
| 源对象类型 | `SourceItemType` | 业务对象类型 |
| 源编码 | `String` | 源编码值 |
| 目标编码 | `String` | 目标编码值 |

> **不变式**：同一 MappingIdentity 在活跃状态下只允许存在一条记录。

### 4.4 映射等价关系（MappingEquivalence）

描述源编码与目标编码之间的语义等价程度，对齐 FHIR R5 `ConceptMap.element.target.relationship`。

| 枚举值 | 英文 | 说明 |
|---|---|---|
| 等价 | `equivalent` | 源与目标语义完全一致 |
| 宽于 | `wider` | 目标编码范围宽于源编码 |
| 窄于 | `narrower` | 目标编码范围窄于源编码 |
| 近似 | `inexact` | 近似但不完全等价 |
| 不等价 | `not-related-to` | 无直接等价关系（保留特殊对照） |

### 4.5 编码体系标识（CodeSystemIdentifier）

用于标识源/目标编码所属的编码体系，便于多编码体系共存。

| 常用值 | 说明 |
|---|---|
| `icd-10-cm` | ICD-10 临床修订版 |
| `icd-11` | ICD-11 |
| `atc` | ATC 药品分类编码 |
| `nhsa-drug` | 国家医保药品目录编码 |
| `nhsa-service` | 国家医保诊疗项目目录编码 |
| `nhsa-device` | 国家医保耗材目录编码 |
| `loinc` | LOINC 检验指标编码 |
| `local` | 院内自定义编码 |

## 5. 领域事件

### 5.1 事件定义

| 事件名称 | 英文名称 | 触发时机 | 携带数据 | 消费方 |
|---|---|---|---|---|
| 对照已创建 | `TerminologyMappingCreatedEvent` | 新增编码映射成功 | 映射标识, 源对象类型, 源编码, 目标编码 | 查询投影、审计、缓存提示（承接早期版本 §6） |
| 对照已修改 | `TerminologyMappingModifiedEvent` | 修改编码映射成功 | 映射标识, 修改字段列表 | 查询投影、审计、缓存提示 |
| 对照已停用 | `TerminologyMappingDeactivatedEvent` | 编码映射被停用 | 映射标识, 停用原因 | 查询投影、缓存失效提示 |
| 对照已恢复 | `TerminologyMappingReactivatedEvent` | 已停用的编码映射恢复启用 | 映射标识 | 查询投影、缓存提示 |
| 对照已删除 | `TerminologyMappingDeletedEvent` | 编码映射被逻辑删除 | 映射标识, 源对象类型, 源编码 | 查询投影、审计 |
| 对照已批量导入 | `TerminologyMappingBatchImportedEvent` | 批量导入完成 | 源对象类型, 新增数, 更新数, 失败数 | 查询投影、审计、缓存批量刷新提示 |

> **命名说明**：早期版本事件名为 `TerminologyCodeMappingCreatedEvent` 等；新 DM 以 `TerminologyMapping*Event` 为权威命名（对齐指南「新 DM 事件名优先」）。语义与触发时机不变。

### 5.2 事件触发规则

| 当前状态 | 操作 | 目标状态 | 发布事件 |
|---|---|---|---|
| — | 创建对照 | 启用 | `TerminologyMappingCreatedEvent` |
| 启用 | 修改属性 | 启用 | `TerminologyMappingModifiedEvent` |
| 启用 | 停用 | 已停用 | `TerminologyMappingDeactivatedEvent` |
| 已停用 | 恢复 | 启用 | `TerminologyMappingReactivatedEvent` |
| 启用/已停用 | 删除 | 已删除 | `TerminologyMappingDeletedEvent` |
| — | 批量导入 | 启用 | `TerminologyMappingBatchImportedEvent` |

## 6. 领域服务

### 6.1 写侧领域服务（TerminologyCodeMappingDomainService）

> 仅包含会**变更对照主数据**的操作；纯查询对照见 §6.2。

#### 6.1.1 新建编码对照（`createMapping`）

- **业务意义**：建立源业务编码到目标编码（医保/院标等）的一条启用态映射，供转换链路引用。
- **边界说明**：BR-TER-001/002；BR-TER-003 活跃态下 MappingIdentity 唯一；BR-TER-011 须带对象类型。
- **入参**：源对象类型、源编码、目标编码、目标名称、可选映射等价关系等。
- **出参**：映射标识。
- **前置条件**：必填完整；无同身份键活跃行冲突。
- **状态变化**：初始化为启用（BR-TER-007 语义）。
- **聚合内影响**：插入一行对照主数据。
- **事件输出**：`TerminologyMappingCreatedEvent`。
- **失败语义**：唯一冲突、必填缺失时拒绝。

#### 6.1.2 修改编码对照（`modifyMapping`）

- **业务意义**：在身份键不变前提下更新目标名称、等价关系等可变属性。
- **边界说明**：BR-TER-004 源对象类型与源编码不可改；仅启用态可改（以落库与交互契约为准）。
- **入参**：映射标识、修改字段 Map。
- **出参**：`—`。
- **前置条件**：记录存在且未删除；状态为启用。
- **状态变化**：`N/A`（属性更新）。
- **聚合内影响**：部分列更新。
- **事件输出**：`TerminologyMappingModifiedEvent`。
- **失败语义**：身份键变更请求、状态非法时拒绝。

#### 6.1.3 停用编码对照（`deactivateMapping`）

- **业务意义**：暂停使用该条对照，保留历史与可恢复性（BR-TER-007）。
- **边界说明**：BR-TER-010 转换查询不返回停用/删除；不停用他行同源映射除非命令要求。
- **入参**：映射标识、停用原因。
- **出参**：`—`。
- **前置条件**：当前为启用。
- **状态变化**：`启用 -> 已停用`。
- **聚合内影响**：更新状态与原因字段。
- **事件输出**：`TerminologyMappingDeactivatedEvent`。
- **失败语义**：重复停用、状态非法时拒绝。

#### 6.1.4 恢复编码对照（`reactivateMapping`）

- **业务意义**：将已停用对照恢复为启用，使转换链路重新命中。
- **边界说明**：BR-TER-009 恢复前须校验同 MappingIdentity 无其他活跃记录。
- **入参**：映射标识。
- **出参**：`—`。
- **前置条件**：当前为已停用；无活跃冲突行。
- **状态变化**：`已停用 -> 启用`。
- **聚合内影响**：更新状态。
- **事件输出**：`TerminologyMappingReactivatedEvent`。
- **失败语义**：冲突仍存在时拒绝。

#### 6.1.5 删除编码对照（`deleteMapping`）

- **业务意义**：逻辑删除且不可恢复，用于彻底下线错误对照（BR-TER-005/007）。
- **边界说明**：BR-TER-006 查询默认过滤已删；不物理删行。
- **入参**：映射标识。
- **出参**：`—`。
- **前置条件**：记录存在且非已删除。
- **状态变化**：`任意 -> 已逻辑删除`。
- **聚合内影响**：逻辑删除标记。
- **事件输出**：`TerminologyMappingDeletedEvent`。
- **失败语义**：重复删除策略以落库与交互契约为准（幂等或拒绝）。

#### 6.1.6 批量导入编码对照（`importMappingBatch`）

- **业务意义**：批量 upsert 对照行，支撑对账文件与第三方码表接入（BR-TER-008）。
- **边界说明**：逐行校验；存在则更新属性、不存在则新增；不建议先删后插（PR-TER-002）。
- **入参**：源对象类型、映射行列表。
- **出参**：导入结果（新增数、更新数、失败数）。
- **前置条件**：每行必填字段完整；对象类型一致。
- **状态变化**：多行插入或更新。
- **聚合内影响**：批量写主表。
- **事件输出**：`TerminologyMappingBatchImportedEvent`。
- **失败语义**：部分行失败计入失败数；是否全回滚以落库与交互契约为准。

### 6.2 读侧查询服务（TerminologyCodeMappingQueryService）

#### 6.2.1 分页查询编码对照（`getTerminologyCodeMappingPage`）

- **业务意义**：维护列表分页检索对照主数据。
- **边界说明**：只读；BR-TER-006 默认不含已删；可含已停用视筛选项（产品约定）。
- **查询范围（读库，无写入）**：术语编码映射主表。
- **过滤口径**：源对象类型、源编码、目标编码、目标名称等组合；租户隔离。
- **组装规则**：分页 DTO。
- **返回约束**：不内嵌导出文件。

#### 6.2.2 按源编码查询目标编码（`getMappingBySource`）

- **业务意义**：单笔业务转换：由源对象类型 + 源编码得到启用态目标编码集合（BR-TER-010）。
- **边界说明**：只读；一对多返回列表；与 **§6.2.5 `lookupTargetCode`** 为同一读语义，**对外契约择一**（或保留其一为门面别名），避免双轨实现。
- **查询范围（读库，无写入）**：主表按身份键前缀（类型+源编码）过滤。
- **过滤口径**：`status=启用` 且未删除。
- **组装规则**：目标编码列表；可附 `targetName` 展示（PR-TER-003）。
- **返回约束**：无命中返回空列表。

#### 6.2.3 按对象类型批量查询对照（`getMappingsBySourceTable`）

- **业务意义**：批量转换与医保申报预处理，减少 N 次单条查询（PR-TER-001）。
- **边界说明**：只读；BR-TER-011 必须带对象类型防串码。
- **查询范围（读库，无写入）**：主表；`sourceItemType` 过滤。
- **过滤口径**：启用且未删；可选时间/version（以落库与交互契约为准）。
- **组装规则**：批量 DTO 列表或 Map 结构。
- **返回约束**：不修改任何行。

#### 6.2.4 按主键查询对照详情（`getById`）

- **业务意义**：编辑回显单条映射全字段。
- **边界说明**：只读；可返回已停用供只读审计（产品约定）。
- **查询范围（读库，无写入）**：主键定位单行。
- **过滤口径**：租户；删除标记。
- **组装规则**：详情 DTO。
- **返回约束**：不存在时空或异常（以落库与交互契约为准）。

#### 6.2.5 按源查目标编码（`lookupTargetCode`）

- **业务意义**：高频转换读路径：实现 → 多目标码；建议作为 **QueryService 对外主入口名**（与 §6.2.2 二选一，以本稿约定为准）。
- **边界说明**：只读；不写库；BR-TER-010 仅启用态。
- **查询范围（读库，无写入）**：主表。
- **过滤口径**：源对象类型 + 源编码。
- **组装规则**：目标编码列表（一对多全量）。
- **返回约束**：不缓存写回（缓存属应用层/基础设施）。

#### 6.2.6 按目标查源编码（`lookupSourceCode`）

- **业务意义**：反向解析：目标码 → 源编码列表，用于对账与逆向转换。
- **边界说明**：只读；BR-TER-010。
- **查询范围（读库，无写入）**：主表。
- **过滤口径**：源对象类型 + 目标编码。
- **组装规则**：源编码列表。
- **返回约束**：无命中返回空。

#### 6.2.7 导出编码对照（`exportTerminologyCodeMapping`）

- **业务意义**：与列表同筛选口径导出稽核文件。
- **边界说明**：**应用层编排**为主：Excel/CSV 格式、异步任务、流控；领域侧可提供同条件只读游标或分页拉取。
- **查询范围（读库，无写入）**：与 `getTerminologyCodeMappingPage` 等价筛选。
- **过滤口径**：同上。
- **组装规则**：行集映射为导出行模型。
- **返回约束**：二进制流或任务 ID 由应用层返回。

### 6.3 领域边界说明

- 写侧仅维护对照主数据生命周期；**lookup** 与分页、导出读路径统一归入 `TerminologyCodeMappingQueryService`，避免在写服务中混入只读 API。
- 编码转换的缓存、批量装配、跨对象 join 由应用层或基础设施承担；对象类型过滤为强制门禁（BR-TER-011）。
- 与 PR-TER-* 实践子规则一致：查询优先、导入幂等、停用与删除语义分离（见 §7.1）。

## 7. 不变式

| 编号 | 不变式 | 说明 |
|---|---|---|
| BR-TER-001 | 源对象类型（sourceItemType）必填 | 确保每条映射有明确的业务对象归属 |
| BR-TER-002 | 源编码与目标编码必须成对出现，不允许为空 | 映射关系的基本完整性 |
| BR-TER-003 | 同一 MappingIdentity（源对象类型+源编码+目标编码）在启用状态下只允许存在一条记录 | 唯一性约束，防止重复对照 |
| BR-TER-004 | 源对象类型和源编码不允许通过修改操作变更（须删除后重建） | 身份键不可变，保障引用一致性 |
| BR-TER-005 | 删除必须逻辑删除，不允许物理删除 | 审计追踪要求 |
| BR-TER-006 | 查询默认只返回未删除记录 | 默认过滤已删除数据 |
| BR-TER-007 | 停用与删除语义分离：停用仅暂停使用、保留历史；删除不可恢复 | 状态语义清晰 |
| BR-TER-008 | 导入时按 MappingIdentity 判重，存在则更新属性，不存在则新增 | 导入幂等性 |
| BR-TER-009 | 恢复已停用记录前须校验同一身份键无其他活跃记录 | 防止恢复后产生重复 |
| BR-TER-010 | 编码转换查询仅返回"启用"状态的对照，不返回已停用或已删除的映射 | 编码转换准确性 |
| BR-TER-011 | 同源编码在不同 `sourceItemTable`（对象类型）下允许并存；检索与导入必须带对象类型过滤 | 承接早期版本 `BR-TER-006`，避免跨对象串码 |

### 7.1 实践子规则（PR-TER-*）（承接早期版本 §3.2）

| 编号 | 说明 |
|---|---|
| PR-TER-001 | 查询是核心能力，优先保障按源对象与源编码检索效率 |
| PR-TER-002 | 导入支持批量新增与批量更新，不建议「先删后插」 |
| PR-TER-003 | `targetName` 主要用于展示，不参与核心身份键（`MappingIdentity`） |
| PR-TER-004 | 停用与删除语义分离：停用仍保留历史可追溯 |

### 8.2 下游影响

| 下游上下文 | 聚合 | 触发方式 | 说明 |
|---|---|---|---|
| 诊断定义 | ConditionDefinition | 查询 | 诊断编码转换：院内码 → ICD 标准码 / 医保码 |
| 药品定义 | MedicationDefinition | 查询 | 药品编码转换：院内码 → ATC 码 / 医保药品码 |
| 诊疗项目定义 | ActivityDefinition | 查询 | 项目编码转换：院内码 → 国家价格项目码 |
| 器材定义 | DeviceDefinition | 查询 | 器材编码转换：院内码 → UDI 码 / 医保耗材码 |
| 医保结算 | Claim | 查询 | 医保申报时统一转换为医保中心编码 |
| 统计报表 | Report | 查询 | 统计时归并为标准分类编码 |

### 8.3 引用规则

> **统一规则**：
> - 下游聚合通过 `lookupTargetCode(源对象类型, 源编码)` 查询目标编码，不直接持有映射记录的引用
> - 编码转换结果为**即时查询**，不缓存在下游聚合中（价格/状态变更时无需同步）
> - 批量编码转换场景（如医保申报）建议使用 `lookupTargetCode` 的批量版本，避免逐条查询

## 9. 补充

### 9.1 编码转换的典型使用场景

```
场景一：门诊诊断编码上传医保

1. 医生在就诊中选择院内诊断（ConditionDefinition.code = "A001"）
2. 出院结算时，系统调用 lookupTargetCode(condition, "A001")
3. TerminologyCodeMapping 返回目标编码 "J06.900"（ICD-10 标准码）
4. 医保申报（Claim）使用标准编码 "J06.900" 上传至医保中心

场景二：药品编码转换

1. 药品目录中院内编码 "MED-20001"
2. 系统调用 lookupTargetCode(medication, "MED-20001")
3. 返回 ATC 编码 "J01CA04"（阿莫西林）
4. 同时返回医保编码 "XA01BD005432"
```

### 9.2 批量导入流程

| 步骤 | 层级 | 说明 |
|---|---|---|
| 1. 上传文件 | 应用层 | 接收 Excel/CSV 文件并解析行数据 |
| 2. 格式校验 | 应用层 | 校验模板格式、必填字段、数据类型 |
| 3. 业务校验 | 领域层 | 按 MappingIdentity 判重、校验源对象类型合法性 |
| 4. 批量写入 | 领域层 | 按判重结果分为新增与更新两批执行 |
| 5. 结果汇总 | 应用层 | 汇总新增数/更新数/失败数及错误明细，返回导入报告 |

> **性能注意**：批量导入采用分批次提交策略（建议每批 500 条），避免单次事务过大导致锁竞争。导入任务调度、进度跟踪属于应用层职责，不在本聚合内处理。
