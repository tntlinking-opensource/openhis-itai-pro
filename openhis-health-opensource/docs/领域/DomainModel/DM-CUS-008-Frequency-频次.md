# DM-CUS-008 Frequency 频次

> **限界上下文**：系统基础 · 频次管理  
> **聚合类型**：实体聚合  
> **版本**：v1.0.1 · **日期**：2026-05-28

---

## 1. 概述

### 1.1 业务定义

频次（Frequency）是对**医嘱执行时间规律**的标准化描述，定义了"多久执行一次、每次几点执行"等时间维度的业务规则。它是 HIS 中药品医嘱、诊疗医嘱、护理计划等业务对象共同依赖的**时间参数基础数据**，回答的核心问题是："**这个医嘱应该按什么节奏执行？**"

常见频次示例：QD（每日一次）、BID（每日两次）、TID（每日三次）、Q8H（每8小时一次）、QOD（隔日一次）、QW（每周一次）、PRN（必要时）。

### 1.2 核心职责

| 职责 | 说明 |
|---|---|
| 频次主数据维护 | 维护频次编码、名称、周期类型、执行次数等标准化配置 |
| 执行时间点展开 | 根据频次定义与医嘱生效时间边界，计算离散执行时间点集合 |
| 跨医嘱类型复用 | 为药品医嘱、诊疗医嘱、护理计划等提供统一的频次引用 |
| 启停管理 | 支持频次定义的启用与停用，控制临床可引用范围 |

### 1.3 适用范围

| 类型 | 说明 |
|---|---|
| 药品医嘱开立 | 医生选择用药频次（如 BID、TID），系统据此计算给药时点 |
| 诊疗医嘱开立 | 住院长期医嘱引用频次（如 QD 换药、QOD 理疗） |
| 护理执行计划 | 护理计划按频次展开执行时间点（如 Q4H 测体温） |
| 住院医嘱执行 | 护士站按频次展开的时间点生成执行单、扫码执行 |

### 1.4 与关键上下游及交换边界的关系

下游医嘱与执行类聚合（如 MedicationRequest、ServiceRequest、CarePlan、Task）通过 `rateCode`（或等价引用）只读引用已启用频次；**已开立实例**应快照当时频次参数，不随主数据后续修改漂移。本聚合提供主数据维护与执行时点展开（`computeExecutionTimePoints`）等读侧能力，不写医嘱事实表。

| 维度 | 上游 | 本聚合 | 下游 |
|---|---|---|---|
| 职责 | — | 频次目录 + 时点展开 | 医嘱、护理执行、执行单 |
| 引用 | — | `rateCode` / 频次标识（以约定为准） | 启用态校验后引用 |

**FHIR**：`Timing` 为数据类型（非独立资源），`Timing.repeat` 表达周期、频率、日内时点等。对外交换可将本聚合字段投射到 `Timing.repeat.frequency`、`period`、`periodUnit`、`timeOfDay` 等。

## 2. 聚合根与持久化形态

### 2.1 持久化形态

**持久化形态**：单表。

聚合根对应表 `cus_frequency`，主键 `id`；一行表示一条可引用的频次定义。

**高频查询模式（建议索引口径）**：按 `rate_code`（唯一）、`name`、`active_flag`、租户；维护列表分页按动态条件。

### 2.2 聚合根标识

| 属性 | 类型 | 说明 |
|---|---|---|
| 频次标识 | `FrequencyId` | 全局唯一标识，系统生成（雪花 ID） |

### 2.3 状态机

```
  [启用] ──停用──> [已停用] ──恢复──> [启用]
```

#### 状态定义

| value | code | info | 语义 |
| ----- | ---- | ---- | ---- |
| 1 | ACTIVE | 启用 | 频次生效中，临床可引用，允许修改、停用、删除 |
| 2 | INACTIVE | 已停用 | 暂停使用，不再可引用，但保留历史，允许恢复、删除 |

> **状态枚举说明**：`active` 与全局文档"生效/进行中"语义一致。频次为字典型聚合，状态机较简单，通过 `activeFlag` 字段表达。删除策略以产品为准（当前实现为物理删除，与采用逻辑删除的主数据区分）。

## 3. 实体

本聚合为**扁平化单实体聚合**，不包含独立子实体。频次主数据的业务特征是"一条记录即一组完整的频次定义"，周期、时点、间隔等参数直接作为聚合根属性管理。

```text
Frequency（聚合根）
════════════════════════════════════════════════════════════

  ┌──────────────────────────────────────────────────────┐
  │  rate_code / name / cycle_type / applicable_scenes  │
  │  active_flag / sort_no / allow_cross_day             │
  └──────────────────────────────────────────────────────┘
```

### 3.1 频次（Frequency）

频次聚合根的属性定义，对应 `cus_frequency` 表。

| 属性 | 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 频次标识 | `id` | `Long` | 是 | 主键，雪花 ID |
| 频次编码 | `rate_code` | `String` | 否 | 频次业务编码（如 QD、BID、TID），填写则全局唯一 |
| 频次名称 | `name` | `String` | 是 | 频次展示名称（如"每日一次"、"每日两次"） |
| 周期类型 | `cycle_type` | `Integer`（`FrequencyCycleType`） | 是 | 见 §4.1 |
| 日计数 | `day_count` | `Integer` | 否 | 日相关计数（如"每N日"中的N） |
| 日间隔 | `day_interval` | `Integer` | 否 | 日间隔（如隔日=2） |
| 日执行时点 | `day_times` | `String` | 否 | 日内执行时点序列（如"08:00,12:00,18:00"） |
| 周周期标记 | `week_cycle_flag` | `Boolean` | 否 | 是否为周周期频次 |
| 总执行次数 | `total_execution_count` | `Integer` | 否 | 固定总执行次数（临时医嘱场景） |
| 执行周期 | `execution_period` | `Integer` | 否 | 执行周期数值 |
| 执行周期单位 | `execution_period_unit` | `String`（`PeriodUnit`） | 否 | 见 §4.2 |
| 适用场景 | `applicable_scenes` | `String` | 否 | 逗号分隔存储，见 §4.3 |
| 允许跨日 | `allow_cross_day` | `Integer` | 否 | 跨日选项，见 §4.4 |
| 是否启用 | `active_flag` | `Boolean` | 是 | 启用标志（`true`=启用 / `false`=停用） |
| 排序号 | `sort_no` | `Integer` | 否 | 列表展示排序 |

> 审计字段（`created_at`/`updated_at`/`created_by`/`updated_by`）、租户字段（`tenant_id`）、并发戳（`concurrency_stamp`）继承自 `BaseAuditedEntity`，遵循统一约定。

## 4. 值对象（含枚举）

### 4.1 周期类型（FrequencyCycleType）

| 枚举值 | 英文 | 说明 | 示例 |
|---|---|---|---|
| 日周期 | `daily` | 按天重复 | QD（每日一次）、BID（每日两次） |
| 周周期 | `weekly` | 按周重复 | QW（每周一次）、BIW（每周两次） |
| 间隔周期 | `interval` | 按固定间隔 | Q8H（每8小时一次）、QOD（隔日一次） |
| 必要时 | `as-needed` | 按需执行，无固定周期 | PRN（必要时） |
| 固定次数 | `fixed-count` | 总执行次数固定 | ST（立即一次）、STAT |

### 4.2 周期单位（PeriodUnit）

| 枚举值 | 英文 | 说明 |
|---|---|---|
| 分钟 | `min` | 每N分钟 |
| 小时 | `h` | 每N小时 |
| 天 | `d` | 每N天 |
| 周 | `wk` | 每N周 |
| 月 | `mo` | 每N月 |

> **FHIR 对齐**：对应 FHIR R5 `Timing.repeat.periodUnit`（`s` / `min` / `h` / `d` / `wk` / `mo` / `a`）。

### 4.3 适用场景（ApplicableScene）

| 枚举值 | 英文 | 说明 |
|---|---|---|
| 门诊 | `outpatient` | 门诊医嘱可引用 |
| 住院 | `inpatient` | 住院医嘱可引用 |
| 护理 | `nursing` | 护理计划可引用 |
| 全部 | `all` | 不限制场景 |

### 4.4 跨日选项（AllowCrossDay）

| 枚举值 | 英文 | 说明 |
|---|---|---|
| 不允许跨日 | `same-day` | 执行时点必须在当日内 |
| 允许跨日 | `cross-day` | 执行时点可跨越自然日（如 Q8H 夜间执行） |
| 按班次 | `by-shift` | 执行时点按护理班次划分 |

### 4.5 频次状态（FrequencyStatus）

见 §2.3 状态定义中的枚举表。

## 5. 领域事件

### 5.1 事件定义

| 事件名称 | 英文名称 | 触发时机 | 携带数据 | 消费方 |
|---|---|---|---|---|
| 频次已创建 | `FrequencyCreatedEvent` | 新增频次定义成功 | 频次标识, 频次编码, 频次名称, 周期类型 | QueryService/缓存、审计（若基础设施启用事件总线；早期版本 §6 为「无事件」，此处为评审补齐后的目标态） |
| 频次已修改 | `FrequencyModifiedEvent` | 频次属性修改成功 | 频次标识, 修改字段列表 | QueryService/缓存、审计 |
| 频次已启用 | `FrequencyActivatedEvent` | 频次从停用恢复为启用 | 频次标识, 频次编码 | QueryService/缓存 |
| 频次已停用 | `FrequencyDeactivatedEvent` | 频次被停用 | 频次标识, 频次编码, 停用原因 | QueryService/缓存、引用方预警 |
| 频次已删除 | `FrequencyDeletedEvent` | 频次被删除 | 频次标识, 频次编码 | QueryService/缓存、审计 |

> **设计说明**：原文档标注"当前未发布事件"。按评审要求（每个状态变更至少 1 个事件），本次补齐完整生命周期事件。下游如医嘱执行缓存、频次下拉缓存可订阅 `FrequencyModifiedEvent` / `FrequencyDeactivatedEvent` 刷新本地缓存。

### 5.2 事件触发规则

| 当前状态 | 操作 | 目标状态 | 发布事件 |
|---|---|---|---|
| — | 创建频次 | 启用 | `FrequencyCreatedEvent` |
| 启用 | 修改属性 | 启用 | `FrequencyModifiedEvent` |
| 启用 | 停用 | 已停用 | `FrequencyDeactivatedEvent` |
| 已停用 | 恢复 | 启用 | `FrequencyActivatedEvent` |
| 启用/已停用 | 删除 | — | `FrequencyDeletedEvent` |

## 6. 领域服务

### 6.1 写侧领域服务（FrequencyDomainService）

> 写侧由应用层定界事务；删除前医嘱引用校验由应用层编排（BR-FRQ-009）。

#### 6.1.1 新增频次（`createFrequency`）

- **业务意义**：定义可复用的用药/执行频次主数据，供医嘱开立与执行计划展开引用。
- **边界说明**：不写医嘱执行事实；PRN 等类型不生成固定时点（BR-FRQ-008）。
- **入参**：频次名称、可选频次编码、周期类型、日执行时点、执行周期、周期单位、适用场景等。
- **出参**：频次标识。
- **前置条件**：BR-FRQ-001 名称非空；BR-FRQ-002 编码若填则全局唯一；日时点格式合法（BR-FRQ-007）。
- **状态变化**：初始化为启用（以落库与交互契约为准）。
- **聚合内影响**：插入频次主表行。
- **事件输出**：`FrequencyCreatedEvent`。
- **失败语义**：唯一冲突、格式非法时拒绝。

#### 6.1.2 修改频次（`modifyFrequency`）

- **业务意义**：调整周期、日时点、适用场景等可变属性，与临床路径变更对齐。
- **边界说明**：BR-FRQ-003 频次编码不可改；BR-FRQ-010 并发带版本戳。
- **入参**：频次标识、修改字段 Map。
- **出参**：`—`。
- **前置条件**：频次存在；命令不含编码变更。
- **状态变化**：`N/A`（除显式改状态字段外）。
- **聚合内影响**：部分列更新。
- **事件输出**：`FrequencyModifiedEvent`。
- **失败语义**：版本冲突、非法字段时拒绝。

#### 6.1.3 启用频次（`activateFrequency`）

- **业务意义**：使已停用频次重新可被新开医嘱引用（BR-FRQ-006 解除停用约束）。
- **边界说明**：不自动修复历史医嘱计划。
- **入参**：频次标识。
- **出参**：`—`。
- **前置条件**：当前为已停用。
- **状态变化**：`已停用 -> 启用`。
- **聚合内影响**：更新状态。
- **事件输出**：`FrequencyActivatedEvent`。
- **失败语义**：状态非法时拒绝。

#### 6.1.4 停用频次（`deactivateFrequency`）

- **业务意义**：阻断新开医嘱引用该频次，保留历史执行口径。
- **边界说明**：BR-FRQ-006 已停用不可开新医嘱；停用原因用于审计（以落库与交互契约为准）。
- **入参**：频次标识、停用原因。
- **出参**：`—`。
- **前置条件**：当前为启用。
- **状态变化**：`启用 -> 已停用`。
- **聚合内影响**：更新状态。
- **事件输出**：`FrequencyDeactivatedEvent`。
- **失败语义**：仍有策略禁止停用的引用时拒绝（若应用层未前置拦截）。

#### 6.1.5 删除频次（`deleteFrequency`）

- **业务意义**：在引用安全前提下移除频次定义，清理测试或错误配置。
- **边界说明**：BR-FRQ-009 引用评估由应用层编排；物理/逻辑删除以产品策略为准。
- **入参**：频次标识。
- **出参**：`—`。
- **前置条件**：无在执行中医嘱引用（应用层保证或领域二次校验）。
- **状态变化**：行删除或标记删除。
- **聚合内影响**：物理删除或逻辑删除一行。
- **事件输出**：`FrequencyDeletedEvent`。
- **失败语义**：存在禁止删除的引用时拒绝。

### 6.2 读侧查询服务（FrequencyQueryService）

#### 6.2.1 初始化频次配置页（`initFrequencyConfigPage`）

- **业务意义**：进入维护页时一次性拉取状态下拉、周期类型、适用场景、跨日选项等只读字典投影。
- **边界说明**：可不写 `cus_frequency`；可聚合术语/CodeSystem 读侧（`BR-FRQ-QRY-001`）；属读多写少。
- **查询范围（读库，无写入）**：字典表、术语缓存、或配置中心；**不含**频次主表必填写。
- **过滤口径**：租户、可见字典项。
- **组装规则**：组合为页面初始化 DTO。
- **返回约束**：不创建频次行。

#### 6.2.2 分页查询频次（`pageFrequencies`）

- **业务意义**：维护列表按名称、编码、状态分页检索频次主数据。
- **边界说明**：只读；`BR-FRQ-QRY-002` 租户隔离。
- **查询范围（读库，无写入）**：`cus_frequency`（或等价表）。
- **过滤口径**：名称模糊、编码精确/模糊、状态、租户。
- **组装规则**：分页 DTO；默认排序以落库与交互契约为准。
- **返回约束**：不返回执行展开结果。

#### 6.2.3 计算执行时间点（`computeExecutionTimePoints`）

- **业务意义**：基于频次定义与医嘱生效时间窗，展开离散执行时刻供护士站执行计划展示。
- **边界说明**：**纯计算、只读、不写库**（`BR-FRQ-QRY-003`）；不修改频次主数据与医嘱聚合；与住院护士站 IF-OEX-01 事务约定一致。
- **查询范围（读库，无写入）**：读频次定义（按编码或 id）；无表写入。
- **过滤口径**：BR-FRQ-004 仅保留满足 `startTime ≤ 时刻 ≤ endTime` 的候选；BR-FRQ-005 若 `endTime ≤ startTime` 则直接返回空集；BR-FRQ-008 PRN 不展开。
- **组装规则**：按周期类型、日时点、间隔生成有序时间点列表；算法步骤见 **§9.1**。
- **返回约束**：只读列表；不持久化计划行（计划持久化属他域/应用层）。

### 6.3 领域边界说明

- 频次聚合维护主数据与状态；**医嘱 MedicationRequest / 执行事实**由他域编排，删除与停用前的引用检查由应用层协同（BR-FRQ-009）。
- `computeExecutionTimePoints` 仅属读侧计算能力，禁止误入写侧领域服务契约（避免与写库事务混淆）。
- `initFrequencyConfigPage` 仅组装字典/术语等**只读投影**，不创建频次行、不承担页面路由与权限；若产品将初始化收口到应用层/BFF，以本稿约定为准。
- 初始化与分页查询为只读或读多写少（`BR-FRQ-QRY-001`/`002`）；术语缓存策略见本稿 **§6.1**。

## 7. 不变式

| 编号 | 不变式 | 说明 |
|---|---|---|
| BR-FRQ-001 | 频次名称不允许为空 | 每个频次必须有可辨识的名称 |
| BR-FRQ-002 | 频次编码若填写则全局唯一 | 确保业务侧引用编码的稳定性 |
| BR-FRQ-003 | 频次编码不允许通过修改操作变更（须删除后重建） | 身份键不可变，保障下游引用一致性 |
| BR-FRQ-004 | 执行时间点计算的任一时刻不早于开始时间、不晚于结束时间 | 时间边界约束 |
| BR-FRQ-005 | 结束时间 ≤ 开始时间时，展开结果为空集 | 退化场景保护 |
| BR-FRQ-006 | 已停用的频次不可被新开医嘱引用 | 引用一致性 |
| BR-FRQ-007 | 日执行时点格式须为合法时间序列（HH:mm 逗号分隔） | 数据格式约束 |
| BR-FRQ-008 | 周期类型为"必要时"（PRN）时，不生成固定执行时间点 | PRN 不展开 |
| BR-FRQ-009 | 删除前须评估是否被在执行中的医嘱引用 | 引用完整性保护（应用层编排） |
| BR-FRQ-010 | 并发更新须带版本戳（concurrencyStamp） | 并发一致性 |
| BR-FRQ-QRY-001 | 初始化与列表为只读或读多写少 | 与术语缓存策略见本稿 **§6.1** |
| BR-FRQ-QRY-002 | 分页过滤须带租户（若多租户） | 与仓储约定一致 |

## 9. 补充

### 9.1 执行时间点展开算法说明

> **契约归属**：下列步骤描述读侧查询服务 **`FrequencyQueryService.computeExecutionTimePoints`**（**§6.2.3**）的计算语义。该方法为**读侧领域方法**：在内存中完成时点展开，**不写库**、不修改频次主数据与医嘱聚合（**BR-FRQ-QRY-003**；与 **§7** 不变式一致）。执行计划行的持久化由他域或应用层编排，不在本方法契约内。

#### 输入

| 项 | 说明 |
|---|---|
| 频次定位 | `rateCode`（如 `TID`）或等价频次标识，用于加载 **§3.1** 启用态频次定义（含 `day_times`、`cycle_type`、间隔/周规则、`total_execution_count` 等） |
| 生效时间窗 | `startTime`：医嘱或执行计划开始生效时刻；`endTime`：结束生效时刻 |
| 可选上下文 | `context`：班次、工作日历、机构时区等；用于日内时点映射、首日/首剂规则、节假日顺延或跳过等（是否启用以产品策略为准） |

#### 处理

1. **加载定义**：按 `rateCode`（或频次标识）读取频次行；须满足启用态及 **BR-FRQ-007**（`day_times` 格式合法）；未命中或已停用则按 **§6.2.3** 失败语义拒绝或返回空集（与实现约定择一，须在服务契约上统一）。
2. **按周期类型展开**（与 **§4.1** 语义一致；**实现须完全读频次表字段，禁止写死魔法数**）：
   - **日周期 / 间隔周期的「天」维度**：自 `startTime` 所在日历日起，按 **`day_interval` → `day_count` → `execution_period`（单位 d）** 优先级解析**日历日步进**（缺省 1）；对每个执行日将 `day_times` 时刻与日期组合为候选时点；**隔日 QOD = `day_interval=2`；隔两日 = `day_interval=3`**；
   - **短间隔周期（min/h）**：当 `execution_period_unit` 为 min/h 时，自 `startTime` 起按 `execution_period` 累加生成候选时点（可与 `day_times` 组合策略以主数据为准）；
   - **周周期**：按 `execution_period`（单位 wk，缺省 1 周）步进，日内时刻取自 `day_times`；
   - **必要时（PRN）**：**不预生成**固定时点，直接得到空候选集（**BR-FRQ-008**）；
   - **固定总次数**：在候选生成过程中累计执行次数，达到 `total_execution_count` 即停止继续生成。
3. **裁剪**：剔除 **`moment < startTime`** 或 **`moment > endTime`** 的候选时点（**BR-FRQ-004**）。若 **`endTime ≤ startTime`**，跳过展开，**直接返回空集**（**BR-FRQ-005**）。
4. **可选叠加**：在候选序列上应用班次映射、首日特殊规则、节假日跳过或顺延等；依赖 `context` 与产品规则，不改变本方法「纯计算、不写库」边界。

#### 输出

- **升序、去重**后的离散执行时间点序列（领域上为只读列表）；类型以实现侧日期时间模型为准，不在本 DM 绑定具体语言类型名。

#### 约束（与不变式对应）

- **纯计算、不写库**（**BR-FRQ-QRY-003**）。
- **`endTime ≤ startTime` → 空集**（**BR-FRQ-005**）。
- **PRN → 不预生成时点（空集）**（**BR-FRQ-008**）。
