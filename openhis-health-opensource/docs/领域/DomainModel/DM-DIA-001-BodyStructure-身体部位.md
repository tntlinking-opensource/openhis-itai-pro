# DM-DIA-001 BodyStructure 身体部位

> **限界上下文**：DIA域 · 身体部位目录  
> **聚合类型**：单表聚合  
> **版本**：v1.0.3 · **日期**：2026-08-02

---

## 1. 概述

### 1.1 业务定义

身体部位（BodyStructure）是全院共享的解剖部位主数据，用于在诊断、检查、手术、护理等场景中提供标准化部位选择。本聚合维护部位层级编码、名称、发布状态及检索码，为跨域引用提供稳定标识。

### 1.2 核心职责

| 职责 | 说明 |
|---|---|
| 部位目录维护 | 维护部位编码、名称、状态 |
| 检索支持 | 自动维护拼音码、五笔码 |
| 层级组织 | 基于业务编码的层级组织部位树 |
| 生命周期控制 | 启用、停用、逻辑删除部位记录 |

### 1.3 适用范围

| 场景 | 说明 |
|---|---|
| 诊断部位选择 | 录入诊断时选择标准化身体部位 |
| 检查申请 | 检查类服务申请绑定部位 |
| 手术与操作 | 手术、操作记录引用部位 |
| 护理评估 | 护理文书与评估中的部位标注 |

### 1.4 与关键上下游及交换边界的关系

身体部位目录的上游主要为采番服务（生成层级 `bus_no`）；下游为诊断、操作、服务申请、观测定义等通过 **身体部位标识** 与 **业务编码** 只读引用。本聚合不承载患者个体化解剖或影像轮廓。

| 维度 | 上游 | 本聚合 | 下游 |
|---|---|---|---|
| 职责 | 采番与编码规则 | 全院部位主数据 | Condition、Procedure、ServiceRequest、ObservationDefinition 等 |
| 引用 | — | `id`、`bus_no` | 跨域仅存标识与编码，不嵌入目录快照 |

## 2. 聚合根与持久化形态

### 2.1 持久化形态

**持久化形态**：单表。

聚合根对应表 `dia_body_structure`，主键 `id`；一行表示一条院内身体部位目录行。

**高频查询模式（建议索引口径）**：按 `bus_no` 层次前缀、`name`/`py_str`/`wb_str`、`status_enum`、租户；树查询按 `bus_no` 稳定排序。

### 2.2 聚合根标识

| 属性 | 类型 | 说明 |
|---|---|---|
| 身体部位标识 | `BodyStructureId`（`Long`） | 主键 |
| 业务编码 | `String` | 层级业务编码，采番与父子拼接生成 |

### 2.3 状态机

```
  [已启用] ──停用──> [已停用] ──重新启用──> [已启用]
      │                    │
      └──删除──> [已删除]   └──删除──> [已删除]
```

#### 状态定义

| value | code | info | 语义 |
| ----- | ---- | ---- | ---- |
| 2 | ACTIVE | 已启用 | 可被新业务引用，允许编辑、停用、删除 |
| 3 | INACTIVE | 已停用 | 不可新引用，历史引用保留，允许重新启用、删除 |
| 4 | DELETED | 已删除 | 逻辑删除终态 | — |

> **状态枚举说明**：持久化字段 `statusEnum` 对齐 `PublicationStatus`（启用/停用语义）；逻辑删除由基类删除标记承载，与状态正交。

## 5. 领域事件

### 5.1 事件定义

| 事件名称（中文） | 英文名称 | 触发时机 | 携带数据 / 最小载荷 | 消费方 |
|---|---|---|---|---|
| 身体部位已创建 | `BodyStructureCreatedEvent` | 新增成功后 | `id`、`busNo`、`name`、`statusEnum`、租户（若有） | QueryService或缓存失效（若启用） |
| 身体部位已修改 | `BodyStructureModifiedEvent` | 编辑成功后 | `id`、变更字段摘要 | 同上 |
| 身体部位已启用 | `BodyStructureActivatedEvent` | 启用成功后 | `id`、`statusEnum` | 同上 |
| 身体部位已停用 | `BodyStructureInactivatedEvent` | 停用成功后 | `id`、`statusEnum` | 同上 |
| 身体部位已删除 | `BodyStructureDeletedEvent` | 删除成功后 | `id` 列表 | 同上 |

### 5.2 事件触发规则

| 当前状态 / 上下文 | 操作 | 目标状态 / 结果 | 发布事件 |
|---|---|---|---|
| — | 新增或编辑（创建） | 启用态行落库 | `BodyStructureCreatedEvent` |
| 已启用 | 新增或编辑（更新字段） | 仍为启用或按入参变更 | `BodyStructureModifiedEvent` |
| 已启用 / 已停用 | 启用（`activeBodyStructure`） | 已启用 | `BodyStructureActivatedEvent` |
| 已启用 | 停用（`inactiveBodyStructure`） | 已停用 | `BodyStructureInactivatedEvent` |
| 已启用 / 已停用 | 逻辑删除（`deleteBodyStructure`） | 已删除（删除标记） | `BodyStructureDeletedEvent` |

> 与 §6.1 写侧方法及 §2.3 状态语义对齐；逻辑删除与 `status_enum` 正交时以落库与交互契约为准。

## 6. 领域服务

### 6.1 写侧领域服务（BodyStructureDomainService）

#### 6.1.1 新增或编辑身体部位（`addOrEditBodyStructure`）

- **业务意义**：维护单条身体部位主数据（新增默认启用，或按 ID 更新已有行）。
- **边界说明**：仅落库 `dia_body_structure`；不级联修改下游诊断/申请已存引用；树形父子关系由业务编码与采番规则约束。
- **入参**：`BodyStructureDto`（含 `id` 或空、`name`、`bus_no` 生成策略由服务内协调采番等）。
- **出参**：操作结果（成功、失败及原因由应用层统一约定）。
- **前置条件**：名称非空（BR-BDS-001）；新增时业务编码符合采番规则（BR-BDS-002）。
- **状态变化**：新增默认 `active`；编辑在启用/停用间按入参与规则变更。
- **聚合内影响**：插入或更新单行；名称变更时重算 `py_str`、`wb_str`（BR-BDS-003）。
- **事件输出**：创建/修改后发布 `BodyStructureCreatedEvent` / `BodyStructureModifiedEvent`（与 §5.1 一致，以落库与交互契约为准）。
- **失败语义**：编码冲突、必填缺失、非法状态时拒绝。

#### 6.1.2 删除身体部位（`deleteBodyStructure`）

- **业务意义**：对一批部位行做逻辑删除，使其不再参与默认选择与树展示（与基类删除标记一致）。
- **边界说明**：仅本表逻辑删除；不物理删除；不追溯删除下游业务事实中的引用字段。
- **入参**：`ids`（批量主键）。
- **出参**：操作结果。
- **前置条件**：目标行存在；删除策略与幂等以落库与交互契约为准。
- **状态变化**：进入逻辑删除终态或等价标记（与 `status_enum` 正交语义以落库与交互契约为准）。
- **聚合内影响**：更新删除标记；可多行。
- **事件输出**：`BodyStructureDeletedEvent`（携带 `id` 列表）。
- **失败语义**：空列表、不存在 ID、约束冲突时拒绝。

#### 6.1.3 启用身体部位（`activeBodyStructure`）

- **业务意义**：将部位行置为可被新业务引用的启用态。
- **边界说明**：仅更新本聚合状态字段。
- **入参**：`id`。
- **出参**：操作结果。
- **前置条件**：目标行存在且未逻辑删除。
- **状态变化**：→ `active`（或等价枚举值）。
- **聚合内影响**：更新 `status_enum`。
- **事件输出**：`BodyStructureActivatedEvent`。
- **失败语义**：不存在或已删除时拒绝。

#### 6.1.4 停用身体部位（`inactiveBodyStructure`）

- **业务意义**：禁止新业务再引用该部位，历史引用保留（BR-BDS-004）。
- **边界说明**：仅本表状态；不通知下游改写历史数据。
- **入参**：`id`。
- **出参**：操作结果。
- **前置条件**：目标行存在。
- **状态变化**：`active` → `inactive`（或等价）。
- **聚合内影响**：更新 `status_enum`。
- **事件输出**：`BodyStructureInactivatedEvent`。
- **失败语义**：不存在、非法迁移时拒绝。

### 6.2 读侧查询服务（BodyStructureQueryService）

#### 6.2.1 查询部位树（`getBodyStructureTree`）

- **业务意义**：为管理端或业务端提供按层级组装的部位树。
- **边界说明**：只读查询，不写库，不做跨域编排。
- **查询范围（读库，无写入）**：`dia_body_structure` 未逻辑删除行（及状态过滤口径以落库与交互契约为准）。
- **过滤口径**：分页条件、关键字等；父节点应先于子节点参与组装（Q-01 约束）。
- **组装规则**：按 `parent_id` 挂载子节点；按 `bus_no` 稳定排序；**排除** `is_deleted=true` 行。
- **返回约束**：森林根节点列表；节点含 `children`；不含非本表大字段。
- **消费方**：管理端上级部位下拉（全状态未删节点）；**IF-DOR-18 / IF-IP-DOR-18** 经 `BodyStructureOptionAssembler` 过滤为仅 **ACTIVE** 的 `OptionDto` 树（节点透出 **`pyStr`/`wbStr`**，供申请单检查行前端模糊过滤）。

#### 6.2.2 查询部位详情（`getBodyStructureInfo`）

- **业务意义**：按主键加载单条部位用于编辑回显或校验。
- **边界说明**：只读查询，不写库，不做跨域编排。
- **查询范围（读库，无写入）**：单行 `id`。
- **过滤口径**：主键精确匹配；排除已删行（若约定）。
- **组装规则**：映射为详情 DTO。
- **返回约束**：单条或空。

#### 6.2.3 查询下拉列表（`getList`）

- **业务意义**：为下拉、检索框提供可选部位列表。
- **边界说明**：只读查询，不写库，不做跨域编排。
- **查询范围（读库，无写入）**：通常仅 `active` 行（以落库与交互契约为准）。
- **过滤口径**：状态、关键字（名称/拼音/五笔）。
- **组装规则**：列表排序稳定（如按 `bus_no`、`id`）。
- **返回约束**：精简列表项（id、name、bus_no 等）。

### 6.3 领域边界说明

- 本聚合定位为身体部位主数据，负责目录生命周期与编码检索语义，不承载患者个体化解剖信息。
- 诊断、执行、申请等业务仅通过标识与业务编码引用，不在本聚合内维护下游业务状态。
- 树结构组装与页面初始化属于应用层编排，领域层聚焦主数据规则。
- **管理端维护页**：列表以**树形表格**展示层级关系；读侧仍调用 `getBodyList` 获取平面数据，前端按 `parentId` 组树并按 `bus_no` 排序；关键词检索时保留命中节点及其祖先路径，避免子节点孤立展示。
- **申请单检查行**：医生站 **IF-DOR-18** 的 `bodyStructureOptions` 由后端返回 **OptionDto 树**（仅 **ACTIVE** 节点，停用子节点上提；含拼音/五笔）；前端使用树形多选下拉，并按名称/业务编码/拼音/五笔做客户端模糊过滤。

## 7. 不变式

| 编号 | 不变式 | 说明 |
|---|---|---|
| BR-BDS-001 | 部位名称不能为空 | 名称必填 |
| BR-BDS-002 | 新增时业务编码必须由采番规则生成 | 禁止手工构造冲突编码 |
| BR-BDS-003 | 名称更新时必须同步重算拼音码与五笔码 | 保证检索一致性 |
| BR-BDS-004 | 停用记录不应用于新业务选择 | 控制引用范围 |
