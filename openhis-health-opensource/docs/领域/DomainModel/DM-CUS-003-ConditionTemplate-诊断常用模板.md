# DM-CUS-003 ConditionTemplate 诊断常用模板

> **限界上下文**：本地扩展 · 诊断模板管理\
> **聚合类型**：实体聚合（单表配置型）\
> **版本**：v1.0.1 · **日期**：2026-05-28

## 1. 概述

### 1.1 业务定义

诊断常用模板（ConditionTemplate）定义了**诊断定义与归属对象（医生个人/科室/全院）之间的模板化绑定关系**。它回答的核心业务问题是："**医生最常使用哪些诊断？如何按个人习惯、科室特色或全院共识快速选择预定义诊断组合？**"——在门诊/住院接诊环节，系统据此构建常用诊断候选列表，医生无需每次从全量目录中逐一检索，显著提升诊断选择效率。

诊断常用模板是**诊断定义（ConditionDefinition）的下游消费方**，属于配置型辅助数据；仅管理「诊断定义与归属对象的绑定关系」，不维护诊断定义主数据，不创建患者诊断记录。本文档编码为 `DM-CUS-003`，无 FHIR 标准资源映射；对外交换时诊断事实体现在 `Condition` 中，模板绑定关系不对外暴露。**ConditionDefinition** 为目录侧主数据，**ConditionTemplate** 为绑定配置，**Condition** 为患者诊断事实。

### 1.2 核心职责

| 职责 | 说明 |
|---|---|
| 常用诊断绑定 | 将诊断定义绑定到归属对象（医生个人/科室/全院），形成可复用的常用诊断集合 |
| 多层级模板管理 | 支持个人模板、科室模板、全院模板三级模板体系，覆盖不同粒度的诊断偏好 |
| 快速选择支撑 | 为医生站提供按归属层级聚合的常用诊断候选列表，替代全量检索 |
| 绑定唯一性保护 | 同一归属对象下同一诊断定义不允许重复绑定，保证模板集合无冗余 |
| 模板生命周期维护 | 支持模板行的新增、删除与分页查询，以逻辑删除控制模板可见性 |

### 1.3 适用范围

| 类型 | 说明 |
|---|---|
| 医生快速开立诊断 | 门诊/住院接诊时，医生从个人常用诊断列表中快速选择诊断，无需逐一检索全量目录 |
| 科室诊断模板维护 | 科室管理者维护本科室的常见诊断集合，新入科医生可直接使用科室模板 |
| 全院通用模板维护 | 管理员维护全院级别的高频诊断集合，适用于全科等跨专科场景 |
| 个人诊断习惯积累 | 医生在日常诊疗中将高频使用的诊断加入个人模板，逐步积累个性化诊断集合 |
| 模板批量管理 | 管理端对模板行进行分页浏览、按绑定类型与诊断名称筛选 |

### 1.4 与关键上下游及交换边界的关系

模板行引用诊断定义（ConditionDefinition）作为「可选项」锚点；归属对象可为医生账号、科室或机构（由绑定类型与 `object_id` 语义表达）。接诊创建诊断事实（Condition）时读取模板列表，**不在本聚合内**修改诊断定义或诊断记录。

| 维度 | 上游 | 本聚合 | 下游 |
|---|---|---|---|
| 职责 | 诊断目录主数据 | 常用项绑定与排序 | Condition 开立时消费模板 |
| 引用 | `definition_id` | `ConditionTemplateId` | 应用层合并多层级模板后展示 |

## 2. 聚合根与持久化形态

### 2.1 持久化形态

**持久化形态**：单表。

聚合根对应表 `cus_condition_template`，主键 `id`；一行表示一条「归属对象 × 诊断定义 × 绑定类型」绑定。

**高频查询模式（建议索引口径）**：按 `(object_id, binding_enum)`、`definition_id`；唯一约束 `ux_cus_condition_template_natural(object_id, definition_id, binding_enum)`；合并列表按绑定类型分三次查询或单次优化查询。

### 2.2 聚合根标识

| 属性 | 类型 | 说明 |
|---|---|---|
| 诊断模板标识 | `ConditionTemplateId` | 系统内部唯一标识（雪花 ID） |

### 2.3 状态机

> 本聚合为配置型绑定关系，不抽取独立迁移状态机；模板行以「存在 / 逻辑删除」表达生命周期。

| 状态 | 说明 |
|---|---|
| 有效 | 模板行存在且 `deleted = false`，参与常用诊断候选查询 |
| 已删除 | 模板行被逻辑删除（`deleted = true`），不出现在默认查询结果中 |

> 与 CUS-001（执行科室）的差异：执行科室为**时段 + 优先级**下的执行位置规则（单表软删表达失效）；诊断模板为**归属对象 × 诊断定义**绑定（逻辑删除表达解绑），二者业务语义不同，勿混用生命周期表述。

## 3. 实体

```text
ConditionTemplate（聚合根，单表配置）
════════════════════════════════════════════════════════════

  ┌──────────────────────────────────────────────────────┐
  │  objectId + definitionId + bindingEnum / sortWeight │
  └──────────────────────────────────────────────────────┘
```

### 3.1 诊断常用模板（ConditionTemplate）

ConditionTemplate 聚合根的属性定义，对应 `cus_condition_template` 表；唯一索引 `ux_cus_condition_template_natural(object_id, definition_id, binding_enum)`。

| 属性 | 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 模板标识 | `id` | `Long` | 是 | 主键，雪花 ID |
| 归属对象标识 | `object_id` | `Long` | 是 | 绑定目标：个人模板取当前账号 ID；科室模板取科室/机构 ID；全院模板取顶层机构 ID |
| 诊断定义标识 | `definition_id` | `Long` | 是 | 关联的诊断定义聚合根 ID |
| 绑定类型 | `binding_enum` | `Integer` 或 **String**（`ConditionTemplateBinding` 语义） | 是 | 见 §4.1，标识模板层级（个人/科室/全院）；**当前 `zxplat` 落库为枚举 `getCode()` 大写字符串**（如 `PERSONAL`、`DEPARTMENT`），与 §4.1 表内小写 `code` 列为同一语义的不同持久化风格，以迁移/种子数据为准 |
| 排序权重 | `sort_weight` | `Integer` | 否 | 同层内展示顺序，默认 `0` |
| 备注 | `remark` | `String` | 否 | 可空 |

> **审计字段**：`created_at / updated_at / created_by / updated_by / deleted / tenant_id` 继承自 `BaseAuditedEntity`，不在属性表中重复列出。

### 3.2 子实体

> 本聚合为单表配置模型，无聚合内子实体。若需支持「模板行附带默认诊断参数」，可引入 `ConditionTemplateOption` 内部实体（架构以本稿约定为准）。

## 4. 值对象

### 4.1 模板绑定类型（`ConditionTemplateBinding` → `bindingEnum`）

| value | code | info | 语义说明 |
|---|---|---|---|
| 1 | `personal` | 个人模板 | `objectId` 为医生账号 ID |
| 2 | `department` | 科室模板 | `objectId` 为科室/机构 ID |
| 3 | `hospital` | 全院模板 | `objectId` 为顶层机构 ID |

### 4.2 模板可见性优先级（隐含规则）

模板展示时按归属层级有序聚合，优先级从高到低：

| 优先级 | 层级 | 说明 |
|---|---|---|
| 1（最高） | 个人模板 | 医生个人积累的常用诊断，最贴合个体临床习惯 |
| 2 | 科室模板 | 科室级别的常见诊断集合，体现专科特色 |
| 3（最低） | 全院模板 | 全院通用高频诊断，适用于跨专科场景 |

> 同层级内按 `排序权重` 升序、`id` 升序排列。

### 4.3 术语表

| 名词 | 定义 |
|---|---|
| 归属对象 | 模板行绑定的目标，由 `objectId` + `bindingEnum` 联合确定语义 |
| 诊断模板 / 诊断套餐 | 某归属对象下的全部模板行集合，构成该对象的常用诊断列表 |
| 模板行 | 一条 ConditionTemplate 记录，表达"某对象绑定了某诊断定义"这一事实 |

## 5. 领域事件

### 5.1 事件定义

| 事件名称 | 英文名称 | 触发时机 | 携带数据 / 最小载荷 | 消费方 |
|---|---|---|---|---|
| 诊断模板已创建 | `ConditionTemplateCreatedEvent` | 绑定导致新增模板行成功 | `templateId`、`definitionId`、`objectId`、`bindingEnum` | 临床接诊编排、缓存（可选） |
| 诊断模板已删除 | `ConditionTemplateDeletedEvent` | 解绑导致模板行逻辑删除 | `templateId`、`definitionId` | 临床接诊编排、缓存（可选） |
| 诊断模板批量已创建 | `ConditionTemplateBatchCreatedEvent` | 多行绑定且合并为单次通知时（可选） | `templateIds[]`、归属键 | 同上 |
| 诊断模板批量已删除 | `ConditionTemplateBatchDeletedEvent` | 多行解绑且合并为单次通知时（可选） | `templateIds[]` | 同上 |

### 5.2 事件触发规则

| 操作 | 发布事件 |
|---|---|
| 绑定（`bindConditionTemplate`） | `ConditionTemplateCreatedEvent` 与/或 `ConditionTemplateBatchCreatedEvent` |
| 解绑（`unbindConditionTemplate`） | `ConditionTemplateDeletedEvent` 与/或 `ConditionTemplateBatchDeletedEvent` |
| 调整排序（`adjustSortWeight`） | 无强制领域事件（若后续补充以本稿约定为准） |

## 6. 领域服务

### 6.1 写侧领域服务（ConditionTemplateDomainService）

> 写侧由应用服务编排事务后调用领域服务完成；写侧方法不使用 `@Transactional`，由应用层定界。

#### 6.1.1 绑定诊断模板（`bindConditionTemplate`）

- **业务意义**：为指定归属对象（个人/科室/全院）挂接常用诊断定义，形成接诊时可点选的模板行；**不区分单条与多条**——同一绑定契约既可提交**一个**诊断定义，也可一次提交**多个**（诊断定义标识列表长度为 1 即单条）。
- **边界说明**：不创建或修改 `ConditionDefinition`；不写就诊事实 `Condition`；仅维护本表绑定关系；多定义时**逐条**受 BR-CTL-001～003/005 等约束；单条失败是否阻断其余条由 BR-CTL-010 与 本稿业务约定；不在此接口内做跨域诊断主数据创建。
- **入参**：归属对象标识、绑定类型；**一个或多个**诊断定义标识（列表或单值封装，以落库与交互契约为准）；逐行可选的排序权重或与多行共用的默认权重策略（以落库与交互契约为准）。
- **出参**：新建诊断模板标识（单条时）；或成功标识列表与失败清单（多条时，结构以本稿约定为准）。
- **前置条件**：对**每一条**待插入行：BR-CTL-001/002/003/005；已绑定条目可跳过（幂等，以落库与交互契约为准）。
- **状态变化**：`N/A`（新建一行或多行有效行）。
- **聚合内影响**：插入**一行或多行**模板主数据。
- **事件输出**：每条成功可发 `ConditionTemplateCreatedEvent`，或整批一次 `ConditionTemplateBatchCreatedEvent`（与 §5.1 发布策略二选一，以落库与交互契约为准）。
- **失败语义**：唯一冲突、引用无效、命令校验失败时拒绝该行或按 BR-CTL-010 记录失败并继续其余条目。

#### 6.1.2 解绑诊断模板（`unbindConditionTemplate`）

- **业务意义**：逻辑删除模板行，使其不再出现在默认候选列表，保留历史与审计；**不区分单条与多条**——同一解绑契约既可传入**一个**模板行标识，也可一次传入**多个**（列表长度为 1 即单条）。
- **边界说明**：逻辑删除不可逆（BR-CTL-007）；不级联删除诊断定义；多行时逐条复用解绑前置与幂等规则。
- **入参**：诊断模板标识（单条）或诊断模板标识**列表**（多条，以落库与交互契约为准）。
- **出参**：`—`；或多条时的成功数量与失败清单（以落库与交互契约为准）。
- **前置条件**：对**每一行**：BR-CTL-004 存在且未删除；已删除行幂等跳过或计成功（以落库与交互契约为准）。
- **状态变化**：一行或多行 `有效 -> 已逻辑删除（deleted）`。
- **聚合内影响**：将对应一行或多行标记 `deleted=true`。
- **事件输出**：每行首次成功删除发 `ConditionTemplateDeletedEvent`，或整批一次 `ConditionTemplateBatchDeletedEvent`（与 §5.1 发布策略二选一，以落库与交互契约为准）。
- **失败语义**：部分失败时返回失败清单（BR-CTL-010）；标识不存在策略以落库与交互契约为准。

#### 6.1.3 调整排序权重（`adjustSortWeight`）

- **业务意义**：在同层级内调整模板行展示顺序，使高频诊断靠前。
- **边界说明**：不改变诊断定义绑定关系；§5 未单列排序事件时以本稿与实现为准（可能无领域事件或合并为通用编辑事件）。
- **入参**：诊断模板标识、新排序权重。
- **出参**：`—`。
- **前置条件**：BR-CTL-004；BR-CTL-008 权重为非负整数。
- **状态变化**：`N/A`（属性更新）。
- **聚合内影响**：更新排序字段。
- **事件输出**：`N/A`（若后续补充 `ConditionTemplateSortAdjustedEvent` 等以本稿约定为准）。
- **失败语义**：行不存在、权重非法时拒绝。

### 6.2 读侧查询服务（ConditionTemplateQueryService）

#### 6.2.1 分页查询模板行（`pageConditionTemplates`）

- **业务意义**：管理端或配置页按条件分页检索模板行，支撑维护与审计。
- **边界说明**：只读查询，不写库，不做跨域编排；诊断名称、对象展示名 join 由应用层扩展（`BR-CTL-QRY-001`）。
- **查询范围（读库，无写入）**：`cus_condition_template`（或等价表名）有效行。
- **过滤口径**：绑定类型、诊断名称关键字、租户、仅未删除。
- **组装规则**：分页 DTO；排序以产品约定为准。
- **返回约束**：不保证含诊断定义全文；停用/废弃定义的状态提示由应用层结合他域数据装配（BR-CTL-006）。

#### 6.2.2 按归属与类型列模板（`listByOwnerAndType`）

- **业务意义**：医生站按当前医生/科室上下文加载候选常用诊断列表。
- **边界说明**：只读；不执行三层合并（见下条）。
- **查询范围（读库，无写入）**：本表；`objectId` + `bindingEnum` 定位。
- **过滤口径**：未删除；可按租户隔离。
- **组装规则**：按排序权重升序、`id` 升序稳定输出。
- **返回约束**：列表体量受归属范围限制；大数据量时由应用层缓存或分页策略补强。
- **门诊医生站落地（IF-DOR-06A，`AS-OP-DOR-002` / `AS-OP-DOR-002-SDD`）**：应用层通常**并行四次**调用本方法（病人历史分支走 `Condition` 事实扫描，不经本方法）：① 医生常用：`objectId` = 当前医师主键，`bindingEnum` = `PERSONAL`（与实现一致，以医师维度解释「个人高频」）；② 用户个人：`objectId` = 当前用户 id，`bindingEnum` = `PERSONAL`；③ 科室：`objectId` = 当前科室 id，`bindingEnum` = `DEPARTMENT`（对齐 §4.1 `department` 语义）。诊断名称/来源展示由应用层再调 `ConditionDefinitionQueryService#listActiveDoctorStationRowsByIds` 装配（见 `DM-CLN-002` §6.2.7）。

#### 6.2.3 合并三级模板（`listMergedTemplates`）

- **业务意义**：接诊界面一次性合并个人→科室→全院模板并去重，贴合临床使用路径。
- **边界说明**：只读；合并优先级与去重键以 `BR-CTL-QRY-002` 为准；不修改任何层级源数据。
- **查询范围（读库，无写入）**：多次读：个人、科室、全院各子查询（或单次优化查询）。
- **过滤口径**：各层仅有效行；同诊断定义多来源时按优先级保留一条。
- **组装规则**：层级优先级 + 同层内排序权重；去重键通常为 `definitionId`（以落库与交互契约为准）。
- **返回约束**：返回合并后的只读投影列表；不写回模板表。

### 6.3 领域边界说明

- `ConditionTemplate` 仅维护「归属对象 × 诊断定义 × 绑定类型」绑定行；**ConditionDefinition** 主数据与 **Condition** 事实由他域维护。
- 写编排由 `ConditionTemplateDomainService` 承担；读编排由 `ConditionTemplateQueryService` 承担；诊断名称 join、对象名称展示由应用层扩展（`BR-CTL-QRY-001`）。
- 合并列表按层级优先级聚合（`BR-CTL-QRY-002`）；配置列表可直接查写表（`BR-CTL-QRY-003`）。

## 7. 不变式

| 编号 | 不变式 | 约束/落地要点 |
|---|---|---|
| BR-CTL-001 | 模板行必须指定绑定类型与诊断定义标识 | `bindingEnum` / `definitionId` 必填，最小必要信息 |
| BR-CTL-002 | 归属对象标识的语义由绑定类型决定 | 个人模板：`objectId` = 当前登录账号 ID；科室模板：`objectId` = 科室/机构 ID；全院模板：`objectId` = 顶层机构 ID |
| BR-CTL-003 | 同一归属对象下同一诊断定义不允许重复绑定 | `(objectId, definitionId, bindingEnum)` 在有效数据中唯一；库侧 `ux_cus_condition_template_natural` 唯一索引兜底 |
| BR-CTL-004 | 操作的模板行必须存在且未被逻辑删除 | 删除/调序前断言 |
| BR-CTL-005 | 绑定的诊断定义须处于"已发布"状态 | 引用完整性，防止绑定草稿或已废弃的诊断定义 |
| BR-CTL-006 | 诊断定义被停用或废弃不影响既有模板行的历史数据 | 模板行保留，但查询展示时应标记诊断定义状态供前端提示 |
| BR-CTL-007 | 逻辑删除不可逆，已删除模板行不允许恢复 | 如需恢复，应重新创建模板行 |
| BR-CTL-008 | 排序权重须为非负整数 | 防止无效排序值；默认值为 `0` |
| BR-CTL-009 | 已删除模板行不参与默认业务查询 | 仓储方法名含 `IsDeletedFalse`；查询默认按未删除口径 |
| BR-CTL-010 | 一次提交多条款项时部分失败不影响其他条目 | `bindConditionTemplate` / `unbindConditionTemplate` 含多标识时采用逐条处理策略，记录失败原因 |
| BR-CTL-011 | 同一归属层级内按排序权重升序、id 升序有序展示 | 防止无序列表导致不确定行为 |
| BR-CTL-012 | 模板行不维护诊断定义主数据，不创建患者诊断记录 | 聚合职责边界，防止职责蔓延 |

### 7.1 子实体规则

### 9.3 三级模板协作流程

```
医生接诊时的常用诊断快速选择流程：

1. 医生进入诊断开立界面
2. 系统调用 listMergedTemplates(账号ID, 科室ID, 机构ID) 获取合并后的常用诊断列表
3. 后端分别查询个人模板、科室模板、全院模板
4. 医生从常用列表中选择诊断，或切换到全量目录检索
5. 选择后系统创建 Condition（诊断记录），不修改模板本身
```

### 9.5 个人 / 科室 / 全院模板职责边界

| 适用范围 | 仅该医生可见 | 该科室全体医生可见 | 全院医生可见 |
| 典型场景 | 医生个人高频诊断积累 | 专科常见诊断 | 全科等通用高频诊断 |
