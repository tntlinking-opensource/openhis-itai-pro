# 病案首页交付任务清单（4401 + 4101A/4102/4103）

> **目标**：勾完本清单后，住院病案首页可端到端使用，且医保患者可成功完成病案查询侧与老系统一致的医保上报能力：  
> - **【4401】** 住院病案首页信息上传  
> - **【4101A】** 医疗保障基金结算清单上传  
> - **【4102】** 结算清单状态修改（提交/待提交）  
> - **【4103】** 结算清单信息查询  
> **前提**：`application/mrms`、domain/mrms、CHS Extension、表结构骨架已存在；**4401 / 4101A / 4102 / 4103 应用层与 CHS Invoker 已成码**，现场联调验收见 §0 D4～D11、§8.6。  
> **本期必做交易**：`4401` · `4101A` · `4102` · `4103`（对照 `InHosEmrDocList.jsp`）。  
> **上报交互（已定）**：  
> - 入口在 **「病案管理 → 病案首页」列表行操作**（大融合：查患者 / 编辑 / 一键上报）；**废止独立「病案检索」「4401上传」菜单**。  
> - **一键上报** = **4401 → 4101A → 4102 正式提交**（一次点完）；分步结果、可单侧重试；已成功默认跳过；任一步失败分步回显。
> - **4102** 亦保留手动「**提交审核** / **撤回审核**」（同义旧称：正式提交审核 / 撤回为待提交）；一键内已含正式提交，不再另开「上报成功后自动提交」开关。
> - **4103** 仅查询（`psn_no`+`setl_id`；可由病案主键/病案号解析）。
> - **医保管理 → 住院业务上报**（对齐进销存运维）：本地失败/待传补传与流水；**平台查询 4103**；日志含 `infno`。  
> **院内工作流（已定）**：**提交→接收→质控→归档** 状态机**保留且跑通**，但对现场用户 **默认无感知（隐性推进）**——类似发药一键背后跑配药；用户侧体验是「结算后填好就能上报」。**质控工作台 / 借阅复印仍为独立菜单能力**（可先少用，以后显式流程再强化），不是「并进上传」。  
> **上传 Gate（已定）**：对用户暴露条件对齐老系统——**已医保结算 + 首页填好（必填/校验过）** 即可上报；**不要求用户先点归档**。隐性流水线在上报前把内部状态推到可上传等价态（实现细节见下节）。  
> **菜单（已定 v1.8+）**：病案管理 = 病案首页 · 质控工作台 · 借阅复印 · 门诊病历查询 · **住院病例查询**；医保管理追加「住院业务上报」。  
> **不在本期**：借阅业务深做、门诊病案主流程、4402 医嘱、旧版 4101 定时任务、**4104**。
> **已开（2026-09-07）**：卫统 N041 CSV、HQMS CSV 多选导出（`upload.weistat` / `upload.hqms`；国基院点 UI 开关）。详见 [11-卫统N041导出-字段对照.md](./11-卫统N041导出-字段对照.md)、[12-HQMS导出-字段对照.md](./12-HQMS导出-字段对照.md)。

## 上报交互决策（一键 vs 分传）

> **国家侧不强制**「必须先 4401 再 4101A」；二者只共用「已医保结算」。老系统分按钮是为了失败可修、提交可确认。

### 已定产品形态

```text
[病案首页列表 · 操作列]
  病案详情 | 结算清单 | 更多(病历/医嘱/…)

[病案首页列表 · 医保业务列]
  一键上报 | 更多(仅首页/仅结算/提交审核/撤回审核/查询结算…)

[结算清单]  → 独立只读预览页 /mrms/settle-list/:caseRecordId
              诊断/手术双码对照；重症/输血分区预留（空则上传 []；无单独费用页签）
              页内可调 4101A 上传 / 4102 / 4103（复用 upload AppService）

[一键上报]  → 4401 → 4101A → 4102(状态=1 正式提交)
              分步成功/失败回显；可「仅重试首页」「仅重试清单」「仅重试提交」
              已成功侧默认跳过
[提交审核]  → 4102 状态=1（单侧；前端文案，同义旧称「正式提交审核」）
[撤回审核]  → 4102 状态=0（单侧；同义旧称「撤回为待提交」；可再传清单）
[查询结算]  → 4103
```

> 一键已含 4102 正式提交；「更多」里保留单侧提交/撤回，便于失败修补与重传。文案真源：`homepage.constants.ts`。

### 隐性工作流（配药/发药模式）

```text
用户只感知：保存首页 →（已结算）一键上报（4401→4101A→4102 正式提交）
系统内部可自动推进：提交 → 接收 →（可配置跳过或自动过）质控 → 归档/冻结等价态
领域状态机与表结构完整保留 → 以后打开「显式病案室流程」只改 UI/开关，不翻模型
```

实现约束：

- 不上报也允许医生反复保存编辑（对齐现场）。  
- **自动管理病案**：上传**前**不归档不冻结；**4401 成功后**隐性归档冻结，之后不可再改。  
- 点一键上报时：Gate 为 **已结算 + 必填校验**；失败留下可诊断日志；成功侧跳过可重试。  
- 现行代码若写死「必须用户归档才能 4401」→ **改掉**，改为「已结算 + 校验通过」；归档改到上传成功之后。

### 「必须单独报一边」——靠单侧重试即可（不必一级双按钮）

一边字段不齐、一边已成功、或清单已提交后只改首页等场景：用「仅重试首页 / 仅重试清单 / 仅重试提交」处理，不必再做两个一级上传主按钮。

补充已定：

- 一键顺序：**4401 → 4101A → 4102 正式提交**；任一步失败分步回显。  
- 入口：**病案首页列表「医保业务」列**（主按钮一键 + 更多分传）；独立「4401上传」菜单可保留作工作台，但不是唯一入口。

### 第 5 点白话：清单「已提交」后再点一键会怎样？

4101A = 把清单传到平台（常相当于草稿/已上传未提交）。  
4102 = 告诉平台「正式提交审核」。

若某行 **结算清单已经是「已提交」**，用户又点「一键上报」：

| 做法 | 含义 |
|------|------|
| **默认** | 4401 / 4101A / 4102 已成功侧**跳过** |
| 要重传清单 | 先 **「撤回审核」(4102→0)**，再一键或单侧重试 4101A → 4102 |

不是国家规定，是避免已提交清单被误覆盖；与老系统「先上传再提交、提交后用待提交撤回」一致。
