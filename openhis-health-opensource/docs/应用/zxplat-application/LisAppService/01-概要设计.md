## 1. 定位

检验申请 → 标本 → 执行 → 审核 → 报告，覆盖检验科完整业务闭环；与 PEIS/PACS/health 医嘱通过 `ServiceRequest` 衔接。

```text
health（HIS侧）                     zxplat/lis（LIS侧）
──────                              ──────
医生站签发检验医嘱                        │
  │                                      ▼
  │  ServiceRequest × N  ──►  LisWorkItemDomainService.createWorkItem() (INT-01)
  │                                      │
  │                              SpecimenGroupingPolicy（合管分组）
  │                                      │
  │                              LisWorkItem + orderLinks（聚合根创建）
  │                                      │
  │                         ┌────────────┼────────────┐
  │                         ▼            ▼            ▼
  │                    采样工作台    标本管理      危急值
  │                    (SMP)        (SAM+TAT     (CRT)
  │                         │      +TRANS)         │
  │                         ▼            ▼            │
  │                    仪器结果 ingress ──► 结果审核  │
  │                    (RES)            (AUD+AUTO)   │
  │                         │            │           │
  │                         ▼            ▼           │
  │                    报告管理 ◄── 审核发布          │
  │                    (REP+REVISE)      │           │
  │                         │            │           │

                                                     │
```

## 2. 边界

### 2.1 系统边界

| 在 LIS | 不在 LIS（归属） |
|--------|------------------|
| 检验工作站（采样、审核、报告） | PEIS 团检编排（[PeisAppService](../PeisAppService/)） |
| 标本全生命周期（采集→转运→上机→废弃） | PACS 影像 / DICOM（[PacsAppService](../PacsAppService/)） |
| 仪器接口（lis-adapter + collector 采集） | 医嘱开立、签发、收费（health 医生站/收费 AS） |
| 检验结果与报告领域（Observation / DiagnosticReport） | 申请单/采血条码版式打印（PrintTemplate（AS-BAS-PRT）） |
| 危急值告警与闭环 | 患者建档、挂号（health 门诊挂号 AS） |
| 质控（QC 领域模型 + Westgard） | 诊疗/标本主数据维护（health 基础数据） |
| TAT 时效监控与统计 | 框架用户/科室/权限（whale-framework） |
| 试剂批号追溯（轻量） | 全院试剂出入库（HIS 物资系统） |
| 微生物检验（三级报告、菌株、药敏） | 微信/公众号（whale-framework） |
| 传染病 CRB 推送（事件发布，不 import CRB） | |

### 2.2 与 health 的数据边界

| 数据 | 存储位置 | 说明 |
|------|----------|------|
| `Patient` / `Encounter` | health | LIS 只存 `patientId` / `encounterId` 引用 |
| `ServiceRequest` | health | 医嘱事实，LIS 只读 |
| `ActivityDefinition` | health | 全院项目目录；与 LIS 共用 `activity_id`（§10.4，不建 `lis_item_map`） |
| `SpecimenDefinition` | health | 全院标本类型；LIS 扩展 |
| **`LisWorkItem`** | zxplat-domain/lis | 检验工单聚合根，LIS 独有 |
| **`LisWorkItemOrder`** | zxplat-domain/lis | 并管明细，LIS 独有 |
| `DiagnosticReport | zxplat-domain/lis | 报告聚合；发布后 upsert **`cln_diagnostic_report_index`** |
| `Observation` | zxplat-domain/lis | **`lis_observation`**；PEIS 经 CLN 引用，见 §10.2 |
| `Device` + capability | zxplat-domain/lis | 仪器实例与检验能力 |
| `lis_*` 配置表 | zxplat-domain/lis | 合管方案、试管方案、模块参数 |

## 4. 核心业务链路

### 4.1 主链路：接单 → 合管 → 采样 → 上机 → 审核 → 发布

```text
HIS 医生站签发检验
  │
  ▼
LisWorkItemDomainService.createWorkItem() (INT-01)
  │  1. 读 ServiceRequest → ActivityDefinition
  │  2. 解析试管方案、合管方案、仪器能力（lis_* 配置表）
  │  3. SpecimenGroupingPolicy.group() → 若干 LisWorkItem
  │  4. 创建 LisWorkItem + orderLinks；生成 barcode
  │
  ▼
LisWorkItem（待采样 available）
  │
  ▼ 采样工作台 SMP-03 签收
LisWorkItem（已采样 collected）
  │
  ▼ SAM-TRANS 转运 / SAM-02 核收
LisWorkItem（已核收 received）
  │
  ▼ SAM-02 上机
LisWorkItem（上机中 processing）
  │
  ▼ RES-01 仪器结果 ingress
Observation（preliminary，待审）
  │
  ▼ AUD-AUTO 自动审核 / AUD-02 人工审核
Observation（final）+ DiagnosticReport（final）
  │
  ▼ AUD-05 发布回写 health
  ├─ upsert cln_diagnostic_report_index（D2）
  └─ projectFromLis → cln_observation（SR 有 encounterId，DM-CLN-007）
医生站 / 体检分科 / 总检 可读 CLN 事实
```

### 4.2 标本状态机

状态挂在 `LisWorkItem.statusEnum`（及 `LisWorkItemOrder.linkStatusEnum`）：

```text
available（HIS 接单 / 待采样）
  → unsatisfactory（拒收，可重采新建）
  → collected（采样签收）
  → received（检验科核收）
  → processing（上机）
  → … Observation: preliminary（结果待审）
  → … Observation: final + DiagnosticReport: final（已发布）
  → entered-in-error（作废）
```

### 4.3 并管链路

N 个 `ServiceRequest` → 1 个 `LisWorkItem`，通过 `LisWorkItemOrder` 解耦：

```text
SR 血常规 ──┐
SR 肝功   ──┼──► LisWorkItem（barcode=xxx, tubeScheme=黄帽血清）
SR 血糖   ──┘       ├─ orderLink(SR血常规)
                     ├─ orderLink(SR肝功)
                     └─ orderLink(SR血糖)
```

### 4.4 TAT 时效监控链路

```text
LisWorkItem 各状态变更
  │
  ▼
自动记录 statusUpdatedAt: Map<StatusEnum, Instant>
  │
  ▼
TAT 定时评估（调度 / 状态变更触发）
  │  读 lis_config.tat.* 超时阈值
  │  计算 elapsed = now - statusUpdatedAt
  │
  ├── 超时 → 预警推送到采样/样本/审核页高亮区域
  │
  └── 完成 → TAT 统计记录（按项目/科室/时段/急诊vs平诊）
```

## 6. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| **LisWorkItem vs ServiceRequest** | 独立聚合根 LisWorkItem | 并管、标本物理态、重采/拒收需独立生命周期；不污染 zxplat-domain |
| **合管策略** | 试管方案 + 仪器能力 + 合管方案 三级约束 | 避免仅按标本类型粗并，以仪器/试管物理约束为真源 |
| **配置存储** | `lis_*` 自有表（不用 framework Setting） | 与仪器能力、试管方案绑定；租户级隔离；可随 Module 独立交付 |
| **FHIR 对齐** | 代码用 zxplat-domain/lis 主键，互操作层 Assembly | 避免两套主键混用；对外导出时按需映射 |
| **1 页面 = 1 AppService** | 21 个页面级 AS | 与 ZXPlat AS-OP-DOR-003 等惯例一致；避免单体 LisAppService |
| **自动审核** | 领域服务 AuditRuleEngine | P1 实现，规则存 lis_config + 参考范围表 |
| **仪器通信** | lis-adapter 独立层 | 协议解析与业务逻辑解耦；HL7/ASTM/HTTP 多种协议可扩展 |
| **微生物** | 独立聚合 MicroIsolate + Observation components | 三级报告、药敏 S/I/R 判读与传统生化为不同模型 |
| **CRB 集成** | 事件驱动（不 import CRB） | LIS 发布 DiagnosticReportFinalizedEvent，CRB 消费 |

## 8. 新增模块设计要点（v2.1）

### 8.1 TAT 时效管理（SAM-TAT）

- **时间戳**：`LisWorkItem.statusUpdatedAt: Map<StatusEnum, Instant>`，状态变更时自动记录
- **阈值配置**：`lis_config` key 格式 `tat.timeout.{项目码}.{科室}.{急诊/平诊}.{阶段}`；支持通配符
- **预警**：推送到采样工作台/样本管理/结果审核页（高亮提醒区域），不建独立页面
- **节假日**：读院点节假日配置表决定是否使用差异化时间窗

### 8.2 标本转运交接（SAM-TRANS）

- **实体**：`LisTransferLog`（源位置、目标位置、操作人、时间、LisWorkItem 列表）
- **送检单**：按病区+标本类型智能分组建议批次
- **签收**：扫码/批量签收，校验标本数量与实际一致，差异告警
- **追溯**：支持按标本/操作人/时间段查询完整交接链

### 8.3 自动审核引擎（AUD-AUTO）

- **引擎**：`AuditRuleEngine`（zxplat-domain/lis 领域服务），规则链顺序执行
- **规则类型**：
  - 参考范围检查（结果在范围内 → 通过）
  - Delta Check（与患者历史值差异 < 阈值 → 通过）
  - 仪器异常标记检查（溶血/脂血/黄疸 → 拦截）
  - 危急值检查（有危急值 → 拦截，走人工审核）
- **审计**：每次自动审核记录（规则ID、放行/拦截、时间戳）

### 8.4 审核分级与双签（AUD-REVIEW）

- **状态扩展**：`LisWorkItemOrder.linkStatusEnum` 增加 `reviewed_level1` / `reviewed_level2`
- **双签项目**：HIV初筛阳性、产前筛查等通过 `lis_config` 配置强制双签项目列表
- **权限委托**：夜班/节假日可配置审核权限委托规则

### 8.5 报告召回与修订（REP-REVISE）

- **版本链**：`Observation.previous` 引用前置版本；`DiagnosticReport.status` = `amended`
- **修订痕迹**：保留 `previousValue → newValue`，附带修订原因和操作人
- **通知**：`DiagnosticReportAmendedEvent` → 触发 CRB-03 更新推送、临床端提醒

### 8.6 微生物检验（MICRO）

- **三级报告**：涂片（partial, 2h）→ 培养鉴定（partial, 24-48h）→ 药敏（final, 48-72h）
- **药敏模型**：在 Observation 中 `components` 扩展，每项抗生素为一个 component（药物码、MIC/KB值、S/I/R判读）
- **菌株**：`MicroIsolate`（isolateNo、specimenId、organismCode、传代记录）

### 8.7 仪器双向通讯（RES-BIDI）

- **worklist 下发**：读 `LisWorkItem` + `orderLinks` 组装仪器指令
- **状态查询**：仪器心跳、故障代码、试剂余量通过 `DeviceMetric` 或扩展字段

### 8.8 试剂批号追溯（RES-REAGENT）

- **轻量设计**：仅存检验科必需批号信息，不实现出入库（归 HIS 物资系统）
- **关联**：`Observation.reagentLotNumber` 字段，质控失控时可按批号追溯

## 10. LIS/PACS/PEIS 跨模块架构约定

> 原独立决策文档 DEC-HEALTH-LPP-001 内容已回归各模块主文档；**LIS 视角全文**见本节，PACS/PEIS 侧见各自 [01-概要设计](../PacsAppService/01-概要设计.md) §7、[PeisAppService/01-概要设计](../PeisAppService/01-概要设计.md) §7。

### 10.1 决策摘要

| # | 议题 | 决策 |

| D1 | Observation 存储 | **分层 + 引用**：`lis_observation` 检验事实；分科/体检写 `cln_observation`；LIS 结果经 `source_observation_id` 引用 |

| D4 | Maven 模块落点 | **全部在 `zxplat` 子包**（`zxplat-domain/*`、`health-application/*`、`*-adapter`、`*-starter`） |

### 10.2 Observation 分层（D1）

```text
health CLN（通用临床事实）
  cln_observation              ← 体检分科小项、体格检查、PEIS 汇总读侧
  cln_observation_definition   ← 小项目录（原 sys_check_item）

lis（检验执行事实）
  lis_observation              ← 仪器/审核后的检验结果（真源）

衔接
  cln_observation.source_observation_id → lis_observation.id（可选）
  cln_observation.service_request_id    → wkf_service_request.id
  lis_observation.service_request_id    → 同上（同一 SR 锚点）
```

| 场景 | 写入 |
|------|------|
| LIS 仪器 ingress / 单条审核 | **仅** `lis_observation` |
| **LIS AUD-05 发布报告** | upsert **`cln_diagnostic_report_index`** + **`LisResultProjectionService#projectFromLis`** → **`cln_observation`**（SR 有 encounterId 时，P0 默认开启） |
| PEIS 诊台补偿刷新（INT-03 / DES-08） | 创建或更新 `cln_observation`，`source_observation_id` → `lis_observation` |
| 分科手工录入 / 常见结果 | **直接** `cln_observation` |
| PACS 检查摘要进体检单 | `cln_observation`（摘要）+ 引用 `pacs_diagnostic_report / DR index |

**禁止**：PEIS 再建平行 `peis_observation` 事实表；禁止 LIS 结果值双写进 `cln_observation` 而不保留 `source_observation_id`。

### 10.3 DiagnosticReport 统一索引（D2）

各模块保留 **报告事实**：LIS `lis_diagnostic_report、PACS `pacs_diagnostic_report、PEIS/health `cln_diagnostic_report。

**索引表** `cln_diagnostic_report_index`（只读聚合）：`module_enum`（LIS/PACS/PEIS/HEALTH）、`source_report_id`、`encounter_id`、`service_request_id`、`status_enum`、`published_at`、展示字段等。

- **写入**：LIS `AUD-05` 发布 / 修订、PACS 报告审核发布、PEIS 总检 `MAS-04` final → upsert index
- **读侧**：医生站、PEIS 总检、CRB、历史报告 **优先查 index**，再穿透模块 DR 明细

### 10.4 项目对照 — 一体化无 map（D3）

- health / LIS / PACS / PEIS **共用 `ActivityDefinition.id`（`activity_id`）**；**不**在 zxplat-domain 维护 `lis_item_map` / `pacs_item_map`
- **LIS 接单真源**：`lis_device_capability` + `lis_device_channel` + `lis_tube_scheme` / `lis_merge_profile`（见 [04-FHIR §2.3](./04-FHIR领域模型.md)）
- **LIS BR-INT-06**：每个 `activity_id` 须在 **`lis_device_capability`** 至少一条在用配置；缺失拒绝整批
- **废止**：health 侧 `lis_item_map`、**CFG-07** mapping IF（`searchMapping` 等）一体化 **不实现**；adapter 院点对照仅在 **lis-adapter** 内
- **AD↔小项 OD**：`cus_activity_observation_link`（[DM-CUS-013](./DM-CUS-013-ActivityObservationLink-项目小项绑定.md)）— **`domain.custom`**；PEIS CFG-04 写；AUD-05 投影只读（D10）
- 区域 FHIR 码表 ≠ 院内 AD → 全院 **`TerminologyCodeMapping`**

### 10.5 Maven 落点（D4）

```text
zxplat/
  zxplat-domain/lis|pacs|peis|clinical/
  health-application/lis|pacs|peis/
  lis-adapter/  pacs-adapter/  peis-adapter/
  lis-starter/  pacs-starter/
```

装配：`zxplat.modules.lis|pacs|peis.enabled=true`。PEIS **无** `peis-starter`（见 [Peis 01 §4](../PeisAppService/01-概要设计.md#4-maven)）。废止独立 `whale-pacs` / `whale-peis` Maven 根模块表述。
