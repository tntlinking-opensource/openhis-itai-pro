## 一、模块定位

### 1.1 是什么

ZXPlat **自研 LIS** 检验科业务；**18 个主页面 AppService**。（INT-01 接单不走独立 AppService，由医生站直接注入 `LisWorkItemDomainService`。）

### 1.2 不是什么

| 不在 LIS | 归属 |
|----------|------|
| 医嘱开立、签发、收费 | health · 医生站/收费 AS |
| 检验/检查 **申请单、采血条码** 版式打印 | PrintTemplate（AS-BAS-PRT） |
| **PACS** 检查影像、Worklist、DICOM | [PacsAppService](../PacsAppService/)（`health-application/pacs`） |
| 患者建档、挂号 | health · 门诊挂号 AS |
| 诊疗/标本 **主数据**（全院目录） | health 基础数据；LIS 维护 **仪器能力/合管**（`lis_device_*`），不建 `lis_item_map` |
| 框架用户/科室/权限 | whale-framework |

### 1.3 领域锚点（FHIR 对齐，详见 [04-FHIR领域模型.md](./04-FHIR领域模型.md)）

| 系统 | 聚合 / FHIR | 职责 |
|------|-------------|------|
| **health** | `Encounter`、`Patient`、`ServiceRequest`、`ChargeItem` | 医嘱意图与收费事实 |
| **health** | `ActivityDefinition`、`SpecimenDefinition` | 项目与标本类型定义 |
| **lis** | **`LisWorkItem`**（聚合根，FHIR↔`Specimen`） | 条码、样本号、标本物理态；**1 管 = 1 工单** |
| **lis** | **`LisWorkItemOrder`**（`orderLinks` 子实体） | 并管：N 个 `ServiceRequest` ↔ 1 个 `LisWorkItem` |
| **lis** | `Task`（可选） | 检验科执行状态机（上机、待审） |
| **lis** | **`Observation`** | 检验结果项（替代 `LisResult`/`LisResultItem`） |
| **lis** | **`DiagnosticReport** | 报告聚合与发布 |
| **lis** | **`Device`** + **`lis_device_capability`** + `lis_device_channel` | 仪器、检验能力、通道 |
| **lis** | **`lis_tube_scheme`** / **`lis_merge_profile`** | 试管方案、合管方案 |
| **lis** | **`lis_config`** | LIS 模块参数（非 framework Setting） |
| **lis** | **`DetectedIssue`** | 危急值告警与闭环（事实在 `Observation.interpretation`） |
| **lis** | `QcMaterial` / `QcRun` / `QcMeasurement` | 质控（≈ `zk*`；测量值可投影为 Observation） |
| **lis** | **`AuditEvent`** | HIS/仪器接口日志（≈ `WBS_LOG`）；仪器遥测用 `DeviceMetric` |

> **合管**：由 `lis_merge_profile` + `lis_device_capability` + `lis_tube_scheme` 驱动，见 [04-FHIR领域模型.md](./04-FHIR领域模型.md) §2.3。

## 二、阶段与优先级

| 阶段 | 目标 | 能否替代遗留 |
|------|------|----------------|
| **P0** | HIS 接单 + 采样签收 + 结果入库 + 审核发布 + 医生站可查报告 + TAT 基础监控 | 替代 `WebService` + `cxt` 主路径 + `dyyl` 审核 |
| **P1** | 危急值 + 仪器通道 + 配置维护 + 接口日志 + 撤单 + 自动审核 + 标本交接 | 替代 `wjz`、`yqtd`、`kdxm` 等 |
| **P2** | 质控全套 + 对账 + 统计分析 + 分级审核 + 报告修订 + 微生物专项 + 试剂追溯 | 替代 `zk*`、`dzgl`、`tjfx`、`XjDyyl` |
| **P3** | 自助机打印、区域平台同步、微信等 | 替代 `echPacs*` 等边缘接口 |

### P0 完工定义（自研 LIS 首版）

- 医生站签发检验 → **内部**创建 `LisWorkItem` + `orderLinks`（分组后）
- 采样台可签收、生成/绑定 **条码**
- 仪器结果可写入（至少 1 种接入方式）
- 检验科可 **审核发布**；医生站 `DM-CLN-006 DiagnosticReportIndex` 或 Lis 报告 API 可打开 PDF/URL
- 撤销：HIS 签退/退费 → LIS 申请作废（或登记 N/A）
- **TAT 基础能力**：各状态节点记录 `updatedAt`，支持超时阈值配置与过期未出报告告警

## 四、标本与执行状态机（对齐遗留 `RECEIVEFLAG`）

状态挂在 **`LisWorkItem.statusEnum`**（及 **`LisWorkItemOrder.linkStatusEnum`**），不写入 `ServiceRequest`：

```text
available（HIS 接单 / 待采样）
  → unsatisfactory（拒收，可重采新建 Specimen）
  → collected（采样签收）
  → received（检验科核收）
  → processing（上机）
  → … Observation: preliminary（结果待审）
  → … Observation: final + DiagnosticReport: final（已发布）
  → entered-in-error（作废）
```

与 `ServiceRequest` **独立**：HIS 医嘱 `ACTIVE/COMPLETED` 由 health 管；未收费是否允许采样读 **`lis_config`**（非 framework Setting）。
