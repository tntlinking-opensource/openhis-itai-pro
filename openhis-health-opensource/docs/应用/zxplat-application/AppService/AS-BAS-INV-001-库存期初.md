# 基础数据 · 库存期初 · 应用服务设计（AS）

> **文档职责**：说明「库存期初」页面的**接口契约（IF）**、业务语义、涉及聚合与 QueryService、规则（BR）、编排意图。  
> **本文必须写**：IF 编号；用户动作与读写属性；关键校验与状态变化；Gap；异常口径；事件语义；非功能约束；业务向测试要点。  
> **本文禁止写**：具体类名/应用方法名；Request/Response 字段明细；包路径；Mapper；伪代码；写库顺序；QueryService 字段组装规则。  
> **页面边界**：挂在 **基础数据** 下**单一菜单「库存期初」**；制单时选择目标库房（药库 / 药房 / 耗材房），按库房形态落 `CABINET_OPENING` / `PHARMACY_OPENING` / `DEPT_OPENING`；**以最后一张已同意单为准**（新单同意作废并回滚前单）；支持**从上一张复制**、Excel 整单导入、追溯码、手工作废、显式关闭期初；**不调用医保进销存**。  
> **已同意/审核中期初明细查询/导出**：不另建报表页；按类型落入 **AS-INV-RPT-002** 药库/药房/科室单据详情报表（显式选 `typeEnum=*_OPENING` 时含 **`APPROVAL`**；筛库房用「目的库位」；导出与列表同筛选）。  
> **交互清单权威**：以已确认业务方案 [`库存期初初始化方案.md`](../业务方案/库存期初初始化方案.md) **v0.16** 为准（目标前端路径 `views/basic/inventory-opening/`）。  

> **编排参照**：同意入账 / 追溯写主档语义对齐药库进货执行单据路径（**AS-INV-WHS-002**），但**无订货来源、不调 350x**；覆盖前单时先走作废回滚再入账。  
> 编码：AS-BAS-INV-001 · **版本**：v0.8 · **日期**：2026-08-24

## 1. 场景概述

### 1.1 目标与边界

| 维度 | 说明 |
| --- | --- |
| **在内** | 期初单列表/详情；按库房新建/编辑/提交/撤回/同意/驳回/删除；**从上一张已同意单复制**；Excel；选品；关闭期初；手工作废当前有效单；同意时**整单替换**入账（先作废前回滚） |
| **在外** | 日常进货/出库/盘点/损益/请领；医保 350x；目录/物价主数据维护；三方纸质确认单流程 |
| **涉及域** | **SupplyRequest**、**SupplyDelivery**、**InventoryItem**、批号定价（`LOT_NUMBER_COST` / `LOT_NUMBER_PRICE`）、**TraceNumber**、**Location**、药品/耗材定义、**SupplyStatus** / **SupplyType** |
| **跨域** | 同意：可选先回滚前有效单 → 再发放+库存+追溯；作废回滚；关闭期初写独立表 |
| **编排权威** | 本文 §2、§4；业务裁决见业务方案 v0.16 |
| **前置** | 目标 Location 已建且启用；药品/耗材目录可用 |
| **后置** | 关闭期初或出现非期初业务单后，该库不可再做期初 |

### 1.2 角色与关键动作

| 角色 | 关键动作 |
| --- | --- |
| **制单员** | 选库房 → 新建或**复制上一张** → 改明细/导入/扫码 → 提交 |
| **审批人** | 同意 / 驳回（同意即覆盖前有效单） |
| **实施负责人** | 关闭期初；手工作废当前有效单 |
| **系统** | 非期初业务单出现时自动封锁该库期初 |

### 1.3 术语与口径约定

| 术语 | 口径 |
| --- | --- |
| **期初单** | `type_enum` ∈ {`CABINET_OPENING`,`PHARMACY_OPENING`,`DEPT_OPENING`}，**执行单据**；同意后触发库存与条件追溯 |
| **库房形态 → 类型** | `WAREHOUSE`→`CABINET_OPENING`；`PHARMACY`→`PHARMACY_OPENING`；`DEPARTMENT_PHARMACY`→`DEPT_OPENING` |
| **当前有效期初单** | 同库唯一 `AGREE` 的 OPENING 单；库存/追溯真源 |
| **目标库房字段** | 写入 `purpose_location_id`（与进货同语义） |
| **覆盖** | 新单同意时：回滚并作废前有效单，再按新单入账（无则建、有则加） |
| **复制上一张** | 服务端将源单明细拷入**新草稿**并返 `bus_no`；源可为当前 `AGREE` 或历史 `EXPIRED_INVALIDATED`；不改源单 |
| **关闭期初** | 库房级闸门（独立表）；关前该库不得有「审核中」期初单；可空关；关闭后禁止新建/提交/同意/复制 |
| **业务封锁** | 供应（非 OPENING 已提交+）或窄口径发放类（发药 OUT/退药/科室领用退回）命中后**必须自动写关闭行**，等同显式关闭 |
| **并发** | 同库「审核中」最多一张；同意时对库房串行，防双计入账 |
| **单内唯一** | 禁止同单内重复 `(itemTable, itemId, lotNumber)` |
| **空明细** | 允许本地空草稿；**落库保存须至少一行** |
| **效期** | 行上效期必填（禁止空） |
| **追溯扫码** | **可选**：西药/中成药可不扫（无码批）；有码仅禁单内重复。**不做**码数=ceil 硬 Gate（与进货区分） |
| **码与数量** | 有码行：写侧前填分摊消化半扫/多扫；UI 可提示建议应扫数，**不挡**提交/同意 |
| **码已在院** | **拒绝同意**：须人工清码后再期初（拍板 5C）；禁止 OUT 冲平叠写 |
| **药库进价** | `CABINET_OPENING` 行进价**硬必填**；药房/耗材房期初可空 |
| **审批岗** | **不**进财务审批白名单；库管/实施同意即可 |
| **撤回** | 完全对齐进货/盘点现网 `withdrawApproval`，不另开特例 |
| **权限** | 关闭/作废与菜单同权 |
| **Excel** | 任一校验失败 → **整单失败**、零写入 |
| **枚举口径** | 一律 `getCode()` 字符串 |
| **医保** | 全流程不调用 |

### 3.1 已拍板裁决（001 / 002 / 004）

#### GAP-OPN-001

- 新增 `SupplyType`：`CABINET_OPENING` / `PHARMACY_OPENING` / `DEPT_OPENING`（序号键建议 `COP`/`POP`/`DOP`）。
- 领域 `createOpening(CreateOpeningCommand)`：对齐 `createGainLoss`/`createStocktake` 的免申请执行单据形态；**不**复用 `createInboundReceipt`（避免订货/`original_bus_no` 耦合）。
- **不**加入财务审批白名单（`isFinanceApprovalRequired` 对 OPENING 为 false）。
- DM-WKF-006 登记为 **BR-SR-012 执行单据**：同意后应用层编排 Delivery + Inventory（整库清零后按本单 rebuild）+ 条件追溯 IN（码已在院拒绝）。

#### GAP-OPN-002

- 采用**独立表**（方案 B），例如 `adm_location_inventory_opening`（名称以实现为准）：
  - `location_id`（PK/UK）、`opening_closed`、`closed_time`、`closed_by`（及审计列按工程惯例）。
- **形态门禁（领域硬约束）**：仅当 Location.`form_enum` ∈ {`WAREHOUSE`,`PHARMACY`,`DEPARTMENT_PHARMACY`} 时允许插入/更新关闭行；**病区/病房/床位等其它形态禁止有行**（写入拒绝；读侧其它形态恒视为「无关闭记录=未关闭」且不得建行）。
- 领域方法：`closeInventoryOpening`（幂等）；Query：`isInventoryOpeningClosed(locationId)`（无行=false）。
- 业务封锁命中时：对该库 **必须同写关闭行**（与显式关闭同态）。

#### GAP-OPN-004

- 应用层闸门 = **供应单判定 OR 发放/发药判定**（有一即封锁，并**必须**触发 002 自动关闭）：
  1. **供应**：同库（以 **`purpose_location_id`** 为准）存在 `type_enum` **非**三类 OPENING、未删、状态为已提交及以上（**纯草稿不挡**）的 `wkf_supply_request`。
  2. **发放类（窄口径，已确认）**：本库已生效的 **门诊/住院发药 OUT**、**退药回库**、**科室领用/退回**（动可用库存者）。调拨/药库出库等已由供应单侧覆盖，不另扩白名单。
- **禁止**用「库存数量>0」当封锁条件（期初同意后必然>0）。

### 3.2 GAP-OPN-003（作废回滚）— 随「最后一张为准」已简化

> **业务真源**：同库同时最多一张当前有效 `AGREE` 期初单。新单同意或手工作废，都走同一套领域 **`voidOpening`** 内聚回滚。

#### 使用场景

| 场景 | 行为 |
| --- | --- |
| **A. 新单同意覆盖** | 找到该库前一张 `AGREE` → `voidOpening` → 再按新单入账 |
| **B. 手工作废** | `voidOpening`；该库无有效期初结果 |
| **C. 复制上一张** | **不**走回滚；只读源单明细生成新草稿（IF-16） |

#### 回滚算法（同事务，封装于 `voidOpening`）

1. 门禁：目标单 `AGREE`；库房未关闭（手工作废）；覆盖场景在同意事务内。
2. 按该单行对五元组（含供应商）定位后 `decreaseQuantity`（数量=该单行量）；不足则失败。
3. 追溯：**T1** — 按 `bus_no` 对当初 `HOSPITAL_IO` IN 补对称 OUT，回退主档剩余（不删历史流水）。
4. 批号价：覆盖场景随后被新单重写；手工作废后**保留最后价**（不重算、不删除）。
5. 单据 → `EXPIRED_INVALIDATED`；发放事实保留审计即可。
6. 领域边界：**`voidOpening` 门面内聚**上述步骤（App 同意覆盖与 IF-15 只调一次）。

#### 同意写追溯（码已在院 · 拍板 5C）

码已在院（`IN_HOSPITAL` 且剩余&gt;0）→ **拒绝同意**，提示人工清码；前单 Void 冲平后仍在院的视为外源脏数据。本单同意后仅写 HOSPITAL_IO **IN**（不再 OUT 冲平叠写）。

- 主档库位/剩余量等**置成与本单一致**；必要时先冲平再记本单 `HOSPITAL_IO` IN。
- **禁止**仅调用现网增量 IN 导致叠量。

| --- | --- | --- |
| 1 | 追溯冲销 | **T1** |
| 2 | 手工作废后批号价 | **保留最后价** |
| 3 | SupplyDelivery | **保留审计，不强制删** |
| 4 | 领域边界 | **`voidOpening` 门面内聚** |
