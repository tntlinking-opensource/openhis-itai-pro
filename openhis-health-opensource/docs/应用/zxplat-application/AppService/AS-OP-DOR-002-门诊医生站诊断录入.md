## 1. 场景概述

### 1.1 目标与边界


| 维度 | 说明 |
| --- | --- |
| **在内** | 载入当前就诊已有诊断列表（IF-DOR-06）；载入四类常用诊断快捷候选（IF-DOR-06A）——**仅查询消费**；载入患者慢特病备案可导入诊断（IF-DOR-06B）——**仅查询消费，且依赖医保模块启用**；按中西医与关键字分页检索诊断定义（IF-DOR-07）；将所选定义保存为就诊诊断（IF-DOR-08，含从慢病备案勾选后的写入）；删除就诊诊断（IF-DOR-09）；**单点切换主诊**（IF-DOR-09A，西医单行 / 中医病证组）。**本页面不负责常用诊断绑定的新增/编辑/删除维护** |
| **在外** | 就诊生命周期（接诊/完诊）、医嘱与处方明细、退费、报告查询、中医辨证在独立 Tab 的扩展录入、**诊断常用模板/归属绑定的独立管理后台（完整分页 CRUD 维护页面）**、患者慢特病备案主数据维护、医保平台目录下载 |
| **涉及域** | 诊断定义目录（ConditionDefinition）；就诊与就诊诊断行（Encounter / EncounterDiagnosis，直挂 `condition_definition_id`）；诊断归属/常用绑定（个人、科室）；Organization / Practitioner（绑定对象解析）；就诊费用性质/参保上下文（解析人员编号与契约，供慢特病备案查询）。**`cln_condition` 已业务退役，禁止再写再读**（见 DD-诊断绑定改造） |
| **编排权威** | 以本文 **§2、§4** 为准 |


### 1.2 角色与关键动作


| 角色 | 关键动作 |
| --- | --- |
| **门诊医生** | 打开诊断录入 → 查看/刷新当前诊断列表与四类常用诊断快捷树 →（医保模块已启用时）查看「慢病备案」候选并勾选导入 → 从快捷树直接选择 或 打开弹窗检索后选择 → 确认写入诊断列表 → 统一提交保存 → **快捷切换主诊**（不必整批保存）→ 必要时删除错误行 |
| **系统** | 仅返回有效（发布）诊断定义；删除前校验医嘱引用；个人/科室绑定时解析登录上下文主键；**医保模块未启用时不展示慢病备案入口且不发起备案查询** |


### 1.3 术语与口径约定


| 术语 | 口径 |
| --- | --- |
| **当前就诊诊断列表** | 绑定在当前门诊就诊下的诊断行集合；展示含中西医类别、编码、名称、主诊标记、排序、验证状态等。Tab 读路径：**`EncounterDiagnosisSnapshotAssembler#buildSnapshot`** 实时扫表 → Mapper **`parseDiagnosisJson`** 结构化（**禁止** API 透传 `diagnosisJson`，见 AS-SDD §1.2.1） |
| **快捷树四类** | 患者历史诊断、当前医生常用诊断、当前用户个人诊断、当前登录科室诊断；数据来自诊断定义元数据与绑定关系合并查询；**本页面仅消费查询结果，不提供维护入口** |
| **慢病备案候选** | 患者在医保平台的有效门慢门特备案病种，经目录映射为可写入的诊断定义候选；**仅医保模块已启用时**出现在快捷树第五类「慢病备案」；未启用时入口隐藏、查询返回「不可用」语义且不调用平台 |
| **备案码→目录映射** | 以门慢门特病种目录代码匹配诊断定义：优先特慢病编码，其次医保编码，再次诊断目录编码；仅匹配**已启用**目录；一对多时优先特慢病诊断目录来源；未匹配行可展示备案名称；**医生点击导入时**可走 IF-DOR-06C 幂等补录 `chronic_spec`（不改其它来源目录）后再写入就诊诊断；歧义/过期仍禁止写入 |
| **中西医检索** | 西医：`source` 落在西医目录取值集合；中医：`source` 落在中医目录取值集合（与目录主数据维护一致） |
| **全量替换策略** | 诊断保存采用**全量提交**模式：前端提交当前就诊下完整的诊断批次（含新增行与已存在行），后端按行内 ID 是否为空区分「新增/更新」；**不在批次中的已存在诊断视为删除**（或由前端显式触发单条删除 IF-DOR-09）。老系统曾使用「先删后插」策略，本期契约继承该语义但不限定实现方式 |
| **QueryService 能力** | 写前门控 **OutpatientEncounterContextQueryModel**（`EncounterContextReader`）；诊断 Tab **`EncounterDiagnosisSnapshotAssembler#buildSnapshot`** → Mapper **`parseDiagnosisJson`**（**禁止** API 透传 `diagnosisJson`，见 AS-SDD §1.2.1） |
| **诊断定义键名（HTTP/快照）** | 与 AS-SDD 及实现对齐：表示诊断定义的 JSON 键与请求子项字段统一为 **`conditionDefinitionId`**、**`conditionDefinitionName`**；不使用旧键 `definitionId` / `conditionName` |
| **接入与工程口径** | 动态应用服务路由、JSON 请求体、写路径跨聚合顺序与**应用层是否声明事务**等，以 AS-SDD 与 `zxplat` 实现对齐说明为准 |

| 维度 | 说明 |
| --- | --- |
| **触发前提** | 已选定门诊就诊与患者；进入诊断 Tab 或主动刷新快捷树 |
| **主路径步骤** | **并行查询四类常用诊断**（左侧快捷树数据源，类间独立可为空）：<br> • **病人历史诊断**：按患者标识扫描诊断事实；**西医**按 `conditionDefinitionId` 去重；**中医**经就诊关联反查 `tcm_syndrome_group`，同组病名+证候合并为一行展示（`PatientHistoryCommonDiagnosisAssembler`）；<br> • **医生常用诊断**：按当前操作者（医师身份）解析常用模板绑定，展示绑定的有效诊断定义；<br> • **用户个人诊断**：按当前登录用户 + **个人模板**绑定（`DM-CUS-003` §4.1 `personal`）查询；<br> • **科室诊断**：按当前登录科室上下文 + **科室模板**绑定（`DM-CUS-003` §4.1 `department`）查询——**不使用**「ORGANIZATION」式机构整包命名，以免与科室维度混淆。<br><br>→ 四类结果分别返回，由前端合并展示；展示字段（中西医类别、来源文案等）遵循 BR-DOD-003。<br>→ 同时下发 **`medicalTypeOptions`**（**BR-OP-DOD-016**），供诊断表「诊断类型」列行编辑 |
| **关键分支** | 任一类查询结果为空时，快捷树对应分支显示为空；四类可独立缓存或合并单次查询 |
| **失败分支** | 查询不可用 → EX-DOD-101 |
| **查询侧说明** | 纯读；与就诊诊断列表独立加载 |

### IF-DOR-08 保存就诊诊断（全量替换策略）


| 维度 | 说明 |
| --- | --- |
| **触发前提** | 已选定就诊与患者；当前诊断列表批次非空 |
| **主路径步骤** | **全量批次处理**：前端提交当前就诊下**完整的诊断批次**（含快捷树选择或弹窗选择后的新增行，以及列表中已存在的行）。对批次每一项：<br> • 若行 ID 为空 → 新增患者诊断事实 + 新增就诊诊断关联；<br> • 若行 ID 非空 → 更新患者诊断事实 + 更新就诊诊断关联。<br><br>**删除语义**：老系统实现采用「先删除该就诊全部诊断再批量插入」策略；本期契约继承**全量替换**语义——不在提交批次中的已存在诊断应由前端显式调用 IF-DOR-09 删除，或由后端依据全量差异比对自动移除（实现选型在 SDD 固化）。 |
| **关键分支** | 批次中存在「仅更新就诊关联、不改写事实」的中医扩展标识时，按标识拆分更新路径（不展开字段）；与中医工作站重复的扩展逻辑以中医 AS 为权威 |
| **失败分支** | 持久化失败 → EX-DOD-105 |
| **查询侧说明** | EncounterQueryService（OutpatientEncounterContextQueryModel）诊断快照随诊断保存类事件更新；病历/质控等消费方按领域事件订阅 |
