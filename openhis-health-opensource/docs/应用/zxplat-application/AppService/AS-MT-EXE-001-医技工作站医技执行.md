# 医技工作站 · 医技执行 · 应用服务设计（AS）

> **文档职责**：医技工作站「医技执行」——左患者 / 中诊疗 / 右耗材；顶栏可切**门诊 / 住院**；可见性轴见可见性 DD；不接药品与皮试。  
> **页面边界**：队列（关键字、门诊就诊开始时间、仅待发耗材、**待执行/已执行**、**住院在院/不在院**）→ 点选 → 执行并记录 / 批量执行 → 执行记录 / 取消执行。  
> **兄弟模块**：`AS-MT-FEE-001` 费用清单；`AS-MT-CHG-001` 医技计费（仅住院、仅耗材、划价不扣库）。  
> **门诊**：列表与护士站按执行科室·耗材房拆开，**无**双侧同态；执行前已收费门控。  
> **住院**：护士执行=计费、医技执行=临床已做（不建诊疗 Charge）；耗材来自医技计费；**取消/签退不互卡**；**待结算/已结算/已离院禁止医技执行与取消**（对齐护士站 EX-IP-EXE-307）；出院确费门禁另见协同 DD。  
> **导航**：`DD-医技工作站-模块索引-2026-09.md`  
> **编码**：AS-MT-EXE-001 · **版本**：v1.5.9 · **日期**：2026-10-17  
> **实现阶段**：应用层已落地 IF-MT-EXE-01～05/03B（见配套 SDD）

## 1. 场景概述

### 1.1 目标与边界

| 维度 | 说明 |
| --- | --- |
| **在内** | 按 **encounterScope（门诊/住院）** 分页患者队列（本站 TECH 可见性轴「有活」准入；**门诊**可选日期区间、关键字、仅待发耗材；**待执行/已执行**整单分桶——门诊看项目+耗材、住院仅项目；**住院不按入院日筛**）；点选后按就诊装载**本站可见**诊疗行与耗材行（两列表同构字段；**同一 `executionQueueFilter` 同时收窄右侧行**）；诊疗执行记录全量分页与净剩可取消列表；批量执行（诊疗写 Procedure 完成；耗材按全局扣库开关推进配药/发放并条件扣库存）；批量取消执行（诊疗追加 CANCEL；耗材对称回退）；登录医技执行人解析 |
| **明确不在本场景** | **收费明细回滚**；**新建 / 修改收费明细**（门诊本站无计费；住院计费见 **AS-MT-CHG-001**）；药品执行、皮试登记、输液支路 |
| **在外** | 费用清单、医技计费、LIS/PACS 外发协议本体、住院护士站、门诊护士站、医嘱开立与签发、药房发药 |
| **涉及域** | Encounter；ServiceRequest；DeviceRequest / DeviceDispense；ChargeItem（读门控 / 列表聚合）；Procedure；InventoryItem；Organization / Location（可见性轴）；Practitioner（执行人） |
| **编排权威** | 以本文 **§2、§4** 为准；可见性以 DD 为准 |

### 1.2 角色与关键动作

| 角色 | 关键动作 |
| --- | --- |
| **医技人员** | 登录医技科 → 切**门诊/住院** → 切**待执行/已执行** →（门诊按日期、）关键字/仅待发耗材刷新队列 → 点选患者 → 勾选本站诊疗与耗材 →（扣库开时可选耗材房）→ **执行并记录** / 批量执行 → 必要时打开执行记录或取消执行 |
| **系统** | 按登录 TECH 与 encounterScope 过滤；门诊已收费门控、列表与护士站互不重叠；住院诊疗认护士挂账、本站写医技侧执行；住院取消/出院/撤回同态见协同 DD |

### 1.3 术语与口径约定

| 术语 | 口径 |
| --- | --- |
| **医技工作站** | 登录科室 `class_enum = TECH` 的工作台；可切门诊/住院；模块含医技执行 / 费用清单 / 医技计费（计费仅住院） |
| **encounterScope** | `OUTPATIENT` / `INPATIENT`；仅收窄就诊类别，**不**改变可见性轴 |
| **本站可见性轴** | 诊疗：`ServiceRequest.org_id` = 当前登录医技科（可扩 bus_no 共看组）；耗材：发放耗材房挂靠科室 = 登录科，或挂靠最近 TECH / 登录科互为祖先链对齐。**禁止**任意 TECH 互看（检验科不见超声科待发）。见 DD §2～§3 |
| **有活（队列）** | 存在本站可见诊疗，或本站可见且待处理耗材。**不**含输液/皮试药支路 |
| **双活** | 同就诊同时有门诊护士站活与医技活 → **两边列表都可见**；点开后各站只看本站行 |
| **执行单（两列表）** | 应答拆 **诊疗列表 + 耗材列表**（**无药品列表**）；行字段名两套一致，便于复用护士站处置行组件 |
| **执行** | 诊疗：在门控通过且净执行次数未超计划时新增 **COMPLETED** Procedure，**`Procedure.org_id` = 登录医技科**（护士侧执行计数 `org_id` 为 null，两侧隔离）。耗材：对医技划价产生的发放行，按全局开关关 → PREPARATION→PREPARED 不扣库；开 → 可就地改房后 PREPARATION→COMPLETED 并按签发批号扣库。**不**变更 DeviceRequest 状态（指定房可回写 `perform_location`）。**住院诊疗不在本动作建 Charge**。**不**做执行侧双侧同态门禁（协同 DD：不要求先后；**EX-MT-EXE-202 预留不抛**） |
| **取消执行** | 诊疗：按 `procedureId` 追加 CANCEL，仅取消**医技侧**记录（写 `org_id`=登录 TECH）。**软落地**：取消本侧**不**互卡护士侧（历史 EX-IP-CXL-207 / EX-MT-EXE-214 **不抛**）。**门诊**无同态。耗材对称回退；不回滚 ChargeItem |
| **门诊计费门控** | 执行前诊疗须存在有效已计费 `ChargeItem`（与门诊护士站「已计费」语义同构） |
| **住院诊疗费用口径** | 诊疗挂账来自**护士执行**既有轨；医技执行只表达临床已做。**禁止**本模块新建诊疗 Charge；**禁止**把「未走医技计费」当成诊疗执行失败原因 |
| **住院耗材** | 医生通常不开医技耗材待发；耗材由 **医技计费** 从登录科耗材房划入（计费+待发），再在本站执行发放/扣库 |
| **待发耗材（医技）** | 本站可见轴下、由医技划价产生、仍待配/待发的耗材；红点不得计入护士站或其它医技科耗材房 |

## 7. 非功能性需求

| 项 | 要求 |
| --- | --- |
| **性能** | 队列与执行单须批量预取目录/发放/计费，禁止按行循环查库 |
| **幂等** | 同一 procedure 完成/取消对冲口径与护士站一致；耗材仅处理准备中态防重发 |
| **并发** | 发放行状态条件更新；失败提示刷新 |
| **一致性** | 执行与耗材扣库同事务；取消与回补同事务；**不**与收费回滚同事务 |
| **审计** | Procedure 执行人/取消原因可追溯；发放操作人可追溯 |
| **安全** | 必须登录 TECH；跨科不可见他科医技单 |

## 8. 测试要点（业务视角）

| 类别 | 要点 |
| --- | --- |
| **正向** | 门诊/住院切换；本科 TECH 单；双活点开只见本站；门诊已收费可执行；住院医技执行不建诊疗 Charge；耗材来自医技划价后发放；取消对冲后再执行 |

| **并发** | 双人同时发同一准备中发放行仅一人成功 |
