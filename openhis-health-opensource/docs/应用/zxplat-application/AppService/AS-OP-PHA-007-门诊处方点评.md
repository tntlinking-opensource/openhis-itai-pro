# 门诊处方点评 · 应用服务设计（AS）

> **文档职责**：说明门诊药房「发药管理 → 处方点评记录」页及「门诊处方查看」批量点评、发药完成自动点评、列表 enrichment 的**接口契约（IF）**、业务语义、涉及聚合与 QueryService、规则（BR）、编排意图；作为 **health-application** `outpatient/pharmacy/prescriptionreview` 包实现的编排权威。
>
> **页面边界（点评记录页）**：筛选区（点评时间、开方时间、是否合理、**重点药类型〔基药/监控/集采/抗生素〕**、**药品性质〔麻醉/精一/精二〕**、关键字〔处方号/业务号 OR〕；**无点评状态筛**——本页仅有效已点评行）→ **分页查询**有效点评行；列表/导出列与「处方点评工作表」数据列对齐（无序号；字段名我方命名）并由读侧装配方级指标 → 点击进入详情时展示**点评信息（编号/状态/结果/人/时间/原因/备注）+ 处方信息**（复用门诊处方查询能力）→ **导出当前页**（`pageNo`+`pageSize`）。**点评记录页无点评/撤销入口**。写侧入口仅在：**门诊处方查看**多选批量点评、撤销点评、发药完成勾选开关后的自动点评。
>
> **编码**：AS-OP-PHA-007 · **版本**：v1.5 · **日期**：2026-09-22
>
> **产品裁决（锁定）**：聚合 **DM-CUS-015 PrescriptionReview**；展示态 PENDING（无行）/ REVIEWED（有效行）；撤销软删后重评插新行；批量共用是否合理/原因/备注且已点评不可选；字段名 `reason`（非「不合理原因」）；不合理必填原因、合理可空；仅已发药门诊处方可评；发药完成且操作员勾选开关时自动点评（点评人=发药人、合理=true、原因/备注可空）；与审方无关、不阻断发药。

## 1. 场景概述

### 1.1 目标与边界

| 维度 | 说明 |
| --- | --- |
| **在内** | 点评记录页初始化（状态下拉、是否合理选项）；有效点评分页与导出；门诊处方查看批量点评；撤销点评；发药完成自动点评（供发药编排调用）；按处方号批量映射有效点评（供门诊处方查看 enrichment）；「仅已发药门诊处方可评」的应用层 Gate |
| **在外** | 审方（处方审核）链路；发药/退药主写路径本体（由 **AS-OP-PHA-001** / **002** 负责）；门诊处方查询主读（**AS-OP-PHA-005**，详情处方信息复用其分页）；住院处方点评；改写 `MedicationRequest` / `MedicationDispense` 状态 |
| **涉及域** | **PrescriptionReview**（点评事实主写读）；**MedicationRequest** / **MedicationDispense**（已发药 Gate 与自动点评锚点只读）；**Practitioner**（点评人姓名） |
| **编排权威** | 本文 **§2、§4**；点评一对一与原因规则以 **DM-CUS-015** 为准；是否已发药由应用层 Gate，领域层不读发放表 |
| **权限** | 药房业务人员；租户过滤由框架基线承担；本期不按管辖药房收窄点评记录 |

### 1.2 角色与关键动作

| 角色 | 关键动作 |
| --- | --- |
| **门诊药房人员 / 质量管理人员** | 进入点评记录页 → 筛选/查询/翻页/导出；在门诊处方查看多选待点评方 → 批量点评；对已点评方撤销后可再评 |
| **发药操作员** | 发药页勾选「发药完成自动点评」开关 → 核发成功后系统自动写入合理点评 |
| **系统** | 下发筛选项；分页/导出有效点评；批量 enrichment 点评态；校验仅已发药可评；自动点评不挡发药主路径 |

### 1.3 术语与口径约定

| 术语 | 口径 |
| --- | --- |
| **处方点评** | 方级质量事后点评事实，锚点为 `prescription_no`；与发药**审方**无关 |
| **待点评（PENDING）** | **展示态**：该处方**无**有效点评行；**不落库** PENDING 行；筛「待点评」时点评表直接空结果（由门诊处方查看侧按「无 enrichment」展示） |
| **已点评（REVIEWED）** | **落库态**：有效行 `status_enum=REVIEWED`；列表/导出仅见有效行 |
| **有效点评** | `is_deleted=false` 的点评行；同一处方号租户内至多一条 |
| **撤销重评** | 软删当前有效行 → 展示回待点评 → 再点评时 **INSERT** 新行（历史软删行保留） |
| **原因（reason）** | 字段名即为 `reason`；**不合理时必填**（去空白非空）；合理时可空；备注 `remark` 始终可选 |
| **仅已发药** | 门诊已签发处方且关联发放存在 `DispenseStatus=COMPLETED` 代表态后方可人工/自动点评；未发药不可选、不可提交 |
| **自动点评** | 发药核发成功且操作员勾选开关：点评人=当前发药人，`reasonableFlag=true`，`reason`/`remark` 可空 |
| **批量点评** | 多处方共用同一 `reasonableFlag` / `reason` / `remark`；批次内不得含已点评方；任一条失败整批失败 |
| **点评记录列表** | 与「处方点评工作表」数据列对齐（无序号）：处方编号、年龄、诊断、药品品种、抗菌药(0/1)、注射剂(0/1)、国家基本药物品种数、药品通用名数、处方金额、处方医师、是否合理(0/1)、存在问题（API 字段名 `reason`）；方级指标为读侧装配，非点评表落库 |
| **点评记录详情** | 详情上半区展示点评信息（`busNo` 作点评编号、状态、是否合理、点评人、时间、原因、备注）；下半区处方信息复用 **AS-OP-PHA-005**（按处方号精确筛）；列表行携带详情所需点评字段但不进工作表列 |
| **导出列** | 与列表同列；前端传 `exportColumns`；**导出条数=当前页 `pageSize`**（携带 `pageNo`） |

## 4. 接口编排说明书（业务步骤）

### IF-PRV-01 点评记录页初始化

| 维度 | 说明 |
| --- | --- |
| **触发前提** | 用户进入「发药管理 → 处方点评记录」页 |
| **主路径步骤** | ① 装配点评状态下拉：待点评 / 已点评。② 装配是否合理下拉：合理 / 不合理（可含「全部」空值语义）。③ 可选返回默认点评时间窗（如本月）供前端预填。④ 返回选项集合 |
| **关键分支** | 点评人下拉本期可不在 init 提供（列表筛可空，或前端远程搜人员，产品约定一种） |
| **失败分支** | 未登录或元数据装配失败 → EX-PRV-101 |
| **查询侧说明** | 纯枚举/日历装配，不写库 |

### IF-PRV-02 分页查询点评记录

| 维度 | 说明 |
| --- | --- |
| **触发前提** | 用户设定筛选（点评时间/开方时间/是否合理/关键字等）后查询或翻页 |
| **主路径步骤** | ① 校验分页窗与时间窗（若传）。② 调用有效点评分页。③ 映射点评字段（处方号/是否合理/原因）。④ 按页内处方号批量装配方级指标（药嘱行→目录标志/收费/年龄/诊断并集/开方人）。⑤ 返回分页 |
| **关键分支** | 状态=待点评 → 空页；各筛空表示不限制；关键字模糊处方号；无药嘱行时指标列可空 |
| **失败分支** | 分页/时间非法 → EX-PRV-102；查询失败 → EX-PRV-103 |
| **查询侧说明** | 主事实在点评表；方级指标跨聚合批量装配，禁止 N+1 |

### IF-PRV-03 导出点评记录

| 维度 | 说明 |
| --- | --- |
| **触发前提** | 用户点击导出；筛选与列表一致；请求携带当前页 `pageNo`/`pageSize` 与 `exportColumns` |
| **主路径步骤** | ① 校验分页窗与 `exportColumns`。② 复用 IF-PRV-02 筛选与 enrichment 拉取**当前页**行。③ 按工作表同列映射导出行（是否合理导出 0/1）。④ 按 `exportColumns` 生成 Excel 并返回 |
| **关键分支** | 零行仍导出表头；若总条数大于已导出累计则 `truncated=true`（提示尚有未导出页） |
| **失败分支** | 同 IF-PRV-02；导出失败 → EX-PRV-104 |
| **查询侧说明** | 与分页同源；导出条数=本页 `pageSize`，不以全量上限窗替代 |

### IF-PRV-04 批量创建点评

| 维度 | 说明 |
| --- | --- |
| **触发前提** | 用户在门诊处方查看多选**待点评且已发药**处方，提交共用是否合理/原因/备注 |
| **主路径步骤** | ① 校验登录医务人员与入参非空。② 校验共用合理标志与原因规则。③ 对每个处方号确认无有效点评。④ Gate：解析处方对应药品申请并以发放完成态确认已发药。⑤ 批量领域创建点评（点评人=当前登录医务人员；`bus_no` 由领域 PRV 日序自生成）。⑥ 返回创建标识列表 |
| **关键分支** | 合理时原因可空；不合理必须原因 |
| **失败分支** | 未发药 → EX-PRV-201；已点评冲突 → EX-PRV-202；原因缺失 → EX-PRV-203；参数非法 → EX-PRV-200；写失败整批回滚 |
| **查询侧说明** | Gate 只读药嘱/发放；写后列表 enrichment 经 IF-PRV-07 可见已点评 |

### IF-PRV-05 撤销点评

| 维度 | 说明 |
| --- | --- |
| **触发前提** | 用户在**门诊处方查看**对有效点评执行撤销（点评记录页不提供撤销） |
| **主路径步骤** | ① 校验登录。② 按点评主键或处方号定位有效行。③ 领域软删撤销。④ 返回成功 |
| **关键分支** | 主键优先于处方号锚点 |
| **失败分支** | 无有效点评 → EX-PRV-204；参数非法 → EX-PRV-200 |
| **查询侧说明** | 撤销后 enrichment 无映射项，展示待点评；可再走 IF-PRV-04 重评 |

### IF-PRV-06 发药完成后自动点评

| 维度 | 说明 |
| --- | --- |
| **触发前提** | **AS-OP-PHA-001** 核发成功后，且操作员勾选自动点评开关；由发药编排调用本 IF |
| **主路径步骤** | ① 校验调用方传入的已完成处方号集合与发药人。② 过滤已有有效点评的处方（跳过，不报冲突阻断）。③ 对剩余方确认发放完成语境（发药编排上下文已 COMPLETED）。④ 以合理=true、原因/备注空创建点评（单条或批量）。⑤ 返回创建结果摘要（成功数/跳过数） |
| **关键分支** | 开关关闭则发药编排**不调用**本 IF；全部已点评则成功数=0 |
| **失败分支** | 自动点评任一步失败 → 本 IF **不抛异常**，响应 `softFailed=true`（**软失败**：**绝不**回滚已成功发药；见 **BR-PRV-A11**）；调用方仅可提示「请稍后手工点评」 |
| **查询侧说明** | 写成功后 enrichment 立即可见已点评合理 |

### IF-PRV-07 按处方号批量映射有效点评

| 维度 | 说明 |
| --- | --- |
| **触发前提** | **AS-OP-PHA-005** 列表/详情装配时传入本页处方号集合 |
| **主路径步骤** | ① 校验登录（或同进程内部调用信任边界以 SDD 为准）。② 批量查询有效点评 Map。③ 映射为消费方 DTO（含状态、是否合理、原因、备注、点评人、时间等） |
| **关键分支** | 空列表返回空 Map；无点评的处方号缺席 |
| **失败分支** | 查询失败 → EX-PRV-103 |
| **查询侧说明** | 仅点评聚合读；姓名可由本 IF 附带或由消费方二次装配（SDD 定一种，推荐本 IF 附带点评人姓名） |

## 6. 事件语义与消费方

| 事件 | 触发相位 | 消费方语义 | 幂等 |
| --- | --- | --- | --- |
| **PrescriptionReviewCreatedEvent** | IF-PRV-04 / IF-PRV-06 创建成功（beforeCommit） | 读侧缓存刷新、审计；门诊处方查看 enrichment 在提交后可见已点评 | 同一处方有效行唯一，重复创建被领域拒绝 |
| **PrescriptionReviewRevokedEvent** | IF-PRV-05 撤销成功（beforeCommit） | 读侧刷新为待点评；允许后续再创建 | 无有效行时撤销失败，不重复发事件 |

**说明**：本 AS **不**消费外域事件驱动点评；发药完成自动点评由 **AS-OP-PHA-001** 同步编排调用 IF-PRV-06，而非监听发放领域事件（本期口径）。

## 7. 非功能性需求

| 类别 | 要求 |
| --- | --- |
| **性能** | 点评分页 ≤ 1500ms（常规时间窗）；IF-PRV-07 批量处方号建议单次 ≤ 200；导出 ≤ 30s 且行数上限（SDD 定，建议 ≤ 5000） |
| **幂等** | 有效一对一防止重复点评；自动点评对已点评方跳过；撤销对已软删失败 |
| **并发** | 同处方并发创建依赖领域存在性校验 + 唯一约束兜底；冲突返回 EX-PRV-202 |
| **一致性** | 写接口同事务落库+事件；自动点评与发药主路径可分事务（发药成功后调用），失败不冲正发药 |
| **审计** | 点评创建/撤销记操作审计；查询/导出可选框架审计 |
| **租户** | 数据限定当前租户 |

## 8. 测试要点（业务视角）

| 类别 | 要点 |
| --- | --- |
| **正向** | 已发药待点评方可批量点评合理/不合理；列表见点评字段全集；详情处方信息走处方查询；导出列同列表 |
| **自动点评** | 开关开且发药成功 → 合理点评、点评人=发药人；开关关 → 无自动行；已点评方跳过不报错挡发药 |
| **撤销重评** | 撤销后展示待点评；再评插入新行；历史软删不可见 |
| **规则** | 未发药拒绝；已点评不可再选；不合理无原因拒绝；合理无原因通过 |
| **筛选** | 点评时间/开方时间/是否合理/重点药类型/药品性质（麻/精）/关键字；待点评筛空页 |
| **协作** | PHA-005 enrichment 显示已点评态；PHA-001 调用自动点评不阻断发药 |
| **并发** | 同方双开点评仅一条成功 |
