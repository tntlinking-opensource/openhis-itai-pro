## 1. 场景概述

### 1.1 目标与边界


| 维度       | 说明                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **在内**   | 加载退药页初始化元数据（读）；分页查询待退药患者列表（读）；按就诊查询**药品**退药明细（读）；确认退药/拒绝退药（写：状态推进、库存回补、追溯码入库）                                                               |
| **在外**   | 医生站申请退费（反向发放单已在医生站生成）；**耗材退药**（另有工作站/场景，不在本页）；医保退货接口调用；双人复核流程；部分数量退药                                                                                          |
| **涉及域**  | MedicationRequest（药品申请）；MedicationDispense（药品发放）；InventoryItem（库存项）；TraceNumberRecord（追溯码记录） |
| **编排权威** | 以医生站申请退费（AS-OP-DOR-004）生成的 `PENDING_REFUND` 状态发放单为入口，本场景仅推进状态至 `REFUNDED` 或 `DECLINED`                                                |


### 1.2 角色与关键动作


| 角色       | 关键动作                                                                 |
| -------- | -------------------------------------------------------------------- |
| **药房药师** | 打开退药管理页 → 查看待退药患者列表 → 选择患者查看退药明细 → 核对实物与单据 → 确认退药或拒绝退药               |
| **系统**   | 加载初始化元数据（科室、退药状态选项）；执行退药患者分页查询；按就诊聚合展示退药明细；执行退药确认编排（状态推进、库存回补、追溯码入库） |


### 1.3 术语与口径约定


| 术语         | 口径                                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **退药负向单**  | 医生站申请退费时生成的负向**药品**请求单（`MedicationRequest`）：**全量拷贝**原单临床字段；`prescription_no`=`T`+原号（**`markAsRefundFromPrescription`**）；`refund_medicine_id` 关联原单 |
| **待退药发放单** | 医生站申请退费时生成的反向**药品**发放单（`MedicationDispense`），状态为 `PENDING_REFUND`，`dispense_enum=REFUND`，`med_req_id` 指向负向请求单（门诊）或原药嘱（住院取消执行） |
| **退药与原发药单** | 退药读/写链路**不**查询、**不**修改原正向 COMPLETED 发药单；统计层发药计正向行、退药计 REFUND 对冲行，二者数量对冲 |
| **批号**     | 与正向发药一致：退药库存回补、追溯均使用发放单上记录的 `lot_number`，发什么批号退什么批号，不在本页另选批号 |
| **确认退药**   | 药房核对实物无误后，将发放单状态从 `PENDING_REFUND` 推进为 `REFUNDED`，并触发库存回补、追溯码入库                                                                 |
| **拒绝退药**   | 药房核对实物不符或患者撤销退药时，将发放单状态推进为 `DECLINED`（终态），须填写拒绝原因                                                                               |
| **退药原因**   | 手写输入字符串，存储于发放单 `reason` 字段，用于记录退药或拒绝的业务原因                                                                                       |
| **全退**     | 不支持部分数量退药，退药即整行全退（`dispense_quantity = quantity`）                                                                               |

### 1.6 业务规则（BR-*）


| 规则 ID          | 规则描述                                                 | 绑定 IF        |
| -------------- | ---------------------------------------------------- | ------------ |
| **BR-PHA-031** | 退药确认仅允许对 `PENDING_REFUND` 状态执行                       | IF-PHA-02-04 |
| **BR-PHA-032** | 已退药（`REFUNDED`）或已拒绝（`DECLINED`）不可重复退药                | IF-PHA-02-04 |
| **BR-PHA-033** | 退药数量须全量退回（`dispense_quantity = quantity`），不支持部分退药    | IF-PHA-02-04 |
| **BR-PHA-034** | 退药成功后必须回补库存（回补量 = 发放行 **`unit_code` 操作单位数量** 经目录五类换成拆零，与发药 **BR-OPP-017** 同口径）；追溯 IN 经 **`recordReturnInLines`** **镜像**原发 OUT 每码实扣（**DD §5** / **BR-TRC-008**），**禁止**新建主档或按当前剩余重分摊 | IF-PHA-02-04 |
| **BR-PHA-035** | 拒绝退药须填写原因，状态推进为 `DECLINED` 终态                        | IF-PHA-02-04 |
| **BR-PHA-036** | 退药/拒绝须记录操作人（`practitioner_id`）与操作时间（`dispense_time`） | IF-PHA-02-04 |
| **BR-PHA-037** | 本页仅处理 `MedicationDispense` 退药；不接受耗材发放单                             | IF-PHA-02-04 |
| **BR-PHA-039** | **退药明细**与 IF-PHA-02-02 队列**同源**按管辖库位 `location_id IN` 收窄（服务端注入，不由客户端传库房）；**管辖 empty** 时不拼谓词 | IF-PHA-02-03 |
| **BR-PHA-038** | 确认退药**仅**推进 `dispense_enum=REFUND` 待退行；退药链路**禁止改写**原正向 COMPLETED 发药单（`status_enum` 不变）。追溯镜像：**禁止**为找 OUT 去改原单；`recordReturnInLines` 先按退药行 `bus_no` 取 OUT，若无（对冲行新单号）则按行上已拷贝 `trace_no` **只读**追溯子表回落未回冲原发 OUT（DD §5 / BR-TRC-008） | IF-PHA-02-03/04 |

## 4. 接口编排说明书（业务步骤）

### IF-PHA-02-01 加载页面初始化元数据


| 维度          | 说明                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------- |
| **触发前提**    | 用户打开「退药管理」页面                                                                                                          |
| **主路径步骤**   | ① 加载科室下拉选列表（OrganizationType=DEPARTMENT, OrganizationClass=CLINIC）；② 加载退药状态下拉选选项（`PENDING_REFUND` 待退药、`REFUNDED` 已退药） |
| **关键分支**    | —                                                                                                                     |
| **失败分支**    | 元数据加载失败（EX-PHA-002-101）                                                                                               |
| **查询侧说明** | 无写库；返回初始化元数据供前端渲染下拉选项                                                                                                 |


### IF-PHA-02-02 分页查询退药患者列表


| 维度          | 说明                                                                                                   |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| **触发前提**    | 用户进入退药管理页或执行查询操作                                                                                     |
| **主路径步骤**   | ① 构建查询条件（科室、患者姓名/身份证/拼音/五笔模糊查询）；② 查询存在 `PENDING_REFUND` 或 `REFUNDED` 状态发放单的就诊记录；③ 按就诊分页返回患者基础信息及退药状态；④ 本页就诊批量回填费用性质 `contractDisplay`（与发药/医生站卡片同口径） |
| **关键分支**    | 无匹配记录时返回空列表；无合同时 `contractDisplay` 为空（前端回落「自费」）                                                                                          |
| **失败分支**    | 查询条件非法或系统异常（EX-PHA-002-101）                                                                          |
| **查询侧说明** | 无写库；列表区依赖联查结果实时渲染                                                                                    |


### IF-PHA-02-03 查询退药明细


| 维度          | 说明                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| **触发前提**    | 用户从退药患者列表中选择某一就诊                                                                                                    |
| **主路径步骤**   | ① 按就诊 ID 查询该就诊下所有药品与耗材发放单；② 过滤状态为 `PENDING_REFUND` 或 `REFUNDED` 的记录；③ 关联负向请求单获取原单信息（药品/耗材名称、规格、批号、开单医生等）；④ 组装退药明细返回 |
| **关键分支**    | 可按 `itemTable` 过滤仅查看药品或仅查看耗材                                                                                        |
| **失败分支**    | 就诊 ID 无效或无权限（EX-PHA-002-101）                                                                                        |
| **查询侧说明** | 无写库；明细区展示待退药或已退药记录的全字段信息                                                                                            |


### IF-PHA-02-04 确认退药或拒绝退药


| 维度          | 说明                                                                                                                                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **触发前提**    | 用户勾选了退药明细项并点击「确认退药」或「拒绝退药」                                                                                                                                                                                                                                                   |
| **主路径步骤**   | ① 校验所选发放单当前状态为 `PENDING_REFUND`（BR-PHA-031）；② 幂等校验：排除已 `REFUNDED` 或 `DECLINED` 的记录（BR-PHA-032）；③ 分支处理：若为确认退药 → 状态推进为 `REFUNDED`，写入退药数量（全量）、退药人、退药时间；若为拒绝退药 → 状态推进为 `DECLINED`，写入拒绝原因（BR-PHA-035）；④ 追溯码：**`recordReturnInLines`** 按原发 OUT 每码镜像 IN（先退药行 `bus_no`，无则按拷贝 `trace_no` 回落未回冲 OUT；原发未扫则跳过，**不新建**主档）；⑤ 库存回补：按药品+批号+药房分组，**操作单位→拆零**后加回账面（**BR-PHA-034** / **BR-OPP-017** 同口径） |
| **关键分支**    | 药品与耗材在同一接口内分别处理，异常时各自记录错误信息                                                                                                                                                                                                                                                  |
| **失败分支**    | 状态不允许退药（EX-PHA-002-201）；重复退药（EX-PHA-002-202）；库存信息缺失（EX-PHA-002-203）                                                                                                                                                                                                          |
| **查询侧说明** | 发放单状态变更后发布领域事件，驱动退药工作台、库存查询、追溯码查询等QueryService刷新                                                                                                                                                                                                                                      |

## 7. 非功能性需求


| 类别              | 要求                                                                                            |

## 8. 测试要点（业务视角）


| 类别     | 要点                                                      |
| ------ | ------------------------------------------------------- |
| **正向** | 确认退药：单条药品退药、单条耗材退药、药品+耗材混合退药；拒绝退药：填写拒绝原因后状态推进为 DECLINED |
| **异常** | 重复确认退药（幂等拦截）；非 PENDING_REFUND 状态尝试退药；库存信息缺失场景           |
| **规则** | BR-PHA-031～037 组合；全量退回数量校验；追溯码拆分与入库正确性；库存回补数量准确性        |
| **并发** | 双开同一退药单连续提交（后到者应失败）                                     |
