## 1. 场景概述

### 1.0 业务意图（读透口径）

医生在**已选定就诊**下打开退费弹窗，同一列表可见「可申请」（已结算）与「可撤销」（退款中）行。申请路径：决定哪些支付单本单要退（产品**不支持半退保留**）；**耗材是否已执行**可在提交前单独门禁。申请只固化医嘱/收费侧过程态；资金冲正属执行阶段。撤销路径：对仍处于退款中的**整笔支付**还原到申请前药/耗/诊与收费态；**已退款或已退药（混有已退药）不可撤**。与本文四条接口解耦的执行侧见 **§1.3**「申请 vs 执行」。

### 1.1 目标与边界


| 维度       | 说明                                                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **在内**   | 按当前就诊加载**可申请/可撤销**账单行（读）；提交前**耗材已执行**门禁（读）；**提交退费申请**（写）；**撤销退费**（写：对称还原药/耗/诊与收费过程态） |
| **在外**   | **支付流水逆向单**、原支付**终态收口**、渠道/医保**实退**等**执行侧**能力；住院退费；医生站工具栏其余按钮（完诊/处方等） |
| **涉及域**  | Encounter（就诊上下文）；ChargeItem；PaymentReconciliation（账单行聚合视角）；MedicationRequest / MedicationDispense；DeviceRequest / DeviceDispense；ServiceRequest |
| **编排权威** | 以本文 **§2、§4** 为准；**产品「半退」**与支付状态机 **`PARTIAL_REFUNDED`** 的区分见 **§1.3** 与 **DM-FIN-002** §2.3 表下说明；**申请/撤销步不写支付逆向单**与初版实现对齐 |


### 1.2 角色与关键动作


| 角色       | 关键动作                                                        |
| -------- | ----------------------------------------------------------- |
| **门诊医生** | 选定患者 → 打开退费弹窗 → 勾选已结算支付单提交申请，或勾选退款中支付单**撤销退费**（均须与 **IF-DRA-01**「支付锚点 + 收费行锚点」成套一致；不支持半退/半取消） |
| **系统**   | 按就诊解析支付挂载收费项；按勾选集合执行门禁与申请/撤销编排                                 |


### 1.3 术语与口径约定


| 术语                     | 口径                                                                                                                                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **申请退费 / 撤销退费**        | 本文仅指 **§1.4** 列出的**四条**后端能力；**不包含**退费页初始化、已结算患者分页、退费历史查询、重开待收查询、综合可退校验等其它接口                                                                                                                                                                            |
| **撤销退费**               | 对仍处**退款中**的整笔支付，对称还原申请时写入的药/耗/诊侧事实，并将拟退收费项回**已结算**；已退款、已退药（或同支付混有已退药）拒绝；耗材若申请前已由护士取消执行，撤销后**不自动恢复已执行** |
| **产品「半退」**             | **全链路语义**（以 **DM** 为权威）：以 **`paymentId`（一笔支付 + `charge_item_ids` 快照）** 为粒度——仅选退部分行时 **资金侧对该笔支付整单冲退**；**未选退行**须 **ChargeItem 账单重生成**（新 `PLANNED` + `refund_id` 链回，**与源原单业务事实一致**）再接续预结算/结算（**BR-PMR-017**、**BR-CHG-015**）。**其中**：**ChargeItem 账单重生成、拟退行过程态**由 **IF-DRA-03**（及初版申请提交流程）覆盖；**支付逆向单及原单资金终态**不在本请求内，属**执行/收口**另册 |
| **申请 vs 执行**            | **申请**（本文 IF-DRA-01～03）：拉可退清单、耗材门禁、提交申请（药/耗/诊与收费项过程态等）。**执行**：支付域逆向流水、原单 `REFUNDED`/`PARTIAL_REFUNDED` 收口、渠道退款等——**不在**初版申请提交路径内调用支付编排（与 **openhis-sever** 现实现一致），由收费/财务后续用例或独立接口承担；详设须写清与 **DM-FIN-002** §6.1.5～6.1.6 的衔接 |
| **「本单退费」标记**           | 提交体对每一收费行携带布尔语义：**为真**表示本行纳入本次退费申请；**为假**表示本行**保留**，走**账单重生成**路径（与初版 `refundFlg` 语义对齐：实现里「未退费」行进入 `creatList`）                                                                                                                                                |
| `PARTIAL_REFUNDED` | **支付流水**状态机终态语义（仍可分次冲退等），**不是**产品「半退」的同义词 |
| **DM 路径**              | `docs/领域/DomainModel/` 下对应文件                                                                                                                                                                                                             |

| **BR-DRA-008** | **IF-DRA-03**：全部拟退收费项持久化后进入**退费中**过程态                                                                      | IF-DRA-03             |

| **BR-DRA-010** | **IF-DRA-03**：药/耗/诊退费或释放类编排（**BR-DRA-005～007**）**仅**针对「本单退费」为**真**之收费行所解析出的请求/发放；「本单退费」为**假**之行**仅**走保留账单重生成（**BR-DRA-004**），**不得**再次进入退药/退耗/诊疗退费分支（**目标契约**；与初版实现差异见 **§4 IF-DRA-03** 表下说明） | IF-DRA-03             |

| **BR-DRA-021** | **IF-DRA-03** 成功响应须按 **paymentId** 返回执行衔接摘要：`refundingChargeItemIds`、`preservedNewChargeItemIds`、`halfRefundOnPayment`；供收费窗执行 AS（**AS-OP-FIN-003**，另册）整单冲正、原单 `REFUNDED` 收口及半退当场 pre+settle | IF-DRA-03             |
| **BR-DRA-022** | **禁止分次退费（口语「半退」）**：**IF-DRA-03** 对每一 **`paymentId`**，提交体须覆盖该支付快照下**全部** `SETTLED` 行（拟退或保留均可）；不得只提交部分行留待后续再申请。与 **AS-OP-FIN-003** **BR-REF-021** 对齐 | IF-DRA-03             |
| **BR-DRA-023** | **IF-DRA-01** 同时返回同就诊下可申请行（`SETTLED`）与可撤销候选行（`REFUNDING`）；**不**返回已退款终态行 | IF-DRA-01 |
| **BR-DRA-024** | **IF-DRA-04**：撤销粒度与申请一致——以 **`paymentId` 整笔**为准，提交体须覆盖该支付下全部 `REFUNDING` 行；禁止半取消 | IF-DRA-04 |
| **BR-DRA-025** | **IF-DRA-04**：任一行已为 `REFUNDED`，或同支付下任一药/耗待退发放已为**已退药/已退耗**，则**整笔支付禁止撤销** | IF-DRA-04 |
| **BR-DRA-026** | **IF-DRA-04** 对称还原申请侧事实：未发药作废→恢复待发药；待退药对冲行作废且原已发完成保留；负向药/耗/诊单作废；诊疗停嘱恢复；拟退收费项 `REFUNDING→SETTLED`；耗材不自动恢复「申请前护士已取消执行」之已执行态。**不**按收费行处方号回写 `MedicationRequest`（药品号真源在请求侧；收费行仅为结算快照，见 **AS-OP-FIN-002 · BR-OPC-026**） | IF-DRA-04 |
| **BR-DRA-027** | **IF-DRA-04** UI/提交不得将「可申请」与「可撤销」支付单混在同一请求 | IF-DRA-04 |


### 1.7 与收费窗执行衔接（申请 vs 执行）

| 维度 | 说明 |
| --- | --- |
| **申请侧（本文）** | 保留行 → 新 `PLANNED`+`refund_id`；拟退行 → `REFUNDING`+药/耗/诊；**不写**支付逆向单、**不**改原支付主单终态 |
| **执行侧（另册 AS-OP-FIN-003）** | `requestOutpatientRefund` → `completeOutpatientRefund`（逆向单，**唯一**退费完成事件）→ `completeOutpatientBillRefund` → 半退时对 `preservedNewChargeItemIds` 当场 pre+settle；失败 `abortOutpatientRefundAttempt`；原单保持 `SUCCESS` |
| **读侧对齐** | 门诊收银 **IF-OPC-03** 与本文 **IF-DRA-01** 共用「排除被替代 `SETTLED`」口径（**BR-REF-020**） |
| **退号（独立）** | **挂号退号整单全退**见 **`AS-OP-FIN-001` IF-REG-10** 与 **DM-FIN-002** `completeRegistrationCancelRefund`；**无半退**、不走本文保留链/拟退编排，**禁止**与门诊账单退费混用 |
| **非目标** | 初版 openhis 收费窗 `refund-payment` 单体写库路径；**退号退费**不在本文四条 IF 内 |

### IF-DRA-01 加载可申请/可撤销退费账单行

### IF-DRA-03 提交退费申请


| 维度          | 说明                                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **触发前提**    | 已勾选拟退集合；建议已通过 **IF-DRA-02**（若 UI 启用）                                                                                                            |
| **主路径步骤**   | 对「本单退费」为**假**的收费行：**重生成**新 **ChargeItem（账单行）** 及关联 **请求/发放** 等，**凡重生成的业务根**须与**源原单行**业务事实**一致（复刻）**，新行入口态为待再结算并 `refund_id` 链回 → 对「本单退费」为**真**之收费行按药品/耗材/诊疗执行分支编排（药/耗负向单 `CANCELLED`；诊疗已完成建负向 `ServiceRequest` 否则 stop 原单；**BR-DRA-010**）→ 将拟退收费项批量置**退费中** |
| **关键分支**    | 原单本身已是负向退药/退耗/退诊疗单时门闩失败（**EX-DRA-301～303**）；同批多行共锚同一原请求**幂等复用**负向单，不视为重复失败                                                                                                                             |
| **失败分支**    | 原单已是负向单（EX-DRA-301～303）；分次退费（EX-DRA-304）；其它业务失败（EX-DRA-399）                                                                                                        |
| **查询侧说明** | 收费项过程态、发药/退药与执行队列、费用摘要等由各领域事件或列表刷新消费                                                                                                            |

> **实现对齐（2026-05-28）**：`DoctorStationRefundApplicationAppService#submitOutpatientRefundApplication` 第二段拟退集合 **R** 仅含 `refundThisEncounter=true` 之行（**BR-DRA-010**）；保留行仅走 **BR-DRA-004** 克隆链。半退同批混合真/假须纳入回归。

### IF-DRA-04 撤销退费


| 维度          | 说明                                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **触发前提**    | 已勾选退款中支付集合；不得与可申请支付混选（**BR-DRA-027**）                                                                                                            |
| **主路径步骤**   | 校验整笔支付覆盖且均为退款中（**BR-DRA-024**）→ 门禁：无已退款收费行、无已退药/已退耗发放（**BR-DRA-025**）→ 对称还原药/耗/诊（**BR-DRA-026**）→ 拟退收费项回已结算 |
| **关键分支**    | 未发药路径恢复待发药；已发药待退路径作废待退对冲行；诊疗已完成路径作废负向单，未完成路径恢复停嘱                                                                                                                             |
| **失败分支**    | 已退款/已退药不可撤（EX-DRA-501）；半取消（EX-DRA-502）；混选申请与撤销（EX-DRA-503）；其它（EX-DRA-399）                                                                                                        |
| **查询侧说明** | 收费项回已结算、发药/退药与执行队列由各领域事件或列表刷新消费                                                                                                            |

## 7. 非功能性需求


| 类别              | 要求                                                                                                                                        |

| **审计**          | 申请与撤销须可追溯至操作者与就诊及收费行集合                                                                                                                       |
