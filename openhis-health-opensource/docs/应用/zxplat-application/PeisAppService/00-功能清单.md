## 一、模块定位

### 1.1 是什么

ZXPlat **自研健康体检管理**：**约 14 个核心主页面 AppService** + 2 个无页面服务（预约衔接、LIS/PACS 外发）。

覆盖：**个检/团检登记 →（HIS 收费）→ 分科检查 → LIS/PACS 结果汇聚 → 总检 → 报告打印发放** 主路径。

### 1.2 不是什么


| 不在 PEIS 核心                   | 归属                                 |
| ---------------------------- | ---------------------------------- |
| **个检/团检收费、退费、发票、折扣、日结**      | **health · HIS 主程序**（门诊/体检收费 AS）   |
| **费用/营收/发票统计、主任收入查询**        | health 收费 AS + PrintTemplate（AS-BAS-PRT）        |
| 体检 **预约号源、时段容量、到检签到写侧**      | zxplat-module-booking H 线                  |
| LIS 采样/上机/检验审核、PACS 登记/待摄/影像 | `LisAppService` / `PacsAppService` |
| 导引单/报告 **版式模板** 渲染           | PrintTemplate（AS-BAS-PRT）                   |
| 全院患者建档、门诊挂号（非体检专线路径）         | health · 门诊 AS                     |

| 传染病报卡、医保结算细则                 | 各自 Module                          |

## 二、阶段与优先级


| 阶段     | 目标                                            | 能否替代遗留（sdpeis）                                 |
| ------ | --------------------------------------------- | ---------------------------------------------- |
| **P0** | 个检登记 + 分科诊台 + 总检 + 报告打印 + LIS/PACS 外发回写 + HIS 收费态衔接 | 替代 NENU 院点 **当前启用** 主路径（收费页归 HIS）              |
| **P1** | 团检合同/批次/登记 + 复查 + 危急值 + **外发路由（可选）** + booking 到检衔接 | 替代 `schoolGroup/*`、`listReview` |
| **P2** | 体检业务统计、异常分析、历史对比（**不含**费用/营收报表）           | 替代 `statistic/*` 中非财务部分（遗留多为注释菜单）            |
| **P3** | 健康证、体检卡等院点选配 | 遗留注释菜单中的边缘能力 |


### P0 完工定义（PEIS 首版）

- 个检：创建 **`Encounter(PE)`** + 按套餐 **`ActivityDefinition`** 展开 **`ServiceRequest`** → **HIS 收费完成**（Client 回读 `ChargeItem`）→ 打印条码/导引单（report）
- 分科诊台：按科室录入 **`cln_observation`**（小项）、常见结果、分科结论；可触发 LIS/PACS 外发
- LIS/PACS：至少 1 种对接方式完成 **申请发送 + 结果回写** 到体检单
- 总检：综述、结论、审核完成；生成 `**DiagnosticReport**
- 报告台：个人报告 PDF 预览/打印
- 可选：读取 booking **到检签到** 自动激活流水（有 H 线时）

**P0 IF 契约进度（v1.8）**：**28** 项 ✅（PEIS AS+SDD，含 INT-05）。成码 / Flyway 见各 AS §3 Gap。

## 四、体检进度表达（多模型联合，不扩展 `Encounter.status_enum`）

> **硬约束**：`Encounter(class=PE)` **仅使用** [DM-ADM-002](./DM-ADM-002-Encounter-就诊.md) **通用** `status_enum`（如 `planned` / `in-progress` / `finished` / `cancelled`）。**禁止**为 PE 新增 `PENDING_MASTER`、`MASTER_REVIEW` 等专用枚举值。  
> 业务上的「待总检 / 总检中 / 已发放」由 **多事实模型联合** 或 **只读聚合视图** 表达（详见 [04-FHIR领域模型.md](./04-FHIR领域模型.md) §3.2）。

| 业务维度 | 承载模型 | 表达 |
|----------|----------|------|
| 预约未到检 | `Appointment`（booking） | 有预约、无 PE `Encounter` 或 Encounter 仍为 `planned` |
| 登记 / 收费 | `Encounter(PE)` + `ChargeItem`（Client） | 已登记；**未收费**时 DES 可阻塞（REG-08） |
| 分科执行 | `ServiceRequest` + **`PeisServiceRequestExt.exec_status_enum`** | `pending` → `checked` → `abandoned` / `deferred` |
| LIS/PACS 外发 | **`PeisServiceRequestExt`** `lis/pacs_dispatch_enum` | `notSent` → `sent` → `resultReceived` |
| 总检 / 报告 | `DiagnosticReport.status_enum` | `partial` → `preliminary` → `final` |
| 报告发放 | `DiagnosticReport + **`PeisReportGrantExt`**（CUS，可选） | 打印/签收/邮寄态 |
| 复查 | `Task`（`focus=Encounter`）或 **`PeisRecheckExt`** | 复查中；完成后关闭 Task |

**列表/统计口径**：各 AS（DES/MAS/REP/RPT）通过 **`PeisEncounterProgressQuery`**（只读聚合，CUS 或 QueryService）联合上述字段输出「待检 / 待总检 / 已完成」等 **展示态**，**不回写** Encounter 专用 status。

```text
Encounter(PE): planned → in-progress → finished | cancelled
  ├─ ChargeItem: 收费完成（Client）
  ├─ ServiceRequest[] + Ext: 分科项目执行
  ├─ DiagnosticReport: 总检报告 final
  ├─ PeisReportGrantExt: 发放签收（可选）
  └─ Task: 复查（可选）
```
