## 登录会话实例（多开浏览器）

`login` / `impersonate` 为每个 Token 对签发独立 `loginSessionId`（Access 与 Refresh 相同）。`selectTenant` / `selectHospital` / `selectOrganizationUnit` 写入 **进程内** `LoginInstanceScopeStore`（按 JWT 实例隔离），**不改库表**。

因此同一账号可以：浏览器 A 挂住院内科、浏览器 B 挂检验科，互不覆盖。`refreshToken` 必须沿用同一 `loginSessionId`。旧 Token 无 claim 时回落 `u:{userId}`（仍按用户一份）。进程重启后内存清空，前端进页会再次 `select*` 即可恢复。

实现注意：`LoginSessionIdRequestContext` 由 JWT 过滤器写入，**禁止**在 `RequestIdInterceptor.preHandle` 清空（否则会回落到 `user_id` 一人一行而串科）；仅请求结束清理。

## Configuration

```yaml
app:
  jwt:
    secret: ${JWT_SECRET:...}
    access-token-expiration: 7200000          # 2h
    refresh-token-expiration: 604800000       # 7d
    impersonation-access-token-expiration: 1800000  # 30min
  session-store:
    type: jdbc                                # jdbc | memory
    cache:
      enabled: true
      expire-after-write-minutes: 2
      maximum-size: 5000
  cache:
    user:
      expire-after-write: 15m
      maximum-size: 2000
```
