# Auto API

> AppService 自动暴露为 REST API 的机制与调用约定。

## 1. 概述

ZXPlat 采用 ABP **Conventional Controllers** 思路：所有以 `AppService` 结尾的 `@Service` Bean 由 `AppServiceControllerRegistrar` 注册为 HTTP 端点，无需手写 Controller。

**实现类**：`com.zxplat.framework.web.api.AppServiceControllerRegistrar`  
**模块**：包 `web`

## 2. 路由规则

| 项 | 规则 |
|----|------|
| HTTP 方法 | **POST**（统一） |
| 路径 | `/api/app/{serviceName}/{methodName}` |
| serviceName | 类名去掉 `AppService` 后首字母小写，如 `UserAppService` → `user` |
| 请求体 | **JSON 数组**，按方法参数顺序：`[arg1, arg2, ...]` |
| 单参数 | 仍用数组：`[{ ... }]` |
| 无参数 | `[]` 或省略 body |

### 示例

| Java | HTTP |
|------|------|
| `UserAppService.getList(UserQueryRequest req)` | `POST /api/app/user/getList` |
| `UserAppService.getById(IdRequest req)` | `POST /api/app/user/getById` |
| `TenantAppService.enable(Long id)` | `POST /api/app/tenant/enable` body: `[123]` |
| `AuthAppService.login(LoginRequest req)` | `POST /api/app/auth/login` |

## 3. 响应格式

统一包装为 `Result<T>`：

```json
{
  "success": true,
  "data": { },
  "message": null,
  "errorCode": null,
  "errors": null
}
```

失败时 `success: false`，含 `errorCode` 与 `message`。分页数据在 `data` 中为 `PagedResult`：

```json
{
  "success": true,
  "data": {
    "items": [],
    "totalCount": 100
  }
}
```

## 4. 认证与 Header

| Header | 说明 |
|--------|------|
| `Authorization` | `Bearer {accessToken}` |
| `X-Tenant-Id` | 客户端可传，但**以服务端登录会话租户为准**（见 [多租户.md](./主题/多租户.md)） |

### 兼容登录路径

Identity 模块同时保留 REST 风格路径（非数组 body）：

| 路径 | 说明 |
|------|------|
| `POST /api/auth/login` | 登录 |
| `POST /api/auth/logout` | 登出 |
| `POST /api/auth/refresh` | 刷新 Token |

## 5. 扩展 Module 未安装时的行为

当调用某 AppService 但对应扩展 Module 未启用/未装配时，包 **core** 的 `ExtensionModuleAppServiceRegistry` 根据 `META-INF/zxplat/module-metadata.json` 返回友好错误（非 404 空响应）。

## 6. OpenAPI / Swagger

- Swagger UI：`/swagger-ui.html`
- OpenAPI JSON：`/v3/api-docs`
- 动态扫描已注册的 AppService 方法生成文档

配置见 `zxplat-app` 的 `springdoc.*`。

## 7. 调用示例

### 创建用户

```bash
POST /api/app/user/create
Authorization: Bearer {token}
Content-Type: application/json

[{
  "userName": "testuser",
  "email": "test@example.com",
  "password": "Test@123456"
}]
```

### 分页查询

```bash
POST /api/app/user/getList
Authorization: Bearer {token}
Content-Type: application/json

[{
  "pageNo": 1,
  "pageSize": 20,
  "keyword": "张",
  "organizationId": "322663218269917184"
}]
```

### 按 ID 操作（IdRequest）

```bash
POST /api/app/user/getById
Authorization: Bearer {token}
Content-Type: application/json

[{"id": 1}]
```

## 8. 日志

| 配置键 | 默认 | 说明 |
|--------|------|------|
| `app.logging.api-params-enabled` | `true` | 是否记录 `/api/app` 请求体 |
| `app.logging.api-params-max-length` | `2000` | 请求体日志截断长度 |

访问摘要 logger：`zxplat.access`（见 [日志与监控.md](./运维/日志与监控.md)）。

## 9. 开发新 API

1. 在 `application` 层新建 `XxxAppService`，加 `@Service`。
2. 使用 public 方法；避免 static、Object 继承方法。
3. 重启后自动注册；在 Swagger 中验证。
4. 查询方法建议以 `get`/`list`/`find` 开头以命中只读事务。
