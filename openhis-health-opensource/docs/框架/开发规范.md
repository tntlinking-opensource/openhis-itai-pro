# 开发规范

> ZXPlat / ZXPlat 后端编码约定，适用于框架模块与 HIS 业务模块。

## 1. 命名规范

### 1.1 类命名

| 类型 | 规则 | 示例 |
|------|------|------|
| 实体 | 名词，无 Entity 后缀 | `User`、`Role` |
| AppService | 以 `AppService` 结尾 | `UserAppService` |
| Repository | 以 `Repository` 结尾 | `UserRepository` |
| 输出 DTO | `XxxDto` | `UserDto` |
| 创建请求 | `CreateXxxRequest` | `CreateUserRequest` |
| 更新请求 | `UpdateXxxRequest`（含 `id`） | `UpdateUserRequest` |
| 查询请求 | `QueryXxxRequest` 或 `XxxQueryRequest` | `UserQueryRequest` |
| 领域 Command | `CreateXxxCommand` 等，放 `domain.command` | `CreateUserCommand` |
| 领域 Query | `XxxQuery`，放 `domain.query` | `UserQuery` |

### 1.2 方法命名

| 操作 | 前缀 |
|------|------|
| 查询 | `get`、`find`、`list`、`query`、`search`、`count`、`exists` |
| 创建 | `create` |
| 更新 | `update`（id 在 Request 内，避免 `update(Long id, ...)` 双参） |
| 删除 | `delete` |
| 状态 | `enable`、`disable`、`lock`、`unlock` |

**多参接口**：合并为单个 `XxxRequest`，便于 Auto API 传参。

### 1.3 包结构

```text
com.zxplat.{product}.{module}/
├── domain/
│   ├── entity/
│   ├── repository/
│   ├── service/       # 领域服务 / Manager
│   ├── command/
│   └── query/
├── application/
│   ├── dto/
│   ├── request/
│   ├── mapper/        # MapStruct
│   └── XxxAppService.java
└── infrastructure/
    └── ...
```

框架模块包根：`com.zxplat.framework.{module}`。

## 2. 分层职责

| 层 | 职责 |
|----|------|
| **Domain** | 实体、Repository 接口、领域服务、Command/Query |
| **Application** | AppService、DTO、Request、Mapper |
| **Infrastructure** | Repository 实现、JWT、外部集成 |
| **Web** | 框架侧由 包 `web` 统一提供 Auto API，业务模块通常无需手写 Controller |

## 3. 对象映射

**禁止使用 `BeanUtils` 或框架 `ObjectMapper.copyProperties`。**

所有映射使用 **MapStruct**：

```java
@Mapper(componentModel = "spring", nullValuePropertyMappingStrategy = NullValuePropertyMappingStrategy.IGNORE)
public interface UserMapper {
    UserDto toDto(User user);
    CreateUserCommand toCommand(CreateUserRequest request);
}
```

## 4. 异常处理

使用 `zxplat-framework` 统一异常，由 `GlobalExceptionHandler` 转为 `Result`：

| 异常 | 用途 |
|------|------|
| `BusinessException` | 业务规则违反 |
| `EntityNotFoundException` | 实体不存在 |
| `ValidationException` | 参数校验失败 |
| `UnauthorizedException` | 未授权 |

## 5. 实体基类

业务实体继承 `BaseAuditedEntity`，多租户实体实现 `IMultiTenant`：

```java
@Entity
@Table(name = "adm_xxx")
public class MyEntity extends BaseAuditedEntity implements IMultiTenant {
    @Column(name = "tenant_id")
    private Long tenantId;
}
```

## 6. AppService 约定

1. 类名以 `AppService` 结尾，标注 `@Service`。
2. 方法自动暴露为 `POST /api/app/{serviceName}/{methodName}`（见 [自动接口.md](./自动接口.md)）。
3. 写操作由 `AppServiceAspect` 自动开启事务；`get*`/`list*`/`find*` 等由 `ReadOnlyTransactionAspect` 只读事务（见 [工作单元.md](./主题/工作单元.md)）。
4. 分页返回 `PagedResult<T>`，统一响应用 `Result<T>`。

## 7. Flyway 迁移

- HIS 核心脚本：`zxplat-core/zxplat-domain/src/main/resources/db/migration/health/`
- 命名：`V{序号}__{描述}.sql`，序号递增
- 框架相关表（`whale_*`）在 `V1__Init.sql` 及后续 health 脚本中维护
- 业务扩展 Module 各自目录 + `META-INF/zxplat/flyway-module.json`

## 8. 分页请求

查询 Request 继承 `BaseQueryRequest`：

```java
public class UserQueryRequest extends BaseQueryRequest {
    private String keyword;
}
```

`pageIndex` 从 0 开始，`pageSize` 默认 10。

## 9. 权限

- 权限名与菜单对齐，授予通过 `PermissionAppService`（Provider：`R` 角色 / `U` 用户）。
- 服务端校验使用 `PermissionChecker` 或 Spring Security 配置。

## 10. 代码审查检查点

- [ ] 无 BeanUtils / ObjectMapper.copyProperties
- [ ] AppService 方法入参为 Request/DTO，无过多散参
- [ ] 实体继承审计基类，租户字段正确
- [ ] Flyway 版本号未冲突
- [ ] 新 AppService 方法名符合只读/读写 AOP 前缀约定
