# Whale-MRMS 功能清单

> 基于 **Whale 框架 + whale-health（HIS）+ whale-emr（文书）+ whale-chs（医保上报）** 技术栈规划，用于指导概要设计与编码排期。  
> **版本**：v0.1 | **日期**：2026-05-29

---

## 一、模块定位与边界

### 1.1 MRMS 是什么

**病案管理（MRMS）** 管理一次住院就诊对应的**病案主档**全生命周期：病案号、病案首页结构化数据、编码、质控、归档、检索调阅、借阅复印，以及对外上报（医保 4401 等）。

与 **电子病历（EMR）** 的分工：

| 维度 | whale-emr | whale-mrms |
|------|-----------|------------|
| 核心对象 | 文书（Document）、模板、版本 | 病案主档（CaseRecord）、病案首页、归档包 |
| 主要内容 | 自由书写 / 结构化病历 JSON | 国标病案首页字段、ICD 编码、归档元数据 |
| 书写场景 | 医生站病程、入院记录等 | 病案首页填写/审核（可在医生站嵌入，逻辑归 MRMS） |
| 锁定粒度 | 单份文书提交/锁定 | 病案级归档锁定（归档后关联文书只读） |
| 质控 | 文书内必填/违禁字等编辑态校验（可选） | 病案级完整性、时效性、首页逻辑质控 |
| PDF | 单文书 OpenPDF 渲染 | 病案卷宗合并预览/导出（编排 EMR PDF） |
| 医保上报 | 不负责 | 组装 4401 载荷，经 `chs-api` 发出 |

与 **whale-health** 的分工：

| 能力 | 归属 | MRMS 消费方式 |
|------|------|----------------|
| 患者、就诊、入出院 | health-domain | Port / 读模型查询 |
| 诊断、手术、费用汇总 | health-domain | 首页自动取值 |
| 转科/离院里程碑 | EncounterHistory（DM-CUS-004） | 事件订阅或 RM 查询 |
| 住院医生站 UI 壳 | health-application + 前端 | 嵌入 MRMS AppService |

与 **whale-chs** 的分工：MRMS 负责**业务数据组装与上传编排**；HTTP/国密/签到由 chs-impl 承担。

### 1.2 用户与角色

| 角色 | 典型操作 |
|------|----------|
| 住院医生 | 填写/提交病案首页、响应质控缺陷 |
| 病案编码员 | 首页编码校对、ICD 审核 |
| 病案管理员 | 接收、质控、归档、检索、借阅审批 |
| 医务/质控 | 规则配置、质量统计 |
| 医保办 | 触发/查看 4401 上传结果 |

### 1.3 范围外（首期不做）

| 项 | 说明 |
|----|------|
| 门诊病案 | 首期仅**住院病案**；门诊病历归 EMR |
| 纸质病案扫描 OCR | 三期以后可选 |
| DRG 分组引擎 | 仅预留首页字段与接口，不内置分组算法 |
| 独立病案仓储 WMS | 实体库房货位管理不在首期 |
| 4401 以外的全部医保交易 | 首期仅 4401；4701 电子病历上传仍归 EMR/协同方案 |

## 二、阶段与优先级

| 阶段 | 说明 | 目标 |
|------|------|------|
| **P0** | 地基 | 病案主档创建、状态机、首页骨架保存、与就诊绑定 |
| **P1** | 核心业务 | 首页自动取值、编码、提交/接收、基础检索 |
| **P2** | 质控与归档 | 质控规则、缺陷闭环、归档锁定、逾期预警、卷宗 PDF 预览 |
| **P3** | 合规与对外 | 借阅复印、审计、医保 4401 上传、统计报表 |
| **P4** | 增强 | 高级质控、无纸化签收、DRG 对接、区域平台扩展 |

**需求追溯**：P1～P2 覆盖 SRS `FR-MED-001`；P3 覆盖 `FR-MED-002`。

## 四、功能明细

### 4.1 病案主档（CaseRecord）

| 序号 | 功能项 | 描述 | 实现要点 | 优先级 | 状态 |
|------|--------|------|----------|--------|------|
| 1.1 | 病案主档创建 | 患者出院（或满足配置条件）时生成病案主档，关联 `patientId`、`encounterId` | 订阅 `DischargeMilestoneRecordedEvent` 或出院结算事件；幂等按 encounter | P0 | ☐ |
| 1.2 | 病案号 | 分配院内病案号 `medcasno`（可配置规则：年度+流水等） | 领域服务发号，租户内唯一 | P0 | ☐ |
| 1.3 | 病案状态机 | 草稿 → 已提交 → 已接收 → 质控中 → 已归档 / 退回 | 枚举 code 持久化；状态迁移写审计 | P0 | ☐ |
| 1.4 | 主档摘要 | 列表展示：姓名、住院号、入出院日期、科室、主治、诊断摘要、状态 | 读模型或主档冗余字段；分页查询 | P1 | ☐ |

| 1.6 | 病案质量评级 | 甲/乙/丙等（首页质控完成后写入） | 字典项；与 6.x 质控结果联动 | P2 | ☐ |

## 五、非功能需求

| 类别 | 要求 |
|------|------|
| 多租户 | 病案主档、首页、病案号规则均租户隔离 |
| 幂等 | 同一 `encounterId` 仅一条有效病案主档；上传 4401 可重入 |
| 性能 | 病案列表检索 P95 &lt; 1s（10 万级主档，索引按 tenant + 出院日期 + 科室） |
| 安全 | 病案查询/预览/借阅全链路审计；RBAC 按角色+科室 |
| 可插拔 | 与 whale-health 同进程部署；Port 抽象便于单测 |
| 数据一致性 | 首页自动取值不覆盖「人工修订」字段（`fillSource` 标记） |

## 七、首期 MVP 建议（Wave 1）

**目标**：出院患者能完成「首页填写 → 提交 → 病案室接收 → 简单检索」，不含借阅与医保上传。

| 包含 | 不包含 |
|------|--------|
| 1.1～1.4、2.1～2.4、3.1～3.4、3.6、3.8、4.1～4.3、5.1～5.4、8.1 | 6.x 完整质控、7.x 归档、9.x 借阅、10.x 4401、11.x 统计 |

**Wave 1 验收**：

1. 出院后自动生成病案主档与病案号  
2. 首页可保存、自动取值、ICD 编码  
3. 医生可提交，病案室可接收/退回  
4. 病案室可按住院号/姓名/日期检索列表
